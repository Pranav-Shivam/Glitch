Hashing: Hash Maps and Hash Sets

A hash map (dictionary) or hash set turns "have I seen this before, and what did I learn about it?" from a scan of everything so far into one O(1) lookup. That trades O(n) memory for time, and it turns the O(n²) "compare every pair" loop into one O(n) pass.

Part 1First Principles

One-paragraph summary

A hash map stores key -> value pairs; a hash set stores only keys. Both use a hash function to turn a key into a number, and that number tells the structure which slot to look in, so insert, lookup and delete take O(1) on average no matter how many items are stored. In problems this means: instead of re-scanning the past to answer "have I seen a partner for this element?", you remember the past in a map, keyed by exactly the thing you will ask about later. That turns O(n²) into O(n) at the cost of O(n) extra memory.

Terminology

TermMeaning
Key / valueThe key is what you look things up by; the value is what you stored for it. A set has keys only.
Hash functionA function that turns a key into an integer (the hash code). Equal keys must give equal hash codes. Python: hash(x). Java: x.hashCode().
Bucket / slotOne position in the internal array. The hash code is reduced to a bucket number (roughly hash % capacity).
CollisionTwo different keys land in the same bucket. Every real hash table has them and has a plan: Java chains entries in a list per bucket; Python probes for the next free slot.
Load factorHow full the table is (items / buckets). When it passes a limit (Java 0.75, Python about 2/3) the table allocates a bigger array and re-inserts everything (resize / rehash).
HashableCan be used as a key. Python: immutable things (int, str, tuple of hashables, frozenset). A list or dict is NOT hashable. Java: any object, but you must be sure equals and hashCode agree; arrays use identity, so int[] is a bad key.
Frequency mapA map from item to how many times it occurred (a counter).
ComplementThe partner that would complete an answer: for a target sum it is target - x.
Canonical formOne agreed representation for a whole class of equivalent things, used as the key. All anagrams share one canonical form: their sorted letters, or their letter-count tuple.
Prefix sumprefix[i] = sum of the first i elements. A subarray sum is a difference of two prefix sums. (Introduced in the Arrays topic.)

What it is, and why it exists

Arrays give you instant access by position: a[5] is O(1). But most questions are not about position. They are about value: "is 7 anywhere in here?", "how many times did "a" appear?", "where did I last see this number?". On an array, a value question costs O(n) because you scan. A hash table gives you instant access by value. Think of it as an array whose index is computed from the key.

How it works inside (conceptual)

  • Insert/lookup/delete: compute the hash code, pick a bucket, compare the key (with == / equals) against the few entries there. Because buckets stay short, this is O(1) on average.
  • Collisions: Java's HashMap keeps a small linked list per bucket (turned into a balanced tree when a bucket reaches 8 entries and the table has at least 64 buckets, so the worst case per bucket is O(log n) for comparable keys). Python's dict and set use open addressing: if the slot is taken by a different key, probe another slot by a fixed rule.
  • Resize: when the table gets too full it doubles and every entry is re-placed. One resize is O(n), but they happen after 1, 2, 4, 8, ... inserts, so the total is O(n) for n inserts (Part 3).
  • Order: Python 3.7+ dict remembers insertion order (language guarantee); Python set does not guarantee any. Java HashMap/HashSet give no order guarantee at all (use LinkedHashMap for insertion order, TreeMap for sorted order).
  • String hashing cost: hashing a string reads every character, so a lookup with a key of length L costs O(L), not O(1). This matters for Group Anagrams (Part 7).

The core invariant

Invariant (say this aloud)

After processing elements 0 .. i-1, the map or set holds exactly the facts about those elements that the current element could ask about, stored under the key you will ask with. So the question "does anything earlier match me?" is one lookup instead of a scan.

Everything in this topic is a choice of two things: what is the key (what will I ask by?) and what is the value (what do I need to know once I find it?). Get these two right and the loop is three lines.

When to use it

  • You keep asking "have I seen X?", "how many X?", or "where was X?" about earlier data.
  • The inner loop of your brute force is a search for a specific value. A search for a specific value is exactly what a hash table replaces.
  • You need to group items by an attribute (anagram class, remainder, first letter).
  • You need to detect duplicates or cycles (a state seen twice).
  • Order does not matter, or you only need the order you inserted in.

Common interview tricks

  • Check before you insert when the answer must use two different elements (Two Sum). Insert first and [3], target 6, returns the same element twice (Part 10, demonstrated).
  • Seed the map with the empty prefix. {0: 1} (count) or {0: -1} (first index) lets a subarray start at index 0 (Type E/F).
  • Tuple (Python) or String (Java) keys let you key by a pair or a signature. int[]/List keys in Java work only if you want identity or content equality respectively: use List<Integer> (content equality) or Arrays.toString if you need a signature.
  • **int[26] / int[128]** beats a map for lowercase letters / ASCII: faster, no boxing. Say the assumption aloud ("lowercase English only").
  • **Dict comprehension / Counter equality** make tiny solutions: Counter(a) == Counter(b) is an anagram check.

Why O(1) on average

A good hash function spreads keys evenly over the buckets. If the table keeps its load factor below a constant (Java 0.75, Python about 2/3), the expected number of entries in any bucket is at most that constant. So a lookup compares the key against a constant number of entries: O(1). It is an average-case promise over keys, not a guarantee for every input.

Amortised: why resizing does not break it

When the table fills, it allocates an array twice as large and re-inserts every entry: that one insert costs O(n). But this happens only when the size reaches 1, 2, 4, 8, ..., so for n inserts the total copying is at most 1 + 2 + 4 + ... + n < 2n. Spread over n inserts that is O(1) per insert, amortised. This is the same argument as a dynamic array (Arrays topic).

 inserts so far:   1   2   4   8   16  ...   n
 resize copies:    1   2   4   8   16  ...   n/2      sum  <  2n
 -> total work for n inserts  =  n (the inserts)  +  <2n (copies)  =  O(n)
 -> per insert                =  O(1) amortised

Worst case, honestly

If an adversary (or bad luck) makes all keys collide, lookups degrade. Measured with a key class whose __hash__ always returns 1: building a set of 500, 1,000 and 2,000 such keys took 0.0044 s, 0.0186 s and 0.0709 s, so each doubling of n about quadruples the time: O(n²) for n inserts. That is why we say "O(1) average". In interviews you state "average O(1); worst O(n) with pathological collisions, rare in practice and mitigated in Java by treeified buckets". Python randomises string hashes per process, which defends against deliberately crafted collisions.

Code that looks worse than it is

Longest Consecutive Sequence has a while inside a for, which looks O(n²). It is O(n): the while only starts at the beginning of a run (x - 1 not in set), and each element is stepped over by exactly one run. Measured on 0..1999 (one run of 2,000): 1,999 total steps with the start check, 1,999,000 steps without it (quadratic). The one guard line is the whole difference.

Amortised argument to say aloud

"Each element is visited by the outer loop once, and by the inner loop at most once, because the inner loop only begins at a run start and a run start has no predecessor. Total work is at most 2n."

Group Anagrams cost is O(n·k) with the count-tuple key (n words of length k; each word is read once to build its key, and hashing a 26-tuple is O(26)), or O(n·k log k) with the sorted-string key. It is not O(n) even though there is one loop, because each key costs O(k) to build and hash.

Four Sum II has two double loops but no quadruple loop: O(n²) time and O(n²) space (the map holds up to n² pair sums). The map converted O(n⁴) into O(n²).

Space and the real cost of memory

  • Space is O(n) for n stored entries, but the constant is large: a Python dict entry is far heavier than a list slot, and Java boxes every Integer/Character key (an object each). When values are small integers or letters, a plain array (int[26]) is both faster and much smaller. Say so in the interview.
  • The O(1)-extra-space alternatives to a set are: sort first (O(n log n), O(1) extra if you may modify the input), or two pointers on sorted data, or use the array itself as the table (the Arrays topic). Knowing the trade is a common follow-up: "Can you do it in O(1) space?"
  • Prefix-sum maps (Type E/F) hold at most n + 1 entries, so O(n) space.

Part 4Core Patterns

Seven types. Every problem in this topic is one of them or a combination. For each, learn the key (what you ask by) and the value (what you need back); the code follows from those two choices. Items 8 and 9 of the standard list (time and space) appear in the line under each template.

Type A: Membership set: seen / dedupe / cycle

Type AEasy to Mediumset

1. What it is. A hash set of everything seen so far. You test x in seen and then add x.

2. What problem it solves. Detecting duplicates, remembering visited states (cycle detection), checking "is this value present?" in O(1), and testing whether a number starts a run (x - 1 not in set).

3. How to recognise it. Words like duplicate, distinct, unique, appears more than once, visited, cycle, repeats, or any inner loop that is just "is value v in the earlier part?"

4. Intuition. The brute-force inner loop does a search for equality. A set answers equality in O(1), so the inner loop disappears.

5. Generic algorithm
  1. seen = set().
  2. For each element x: if x in seen, you found the repeat (return or count it).
  3. Otherwise seen.add(x).
  4. Variant: build the set first, then query it (Longest Consecutive Sequence, Valid Sudoku uses several sets).

6. State, validity condition, step. State: seen. Invariant: seen is exactly the set of distinct values in nums[0..i-1]. Valid-answer condition: the current value is already in seen. Step: test, then add.

7. Template (Python and Java), taken from the verified solution of Contains Duplicate.

def contains_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False
static boolean containsDuplicate(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    for (int x : nums)
        if (!seen.add(x)) return true;      // add() returns false if already present
    return false;
}

Type B: Complement lookup: map value to index

Type BEasy to Mediummap value -> index

1. What it is. A map from value to the index (or count) where you saw it, queried for the partner the current element needs.

2. What problem it solves. Pair problems on unsorted data: two numbers that add to a target, difference of k, pairs whose sum satisfies a rule. Brute force tests every pair; the map tests every partner directly.

3. How to recognise it. "Find two ... that sum/xor/differ by ...", "pairs", "return indices". Unsorted input, and the answer needs positions or counts (sorting would lose positions).

4. Intuition. For each x only one value can complete it: target - x. Instead of searching for that value, remember every earlier value in a map and look it up.

5. Generic algorithm
  1. seen = {} (value -> index).
  2. For each i, x: need = target - x.
  3. If need in seen: answer is (seen[need], i).
  4. Else seen[x] = i. Insert after the check so an element cannot pair with itself.

6. State, validity condition, step. State: seen. Invariant: seen holds every value in nums[0..i-1] with its index. Valid-answer condition: target - x is in seen. Step: check first, insert second. If duplicates matter, a later index overwrites an earlier one, which is fine for finding a pair.

7. Template (Python and Java), taken from the verified solution of Two Sum.

def two_sum(nums, target):
    seen = {}                          # value -> index where we saw it
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:               # check BEFORE inserting x
            return [seen[need], i]
        seen[x] = i
    return []
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> index
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // Integer, not int: may be null
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    return new int[]{};
}

Type C: Frequency counting

Type CEasy to Mediummap item -> count

1. What it is. A counter: a map from item to how many times it occurred (or how many are still available).

2. What problem it solves. Comparing multisets (anagrams, ransom note), finding the most or least frequent items, and checking "do I have enough of each?".

3. How to recognise it. "how many times", "most frequent", "top k", "anagram", "permutation of", "same characters", "can be constructed from".

4. Intuition. Two collections are the same multiset exactly when their counters are equal. Counting once replaces comparing in every order.

5. Generic algorithm
  1. Build count over the first collection (one pass).
  2. Walk the second collection, decrementing; fail if a count would go below 0.
  3. For "top k": bucket items by frequency (index = count), then read buckets from the highest.

6. State, validity condition, step. State: count. Invariant: count[c] = available copies of c minus used copies. Valid-answer condition: never negative, and (with equal lengths) all zero at the end. Step: decrement and test.

7. Template (Python and Java), taken from the verified solution of Valid Anagram.

def is_anagram(s, t):
    if len(s) != len(t):
        return False
    count = {}
    for ch in s:
        count[ch] = count.get(ch, 0) + 1
    for ch in t:
        if count.get(ch, 0) == 0:       # t has more of ch than s
            return False
        count[ch] -= 1
    return True                          # equal lengths, no overdraw => all zero
static boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] count = new int[26];           // lowercase letters only (state this assumption)
    for (char c : s.toCharArray()) count[c - 'a']++;
    for (char c : t.toCharArray())
        if (--count[c - 'a'] < 0) return false;
    return true;
}

Type D: Canonical key: group or match by a normalised form

Type DMediummap key -> group

1. What it is. Compute a canonical form of each item so that things which should be treated as the same get the identical key, then put that key in a map.

2. What problem it solves. Grouping (anagrams, strings that shift to each other, lines through a point), and structural matching where two sequences must follow the same pattern (isomorphic strings).

3. How to recognise it. "group together", "same pattern", "equivalent", "belong to the same class", "normalise".

4. Intuition. The hard part is not the map, it is choosing the key. A good key is the same for every member of the class and different across classes, and it is hashable.

5. Generic algorithm
  1. Decide the canonical form (sorted letters, count tuple, reduced fraction, first-occurrence pattern).
  2. For each item compute its key.
  3. groups[key].append(item).
  4. Return groups.values().

6. State, validity condition, step. State: groups. Invariant: items in a bucket all have equal canonical form. Valid condition: keys are equal iff items are equivalent (check both directions: that is exactly the two-way map in Isomorphic Strings). Step: compute key, append.

7. Template (Python and Java), taken from the verified solution of Group Anagrams.

def group_anagrams(strs):
    groups = {}                          # canonical key -> words
    for w in strs:
        count = [0] * 26
        for ch in w:
            count[ord(ch) - ord('a')] += 1
        groups.setdefault(tuple(count), []).append(w)   # tuple, not list: lists are unhashable
    return list(groups.values())
static List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String w : strs) {
        int[] count = new int[26];
        for (char c : w.toCharArray()) count[c - 'a']++;
        String key = Arrays.toString(count);          // int[] has identity hashCode: needs a String key
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
    }
    return new ArrayList<>(groups.values());
}

Type E: Prefix sum (or prefix remainder) plus a counting map

Type EMediummap prefix -> count

1. What it is. Turn "sum of a subarray" into "difference of two prefix sums", and store counts of earlier prefixes in a map.

2. What problem it solves. Counting (or testing for) contiguous subarrays with a given sum, a sum divisible by k, or a balanced count, on arrays that may contain negatives or zeros (where a sliding window breaks).

3. How to recognise it. "number of contiguous subarrays", "subarray sum equals", "divisible by k", "equal number of". The word subarray plus count is the loudest clue.

4. Intuition. sum(nums[j..i]) = prefix[i] - prefix[j-1]. For a fixed end i, the subarrays that sum to k correspond to earlier prefixes equal to prefix[i] - k. So you only need to know how many earlier prefixes had that value.

5. Generic algorithm
  1. count = {0: 1} (the empty prefix).
  2. Running prefix = 0, total = 0.
  3. For each x: prefix += x; total += count.get(prefix - k, 0); count[prefix] += 1.
  4. For "divisible by k", replace the prefix with prefix % k and look up the same remainder.

6. State, validity condition, step. State: prefix, count. Invariant: count[v] = number of prefixes among prefix[0..i-1] equal to v (including the empty prefix). Valid condition: an earlier prefix equals prefix - k. Step: add matches then record the current prefix.

7. Template (Python and Java), taken from the verified solution of Subarray Sum Equals K.

def subarray_sum(nums, k):
    count = {0: 1}                       # the empty prefix: lets a subarray start at index 0
    prefix = total = 0
    for x in nums:
        prefix += x
        total += count.get(prefix - k, 0)    # earlier prefixes P with prefix - P == k
        count[prefix] = count.get(prefix, 0) + 1
    return total
static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    count.put(0, 1);                                  // empty prefix
    int prefix = 0, total = 0;
    for (int x : nums) {
        prefix += x;
        total += count.getOrDefault(prefix - k, 0);
        count.merge(prefix, 1, Integer::sum);
    }
    return total;
}

Type F: First / last seen index

Type FEasy to Mediummap value -> earliest or latest index

1. What it is. The map stores a position instead of a count: the earliest index (for longest-length questions) or the latest index (for nearest-repeat questions).

2. What problem it solves. Longest subarray with a property, and "are two equal items within distance k?".

3. How to recognise it. "longest subarray with equal 0s and 1s", "longest subarray summing to k", "within k positions", "closest repeat".

4. Intuition. To maximise a length i - j you want the smallest j, so store the first time a prefix appears and never overwrite it. To check distance to the nearest repeat you want the largest j, so overwrite every time.

5. Generic algorithm
  1. Seed with {0: -1} when a prefix of zero length is valid.
  2. Compute the running key (balance, prefix sum, remainder, or the value itself).
  3. If the key is in the map: candidate length = i - map[key].
  4. Insert the index only if absent (earliest) or always (latest).

6. State, validity condition, step. State: first (or last) and the running key. Invariant: first[v] is the smallest index whose prefix equals v. Valid condition: key seen before. Step: measure, then insert-if-absent. Overwriting the earliest index silently shortens answers (Part 10).

7. Template (Python and Java), taken from the verified solution of Contiguous Array.

def find_max_length(nums):
    first = {0: -1}                      # balance -> EARLIEST index it appeared at
    bal = best = 0
    for i, x in enumerate(nums):
        bal += 1 if x == 1 else -1       # treat 0 as -1
        if bal in first:
            best = max(best, i - first[bal])
        else:
            first[bal] = i               # store only the first time: keeps subarrays longest
    return best
static int findMaxLength(int[] nums) {
    Map<Integer, Integer> first = new HashMap<>();
    first.put(0, -1);
    int bal = 0, best = 0;
    for (int i = 0; i < nums.length; i++) {
        bal += nums[i] == 1 ? 1 : -1;
        Integer j = first.get(bal);
        if (j != null) best = Math.max(best, i - j);
        else first.put(bal, i);
    }
    return best;
}

Type G: Design with a map plus a companion structure

Type GMediummap + array / list

1. What it is. A hash map gives O(1) find by key; a second structure gives the other O(1) operation you need (random pick, ordering, eviction). The map stores where each key lives in that structure.

2. What problem it solves. Data-structure design questions: O(1) insert/delete/random, LRU cache (map + doubly linked list), time-based stores, rate limiters, in-memory databases.

3. How to recognise it. "design a data structure that supports ... all in O(1)", "random element", "least recently used", "evict".

4. Intuition. A hash map cannot pick a random element or keep order; an array can pick randomly but cannot find a value. Keep both and let the map record each value's array index. Deleting from the middle of an array is O(n), unless you swap the victim with the last element first.

5. Generic algorithm
  1. items = [] (dense array), pos = {} (value -> index).
  2. Insert: append, record index.
  3. Remove: look up index i, move the last element into slot i, update its index, pop the end.
  4. Random: pick a random index in the array.

6. State, validity condition, step. State: items, pos. Invariant: pos[items[i]] == i for every i, and items has no holes. Step: every operation must restore the invariant before returning. The classic bug is forgetting to update the moved element's index.

7. Template (Python and Java), taken from the verified solution of Insert Delete GetRandom O(1).

class RandomizedSet:
    def __init__(self):
        self.items = []                   # dense array: random pick in O(1)
        self.pos = {}                     # value -> its index in items

    def insert(self, val):
        if val in self.pos:
            return False
        self.pos[val] = len(self.items)
        self.items.append(val)
        return True

    def remove(self, val):
        if val not in self.pos:
            return False
        i = self.pos.pop(val)
        last = self.items.pop()           # O(1): remove from the END
        if i < len(self.items):           # val was not the last element
            self.items[i] = last          # move last into the hole
            self.pos[last] = i
        return True

    def get_random(self):
        return random.choice(self.items)
static class RandomizedSet {
    private final List<Integer> items = new ArrayList<>();
    private final Map<Integer, Integer> pos = new HashMap<>();
    private final Random rnd = new Random();

    boolean insert(int val) {
        if (pos.containsKey(val)) return false;
        pos.put(val, items.size());
        items.add(val);
        return true;
    }
    boolean remove(int val) {
        Integer i = pos.remove(val);
        if (i == null) return false;
        int last = items.remove(items.size() - 1);   // index overload: removes the LAST slot
        if (i < items.size()) {
            items.set(i, last);
            pos.put(last, i);
        }
        return true;
    }
    int getRandom() {
        return items.get(rnd.nextInt(items.size()));
    }
}

One progression in full: Subarray Sum Equals K

  1. Brute force. For every start i, extend j and keep a running sum; count when it equals k. O(n²) time, O(1) space.
  2. Why it is slow. Sums of overlapping ranges are rebuilt from scratch: the sum of [i..j] and [i..j+1] share all but one element, and different starts re-add the same numbers.
  3. Observation 1. sum(i..j) = P[j] - P[i-1], so the whole question is about differences of prefix sums.
  4. Observation 2. For a fixed end j, I need **how many earlier P values equal P[j] - k**. I do not need which ones.
  5. Better approach. Keep a counting map of prefix sums seen so far; add count[P[j] - k] to the answer; then record P[j]. Seeding {0: 1} handles subarrays starting at index 0.
  6. Comparison. O(n²) time / O(1) space -> O(n) time / O(n) space. A sliding window would be O(n) / O(1) but only when all numbers are non-negative.

Why this is the pattern, not a trick

Every row of the table has the same shape: the brute force repeats a search for a specific fact about the past, and the fact can be named in advance (a value, a count, a prefix, an index). Once you can name it, store it under that name.

Contains Duplicate

Type AEasyLeetCode 217O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (NeetCode 150; Tech Interview Handbook week-1 list; local research 2026-10-04).

Problem. Return true if any value appears at least twice.

Example. [1, 2, 3, 1] -> true; [1, 2, 3, 4] -> false.

Recognise before coding. The word "duplicate". The brute force inner loop is an equality search.

Skill it teaches. Type A in its purest form. Interviewers often follow with: "O(1) space?" (sort then compare neighbours, O(n log n)).

1Brute force
def contains_duplicate_brute(nums):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] == nums[j]:
                return True
    return False
static boolean containsDuplicateBrute(int[] nums) {
    for (int i = 0; i < nums.length; i++)
        for (int j = i + 1; j < nums.length; j++)
            if (nums[i] == nums[j]) return true;
    return false;
}

Cost: O(n²) time, O(1) space.

2Observation

"Have I seen this value?" is an equality query on the past; a set answers it in O(1). set.add in Java returns false when the value was already present, so the check and the insert are one call.

3Optimal
def contains_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False
static boolean containsDuplicate(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    for (int x : nums)
        if (!seen.add(x)) return true;      // add() returns false if already present
    return false;
}

Cost: O(n) time, O(n) space.

Follow-up: trade memory for time. Sort and compare adjacent values: O(n log n), O(1) extra if you may modify the input. A shortcut len(set(nums)) != len(nums) is correct but always builds the whole set; the loop can stop at the first repeat.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Happy Number

Type AEasyLeetCode 2021,000-step cap → O(log n)/step
ShowHide

Where it is reported. Added for pattern coverage (Type A used for cycle detection).

Problem. Repeatedly replace n by the sum of the squares of its digits. n is happy if this reaches 1; otherwise it loops forever in a cycle that does not contain 1.

Example. 19 -> 1 (19 -> 82 -> 68 -> 100 -> 1): true; 2 loops: false.

Recognise before coding. "Repeat until...", "loops endlessly". A process with finitely many states either ends or revisits a state.

Skill it teaches. A set of seen states proves a cycle the moment a state repeats. Foreshadows linked-list cycle detection (fast/slow pointers do the same with O(1) space).

1Brute force
def is_happy_brute(n):
    for _ in range(1000):                # every start reaches 1 or loops within ~1000 steps
        if n == 1:
            return True
        n = sum(int(d) ** 2 for d in str(n))
    return False
static boolean isHappyBrute(int n) {
    for (int it = 0; it < 1000; it++) {
        if (n == 1) return true;
        int total = 0;
        for (char c : Integer.toString(n).toCharArray()) total += (c - '0') * (c - '0');
        n = total;
    }
    return false;
}

Cost: bounded loop (1,000 steps).

2Observation

The brute force trick is to run a fixed number of iterations (here 1,000) and see whether you reach 1; it works because the sequence is bounded, but it is a guess. The set makes the stopping rule exact: stop when n is 1 or n was seen.

3Optimal
def is_happy(n):
    def step(x):
        total = 0
        while x:
            x, d = divmod(x, 10)
            total += d * d
        return total
    seen = set()
    while n != 1 and n not in seen:      # a repeated value means we are in a cycle
        seen.add(n)
        n = step(n)
    return n == 1
static boolean isHappy(int n) {
    Set<Integer> seen = new HashSet<>();
    while (n != 1 && seen.add(n)) {      // add() false => repeated => cycle
        int total = 0;
        for (int x = n; x > 0; x /= 10) total += (x % 10) * (x % 10);
        n = total;
    }
    return n == 1;
}

Cost: O(log n) per step, steps bounded; O(log n) space.

Follow-up: O(1) space. Floyd's fast/slow pointers on the sequence (Linked List topic).

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Longest Consecutive Sequence

Type AMediumLeetCode 128O(n²)+ → O(n)
ShowHide

Where it is reported. Frequently asked (NeetCode 150).

Problem. Return the length of the longest run of consecutive integers (in any order in the array) in O(n) time.

Example. [100, 4, 200, 1, 3, 2] -> 4 (1, 2, 3, 4).

Recognise before coding. "Consecutive" with an O(n) requirement rules out sorting (O(n log n)). A set gives O(1) neighbour checks.

Skill it teaches. The run-start guard: begin counting only at x where x - 1 is absent. This is the amortisation example in Part 3.

1Brute force
def longest_consecutive_brute(nums):
    best = 0
    for x in nums:
        length = 1
        while (x + length) in nums:       # `in` on a list is O(n)
            length += 1
        best = max(best, length)
    return best
static int longestConsecutiveBrute(int[] nums) {
    int best = 0;
    for (int x : nums) {
        int length = 1;
        while (contains(nums, x + length)) length++;
        best = Math.max(best, length);
    }
    return best;
}
static boolean contains(int[] a, int v) {
    for (int y : a) if (y == v) return true;
    return false;
}

Cost: O(n²) or worse (list membership).

2Observation

Brute force starts a count at every element and extends it. Elements in the middle of a run repeat work the start already did (O(n²) with set lookups, worse with list lookups). With the guard, every element is visited by exactly one run.

3Optimal
def longest_consecutive(nums):
    s = set(nums)
    best = 0
    for x in s:
        if x - 1 in s:                   # x is not the start of a run: skip
            continue
        length = 1
        while x + length in s:           # walk the run once, from its start
            length += 1
        best = max(best, length)
    return best
static int longestConsecutive(int[] nums) {
    Set<Integer> s = new HashSet<>();
    for (int x : nums) s.add(x);
    int best = 0;
    for (int x : s) {
        if (s.contains(x - 1)) continue;             // not the start of a run
        int length = 1;
        while (s.contains(x + length)) length++;
        best = Math.max(best, length);
    }
    return best;
}

Cost: O(n) time, O(n) space.

Iterate over the set, not the list, so duplicates do not repeat work. Measured: on 0..1999, 1,999 steps with the guard, 1,999,000 without it.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Valid Sudoku

Type AMediumLeetCode 36O(81²) → O(81) = O(1)
ShowHide

Where it is reported. Frequently asked (NeetCode 150).

Problem. Given a partially filled 9x9 board (. = empty), check that no row, column or 3x3 box repeats a digit. The board need not be solvable.

Example. A standard puzzle board with one repeated 8 in a box -> false.

Recognise before coding. "No repeats in each row/column/box" is 27 duplicate checks.

Skill it teaches. Many sets, one per constraint. The box index formula (r // 3) * 3 + c // 3 is the whole trick.

1Brute force
def is_valid_sudoku_brute(board):
    cells = [(r, c, board[r][c]) for r in range(9) for c in range(9) if board[r][c] != '.']
    for a in range(len(cells)):
        for b in range(a + 1, len(cells)):
            r1, c1, v1 = cells[a]
            r2, c2, v2 = cells[b]
            same_box = (r1 // 3, c1 // 3) == (r2 // 3, c2 // 3)
            if v1 == v2 and (r1 == r2 or c1 == c2 or same_box):
                return False
    return True
static boolean isValidSudokuBrute(char[][] board) {
    for (int r1 = 0; r1 < 9; r1++)
        for (int c1 = 0; c1 < 9; c1++) {
            if (board[r1][c1] == '.') continue;
            for (int r2 = 0; r2 < 9; r2++)
                for (int c2 = 0; c2 < 9; c2++) {
                    if (r1 == r2 && c1 == c2) continue;
                    boolean sameBox = r1 / 3 == r2 / 3 && c1 / 3 == c2 / 3;
                    if (board[r1][c1] == board[r2][c2] && (r1 == r2 || c1 == c2 || sameBox))
                        return false;
                }
        }
    return true;
}

Cost: O(81²).

2Observation

Brute force compares every filled cell with every other filled cell. Instead keep 9 row sets, 9 column sets and 9 box sets; each cell is checked against three sets in O(1).

3Optimal
def is_valid_sudoku(board):
    rows = [set() for _ in range(9)]
    cols = [set() for _ in range(9)]
    boxes = [set() for _ in range(9)]
    for r in range(9):
        for c in range(9):
            v = board[r][c]
            if v == '.':
                continue
            b = (r // 3) * 3 + c // 3        # box index 0..8
            if v in rows[r] or v in cols[c] or v in boxes[b]:
                return False
            rows[r].add(v)
            cols[c].add(v)
            boxes[b].add(v)
    return True
static boolean isValidSudoku(char[][] board) {
    boolean[][] rows = new boolean[9][10], cols = new boolean[9][10], boxes = new boolean[9][10];
    for (int r = 0; r < 9; r++)
        for (int c = 0; c < 9; c++) {
            if (board[r][c] == '.') continue;
            int v = board[r][c] - '0', b = (r / 3) * 3 + c / 3;
            if (rows[r][v] || cols[c][v] || boxes[b][v]) return false;
            rows[r][v] = cols[c][v] = boxes[b][v] = true;
        }
    return true;
}

Cost: O(81) = O(1) time and space (constant board).

Java: boolean[9][10] (index by digit) is smaller and faster than 27 HashSets; the same invariant holds. Follow-up: n x n board, then time and space become O(n²).

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Two Sum

Type BEasyLeetCode 1O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (NeetCode 150 Arrays & Hashing list; local research dsa-array-problem-frequency-2026.md: recurs across Blind 75, Tech Interview Handbook and a Meta top-30 list; a third-party summary claims 100% frequency at Amazon, method unknown). Web search 2026-10-09.

Problem. Given an integer array and a target, return the indices of two different elements that add to the target. (LeetCode guarantees exactly one answer. The version tested here returns [] when there is none, and the harness checks the returned pair is real rather than demanding the same pair as the brute force.)

Example. nums = [8, 3, 5, 2, 7], target = 9 returns [3, 4] (values 2 and 7).

Recognise before coding. Unsorted input, a pair, and the answer needs indices. Ask: is the array sorted? Is O(1) space required? If either is yes, think two pointers.

Skill it teaches. The base template of the whole topic: "ask for the partner, then remember myself". Every Type B problem is this loop.

1Brute force
def two_sum_brute(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []
static int[] twoSumBrute(int[] nums, int target) {
    int n = nums.length;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (nums[i] + nums[j] == target)
                return new int[]{i, j};
    return new int[]{};
}

Cost: O(n²) time, O(1) space.

2Observation

For each x, exactly one value completes the pair: target - x. Brute force searches the rest of the array for it (O(n)); a map answers "is that value earlier, and where?" in O(1). Insert x only after checking, so an element cannot pair with itself.

3Optimal
def two_sum(nums, target):
    seen = {}                          # value -> index where we saw it
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:               # check BEFORE inserting x
            return [seen[need], i]
        seen[x] = i
    return []
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> index
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // Integer, not int: may be null
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    return new int[]{};
}

Cost: O(n) time, O(n) space.

Java: target - nums[i] is an int subtraction; with values up to ±10⁹ the result stays within int range, but with larger inputs use long. seen.get(...) returns Integer, so test for null, do not unbox first.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

4Sum II

Type BMediumLeetCode 454O(n⁴) → O(n²)
ShowHide

Where it is reported. Added for pattern coverage (Type B on pair sums: a twist on Two Sum). Not found in the lists read.

Problem. Given four arrays of the same length n, count the tuples (i, j, k, l) with a[i] + b[j] + c[k] + d[l] == 0.

Example. a=[1,2], b=[-2,-1], c=[-1,2], d=[0,2] -> 2.

Recognise before coding. Four independent choices with a sum constraint. n⁴ is too slow; "meet in the middle" splits it into two halves of n² each.

Skill it teaches. Hashing derived values (pair sums), counting ways, and the meet-in-the-middle idea.

1Brute force
def four_sum_count_brute(a, b, c, d):
    total = 0
    for x in a:
        for y in b:
            for z in c:
                for w in d:
                    if x + y + z + w == 0:
                        total += 1
    return total
static int fourSumCountBrute(int[] a, int[] b, int[] c, int[] d) {
    int total = 0;
    for (int x : a) for (int y : b) for (int z : c) for (int w : d)
        if (x + y + z + w == 0) total++;
    return total;
}

Cost: O(n⁴) time.

2Observation

Fix the first two choices and the last two choices separately: a+b takes n² values and c+d takes n² values. Store counts of the first half and look up the negation of each second-half sum.

3Optimal
def four_sum_count(a, b, c, d):
    ab = {}                              # sum of one pair from a,b -> how many ways
    for x in a:
        for y in b:
            ab[x + y] = ab.get(x + y, 0) + 1
    total = 0
    for z in c:
        for w in d:
            total += ab.get(-(z + w), 0)  # complement lookup, as in Two Sum
    return total
static int fourSumCount(int[] a, int[] b, int[] c, int[] d) {
    Map<Integer, Integer> ab = new HashMap<>();
    for (int x : a) for (int y : b) ab.merge(x + y, 1, Integer::sum);
    int total = 0;
    for (int z : c) for (int w : d) total += ab.getOrDefault(-(z + w), 0);
    return total;
}

Cost: O(n²) time, O(n²) space.

This is the Type B template with sums as keys and counts as values. 3Sum is not solved this way (it has one array and a distinct-triples requirement): that belongs to Two Pointers.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Valid Anagram

Type CEasyLeetCode 242O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (NeetCode 150; Tech Interview Handbook week-1 list).

Problem. Return true if t is a rearrangement of the letters of s. (Tested for lowercase English letters, the LeetCode constraint.)

Example. s = "anagram", t = "nagaram" -> true; s = "rat", t = "car" -> false.

Recognise before coding. "Same letters", "rearrangement". Two multisets are equal exactly when their counters are equal.

Skill it teaches. Counting as comparison. The decrement-and-check form needs one counter, not two.

1Brute force
def is_anagram_brute(s, t):
    rest = list(t)
    for ch in s:
        if ch in rest:
            rest.remove(ch)             # O(n) search + O(n) shift
        else:
            return False
    return not rest
static boolean isAnagramBrute(String s, String t) {
    List<Character> rest = new ArrayList<>();
    for (char c : t.toCharArray()) rest.add(c);
    for (char c : s.toCharArray())
        if (!rest.remove(Character.valueOf(c))) return false;   // remove(Object), not remove(int)
    return rest.isEmpty();
}

Cost: O(n²) time, O(n) space.

2Observation

Brute force removes each letter of s from a list copy of t: each removal is an O(n) search and shift. Count once instead. After equal lengths are confirmed, decrementing t's letters can never leave a positive count behind, so "no count went negative" already proves equality.

3Optimal
def is_anagram(s, t):
    if len(s) != len(t):
        return False
    count = {}
    for ch in s:
        count[ch] = count.get(ch, 0) + 1
    for ch in t:
        if count.get(ch, 0) == 0:       # t has more of ch than s
            return False
        count[ch] -= 1
    return True                          # equal lengths, no overdraw => all zero
static boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] count = new int[26];           // lowercase letters only (state this assumption)
    for (char c : s.toCharArray()) count[c - 'a']++;
    for (char c : t.toCharArray())
        if (--count[c - 'a'] < 0) return false;
    return true;
}

Cost: O(n) time, O(1) space (26 letters).

Follow-up: Unicode input. Replace int[26] with a HashMap<Integer,Integer> over code points (Python dict already handles it). Say the lowercase assumption aloud at the start.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Top K Frequent Elements

Type CMediumLeetCode 347O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (NeetCode 150). Local array research assigns it to the Heaps topic; it is solved here with a counter and bucket sort, the heap version is left for Heaps.

Problem. Return the k most frequent values (the answer is unique on LeetCode; the harness accepts any k distinct values whose frequencies match the top k).

Example. nums = [1,1,1,2,2,3], k = 2 -> [1, 2].

Recognise before coding. "Most frequent", "top k". Count first. Then selecting needs either a heap (O(n log k)), a sort (O(n log n)) or buckets (O(n)).

Skill it teaches. Type C plus bucket by frequency: a frequency is at most n, so use the frequency as an array index.

1Brute force
def top_k_frequent_brute(nums, k):
    distinct = []
    for x in nums:
        if x not in distinct:
            distinct.append(x)
    pairs = [(nums.count(x), x) for x in distinct]     # nums.count is O(n)
    pairs.sort(reverse=True)
    return [x for _, x in pairs[:k]]
static int[] topKFrequentBrute(int[] nums, int k) {
    List<int[]> pairs = new ArrayList<>();             // {count, value}
    Set<Integer> done = new HashSet<>();
    for (int x : nums) {
        if (!done.add(x)) continue;
        int c = 0;
        for (int y : nums) if (y == x) c++;
        pairs.add(new int[]{c, x});
    }
    pairs.sort((a, b) -> b[0] != a[0] ? Integer.compare(b[0], a[0]) : Integer.compare(b[1], a[1]));
    int[] out = new int[k];
    for (int i = 0; i < k; i++) out[i] = pairs.get(i)[1];
    return out;
}

Cost: O(n²) time.

2Observation

Brute force calls nums.count(x) for each distinct x, which re-scans the array each time. Count once (one pass), then place each value in buckets[count], and read buckets from the largest count down until you have k values.

3Optimal
def top_k_frequent(nums, k):
    count = {}
    for x in nums:
        count[x] = count.get(x, 0) + 1
    buckets = [[] for _ in range(len(nums) + 1)]       # buckets[f] = values seen exactly f times
    for x, f in count.items():
        buckets[f].append(x)
    out = []
    for f in range(len(nums), 0, -1):                  # highest frequency first
        for x in buckets[f]:
            out.append(x)
            if len(out) == k:
                return out
    return out
static int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int x : nums) count.merge(x, 1, Integer::sum);
    List<Integer>[] buckets = new List[nums.length + 1];
    for (Map.Entry<Integer, Integer> e : count.entrySet()) {
        int f = e.getValue();
        if (buckets[f] == null) buckets[f] = new ArrayList<>();
        buckets[f].add(e.getKey());
    }
    int[] out = new int[k];
    int m = 0;
    for (int f = nums.length; f >= 1 && m < k; f--)
        if (buckets[f] != null)
            for (int x : buckets[f]) {
                if (m == k) break;
                out[m++] = x;
            }
    return out;
}

Cost: O(n) time, O(n) space.

Interview talking point: heap solution is O(n log k) and is what the Heaps topic teaches; bucket sort wins when k is large but needs O(n) extra array. Mention both.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Group Anagrams

Type DMediumLeetCode 49O(n² · k log k) → O(n·k)
ShowHide

Where it is reported. Frequently asked (NeetCode 150; Tech Interview Handbook week-1 list; local research 2026-10-04).

Problem. Group the strings so that each group contains anagrams of each other. Any order of groups and of words is accepted (the harness compares sorted groups).

Example. ["eat","tea","tan","ate","nat","bat"] -> [["eat","tea","ate"],["tan","nat"],["bat"]] in any order.

Recognise before coding. "Group by". The map is easy; the key is the problem. The key must be identical for all anagrams and different otherwise.

Skill it teaches. Designing a canonical key and knowing its cost. Two good keys: sorted letters (cost O(k log k)) or the 26-count tuple (cost O(k)).

1Brute force
def group_anagrams_brute(strs):
    groups = []                          # list of (sorted_key, [words])
    for w in strs:
        key = sorted(w)
        for k, bucket in groups:         # linear scan of existing groups
            if k == key:
                bucket.append(w)
                break
        else:
            groups.append((key, [w]))
    return [bucket for _, bucket in groups]
static List<List<String>> groupAnagramsBrute(String[] strs) {
    List<char[]> keys = new ArrayList<>();
    List<List<String>> groups = new ArrayList<>();
    for (String w : strs) {
        char[] key = w.toCharArray();
        Arrays.sort(key);
        int found = -1;
        for (int g = 0; g < keys.size() && found < 0; g++)
            if (Arrays.equals(keys.get(g), key)) found = g;
        if (found < 0) {
            keys.add(key);
            groups.add(new ArrayList<>());
            found = groups.size() - 1;
        }
        groups.get(found).add(w);
    }
    return groups;
}

Cost: O(n² · k log k) time.

2Observation

Brute force, for each word, sorts it and scans every existing group for a match: O(n) scans per word. Hash the key instead. In Python the key must be a tuple, not a list (lists are unhashable); in Java an int[] has identity hashing, so convert it to a String.

3Optimal
def group_anagrams(strs):
    groups = {}                          # canonical key -> words
    for w in strs:
        count = [0] * 26
        for ch in w:
            count[ord(ch) - ord('a')] += 1
        groups.setdefault(tuple(count), []).append(w)   # tuple, not list: lists are unhashable
    return list(groups.values())
static List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String w : strs) {
        int[] count = new int[26];
        for (char c : w.toCharArray()) count[c - 'a']++;
        String key = Arrays.toString(count);          // int[] has identity hashCode: needs a String key
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
    }
    return new ArrayList<>(groups.values());
}

Cost: O(n·k) time, O(n·k) space.

Follow-up: "What if letters are Unicode?" Use a sorted-string key, or a sorted tuple of (char, count). Trap: the key "".join(sorted(w)) is simpler to write and fine in an interview; know that it costs O(k log k) per word and say so.

Type DEasyLeetCode 205O(n²) → O(n)
ShowHide

Where it is reported. Added for pattern coverage (Type D, two-way mapping). Not found in the lists read.

Problem. Two strings are isomorphic if the characters of s can be replaced to get t, with every character mapping to exactly one character and no two characters mapping to the same one.

Example. "egg", "add" -> true; "foo", "bar" -> false; "badc", "baba" -> false.

Recognise before coding. "Mapping", "replace", "same pattern". A one-way map is not enough: "ab" vs "aa" must be false.

Skill it teaches. When the relation must be one-to-one, enforce it in both directions with two maps. Looks like Type C but the key insight is Type D.

1Brute force
def is_isomorphic_brute(s, t):
    if len(s) != len(t):
        return False
    n = len(s)
    for i in range(n):
        for j in range(i + 1, n):
            if (s[i] == s[j]) != (t[i] == t[j]):
                return False
    return True
static boolean isIsomorphicBrute(String s, String t) {
    if (s.length() != t.length()) return false;
    int n = s.length();
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if ((s.charAt(i) == s.charAt(j)) != (t.charAt(i) == t.charAt(j)))
                return false;
    return true;
}

Cost: O(n²) time, O(1) space.

2Observation

Brute force checks, for every pair of positions, that "s equal at i and j" matches "t equal at i and j". The map version stores s->t and t->s and rejects any contradiction as it goes.

3Optimal
def is_isomorphic(s, t):
    if len(s) != len(t):
        return False
    s2t, t2s = {}, {}                    # two maps = one-to-one in both directions
    for a, b in zip(s, t):
        if s2t.get(a, b) != b or t2s.get(b, a) != a:
            return False
        s2t[a] = b
        t2s[b] = a
    return True
static boolean isIsomorphic(String s, String t) {
    if (s.length() != t.length()) return false;
    Map<Character, Character> s2t = new HashMap<>(), t2s = new HashMap<>();
    for (int i = 0; i < s.length(); i++) {
        char a = s.charAt(i), b = t.charAt(i);
        if (s2t.getOrDefault(a, b) != b || t2s.getOrDefault(b, a) != a) return false;
        s2t.put(a, b);
        t2s.put(b, a);
    }
    return true;
}

Cost: O(n) time, O(σ) space.

Bug check (executed): with only the s->t map, s = "ab", t = "aa" returns true (it should be false). See Part 10.

Subarray Sum Equals K

Type EMediumLeetCode 560O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (Meta top-30 list per Verve Copilot; interviewing.io; Educative; Design Gurus; local research 2026-10-04 reports 81% Meta / 72.9% Amazon from a third-party summary, method unknown). Introduced in the Arrays topic; here it is studied as a hashing problem.

Problem. Count the contiguous subarrays whose sum equals k. The array may contain negatives and zeros.

Example. [1, 2, 1, 2, 1], k = 3 -> 4.

Recognise before coding. "Number of subarrays with sum k", with negatives allowed, so no sliding window. Prefix sums plus a counter.

Skill it teaches. The anchor of Type E: range sum as a prefix difference, a counting map seeded with the empty prefix, and the order "match first, record second".

1Brute force
def subarray_sum_brute(nums, k):
    n, total = len(nums), 0
    for i in range(n):
        run = 0
        for j in range(i, n):
            run += nums[j]
            if run == k:
                total += 1
    return total
static int subarraySumBrute(int[] nums, int k) {
    int total = 0;
    for (int i = 0; i < nums.length; i++) {
        int run = 0;
        for (int j = i; j < nums.length; j++) {
            run += nums[j];
            if (run == k) total++;
        }
    }
    return total;
}

Cost: O(n²) time, O(1) space.

2Observation

Brute force re-sums overlapping ranges. For fixed end j you only need the number of earlier prefixes equal to P[j] - k. Look it up, then add P[j] to the map.

3Optimal
def subarray_sum(nums, k):
    count = {0: 1}                       # the empty prefix: lets a subarray start at index 0
    prefix = total = 0
    for x in nums:
        prefix += x
        total += count.get(prefix - k, 0)    # earlier prefixes P with prefix - P == k
        count[prefix] = count.get(prefix, 0) + 1
    return total
static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    count.put(0, 1);                                  // empty prefix
    int prefix = 0, total = 0;
    for (int x : nums) {
        prefix += x;
        total += count.getOrDefault(prefix - k, 0);
        count.merge(prefix, 1, Integer::sum);
    }
    return total;
}

Cost: O(n) time, O(n) space.

Bug check (executed): without the seed {0: 1}, [-1], k = -1 returns 0 instead of 1: subarrays starting at index 0 are missed. Java: use long for the prefix when sums can exceed int.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Subarray Sums Divisible by K

Type EMediumLeetCode 974O(n²) → O(n)
ShowHide

Where it is reported. Added for pattern coverage (Type E with remainders; the Java negative-modulo trap). Not found in the lists read.

Problem. Count the contiguous subarrays whose sum is divisible by k (k >= 1). The array may contain negatives.

Example. [4, 5, 0, -2, -3, 1], k = 5 -> 7.

Recognise before coding. "Divisible by k" means the prefix sums at both ends have the same remainder.

Skill it teaches. Prefix remainders as the key; counting pairs of equal remainders; the remainder normalisation difference between Python and Java.

1Brute force
def subarrays_div_by_k_brute(nums, k):
    total = 0
    for i in range(len(nums)):
        run = 0
        for j in range(i, len(nums)):
            run += nums[j]
            if run % k == 0:
                total += 1
    return total
static int subarraysDivByKBrute(int[] nums, int k) {
    int total = 0;
    for (int i = 0; i < nums.length; i++) {
        long run = 0;
        for (int j = i; j < nums.length; j++) {
            run += nums[j];
            if (run % k == 0) total++;
        }
    }
    return total;
}

Cost: O(n²) time.

2Observation

(P[j] - P[i]) % k == 0 exactly when P[j] % k == P[i] % k. So count earlier prefixes with the same remainder, seeded with remainder 0 once.

3Optimal
def subarrays_div_by_k(nums, k):
    count = {0: 1}                       # remainder -> how many prefixes have it
    prefix = total = 0
    for x in nums:
        prefix = (prefix + x) % k        # Python % is already 0..k-1, even for negatives
        total += count.get(prefix, 0)
        count[prefix] = count.get(prefix, 0) + 1
    return total
static int subarraysDivByK(int[] nums, int k) {
    int[] count = new int[k];
    count[0] = 1;
    int prefix = 0, total = 0;
    for (int x : nums) {
        prefix = ((prefix + x) % k + k) % k;          // Java % can be negative: normalise to 0..k-1
        total += count[prefix]++;
    }
    return total;
}

Cost: O(n) time, O(k) space.

Bug check (executed): in Java (prefix + x) % k can be negative. The unfixed version on [-1, 2, 9], k = 2 throws ArrayIndexOutOfBoundsException: Index -1 out of bounds for length 2. Fix: ((p % k) + k) % k or Math.floorMod. Python's % already returns 0..k-1.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Contiguous Array

Type FMediumLeetCode 525O(n²) → O(n)
ShowHide

Where it is reported. Added for pattern coverage (Type F, earliest index). Not found in the lists read.

Problem. Return the length of the longest contiguous subarray of a 0/1 array that has equal numbers of 0 and 1.

Example. [0, 1, 1, 0] -> 4; [0, 1] -> 2.

Recognise before coding. "Equal number of" two kinds of elements = a sum of zero if you map 0 to -1.

Skill it teaches. Reduction to a prefix-sum problem, then the first-seen index to maximise length.

1Brute force
def find_max_length_brute(nums):
    best = 0
    for i in range(len(nums)):
        bal = 0
        for j in range(i, len(nums)):
            bal += 1 if nums[j] == 1 else -1
            if bal == 0:
                best = max(best, j - i + 1)
    return best
static int findMaxLengthBrute(int[] nums) {
    int best = 0;
    for (int i = 0; i < nums.length; i++) {
        int bal = 0;
        for (int j = i; j < nums.length; j++) {
            bal += nums[j] == 1 ? 1 : -1;
            if (bal == 0) best = Math.max(best, j - i + 1);
        }
    }
    return best;
}

Cost: O(n²) time.

2Observation

Treat 0 as -1; then equal counts means balance 0, and two equal prefix balances bound a balanced subarray. To make it as long as possible, keep the earliest index of each balance.

3Optimal
def find_max_length(nums):
    first = {0: -1}                      # balance -> EARLIEST index it appeared at
    bal = best = 0
    for i, x in enumerate(nums):
        bal += 1 if x == 1 else -1       # treat 0 as -1
        if bal in first:
            best = max(best, i - first[bal])
        else:
            first[bal] = i               # store only the first time: keeps subarrays longest
    return best
static int findMaxLength(int[] nums) {
    Map<Integer, Integer> first = new HashMap<>();
    first.put(0, -1);
    int bal = 0, best = 0;
    for (int i = 0; i < nums.length; i++) {
        bal += nums[i] == 1 ? 1 : -1;
        Integer j = first.get(bal);
        if (j != null) best = Math.max(best, i - j);
        else first.put(bal, i);
    }
    return best;
}

Cost: O(n) time, O(n) space.

Bug checks (executed): omit the seed {0: -1} and [0, 1] returns 0 instead of 2; overwrite the stored index every time and [0, 1, 0, 1] returns 2 instead of 4.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Contains Duplicate II

Type FEasyLeetCode 219O(n·k) → O(n)
ShowHide

Where it is reported. Added for pattern coverage (Type F, latest index). A search summary lists it among fixed-window problems for the Sliding Window topic; it needs no window here.

Problem. Return true if two equal values sit at indices i != j with |i - j| <= k.

Example. [1, 2, 3, 1], k = 3 -> true; [1, 0, 1, 1], k = 1 -> true; [1, 2, 3, 1, 2, 3], k = 2 -> false.

Recognise before coding. "Within k". Only the nearest earlier equal value matters.

Skill it teaches. Which index to store: the latest, because it is closest to any future repeat.

1Brute force
def contains_nearby_duplicate_brute(nums, k):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, min(n, i + k + 1)):
            if nums[i] == nums[j]:
                return True
    return False
static boolean containsNearbyDuplicateBrute(int[] nums, int k) {
    int n = nums.length;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n && j <= i + k; j++)
            if (nums[i] == nums[j]) return true;
    return false;
}

Cost: O(n·k) time, O(1) space.

2Observation

Brute force scans the next k positions for each i. A map value -> last index answers "how far back was the nearest equal value?" directly. Overwrite every time, never keep the first.

3Optimal
def contains_nearby_duplicate(nums, k):
    last = {}                            # value -> most recent index
    for i, x in enumerate(nums):
        if x in last and i - last[x] <= k:
            return True
        last[x] = i                      # always overwrite: the latest index is the closest
    return False
static boolean containsNearbyDuplicate(int[] nums, int k) {
    Map<Integer, Integer> last = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        Integer j = last.get(nums[i]);
        if (j != null && i - j <= k) return true;
        last.put(nums[i], i);
    }
    return false;
}

Cost: O(n) time, O(n) space.

Bug check (executed): storing the first index and never updating it returns false for [0, 1, 0, 0], k = 1 (the correct answer is true).

Insert Delete GetRandom O(1)

Type GMediumLeetCode 380O(n)/op → O(1)/op
ShowHide

Where it is reported. Frequently asked (listed in a Medium compilation of map interview questions and on a third-party Apple frequency table; not found on a Meta index; web search 2026-10-09). Also added for pattern coverage (Type G).

Problem. Design a set with insert(val), remove(val) and getRandom() (uniformly random element), each in average O(1). insert returns false if present; remove returns false if absent.

Example. insert 1, insert 2, remove 1, getRandom -> 2.

Recognise before coding. "All operations in O(1)" plus "random". A set cannot pick a random element; an array cannot find by value.

Skill it teaches. Type G: a map to locate, an array to pick, and swap-with-last to delete from an array in O(1). The invariant pos[items[i]] == i.

1Brute force
class RandomizedSetBrute:
    def __init__(self):
        self.items = []

    def insert(self, val):
        if val in self.items:             # O(n) membership
            return False
        self.items.append(val)
        return True

    def remove(self, val):
        if val not in self.items:
            return False
        self.items.remove(val)            # O(n) search and shift
        return True

    def get_random(self):
        return random.choice(self.items)
static class RandomizedSetBrute {
    private final List<Integer> items = new ArrayList<>();
    private final Random rnd = new Random();

    boolean insert(int val) {
        if (items.contains(val)) return false;
        items.add(val);
        return true;
    }
    boolean remove(int val) {
        return items.remove(Integer.valueOf(val));   // remove(Object), not remove(int index)
    }
    int getRandom() {
        return items.get(rnd.nextInt(items.size()));
    }
}

Cost: O(n) for insert/remove.

2Observation

A list-only solution makes insert and remove O(n) because membership and deletion scan. Keep pos: value -> index. On remove, copy the last element into the vacated slot, update its index, and pop the end.

3Optimal
class RandomizedSet:
    def __init__(self):
        self.items = []                   # dense array: random pick in O(1)
        self.pos = {}                     # value -> its index in items

    def insert(self, val):
        if val in self.pos:
            return False
        self.pos[val] = len(self.items)
        self.items.append(val)
        return True

    def remove(self, val):
        if val not in self.pos:
            return False
        i = self.pos.pop(val)
        last = self.items.pop()           # O(1): remove from the END
        if i < len(self.items):           # val was not the last element
            self.items[i] = last          # move last into the hole
            self.pos[last] = i
        return True

    def get_random(self):
        return random.choice(self.items)
static class RandomizedSet {
    private final List<Integer> items = new ArrayList<>();
    private final Map<Integer, Integer> pos = new HashMap<>();
    private final Random rnd = new Random();

    boolean insert(int val) {
        if (pos.containsKey(val)) return false;
        pos.put(val, items.size());
        items.add(val);
        return true;
    }
    boolean remove(int val) {
        Integer i = pos.remove(val);
        if (i == null) return false;
        int last = items.remove(items.size() - 1);   // index overload: removes the LAST slot
        if (i < items.size()) {
            items.set(i, last);
            pos.put(last, i);
        }
        return true;
    }
    int getRandom() {
        return items.get(rnd.nextInt(items.size()));
    }
}

Cost: O(1) average per operation, O(n) space.

Verification: tested by running random operation sequences against a reference set, checking return values, that every getRandom is present, and the invariant after every operation. Uniformity of getRandom is by construction (random.choice over a dense array) and was not statistically tested. Follow-up: duplicates allowed (LeetCode 381) needs value -> set of indices.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python (3.11) and in Java (JDK 27); see Appendix B.

Part 8Problem-Solving Method

A repeatable process for any hashing problem. Each step has a question to ask and a sentence to say aloud, so the interviewer hears your reasoning, not just code.

StepAsk yourselfSay aloud (example)
1. Understand the inputWhat are the types and ranges? Can values be negative, repeated, absent? Is it sorted?"So I get an unsorted int array that can contain negatives and duplicates, and I return indices?"
2. ConstraintsHow big is n? Is extra memory allowed?"With n up to 10⁵, O(n²) is too slow; O(n) extra memory is fine unless you say otherwise."
3. Edge casesEmpty, one element, all equal, no answer, overflow?"What should I return if no pair exists: empty list, -1, or can I assume one exists?"
4. Brute forceWhat is the obvious loop, and what does it cost?"Brute force checks every pair: O(n²) time, O(1) space."
5. Find the bottleneckWhich inner loop is a search for a specific fact about the past?"The inner loop is just looking for target minus x among earlier elements."
6. Name the patternWhich of A to G? What is the key? What is the value?"I will keep a map from value to index, keyed by what I will ask for."
7. Design the approachWhat is in the map after i elements? In what order do I check and insert?"After each step the map holds all earlier values. I check for the complement first, then insert."
8. State complexityTime, space, average vs worst."O(n) time, O(n) space; O(1) map operations are average-case."
9. CodeSmall named variables; one pass; no hidden assumptions.(narrate the three lines of the loop)
10. TestTrace the example, then a duplicate, then an empty case."Tracing [3, 3], target 6: first 3 is not found, inserted; second 3 finds index 0. Good."

The "write this down before coding" checklist

  • Key: what exactly will I look up by?
  • Value: what do I need to know once I find it (count, index, list, nothing)?
  • Seed: is there an empty prefix or initial entry ({0: 1}, {0: -1})?
  • Order: do I check then insert, or insert then check? (Check first when an element must not match itself.)
  • Overwrite policy: keep the first index, the last index, or a count?
  • Answer condition: what hit in the map means "found", and what do I return when nothing is found?
  • Type hazards: is the key hashable (tuple/String)? Can sums overflow? Can % be negative?

T2: Complement map (value -> index)

def two_sum(nums, target):
    seen = {}                          # value -> index where we saw it
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:               # check BEFORE inserting x
            return [seen[need], i]
        seen[x] = i
    return []
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> index
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // Integer, not int: may be null
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    return new int[]{};
}

Applies to: Two Sum, any "pair with target".

Time: O(n) time, O(n) space

The line people get wrong: Inserting before checking (pairs an element with itself).

T3: Counter, decrement-and-check

def is_anagram(s, t):
    if len(s) != len(t):
        return False
    count = {}
    for ch in s:
        count[ch] = count.get(ch, 0) + 1
    for ch in t:
        if count.get(ch, 0) == 0:       # t has more of ch than s
            return False
        count[ch] -= 1
    return True                          # equal lengths, no overdraw => all zero
static boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] count = new int[26];           // lowercase letters only (state this assumption)
    for (char c : s.toCharArray()) count[c - 'a']++;
    for (char c : t.toCharArray())
        if (--count[c - 'a'] < 0) return false;
    return true;
}

Applies to: Valid Anagram, Ransom Note, "enough of each?".

Time: O(n) time, O(σ) space

The line people get wrong: Forgetting the length check.

T4: Canonical key -> group

def group_anagrams(strs):
    groups = {}                          # canonical key -> words
    for w in strs:
        count = [0] * 26
        for ch in w:
            count[ord(ch) - ord('a')] += 1
        groups.setdefault(tuple(count), []).append(w)   # tuple, not list: lists are unhashable
    return list(groups.values())
static List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String w : strs) {
        int[] count = new int[26];
        for (char c : w.toCharArray()) count[c - 'a']++;
        String key = Arrays.toString(count);          // int[] has identity hashCode: needs a String key
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
    }
    return new ArrayList<>(groups.values());
}

The line people get wrong: Using a list/array as the key.

T5: Prefix sum + count map

def subarray_sum(nums, k):
    count = {0: 1}                       # the empty prefix: lets a subarray start at index 0
    prefix = total = 0
    for x in nums:
        prefix += x
        total += count.get(prefix - k, 0)    # earlier prefixes P with prefix - P == k
        count[prefix] = count.get(prefix, 0) + 1
    return total
static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    count.put(0, 1);                                  // empty prefix
    int prefix = 0, total = 0;
    for (int x : nums) {
        prefix += x;
        total += count.getOrDefault(prefix - k, 0);
        count.merge(prefix, 1, Integer::sum);
    }
    return total;
}

Applies to: Subarray Sum Equals K, Subarray Sums Divisible by K, Pairs of Songs.

Time: O(n) time, O(n) space

The line people get wrong: Missing seed {0: 1}, or recording the prefix before looking up.

T6: First-seen index (longest)

def find_max_length(nums):
    first = {0: -1}                      # balance -> EARLIEST index it appeared at
    bal = best = 0
    for i, x in enumerate(nums):
        bal += 1 if x == 1 else -1       # treat 0 as -1
        if bal in first:
            best = max(best, i - first[bal])
        else:
            first[bal] = i               # store only the first time: keeps subarrays longest
    return best
static int findMaxLength(int[] nums) {
    Map<Integer, Integer> first = new HashMap<>();
    first.put(0, -1);
    int bal = 0, best = 0;
    for (int i = 0; i < nums.length; i++) {
        bal += nums[i] == 1 ? 1 : -1;
        Integer j = first.get(bal);
        if (j != null) best = Math.max(best, i - j);
        else first.put(bal, i);
    }
    return best;
}

Applies to: Contiguous Array, Max Size Subarray Sum k, Continuous Subarray Sum.

Time: O(n) time, O(n) space

The line people get wrong: Overwriting the first index; missing seed {0: -1}.

T7: Set + run-start guard

def longest_consecutive(nums):
    s = set(nums)
    best = 0
    for x in s:
        if x - 1 in s:                   # x is not the start of a run: skip
            continue
        length = 1
        while x + length in s:           # walk the run once, from its start
            length += 1
        best = max(best, length)
    return best
static int longestConsecutive(int[] nums) {
    Set<Integer> s = new HashSet<>();
    for (int x : nums) s.add(x);
    int best = 0;
    for (int x : s) {
        if (s.contains(x - 1)) continue;             // not the start of a run
        int length = 1;
        while (s.contains(x + length)) length++;
        best = Math.max(best, length);
    }
    return best;
}

Applies to: Longest Consecutive Sequence.

Time: O(n) time, O(n) space

The line people get wrong: Dropping x - 1 not in set (makes it O(n²)).

T8: Map + array (swap-with-last)

class RandomizedSet:
    def __init__(self):
        self.items = []                   # dense array: random pick in O(1)
        self.pos = {}                     # value -> its index in items

    def insert(self, val):
        if val in self.pos:
            return False
        self.pos[val] = len(self.items)
        self.items.append(val)
        return True

    def remove(self, val):
        if val not in self.pos:
            return False
        i = self.pos.pop(val)
        last = self.items.pop()           # O(1): remove from the END
        if i < len(self.items):           # val was not the last element
            self.items[i] = last          # move last into the hole
            self.pos[last] = i
        return True

    def get_random(self):
        return random.choice(self.items)
static class RandomizedSet {
    private final List<Integer> items = new ArrayList<>();
    private final Map<Integer, Integer> pos = new HashMap<>();
    private final Random rnd = new Random();

    boolean insert(int val) {
        if (pos.containsKey(val)) return false;
        pos.put(val, items.size());
        items.add(val);
        return true;
    }
    boolean remove(int val) {
        Integer i = pos.remove(val);
        if (i == null) return false;
        int last = items.remove(items.size() - 1);   // index overload: removes the LAST slot
        if (i < items.size()) {
            items.set(i, last);
            pos.put(last, i);
        }
        return true;
    }
    int getRandom() {
        return items.get(rnd.nextInt(items.size()));
    }
}

Applies to: Insert Delete GetRandom O(1), LRU-style designs.

Time: O(1) per operation, O(n) space

The line people get wrong: Not updating the moved element's index; missing i < len guard.

Exercise 1: In-memory key-value store with expiry

Scenario. You are building the cache layer of a small service. It stores string keys and values in memory, and callers care about both correctness and cost per operation.

LevelRequirement (each adds to the previous)

Exercise 2: LRU cache

Scenario. A thumbnail service wants to keep the most recently used N images in memory.

LevelRequirement

Design HashMap · LeetCode 706

Idea. Type G. A fixed array of buckets; each bucket is a short list of key/value pairs; key % 1009 picks the bucket. Real tables also resize when the load factor grows; this fixed-size version is correct for any number of keys but degrades to O(n / 1009) per operation as it fills.

Brute force
class MyHashMapBrute:
    def __init__(self):
        self.pairs = []                  # unsorted list of [key, value]

    def put(self, key, value):
        for p in self.pairs:
            if p[0] == key:
                p[1] = value
                return
        self.pairs.append([key, value])

    def get(self, key):
        for k, v in self.pairs:
            if k == key:
                return v
        return -1

    def remove(self, key):
        self.pairs = [p for p in self.pairs if p[0] != key]
static class MyHashMapBrute {
    private final List<int[]> pairs = new ArrayList<>();

    void put(int key, int value) {
        for (int[] p : pairs) if (p[0] == key) { p[1] = value; return; }
        pairs.add(new int[]{key, value});
    }
    int get(int key) {
        for (int[] p : pairs) if (p[0] == key) return p[1];
        return -1;

        pairs.removeIf(p -> p[0] == key);

Optimal
class MyHashMap:
    SIZE = 1009                          # prime bucket count

    def __init__(self):
        self.buckets = [[] for _ in range(self.SIZE)]

    def _bucket(self, key):
        return self.buckets[key % self.SIZE]

    def put(self, key, value):
        b = self._bucket(key)
        for p in b:
            if p[0] == key:
                p[1] = value
                return
        b.append([key, value])

    def get(self, key):
        for k, v in self._bucket(key):
            if k == key:
                return v
        return -1

    def remove(self, key):
        b = self._bucket(key)
        for i, p in enumerate(b):
            if p[0] == key:
                b[i] = b[-1]             # swap-delete inside the chain
                b.pop()
                return
static class MyHashMap {
    private static final int SIZE = 1009;
    private final List<int[]>[] buckets = new List[SIZE];

    private List<int[]> bucket(int key) {
        int i = key % SIZE;
        if (buckets[i] == null) buckets[i] = new ArrayList<>();
        return buckets[i];
    }
    void put(int key, int value) {
        List<int[]> b = bucket(key);
        for (int[] p : b) if (p[0] == key) { p[1] = value; return; }
        b.add(new int[]{key, value});
    }
    int get(int key) {
        for (int[] p : bucket(key)) if (p[0] == key) return p[1];
        return -1;
    }
    void remove(int key) {
        List<int[]> b = bucket(key);
        for (int i = 0; i < b.size(); i++)
            if (b.get(i)[0] == key) {
                b.set(i, b.get(b.size() - 1));
                b.remove(b.size() - 1);
                return;
            }
    }
}

Time: O(n / B) per operation for B buckets (average O(1) when n is about B); O(n + B) space

Verified: brute force and optimal agreed on 4,000 random inputs in Python and in Java (Appendix B).

Max Points on a Line · LeetCode 149

Idea. Type D. For each anchor point, key every other point by its reduced direction (dx/g, dy/g) with a canonical sign, so the same line from the anchor gets the same key. Integers avoid float-slope precision problems. Tests used distinct points, as LeetCode guarantees.

Brute force
def max_points_brute(points):
    n = len(points)
    if n <= 2:
        return n
    best = 2
    for i in range(n):
        for j in range(i + 1, n):
            (x1, y1), (x2, y2) = points[i], points[j]
            on = 0
            for x, y in points:
                if (x2 - x1) * (y - y1) == (y2 - y1) * (x - x1):   # cross product == 0
                    on += 1
            best = max(best, on)
    return best
static int maxPointsBrute(int[][] points) {
    int n = points.length;
    if (n <= 2) return n;
    int best = 2;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++) {
            int on = 0;

                if ((long) (points[j][0] - points[i][0]) * (p[1] - points[i][1])
                        == (long) (points[j][1] - points[i][1]) * (p[0] - points[i][0])) on++;
            best = Math.max(best, on);
        }
    return best;
}
Optimal
from math import gcd

def max_points(points):
    n = len(points)
    best = min(n, 2)
    for i in range(n):
        slopes = {}                      # direction from points[i] -> how many points share it
        for j in range(i + 1, n):
            dx = points[j][0] - points[i][0]
            dy = points[j][1] - points[i][1]
            g = gcd(dx, dy)              # gcd(0, 0) never happens: points are distinct
            dx, dy = dx // g, dy // g
            if dx < 0 or (dx == 0 and dy < 0):
                dx, dy = -dx, -dy        # one canonical sign per direction
            slopes[(dx, dy)] = slopes.get((dx, dy), 0) + 1
            best = max(best, slopes[(dx, dy)] + 1)
    return best
static int gcd(int a, int b) { return b == 0 ? Math.abs(a) : gcd(b, a % b); }

static int maxPoints(int[][] points) {
    int n = points.length, best = Math.min(n, 2);
    for (int i = 0; i < n; i++) {
        Map<String, Integer> slopes = new HashMap<>();
        for (int j = i + 1; j < n; j++) {
            int dx = points[j][0] - points[i][0], dy = points[j][1] - points[i][1];
            int g = gcd(dx, dy);
            dx /= g; dy /= g;
            if (dx < 0 || (dx == 0 && dy < 0)) { dx = -dx; dy = -dy; }
            int c = slopes.merge(dx + "/" + dy, 1, Integer::sum);
            best = Math.max(best, c + 1);
        }
    }
    return best;
}
