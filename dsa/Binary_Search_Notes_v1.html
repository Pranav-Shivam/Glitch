Binary Search

Binary search finds a position in sorted data, or a number in a range of possible answers, by looking at the middle and discarding the half that cannot hold the answer. It turns O(n) into O(log n): about 31 looks for two billion items. The skill that matters in interviews is seeing it in disguise, wherever a yes/no question flips exactly once.

Part 1First Principles

One-paragraph summary

Binary search finds a spot in a sorted collection by repeatedly looking at the middle and throwing away the half that cannot contain the answer. It turns "look at every item" (O(n)) into "look at about log2(n) items" (O(log n)): a sorted list of two billion numbers needs at most 31 looks (measured in Appendix B). The big idea for interviews is wider than "find a number in a sorted array": it works on anything where a yes/no question flips exactly once (no, no, no, yes, yes, yes). That can be positions in an array, or a range of possible answers such as "the slowest eating speed that still finishes in time".

 Sorted array, looking for 11.   Each look removes half of what is left.

 index:   0   1   2   3   4   5   6
 value:   1   3   5   7   9  11  13
          lo          mid          hi        step 1: mid = 3, value 7  < 11  -> answer is to the RIGHT
                       [dead zone: 1 3 5 7 can never be 11]

 index:               4   5   6
 value:               9  11  13
                      lo mid  hi             step 2: mid = 5, value 11 = 11  -> found

 7 items -> 2 looks.   Linear scan would have needed 6.   1,000,000 items -> at most 20 looks.

Why it exists and what problem it solves

  • Speed on sorted data. Looking at every item costs O(n). If the data is sorted, one comparison with the middle item tells you which half to discard, so the cost is O(log n).
  • Better than a hash map when order matters. A hash map answers "is x here?" in O(1) but has no sense of order. It cannot answer "the first value that is at least x", "the largest value at most x" (floor), or "how many values are below x". Binary search on a sorted array answers all of these.
  • Better than re-sorting. If you sort once (O(n log n)) and then ask many questions, each question costs O(log n) instead of O(n).
  • It searches answers, not just arrays. "What is the smallest capacity that works?" has no array to search, but the answers 1, 2, 3, ... form a sorted line of yes/no results. You search that line without ever building it.

The core invariant

Write this down before every loop

The answer, if it exists, is always inside the current search space. Every line you write in the loop must keep that sentence true: you may only discard a part of the space after you have proved the answer is not in it. In "first yes" form: everything left of lo is a known no, everything right of hi is a known yes (or hi itself is still a candidate). All the off-by-one bugs in this topic (Part 10) are a violation of this sentence.

How it works inside (conceptual)

  • Each step does one comparison and discards half of the remaining space. After k steps about n / 2^k items remain. The loop ends when one or zero remain, so k is about log2(n).
  • The array must allow O(1) access to the middle (random access). A Python list, a Java array or ArrayList has this. A linked list does not: reaching the middle costs O(n), which destroys the gain. This is why Linked List (next topic) uses a different trick for the middle.
  • The predicate must be monotone. If the answers can flip back (yes, no, yes), one look at the middle cannot tell you which side holds the boundary.
  • Nothing is stored: the search needs O(1) extra space (lo, hi, mid).

When to use it

  • The input is sorted (or sorted after one sort()), and you want a position, a count, a floor/ceiling or the first/last of something.
  • The input is sorted then rotated, or has a mountain / single-peak shape: still enough structure to discard half.
  • The question is "minimise the maximum" or "find the smallest/largest value such that a check passes" and the check gets easier as the value grows. (Search the answer, Type F.)
  • The constraint text says n up to 10^5 or 10^9 with a hint such as "O(log n)" or an answer range that is huge but a check is cheap.

Where you already meet it

  • git bisect: finds the first bad commit among thousands in about log2(n) test runs. The predicate is "does the test fail at this commit?" and it is monotone, as in First Bad Version.
  • Database indexes (B-trees) binary-search inside every page; dictionary and phone-book lookup; the "higher or lower" guessing game.
  • Python bisect, Java Arrays.binarySearch and TreeMap.floorKey, and every sorted autocomplete / version-history / log-lookup feature.
  • Capacity and tuning questions in real systems: "what is the smallest worker count that clears the queue by 6 pm?" is binary search on the answer.

Why it is log n (the argument, not just the label)

Let T(n) be the number of looks needed for n candidates. One look leaves at most half, so T(n) = T(n / 2) + 1, with T(1) = 1. Halving n over and over reaches 1 after log2(n) rounds, so T(n) is about log2(n) + 1. The base of the logarithm does not matter for big-O (log2 n and log10 n differ by a constant), but it is useful to remember that 2^30 is about a billion: one billion items need about 30 looks, which is why a 10^9-wide answer range is fine.

Looks worse than it is

  • A loop inside the binary search. Koko Eating Bananas has a for over the piles inside a while lo < hi. That is O(n x log(max pile)), a product, not n squared: the outer loop runs about 30 times no matter how large n is.
  • Recursion. A recursive binary search is still O(log n) time, and O(log n) stack. The iterative one uses O(1). Prefer iterative.
  • "It is a sorted array so everything is log n". Only the search is. Building the sorted array costs O(n log n); inserting into it costs O(n) (shifting).
  • Amortised cost. Binary search has none: every step does the same constant work. (The amortised idea belongs to the stack, queue and sliding-window topics.)

Best, average, worst

Exact match: best O(1), average and worst O(log n). Boundary and answer-space searches (Types B to F) never return early, so they always take about log n iterations: best = average = worst. Cost on the answer range matters more than on the array length: if the answer is up to 10^9, that is about 30 iterations whatever n is.

Type A: Exact match in a sorted array

Type AEasyclosed interval, return early

1. What it is. Find the index of target in a sorted array, or report that it is absent. The one pattern where you stop the moment you find it.

2. What problem it solves. A yes/no and where, in O(log n) instead of O(n).

3. How to recognise it. "Sorted array", "find the index of", "return -1 if not found", "O(log n) required". Values are usually distinct.

4. Intuition. Compare with the middle. Equal: done. Smaller than the target: the middle and everything left of it are too small, discard them. Larger: the middle and everything right of it are too big, discard them.

5. Generic algorithm
  1. lo = 0, hi = n - 1 (both are real candidates).
  2. While lo <= hi (the space is not empty): mid = lo + (hi - lo) // 2.
  3. If nums[mid] == target, return mid.
  4. If nums[mid] < target: lo = mid + 1. Else: hi = mid - 1. (Both skip mid, which was just ruled out.)
  5. Loop ended with an empty space: return -1.

6. State, validity condition, step. State: lo, hi. Invariant: if the target is present, its index is in [lo, hi]. Validity: the space is non-empty while lo <= hi. Step: the answer branch moves a bound past mid (mid + 1 / mid - 1). Moving to mid instead can loop forever (Part 10, B2).

7. Template (Python and Java), taken from the verified solution of Binary Search (704).

def search(nums, target):
    lo, hi = 0, len(nums) - 1              # the answer, if it exists, is inside [lo, hi]
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1                    # mid is too small, and so is everything left of it
        else:
            hi = mid - 1                    # mid is too big, and so is everything right of it
    return -1
static int search(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // not (lo + hi) / 2: that can overflow int
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Type B: First yes: lower bound / boundary

Type BEasy to Mediumhalf-open [lo, hi), hi = mid

1. What it is. Find the first index where a monotone predicate becomes true (F F F T T T). The answer always exists in [lo, hi] because hi itself is a legal "answer" (even "none of them", represented as n).

2. What problem it solves. First/last occurrence, first value >= x, insert position, count of values (two lower bounds), and every "first bad / first failing / first that works" problem.

3. How to recognise it. "First", "earliest", "leftmost", "smallest index such that", "insert position", "first version that is bad". Duplicates are allowed.

4. Intuition. Do not ask "is this the answer?" Ask "is the predicate already true here?" If yes, the first true is here or to the left, so keep mid (hi = mid). If no, the first true is strictly to the right, so lo = mid + 1. The loop ends when lo == hi: one candidate remains and it is the boundary.

5. Generic algorithm
  1. lo = 0, hi = n (n means "none of them is true"). For a number line like versions, lo = 1, hi = n.
  2. While lo < hi: mid = lo + (hi - lo) // 2.
  3. If predicate(mid) is true: hi = mid (mid may be the answer, keep it).
  4. Else: lo = mid + 1.
  5. Return lo (== hi). Check it is in range and, if the problem needs a match, that it really matches.

6. State, validity condition, step. State: lo, hi. Invariant: the first true index is in [lo, hi]; every index below lo is false. Validity: lo < hi. Step: hi = mid / lo = mid + 1. The line people get wrong: after the loop lo may equal n (no true exists): check lo == len(nums) before indexing.

def first_bad_version(n):
    lo, hi = 1, n                           # the first bad version is somewhere in [lo, hi]
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if isBadVersion(mid):
            hi = mid                        # mid might BE the first bad one: keep it
        else:
            lo = mid + 1                    # mid is good, so the first bad is after it
    return lo

Type C: Last yes: largest value that works (upper mid)

Type CEasy to Mediumlo = mid needs mid rounded UP

1. What it is. Find the last position (or the largest value) where a predicate is still true (T T T F F F). Mirror of Type B.

2. What problem it solves. Integer square root, last occurrence, largest x with some property, "floor" lookups.

3. How to recognise it. "Largest", "last", "floor", "round down", "at most". Often sqrt, pow, capacity.

4. Intuition. If the predicate is true at mid, mid might be the answer or the answer is to the right: keep it with lo = mid. If false, discard it: hi = mid - 1. Because lo = mid does not move forward when mid == lo, the middle must be rounded up or the loop never ends.

5. Generic algorithm
  1. lo = 0, hi = max possible answer.
  2. While lo < hi: mid = (lo + hi + 1) // 2 (upper middle).
  3. If predicate(mid) is true: lo = mid. Else: hi = mid - 1.
  4. Return lo.

6. State, validity condition, step. State: lo, hi. Invariant: the answer is in [lo, hi] and lo is always a valid (true) position. The line people get wrong: mid = (lo + hi) // 2 with lo = mid loops forever when hi = lo + 1. Verified failing input: x = 2 in Sqrt (Part 10, B1). Alternative that avoids the issue: find the first false with Type B, then subtract 1.

Type D: Rotated sorted array

Type DMediumcompare mid with an anchor

1. What it is. A sorted array that was cut at some point and swapped ([4,5,6,7,0,1,2]). At least one half around mid is still sorted, and you can tell which by comparing with an end.

2. What problem it solves. Search for a value, or find the minimum (the rotation point), in O(log n).

3. How to recognise it. "Sorted array rotated at an unknown pivot", "rotated", "shifted", "find the minimum in a rotated array", "O(log n)". Distinct values unless the statement says duplicates.

4. Intuition. Find-min: compare nums[mid] with nums[hi]. If nums[mid] > nums[hi] the drop is to the right of mid. Otherwise mid is already in the small right part and could be the minimum. Search: at least one of [lo..mid] or [mid..hi] is sorted; ask whether the target lies inside that sorted half; if yes go there, if no go to the other half.

5. Generic algorithm
  1. Find-min: lo = 0, hi = n - 1; while lo < hi: mid; if nums[mid] > nums[hi] then lo = mid + 1 else hi = mid; return nums[lo].
  2. Search: while lo <= hi: if nums[mid] == target return; if nums[lo] <= nums[mid] the left half is sorted: test nums[lo] <= target < nums[mid] to choose the side; else the right half is sorted: test nums[mid] < target <= nums[hi].

6. State, validity condition, step. State: lo, hi. Invariant: the minimum (or the target) is in [lo, hi]. Validity: compare against the right end nums[hi], which is always on the correct side of the drop. Lines people get wrong: comparing with nums[lo] (fails on a non-rotated array, verified: [6, 1] gives 6), and nums[lo] < nums[mid] instead of <= in search (verified: [4, 0] target 0 returns -1). Duplicates break it: [1, 0, 1, 1, 1] target 0 returns -1 instead of 1 (Search in Rotated II, practice).

Type E: Peak and hidden structure

Type EMediumdecide from a neighbour, not a target

1. What it is. The array is not sorted, but a local comparison (mid versus a neighbour, or the parity of an index) still tells you which half must contain what you want.

2. What problem it solves. A peak in an unsorted array (adjacent values differ), a mountain top, the one element that appears once in a sorted array of pairs.

3. How to recognise it. "Find any peak", "mountain", "adjacent elements are different", "every element appears twice except one" and the array is sorted, "O(log n)" despite no sorted order.

4. Intuition. Peak: if nums[mid] < nums[mid + 1] you are going uphill; walking right you must either keep climbing to the end (the last element is then a peak, because outside the array counts as minus infinity) or come down after a top. A peak exists on the right. Otherwise a peak exists at mid or on the left. Single element: before the single one, each pair starts at an even index; after it, at an odd index. So at an even mid, nums[mid] == nums[mid + 1] means the single one is further right.

5. Generic algorithm
  1. lo = 0, hi = n - 1; while lo < hi.
  2. Peak: if nums[mid] < nums[mid + 1]: lo = mid + 1; else hi = mid. Return lo.
  3. Single: force mid even (mid -= 1 if odd); if nums[mid] == nums[mid + 1]: lo = mid + 2; else hi = mid.

6. State, validity condition, step. State: lo, hi. Invariant (peak): a peak exists in [lo, hi]. Validity: mid + 1 <= hi is guaranteed because lo < hi. Lines people get wrong: while lo <= hi with nums[mid + 1] reads past the end on a one-element array (verified: [0] raises IndexError); forgetting to make mid even in the single-element problem.

Type F: Binary search on the answer

Type FMedium to Hardmonotone feasibility check

1. What it is. There is no array to search. The thing being searched is a number (speed, capacity, days, distance). For each candidate number a helper feasible(x) answers yes/no in O(n), and the answers are monotone: once feasible, always feasible for larger x (or the reverse).

2. What problem it solves. "Minimise the maximum", "maximise the minimum", "smallest x such that ...", "at least ... within ... days/hours".

3. How to recognise it. "Minimum speed / capacity / time / days such that ...", "minimise the largest sum", "split into k parts", constraints with answers up to 10^9 or 10^18 and n up to 10^5, and the check is a simple greedy.

4. Intuition. Brute force would try x = 1, 2, 3, ... and run the check each time. But if x = 7 fails, x = 3 fails too, and if x = 7 works then x = 9 works too. So the results look like F F F T T T, which is exactly the Type B shape: find the first true. The "array" never exists in memory.

5. Generic algorithm
  1. Choose the range: lo = the smallest value that could possibly work, hi = a value that surely works.
  2. Write feasible(x) as a separate small function. Make sure it is monotone.
  3. While lo < hi: mid; if feasible(mid): hi = mid else lo = mid + 1.
  4. Return lo.

6. State, validity condition, step. State: lo, hi (answer values, not indexes). Invariant: hi is feasible, everything below lo is infeasible. Validity: feasible is monotone. Lines people get wrong: the range (lo = max(weights) for Capacity, not 1), ceiling division (p + k - 1) // k (floor division fails, verified: piles = [7], h = 1 returns 4), and long for sums in Java.

Type G: Search in a 2D matrix

Type GMediumflatten the index

1. What it is. If the matrix is sorted row by row and each row starts after the previous one ends, then reading it row by row gives one sorted list of m x n items. Map a flat index back to (row, col) with mid // cols and mid % cols.

2. What problem it solves. Search in a fully sorted matrix in O(log(m x n)).

3. How to recognise it. "Each row is sorted and the first integer of each row is greater than the last integer of the previous row". If the statement only says rows are sorted and columns are sorted, it is the look-alike (Problem 13): the staircase walk.

4. Intuition. Do not copy the matrix into a list. Pretend it is flat and compute the cell on demand.

5. Generic algorithm
  1. lo = 0, hi = rows * cols - 1.
  2. While lo <= hi: mid; v = matrix[mid // cols][mid % cols].
  3. Same as Type A.

6. State, validity condition, step. State: lo, hi over virtual indexes. Invariant: same as Type A. Lines people get wrong: swapping // and %, or dividing by rows instead of cols.

def search_matrix(matrix, target):

Type H: Lookup in a growing sorted log

Type HMediumbisect inside a data structure

1. What it is. A data structure that keeps a sorted list (timestamps, version numbers, prefix sums) and answers floor/ceiling queries with a binary search.

2. What problem it solves. "What was the value at time t?", "which bucket does this random number fall in?", versioned configs, snapshots, weighted random choice, price at a date.

3. How to recognise it. "Latest value at or before timestamp t", "timestamps are strictly increasing", "pick an index with probability proportional to weight", "snapshot id".

4. Intuition. Append is cheap because the keys only grow, so the list stays sorted for free. A query is a floor lookup: find the first entry after the query and step back one. For weighted random choice, the prefix sums turn "which weight bucket is this random number in" into the first prefix >= r.

5. Generic algorithm
  1. set: append (timestamp, value) to the list for that key.
  2. get: i = bisect_right(times, t) (first timestamp greater than t); answer is values[i - 1] if i > 0, else "none".
  3. Weighted pick: prefix = accumulate(w); draw r in 1..total; first i with prefix[i] >= r.

6. State, validity condition, step. State: parallel lists per key (times, values). Invariant: times are non-decreasing. Lines people get wrong: bisect_left instead of bisect_right (a get at exactly a stored timestamp returns the previous value; verified), and forgetting the "nothing earlier" case (i == 0).

7. Template (Python and Java), taken from the verified solution of Time Based Key-Value Store (981); Random Pick with Weight is Problem 15.

import bisect

    def __init__(self):
        self.times = {}                     # key -> timestamps, increasing (set() timestamps only grow)
        self.vals = {}                      # key -> values, same order

        self.times.setdefault(key, []).append(timestamp)
        self.vals.setdefault(key, []).append(value)

    def get(self, key, timestamp):
        ts = self.times.get(key)
        if not ts:
            return ""
        i = bisect.bisect_right(ts, timestamp)        # first index whose timestamp is > the query
        return self.vals[key][i - 1] if i else ""     # the one just before it is the latest <= query

    Map<String, List<String>> vals = new HashMap<>();

Type I: Partition search (two sorted arrays)

Type IMedium to Hardsearch the cut, not the value

1. What it is. Instead of searching for a value, search for a cut position in the shorter of two sorted arrays so that the left parts of both arrays together hold exactly half of all items, and everything on the left is <= everything on the right.

2. What problem it solves. Median of two sorted arrays in O(log(min(m, n))); k-th element of two sorted arrays.

3. How to recognise it. "Two sorted arrays", "median", "k-th smallest of the union", with an O(log) requirement (merging in O(m + n) is the easy answer that does not satisfy it).

4. Intuition. Pick i items from a; then you need j = half - i from b. A split is correct when a_left <= b_right and b_left <= a_right. If a_left > b_right you took too many from a: go left. If b_left > a_right you took too few: go right. This is a monotone "too many / too few" signal, so binary search applies.

5. Generic algorithm
  1. Make a the shorter array (so j never goes negative).
  2. lo = 0, hi = len(a); while lo <= hi: i = (lo + hi) // 2, j = half - i.
  3. Read the four border values with sentinels (minus/plus infinity) when a side is empty.
  4. If a_left > b_right: hi = i - 1; elif b_left > a_right: lo = i + 1; else the split is valid.
  5. Odd total: max(a_left, b_left). Even: average of that and min(a_right, b_right).

6. State, validity condition, step. State: lo, hi over cut positions in a. Invariant: a valid cut exists with i in [lo, hi]. Lines people get wrong: skipping the "shorter array" swap (verified: a = [2], b = [] raises IndexError), and the sentinels.

7. Template (Python and Java), taken from the verified solution of Median of Two Sorted Arrays (4).

def find_median(a, b):
    if len(a) > len(b):
        a, b = b, a                         # binary search the SHORTER array: fewer steps, no j < 0
    m, n = len(a), len(b)
    half = (m + n + 1) // 2                 # size of the left part (one extra on the left if odd)
    lo, hi = 0, m
    while lo <= hi:
        i = (lo + hi) // 2                  # take i elements from a for the left part
        j = half - i                        # and j = half - i elements from b
        a_left = a[i - 1] if i > 0 else float('-inf')
        a_right = a[i] if i < m else float('inf')
        b_left = b[j - 1] if j > 0 else float('-inf')
        b_right = b[j] if j < n else float('inf')
        if a_left > b_right:
            hi = i - 1                      # took too many from a
        elif b_left > a_right:
            lo = i + 1                      # took too few from a
        else:                               # a_left <= b_right and b_left <= a_right: a valid split
            if (m + n) % 2:
                return max(a_left, b_left)
            return (max(a_left, b_left) + min(a_right, b_right)) / 2
static double findMedian(int[] a, int[] b) {
    if (a.length > b.length) return findMedian(b, a);       // search the shorter array
    int m = a.length, n = b.length, half = (m + n + 1) / 2;
    int lo = 0, hi = m;
    while (lo <= hi) {
        int i = (lo + hi) / 2, j = half - i;
        int aL = i > 0 ? a[i - 1] : Integer.MIN_VALUE, aR = i < m ? a[i] : Integer.MAX_VALUE;
        int bL = j > 0 ? b[j - 1] : Integer.MIN_VALUE, bR = j < n ? b[j] : Integer.MAX_VALUE;
        if (aL > bR) hi = i - 1;
        else if (bL > aR) lo = i + 1;
        else {
            if ((m + n) % 2 == 1) return Math.max(aL, bL);
            return (Math.max(aL, bL) + (long) Math.min(aR, bR)) / 2.0;
        }
    }
    throw new IllegalArgumentException("inputs must be sorted");
}

Where it is reported. Frequently asked. Grind 75 (Binary Search section); NeetCode 150 list (community copy, not checked on neetcode.io); company-tag scores: Meta 45.0, Microsoft 47.3, Amazon 43.6, Apple 22.0.

Problem. Given an array of distinct integers sorted in ascending order and a target, return the index of target, or -1 if it is not in the array. Required: O(log n).

Example. nums = [-1, 0, 3, 5, 9, 12], target = 9 → 4. target = 2 → -1.

Recognise before coding. "Sorted", "return the index", "O(log n)". Nothing else is needed: this is the template itself.

Skill it teaches. Type A, and the discipline of the loop condition: while lo <= hi with both bounds moving past mid.

1Brute force

Scan left to right. Correct but ignores the order.

def search_brute(nums, target):
    for i, x in enumerate(nums):
        if x == target:
            return i
    return -1
static int searchBrute(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) if (nums[i] == target) return i;
    return -1;
}

Cost: O(n) time, O(1) space.

2Observation

The array is sorted, so one comparison with the middle value removes the middle and an entire side. Keep the invariant "if the target exists it is in [lo, hi]" and the code writes itself.

3Optimal solution
def search(nums, target):
    lo, hi = 0, len(nums) - 1              # the answer, if it exists, is inside [lo, hi]
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1                    # mid is too small, and so is everything left of it
        else:
            hi = mid - 1                    # mid is too big, and so is everything right of it
    return -1
static int search(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // not (lo + hi) / 2: that can overflow int
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Cost: O(log n) time, O(1) space.

Say aloud. "Both bounds are real candidates, so I use lo <= hi. After comparing I move past mid because mid is already ruled out. If the loop ends the space is empty, so -1."

First Bad Version

Type BEasyLeetCode 278
ShowHide

Where it is reported. Frequently asked. Grind 75 (Binary Search section); company-tag scores: Meta 45.0, Amazon 38.9, Microsoft 27.3, Apple 22.0.

Problem. Versions 1..n. Once a version is bad, every later version is bad too. isBadVersion(v) tells you whether version v is bad. Find the first bad version with as few calls as possible.

Example. n = 5, first bad = 4: the calls are isBadVersion(3) → false, isBadVersion(5) → true, isBadVersion(4) → true, so the answer is 4.

Recognise before coding. "First", "all later ones are also bad" (= monotone), "minimise the number of calls".

Skill it teaches. Type B: the half-open loop with hi = mid. This is the cleanest statement of "find the first yes".

1Brute force

Check 1, 2, 3, ... until one is bad.

def first_bad_version_brute(n):
    for v in range(1, n + 1):
        if isBadVersion(v):
            return v
static int firstBadVersionBrute(int n) {
    for (int v = 1; v <= n; v++) if (isBadVersion(v)) return v;
    return -1;
}

Cost: O(n) calls.

2Observation

The answers look like good good good bad bad bad. If mid is bad, the first bad is mid or earlier, so keep mid (hi = mid). If mid is good, the first bad is strictly later (lo = mid + 1). Stop when lo == hi.

3Optimal solution
def first_bad_version(n):
    lo, hi = 1, n                           # the first bad version is somewhere in [lo, hi]
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if isBadVersion(mid):
            hi = mid                        # mid might BE the first bad one: keep it
        else:
            lo = mid + 1                    # mid is good, so the first bad is after it
    return lo
static int firstBadVersion(int n) {
    int lo = 1, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (isBadVersion(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

Cost: O(log n) calls, O(1) space.

Measured. For n = 1,000,000 and first bad 777,777 the optimal code called isBadVersion 20 times (Appendix B). Edge. Use lo + (hi - lo) / 2; with n = 2147483647, (lo + hi) / 2 overflowed and the loop did not finish in 100 steps (Appendix B).

Type BMediumLeetCode 34
ShowHide

Where it is reported. Frequently asked. Company-tag scores: Meta 73.1, Apple 63.7, Amazon 60.8, Microsoft 53.8, Google 52.2; also on the Educative list (Google, Microsoft).

Problem. Given a sorted array (duplicates allowed) and a target, return [first, last] index of target, or [-1, -1]. Required: O(log n).

Example. nums = [5, 7, 7, 8, 8, 10], target = 8 → [3, 4]. target = 6 → [-1, -1].

Recognise before coding. "First and last", "duplicates", "O(log n)". A plain Type A returns any match, which is not enough.

Skill it teaches. Reuse one lower_bound twice: the last index of x is lower_bound(x + 1) - 1. One tool, two answers.

1Brute force

Scan the whole array and remember the first and last matches.

def search_range_brute(nums, target):
    first, last = -1, -1
    for i, x in enumerate(nums):
        if x == target:
            if first == -1:
                first = i
            last = i
    return [first, last]
static int[] searchRangeBrute(int[] nums, int target) {
    int first = -1, last = -1;
    for (int i = 0; i < nums.length; i++) {
        if (nums[i] == target) { if (first == -1) first = i; last = i; }
    }
    return new int[]{first, last};
}

Cost: O(n) time, O(1) space.

2Observation

"First position with value >= target" is a boundary search. The first position with value >= target + 1 is one past the last target. So two calls of the same function give both ends, and the match check is nums[first] == target.

3Optimal solution
def search_range(nums, target):
    def lower_bound(x):                     # first index i with nums[i] >= x  (len(nums) if none)
        lo, hi = 0, len(nums)
        while lo < hi:
            mid = lo + (hi - lo) // 2
            if nums[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    first = lower_bound(target)
    if first == len(nums) or nums[first] != target:
        return [-1, -1]
    return [first, lower_bound(target + 1) - 1]    # one past the last 'target' is the first >= target+1
static int lowerBound(int[] nums, int x) {      // first index i with nums[i] >= x, or nums.length
    int lo = 0, hi = nums.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}

static int[] searchRange(int[] nums, int target) {
    int first = lowerBound(nums, target);
    if (first == nums.length || nums[first] != target) return new int[]{-1, -1};
    return new int[]{first, lowerBound(nums, target + 1) - 1};
}

Cost: O(log n) time, O(1) space.

Edge cases to say aloud. Empty array (first == 0 == len(nums) → [-1, -1]), target bigger than everything (first == len(nums): check the index before reading nums[first]), target smaller than everything. Java. target + 1 overflows if target == Integer.MAX_VALUE; LeetCode limits values to 10^9, but mention it.

Find K Closest Elements

Type BMediumLeetCode 658
ShowHide

Where it is reported. Frequently asked. Company-tag scores: Meta 47.0, Apple 46.0, Amazon 45.1, Microsoft 35.7 (Google not seen in the part of the Google file that was read). Added after a review of this page found it was frequent but unsolved.

Problem. Given a sorted array arr, an integer k and a value x, return the k elements closest to x, sorted ascending. If two are equally close, the smaller one wins.

Example. arr = [1, 2, 3, 4, 5], k = 4, x = 3 → [1, 2, 3, 4]. x = -1 → [1, 2, 3, 4].

Recognise before coding. "k closest", "sorted array". The answer is always a contiguous window of length k, so you are searching for the window's left edge, not a value.

Skill it teaches. Type B on a window start: a different thing to search. Compare the two elements that would enter and leave as the window slides.

1Brute force

Sort all elements by (distance to x, value), take the first k, sort them back. O(n log n).

def find_closest_brute(arr, k, x):
    best = sorted(arr, key=lambda v: (abs(v - x), v))[:k]     # closest first, smaller value wins ties
    return sorted(best)
static List<Integer> findClosestBrute(int[] arr, int k, int x) {
    List<Integer> all = new ArrayList<>();
    for (int v : arr) all.add(v);
    all.sort((a, b) -> Math.abs(a - x) != Math.abs(b - x) ? Math.abs(a - x) - Math.abs(b - x) : a - b);
    List<Integer> res = new ArrayList<>(all.subList(0, k));
    Collections.sort(res);
    return res;
}

Cost: O(n log n) time, O(n) space.

2Observation

The closest k elements of a sorted array form a window arr[i..i+k-1]. For a candidate start mid, compare x - arr[mid] (how far the leftmost element is) with arr[mid + k] - x (how far the element just outside on the right is). If the left one is farther, sliding right is better: lo = mid + 1. Otherwise keep mid (ties keep the smaller value, which is on the left). The start lies in [0, n - k], so mid + k never leaves the array.

3Optimal solution
def find_closest(arr, k, x):
    lo, hi = 0, len(arr) - k                # the window of k starts somewhere in [0, n - k]
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if x - arr[mid] > arr[mid + k] - x:
            lo = mid + 1                    # arr[mid + k] is closer than arr[mid]: slide the window right
        else:
            hi = mid                        # arr[mid] is at least as close (ties keep the smaller): stay left
    return arr[lo:lo + k]
static List<Integer> findClosest(int[] arr, int k, int x) {
    int lo = 0, hi = arr.length - k;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (x - arr[mid] > arr[mid + k] - x) lo = mid + 1;
        else hi = mid;
    }
    List<Integer> res = new ArrayList<>();
    for (int i = lo; i < lo + k; i++) res.add(arr[i]);
    return res;
}

Cost: O(log(n - k) + k) time (the search, then copying the window), O(1) extra space.

Why hi = n - k: a window starting later would run past the end. Verified on 4000 small and 300 larger random inputs (up to 500 elements) in both languages, including duplicates in the array.

Problem. Given a non-negative integer x, return the integer part of its square root, without using sqrt or **0.5.

Example. x = 8 → 2 (2.828... rounded down). x = 4 → 2. x = 0 → 0.

1Brute force

Count i upward while (i + 1) * (i + 1) <= x. For x up to 2^31 - 1 this loops up to 46,340 times: fine, but it is the thing to improve.

def my_sqrt_brute(x):
    i = 0
    while (i + 1) * (i + 1) <= x:
        i += 1
    return i
static int mySqrtBrute(int x) {
    long i = 0;
    while ((i + 1) * (i + 1) <= x) i++;
    return (int) i;
}

Cost: O(sqrt x) time, O(1) space.

2Observation

The question "is m * m <= x?" is true for small m and false for large m: T T T F F F. We want the last true. Search [0, x]: if mid * mid <= x, mid could be the answer (lo = mid); otherwise it is too big (hi = mid - 1). Round mid up or the loop stalls.

3Optimal solution
def my_sqrt(x):
    lo, hi = 0, x                           # largest m with m*m <= x lies in [0, x]
    while lo < hi:
        mid = (lo + hi + 1) // 2            # UPPER middle, because the branch below does lo = mid
        if mid * mid <= x:
            lo = mid                        # mid works, so the answer is mid or more
        else:
            hi = mid - 1                    # mid is too big
    return lo
static int mySqrt(int x) {
    long lo = 0, hi = x;                    // long: mid * mid overflows int once mid > 46340
    while (lo < hi) {
        long mid = (lo + hi + 1) / 2;       // upper middle, because of lo = mid
        if (mid * mid <= x) lo = mid;
        else hi = mid - 1;
    }
    return (int) lo;
}

Cost: O(log x) time, O(1) space.

Type DMediumLeetCode 33
ShowHide

Where it is reported. Frequently asked. Grind 75 and NeetCode 150; company-tag scores: Amazon 71.6, Microsoft 68.5, Meta 58.1, Google 57.9, Apple 48.7; Educative lists Google, Amazon, Microsoft. (Listed as deferred to Binary Search in the Arrays notes.)

Problem. An array of distinct integers sorted ascending was rotated at an unknown pivot ([0,1,2,4,5,6,7] → [4,5,6,7,0,1,2]). Return the index of target, or -1. Required: O(log n).

Example. nums = [4, 5, 6, 7, 0, 1, 2], target = 0 → 4. target = 3 → -1.

Recognise before coding. "Rotated". The array is two sorted runs; at least one half around any mid is fully sorted.

Skill it teaches. Type D. Decide which half is sorted, test whether the target lies inside it, go there or go to the other half.

1Brute force

Linear scan.

def search_rotated_brute(nums, target):
    for i, x in enumerate(nums):
        if x == target:
            return i
    return -1
static int searchRotatedBrute(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) if (nums[i] == target) return i;
    return -1;
}

Cost: O(n) time, O(1) space.

2Observation

Look at nums[lo] <= nums[mid]: if true, [lo..mid] has no drop in it, so it is sorted. Then nums[lo] <= target < nums[mid] is a plain range test. If false, the right half [mid..hi] is sorted and the test is nums[mid] < target <= nums[hi]. Either way, one half is discarded.

3Optimal solution
def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:                       # left half [lo..mid] is sorted
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1                            # target is inside the sorted left half
            else:
                lo = mid + 1
        else:                                           # right half [mid..hi] is sorted
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1                            # target is inside the sorted right half
            else:
                hi = mid - 1
    return -1
static int searchRotated(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return mid;
        if (nums[lo] <= nums[mid]) {                    // left half sorted
            if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {                                        // right half sorted
            if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}

Cost: O(log n) time, O(1) space.

Verified bugs. nums[lo] < nums[mid] (strict) instead of <=: fails on [4, 0], target 0 (returns -1, correct 1). With duplicates this code is wrong: [1, 0, 1, 1, 1], target 0 returns -1 (correct 1); that variant is Search in Rotated Sorted Array II, the Part 14 practice problem. Both in Appendix B (B3, B4).

        else hi = mid;
    }
    return nums[lo];

1Brute force

def split_array_brute(nums, k):
    n = len(nums)
    pre = [0]
    for x in nums:
        pre.append(pre[-1] + x)
    INF = float('inf')
    # dp[j][i] = smallest possible "largest piece sum" when the first i numbers form j pieces
    dp = [[INF] * (n + 1) for _ in range(k + 1)]
    dp[0][0] = 0
    for j in range(1, k + 1):
        for i in range(1, n + 1):
            for t in range(j - 1, i):
                dp[j][i] = min(dp[j][i], max(dp[j - 1][t], pre[i] - pre[t]))
    return dp[k][n]
static int splitArrayBrute(int[] nums, int k) {
    int n = nums.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];
    long INF = Long.MAX_VALUE / 2;
    long[][] dp = new long[k + 1][n + 1];
    for (long[] row : dp) Arrays.fill(row, INF);
    dp[0][0] = 0;
    for (int j = 1; j <= k; j++)
        for (int i = 1; i <= n; i++)
            for (int t = j - 1; t < i; t++)
                dp[j][i] = Math.min(dp[j][i], Math.max(dp[j - 1][t], pre[i] - pre[t]));
    return (int) dp[k][n];
}

Cost: O(k x n^2) time, O(k x n) space.

        vals.computeIfAbsent(key, k -> new ArrayList<>()).add(value);
    }

    String get(String key, int timestamp) {
        List<Integer> ts = times.get(key);
        if (ts == null) return "";
        int lo = 0, hi = ts.size();                   // find the first index with timestamp > query
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (ts.get(mid) <= timestamp) lo = mid + 1;
            else hi = mid;
        }
        return lo == 0 ? "" : vals.get(key).get(lo - 1);
    }
}

Where it is reported. Frequently asked. NeetCode 150 list; company-tag scores: Amazon 76.8, Microsoft 75.2, Google 73.9, Meta 66.8, Apple 63.7 (the highest binary-search-tagged problem at Google, Amazon and Microsoft).

Problem. Two sorted arrays nums1 (size m) and nums2 (size n). Return the median of the combined sorted array in O(log(m + n)).

Example. [1, 3], [2] → 2.0. [1, 2], [3, 4] → 2.5.

Recognise before coding. "Two sorted arrays", "median", "O(log (m+n))". Merging is O(m + n) and is exactly the answer the O(log) requirement rules out.

Skill it teaches. Type I: binary search on a cut position, with sentinels for empty sides. The hardest one in this set; you are not expected to derive it cold, but to know it exists and explain the invariant.

1Brute force

Merge (or concatenate and sort) and read the middle.

def find_median_brute(a, b):
    m = sorted(a + b)
    n = len(m)
    if n % 2:
        return m[n // 2]
    return (m[n // 2 - 1] + m[n // 2]) / 2
static double findMedianBrute(int[] a, int[] b) {
    int[] m = new int[a.length + b.length];
    System.arraycopy(a, 0, m, 0, a.length);
    System.arraycopy(b, 0, m, a.length, b.length);
    Arrays.sort(m);

    if (n % 2 == 1) return m[n / 2];

}

Cost: O((m + n) log(m + n)) with sorting, O(m + n) merging.

2Observation

A median splits the combined sorted list into a left half and a right half of equal size (left gets the extra item if the total is odd). If you take i items from a into the left half, you must take j = half - i from b. The split is right when a_left <= b_right and b_left <= a_right. If a_left > b_right you took too many from a; if b_left > a_right, too few. That is a monotone signal on i.

3Optimal solution
def find_median(a, b):
    if len(a) > len(b):
        a, b = b, a                         # binary search the SHORTER array: fewer steps, no j < 0
    m, n = len(a), len(b)
    half = (m + n + 1) // 2                 # size of the left part (one extra on the left if odd)
    lo, hi = 0, m
    while lo <= hi:
        i = (lo + hi) // 2                  # take i elements from a for the left part
        j = half - i                        # and j = half - i elements from b
        a_left = a[i - 1] if i > 0 else float('-inf')
        a_right = a[i] if i < m else float('inf')
        b_left = b[j - 1] if j > 0 else float('-inf')
        b_right = b[j] if j < n else float('inf')
        if a_left > b_right:
            hi = i - 1                      # took too many from a
        elif b_left > a_right:
            lo = i + 1                      # took too few from a
        else:                               # a_left <= b_right and b_left <= a_right: a valid split
            if (m + n) % 2:
                return max(a_left, b_left)
            return (max(a_left, b_left) + min(a_right, b_right)) / 2
static double findMedian(int[] a, int[] b) {
    if (a.length > b.length) return findMedian(b, a);       // search the shorter array
    int m = a.length, n = b.length, half = (m + n + 1) / 2;
    int lo = 0, hi = m;
    while (lo <= hi) {
        int i = (lo + hi) / 2, j = half - i;
        int aL = i > 0 ? a[i - 1] : Integer.MIN_VALUE, aR = i < m ? a[i] : Integer.MAX_VALUE;
        int bL = j > 0 ? b[j - 1] : Integer.MIN_VALUE, bR = j < n ? b[j] : Integer.MAX_VALUE;
        if (aL > bR) hi = i - 1;
        else if (bL > aR) lo = i + 1;
        else {
            if ((m + n) % 2 == 1) return Math.max(aL, bL);
            return (Math.max(aL, bL) + (long) Math.min(aR, bR)) / 2.0;
        }
    }
    throw new IllegalArgumentException("inputs must be sorted");
}

Cost: O(log(min(m, n))) time, O(1) space.

The five-line write-down (do this before typing the loop)

Write this in a comment first
  1. Search space: what are lo and hi? Indexes or answer values? Is hi a real candidate or "one past the end"?
  2. Predicate: the yes/no question, and one example showing it flips once (F F T T).
  3. What am I finding: exact match (early return), first true, last true?
  4. Update rules: on true, on false. Each must keep the invariant "answer is in [lo, hi]" and make progress (the space must shrink on every path).

def ship_within_days(weights, days):
    lo, hi = max(weights), sum(weights)     # below max(weights) a package never fits; sum always works
    while lo < hi:
        mid = lo + (hi - lo) // 2
        need, load = 1, 0                   # greedy: fill each day as full as the capacity allows
        for w in weights:
            if load + w > mid:
                need += 1
                load = 0
            load += w
        if need <= days:
            hi = mid                        # feasible: try a smaller capacity
        else:
            lo = mid + 1
    return lo
static int shipWithinDays(int[] weights, int days) {
    int lo = 0, hi = 0;
    for (int w : weights) { lo = Math.max(lo, w); hi += w; }
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        int need = 1, load = 0;
        for (int w : weights) {
            if (load + w > mid) { need++; load = 0; }
            load += w;
        }
        if (need <= days) hi = mid;
        else lo = mid + 1;
    }

}

        self.times = {}                     # key -> timestamps, increasing (set() timestamps only grow)
        self.vals = {}                      # key -> values, same order

    def set(self, key, value, timestamp):
        self.times.setdefault(key, []).append(timestamp)
        self.vals.setdefault(key, []).append(value)

    def get(self, key, timestamp):
        ts = self.times.get(key)
        if not ts:
            return ""
        i = bisect.bisect_right(ts, timestamp)        # first index whose timestamp is > the query
        return self.vals[key][i - 1] if i else ""     # the one just before it is the latest <= query

    Map<String, List<Integer>> times = new HashMap<>();
    Map<String, List<String>> vals = new HashMap<>();

    void set(String key, String value, int timestamp) {
        times.computeIfAbsent(key, k -> new ArrayList<>()).add(timestamp);
        vals.computeIfAbsent(key, k -> new ArrayList<>()).add(value);
    }

    String get(String key, int timestamp) {
        List<Integer> ts = times.get(key);
        if (ts == null) return "";

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (ts.get(mid) <= timestamp) lo = mid + 1;
            else hi = mid;
        }

Exercise 1: Versioned configuration store ("what was the setting at 14:05?")

Scenario. A feature-flag service stores every change to every setting. Support and debugging need to read what a setting was at any past moment.

LevelRequirement (each adds to the previous)
1set(key, value, ts) with non-decreasing timestamps per key; get(key, ts) returns the value in effect at ts (latest change <= ts), or None if the key had no value yet.
2Writes can arrive out of order (late events), and you need delete(key, ts) (a tombstone: after it the key has no value). get must respect tombstones.
3Retention: drop versions older than a cutoff to bound memory, while get for times inside the retention window stays correct (including the value that was still in effect at the cutoff). Add history(key, t1, t2) returning every change in [t1, t2].

What this exercises. Type H. Per key, a sorted list of versions and bisect_right for the floor lookup. Justify: parallel lists vs list of tuples (bisect on times only), bisect.insort cost for out-of-order writes (O(n) shift) versus a balanced tree, tombstones vs deletion, and how you find the retention cut with a second bisect.

  • Test: a get exactly at a stored timestamp, before the first version, after the last, two versions with the same timestamp, a tombstone followed by a set, an out-of-order insert in the middle, history with both endpoints on stored timestamps, retention that removes everything except the latest version.
  • Edge cases: empty store, unknown key, negative timestamps, t1 > t2, huge timestamps, values that are None vs "missing".
  • Interviewer extensions (stated, not solved): thread safety (readers during a write: copy-on-write list or a lock per key), many millions of keys (memory per version), persistence and replay after a crash, whether to keep versions in a database with a clustered index on (key, ts).

Exercise 2: Capacity planner ("the smallest fleet that clears the queue by 6 pm")

Scenario. A batch system has a list of jobs with known durations that must run in the given order, split into consecutive groups, one group per worker. Management wants the smallest per-worker time budget that lets w workers finish everything.

LevelRequirement (each adds to the previous)
1Given durations and w workers, return the minimum time budget T such that the jobs, in order, can be assigned to at most w workers with each worker's total <= T (this is the Problem 11 shape; implement it with an explicit feasible(T) function).
2Add a fixed startup cost s per worker (so a worker with total x takes x + s), and a different rate per worker type. Check again: is feasible still monotone? Then return the smallest w (not T) that meets a deadline D.
3Durations are real numbers (seconds with fractions); return the smallest T to within 1e-6. Then add a cooldown rule: after any worker finishes it cannot be reused for c seconds. Decide whether binary search is still valid and justify it with a small counter-example or a proof.

What this exercises. Type F. A separate feasible(T), the right range (lo = max(durations), hi = sum(durations)), a monotonicity argument for every added rule, and what changes for real-valued answers (loop count instead of lo == hi).

  • Test: one job, w = 1 (answer is the sum), w >= len(durations) (answer is the max), all jobs equal, one huge job, the answer exactly at a boundary, floating-point answer precision, a deliberately non-monotone variant to confirm your reasoning catches it.
  • Edge cases: empty list, w = 0, negative durations, durations of 0, overflow of the sum (Java long), 1e-6 tolerance vs relative tolerance.
  • Interviewer extensions (stated, not solved): estimating T when durations are only known as distributions, an online version where jobs keep arriving, a distributed planner where the check itself is expensive (cache results, shrink the range with a quick bound), and what happens if the feasibility check is only approximately monotone (noise).

Kth Missing Positive Number · LeetCode 1539

Idea. Type B with a derived predicate. For index i, arr[i] - (i + 1) counts the positive integers missing before arr[i]. It never decreases with i. Find the first index where that count is >= k; call it lo. Then exactly lo array values lie below the answer, so the answer is lo + k.

def find_kth_positive(arr, k):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if arr[mid] - (mid + 1) >= k:       # numbers missing before arr[mid] is arr[mid] - (mid + 1)
            hi = mid
        else:
            lo = mid + 1
    return lo + k                           # lo array values are below the answer, so shift k by lo
static int findKthPositive(int[] arr, int k) {
    int lo = 0, hi = arr.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] - (mid + 1) >= k) hi = mid;
        else lo = mid + 1;
    }
    return lo + k;
}

Search in Rotated Sorted Array II · LeetCode 81

Idea. Type D with duplicates. Same as Problem 5, plus one case: when nums[lo] == nums[mid] == nums[hi] you cannot tell which half is sorted, so shrink both ends by one and continue. Worst case (all equal except one) is O(n), which is unavoidable: a lone different value can hide anywhere.

def search_rotated_ii(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] == target:
            return True
        if nums[lo] == nums[mid] == nums[hi]:
            lo += 1                         # cannot tell which half is sorted: shrink both ends
            hi -= 1
        elif nums[lo] <= nums[mid]:         # left half sorted
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                               # right half sorted
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return False
static boolean searchRotatedII(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return true;
        if (nums[lo] == nums[mid] && nums[mid] == nums[hi]) { lo++; hi--; }
        else if (nums[lo] <= nums[mid]) {
            if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {
            if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return false;
}

Cost: O(log n) average, O(n) worst case, O(1) space.

Kth Smallest Element in a Sorted Matrix · LeetCode 378

Idea. Type F (search the values) with a staircase count. Search values in [matrix[0][0], matrix[n-1][n-1]]. For a guess mid, count how many entries are <= mid by walking from the bottom-left corner: if the cell is <= mid, the whole column above it is too, so add r + 1 and move right; otherwise move up. If the count is >= k the answer is mid or less, else it is more. The final lo is always an element of the matrix (the smallest value with count >= k).

def kth_smallest(matrix, k):
    n = len(matrix)
    lo, hi = matrix[0][0], matrix[n - 1][n - 1]       # the answer is a VALUE in [smallest, largest]
    while lo < hi:
        mid = lo + (hi - lo) // 2
        count, r, c = 0, n - 1, 0                     # count entries <= mid, walking from bottom-left
        while r >= 0 and c < n:
            if matrix[r][c] <= mid:
                count += r + 1                        # the whole column above (r, c) is <= mid too
                c += 1
            else:
                r -= 1
        if count >= k:
            hi = mid                                  # at least k values are <= mid: answer is mid or less
        else:
            lo = mid + 1
    return lo
static int kthSmallest(int[][] matrix, int k) {
    int n = matrix.length;
    int lo = matrix[0][0], hi = matrix[n - 1][n - 1];
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        int count = 0, r = n - 1, c = 0;
        while (r >= 0 && c < n) {
            if (matrix[r][c] <= mid) { count += r + 1; c++; }
            else r--;
        }
        if (count >= k) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

Cost: O(n log(max - min)) time, O(1) space. A heap solution is O(k log n) (Heaps topic).

Minimum Number of Days to Make m Bouquets · LeetCode 1482

Idea. Type F. Impossible if m * k > len(bloomDay) (check first, using long in Java). Otherwise "can make m bouquets by day d" is monotone in d. Count runs of k adjacent flowers with bloomDay <= d; an unbloomed flower resets the run. Search [min(bloomDay), max(bloomDay)].

def min_days(bloom_day, m, k):
    if m * k > len(bloom_day):
        return -1                           # not enough flowers at all
    lo, hi = min(bloom_day), max(bloom_day)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        bouquets = run = 0                  # on day mid, count runs of k ADJACENT bloomed flowers
        for d in bloom_day:
            if d <= mid:
                run += 1
                if run == k:
                    bouquets += 1
                    run = 0
            else:
                run = 0                     # an unbloomed flower breaks adjacency
        if bouquets >= m:
            hi = mid
        else:
            lo = mid + 1
    return lo
static int minDays(int[] bloomDay, int m, int k) {
    if ((long) m * k > bloomDay.length) return -1;       // long: m * k can pass 2^31
    int lo = Integer.MAX_VALUE, hi = 0;
    for (int d : bloomDay) { lo = Math.min(lo, d); hi = Math.max(hi, d); }
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        int bouquets = 0, run = 0;
        for (int d : bloomDay) {
            if (d <= mid) { run++; if (run == k) { bouquets++; run = 0; } }
            else run = 0;
        }
        if (bouquets >= m) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

Cost: O(n log(max - min)) time, O(1) space.

Find Minimum in Rotated Sorted Array II · LeetCode 154

Idea. Type D with duplicates. Compare nums[mid] with nums[hi]. If greater, the minimum is right of mid. If smaller, mid could be the minimum: hi = mid. If equal, you cannot tell, but dropping hi (hi -= 1) is safe because mid has the same value, so the minimum value is not lost. Worst case O(n) (e.g. all equal).

def find_min_dup(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] > nums[hi]:
            lo = mid + 1
        elif nums[mid] < nums[hi]:
            hi = mid
        else:
            hi -= 1                         # equal: cannot tell, but dropping hi is safe (mid has the same value)
    return nums[lo]
static int findMinDup(int[] nums) {
    int lo = 0, hi = nums.length - 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] > nums[hi]) lo = mid + 1;
        else if (nums[mid] < nums[hi]) hi = mid;
        else hi--;
    }
    return nums[lo];
}

Cost: O(log n) average, O(n) worst case, O(1) space.
