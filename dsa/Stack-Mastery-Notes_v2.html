Part 1First Principles

In one paragraph

A stack is a pile where you only touch the top. Many problems have a hidden pile: things you have started but cannot finish yet, and the next thing that happens always finishes the newest unfinished one first (a bracket closes, a letter is erased, a bigger number arrives). Without a stack you rescan backwards to find that newest unfinished item, O(n) each time and O(n²) overall. With a stack it is sitting on top, O(1) each time, so the whole scan becomes O(n).

What a stack is

A stack is a list with one open end, called the top. You add at the top (push), remove from the top (pop), and look at the top without removing it (peek). The last item in is the first item out. This is LIFO, last in, first out.

The video's picture is a stack of plates in a cafeteria. Clean plates go on the pile, and the plate on top is the first one taken to be used.

Why it exists

Many problems have this shape: you start something, you cannot finish it until something later happens, and when it happens you must finish the most recent unfinished thing first.

  • Brackets: the last bracket opened must be the first one closed.
  • Nested function calls: the innermost call returns first.
  • Undo: the latest action is reversed first.

A stack remembers unresolved things in the order they must be resolved.

What it does better than an array and a loop

With only an array and a loop, finding the most recent unresolved item means rescanning backwards, which costs O(n) every time. A stack keeps that item at the top, so you reach it in O(1).

How it works inside

A stack is a dynamic array where you only touch the last slot, or a linked list where you only touch the head. Both give O(1) push and pop. Nothing has to shift, because the open end is the only end you use.

The core invariant

Invariant

The stack holds exactly the items that are still unresolved, in the order they must be resolved: the newest on top. Every algorithm in these notes is this sentence plus a rule for when the top gets resolved. For a monotonic stack the sentence gets one more clause: the unresolved items are also sorted (decreasing or increasing from bottom to top), which is why a single comparison with the top decides everything.

Use a stack when

  • Symbols must match or nest
  • You need the most recent unresolved item
  • You are simulating reversal or undo
  • You need the next greater or smaller element
  • You want to simulate recursion with your own loop
  • You are evaluating expressions

Do not use a stack when

  • You need the middle or both ends (use a deque)
  • You need the smallest or largest of everything seen so far (use a heap)
  • A contiguous range with both ends moving is the idea (use a sliding window)
  • You need lookup by value (use a hash map)
  • First come, first served (use a queue)

Where you already meet stacks

From the video: A stack is not only a data structure. After enough problems it becomes a coding pattern you can spot: you have pending items, and a later item resolves the most recent ones.

  • Matching parentheses. The first stack problem most people see. It checks whether an expression is valid before you spend time evaluating it.
  • Evaluating expressions. Use the same stack to solve small portions and combine them.
  • Parsing code. A compiler knows a bracket was never matched the same way parenthesis matching does.
  • Undo and redo. The undo button keeps a stack of your operations and undoes the topmost one first.
  • The call stack. Recursion is the system's stack. An iterative DFS uses your own.

Best, average and worst case

The basic operations have no real best or worst case: pop is always O(1), and push is O(1) except for the occasional resize (single worst push O(n), amortized O(1)). For algorithms the time is O(n) on every input, but the space changes:

Input shapeSpace used (Next Greater, left to right)Why
Strictly decreasing, like 5 4 3 2 1O(n), the worst caseNothing is ever popped, everyone waits.
Strictly increasing, like 1 2 3 4 5O(1) at any momentEach new value pops the previous one.
RandomUsually smallThe stack keeps only the elements that no later element has beaten yet.

Why the monotonic stack is O(n), not O(n²)

A monotonic stack has a while loop inside a for loop, which looks quadratic. It is not. Count the work by the items, not by the loops:

  1. Every item is pushed exactly once. That is n pushes.
  2. An item can be popped only if it was pushed, and only once. That is at most n pops.
  3. Each pop is one pass of the inner loop, and each outer iteration adds one more failed comparison. Total comparisons ≤ pushes + pops + n ≤ 3n.
Say this aloud

"The inner while loop looks nested, but each element enters the stack once and leaves at most once, so the total work is O(n), amortized O(1) per element."

Type AMatching and nesting

Every closer must match the most recent opener that is still open.

Recognize it

  • Brackets, tags, quotes, or any paired symbols
  • The words valid, balanced, well-formed, nested
Algorithm
  1. Start with an empty stack.
  2. Push every opener.
  3. On a closer, the stack must be non-empty and its top must pair with the closer. Pop it.
  4. After the last symbol the stack must be empty.
Pseudocode
stack = empty
for each symbol c:
    if c is an opener:    push c
    else:                 if stack is empty: return invalid
                          top = pop()
                          if top does not pair with c: return invalid
return stack is empty

InvariantThe stack is the list of unmatched openers, outermost at the bottom, innermost on top. A closer is only legal if it pairs with the top.
Each stepOpener: push. Closer: stack empty means invalid; otherwise pop and check that it pairs.
ResultValid only if the stack is empty at the end.

Template code for Type A (verified, taken from this problem)
def valid_parentheses(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in pairs:                              # closer
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:                                        # opener
            stack.append(ch)
    return not stack                                 # leftover openers => invalid
static boolean optimal(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char ch : s.toCharArray()) {
        if (ch == '(' || ch == '[' || ch == '{') {
            stack.push(ch);
        } else {
            if (stack.isEmpty()) return false;      // closer with nothing open
            char open = stack.pop();
            if ((ch == ')' && open != '(') || (ch == ']' && open != '[') || (ch == '}' && open != '{'))
                return false;
        }
    }
    return stack.isEmpty();                          // leftover openers => invalid
}

Type BCancel and undo

The stack is the result so far, and a new item may cancel the top.

Recognize it

  • Remove adjacent pairs, backspace, undo, cancel out
  • Simulations where only the latest survivor can interact with the new arrival
Algorithm
  1. Treat the stack as the answer built so far.
  2. For each item, check whether it cancels the top.
  3. Use a while loop if one item can cancel several, as in asteroids.
  4. If the item survives, push it. The stack read bottom to top is the result.
Pseudocode
stack = empty
for each item x:
    alive = true
    while alive and stack not empty and cancels(stack.top, x):
        resolve(stack.pop(), x)       # may mark x as destroyed
    if alive: push x
return stack, bottom to top
StateA stack holding the survivors so far, which is the answer being built.
InvariantNo two neighbouring survivors cancel each other. Only the newest survivor can interact with a new arrival.
Each stepWhile the new item cancels the top, resolve the pair (pop). If the new item survives, push it.
ResultThe stack read bottom to top is the answer.
TimeO(n)
SpaceO(n)

def make_great(s):
    stack = []
    for ch in s:
        if stack and abs(ord(stack[-1]) - ord(ch)) == 32:
            stack.pop()
        else:

    StringBuilder stack = new StringBuilder();

Type CExpressions and nested context

Operators act on the latest results, and brackets pause the work in progress.

Recognize it

  • Postfix or prefix expressions, calculators
  • Nested structures where content is transformed, like 3[a2[c]]
Algorithm
  1. Postfix: push numbers. An operator pops the right operand, then the left operand, and pushes the result.
  2. Nested: on an opening bracket, push the state you are in the middle of, and start fresh.
  3. On a closing bracket, pop the saved state and combine it with what you just built.
  4. Compilers match brackets in code the same way.
Pseudocode
RPN:     for token: if number: push
                    else: b = pop(); a = pop(); push(a op b)
Nested:  on '[':  push (current, count); reset current and count
         on ']':  (prev, k) = pop(); current = prev + current * k
StateRPN: a stack of finished operand values. Nested: a stack of paused outer contexts (the string so far and the repeat count).
InvariantRPN: the stack holds results that are final but not yet consumed by an operator. Nested: each saved context is exactly the work paused when that bracket opened.
Each stepRPN: number pushes, operator pops two (right operand first) and pushes the result. Nested: [ saves and resets, ] restores and combines.
ResultRPN: the single value left. Nested: the string being built when the input ends.

def decode_string(s):
    stack = []                                # saved (previous_string, repeat_count)
    cur, num = "", 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)          # multi-digit counts
        elif ch == '[':
            stack.append((cur, num))          # save context
            cur, num = "", 0
        elif ch == ']':
            prev, k = stack.pop()             # restore context
            cur = prev + cur * k
        else:
            cur += ch
    return cur
static String optimal(String s) {
    Deque<StringBuilder> strs = new ArrayDeque<>();      // saved previous strings
    Deque<Integer> counts = new ArrayDeque<>();          // saved repeat counts
    StringBuilder cur = new StringBuilder();
    int num = 0;
    for (char ch : s.toCharArray()) {
        if (Character.isDigit(ch)) {
            num = num * 10 + (ch - '0');                 // multi-digit counts
        } else if (ch == '[') {
            strs.push(cur);                              // save context
            counts.push(num);
            cur = new StringBuilder();
            num = 0;
        } else if (ch == ']') {
            StringBuilder prev = strs.pop();             // restore context
            int k = counts.pop();
            for (int i = 0; i < k; i++) prev.append(cur);
            cur = prev;
        } else {
            cur.append(ch);
        }
    }
    return cur.toString();
}

Type DMonotonic stack: next greater or smaller

Elements wait on the stack for an answer, and a later element resolves many of them at once.

Recognize it

  • Next greater, next smaller, previous greater, previous smaller
  • How many days until, how far until, the first element to the right that is bigger
  • Spans and online streams of values
Algorithm
  1. Keep a stack of indices that are still waiting for an answer.
  2. For each new element, while it beats the top, pop the top and record the answer for it.
  3. Push the new element.
  4. Whatever remains at the end has no answer. Give it -1 or 0.
Pseudocode
stack = empty                     # holds indices
for i in 0 .. n-1:
    while stack not empty and nums[stack.top] < nums[i]:
        j = pop()
        answer[j] = f(i, j)           # value nums[i], or distance i - j
    push i
# leftovers have no answer

def daily_temps(t):
    ans = [0] * len(t)
    stack = []                                # indices, temperatures decreasing
    for i, x in enumerate(t):
        while stack and t[stack[-1]] < x:
            j = stack.pop()
            ans[j] = i - j
        stack.append(i)
    return ans
static int[] optimal(int[] t) {
    int[] ans = new int[t.length];

Type ESpan, area and contribution

For each element, the nearest bigger or smaller element on each side gives its reach.

Recognize it

  • Largest rectangle, span, widest range where an element is the minimum
  • For every element treated as the minimum or maximum of a range
  • Water or area trapped between walls
Algorithm
  1. Decide which neighbor matters: the nearest smaller (for minimum) or nearest greater (for maximum).
  2. Use a monotonic stack to find that neighbor on both sides.
  3. Width is right - left - 1. Multiply by the height, or count the subarrays.
  4. Add a sentinel so nothing stays on the stack unmeasured.
  5. With equal values, make one side strict and the other non-strict.
Pseudocode
for each element i:
    left[i]  = index of nearest smaller on the left   (or -1)
    right[i] = index of nearest smaller on the right  (or n)
    width = right[i] - left[i] - 1
    area = height[i] * width              # or count subarrays: (i-left) * (right-i)
StateA stack of (start index, height) with heights increasing, or just indices.
InvariantThe stacked heights are increasing, so when a shorter bar arrives, everything taller on the stack has reached its right edge exactly here, and the item below it is its left edge.
Each stepPop while the top is taller than the new bar. For each pop the width is now known, so compute the area (or the count of subarrays) at once.
ResultThe best area seen. Append a sentinel 0 so every bar is popped and measured.
TimeO(n)
SpaceO(n)

def largest_rectangle(heights):
    stack = []                                # (start_index, height), heights increasing
    best = 0
    for i, h in enumerate(heights + [0]):     # sentinel 0 flushes the stack
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            best = max(best, height * (i - idx))
            start = idx                       # current bar extends left to idx
        stack.append((start, h))
    return best
static int optimal(int[] heights) {
    Deque<int[]> stack = new ArrayDeque<>();             // {start_index, height}, heights increasing
    int best = 0;
    for (int i = 0; i <= heights.length; i++) {
        int h = (i == heights.length) ? 0 : heights[i];  // sentinel 0 flushes the stack
        int start = i;
        while (!stack.isEmpty() && stack.peek()[1] > h) {
            int[] top = stack.pop();
            best = Math.max(best, top[1] * (i - top[0]));
            start = top[0];                              // current bar extends left to here
        }
        stack.push(new int[]{start, h});
    }
    return best;
}

Type FDesign with stacks

Carry extra information with each entry, or use two stacks to imitate another structure.

Recognize it

  • Design a stack that also returns min or max in O(1)
  • Implement a queue using only stacks
Algorithm
  1. Ask what extra fact must be known at every depth, and store it next to the value so popping restores it.
  2. To imitate a queue, use an inbox and an outbox.
  3. Move items from inbox to outbox only when the outbox is empty.
  4. Argue the cost with amortized analysis: each item moves at most once.
Pseudocode
MinStack:  push(x): store (x, min(x, current min))
           pop(): remove the pair, the old min is restored
Queue:     enqueue(x): inbox.push(x)
           dequeue():  if outbox empty: move all inbox -> outbox
                       return outbox.pop()
StateEach entry carries the extra fact (for Min Stack: the minimum up to and including that entry). For the queue: an inbox stack and an outbox stack.
InvariantMin Stack: the extra fact in the top entry is correct for the whole stack, so popping automatically restores the earlier answer. Queue: every item in the outbox is older than every item in the inbox, and the outbox top is the oldest.
Each stepPush computes the fact from the current top. Pop just discards. For the queue, refill the outbox from the inbox only when the outbox is empty.
ResultEvery operation answers in O(1) (amortized for the queue).
TimeO(1) per operation (amortized for the queue)
SpaceO(n)

class MinStack:                               # one stack of (value, min_so_far)
    def __init__(self):
        self.s = []

    def push(self, x):
        mn = min(x, self.s[-1][1]) if self.s else x
        self.s.append((x, mn))

    def pop(self):
        return self.s.pop()[0]

    def top(self):
        return self.s[-1][0]

    def get_min(self):
        return self.s[-1][1]
class MinStack {                                             // one stack of {value, min_so_far}
    private final Deque<int[]> s = new ArrayDeque<>();
    void push(int x) {
        int mn = s.isEmpty() ? x : Math.min(x, s.peek()[1]);
        s.push(new int[]{x, mn});
    }
    int pop() { return s.pop()[0]; }
    int top() { return s.peek()[0]; }

Type GA stack in disguise

Transform the input first, then the stack appears.

Recognize it

  • Objects that merge or block each other along a line
  • A greedy order after sorting where each item compares with the last kept one
Algorithm
  1. Find the key quantity that makes the problem one-dimensional, such as arrival time.
  2. Sort so you process items in the order they interact.
  3. Check how each item compares with the previous survivor. If only the last survivor matters, it is a stack.
  4. Push or merge based on that comparison.
Pseudocode
sort items by position, nearest to the target first
for each item:
    t = arrival_time(item)
    if stack empty or t > stack.top: push t      # new fleet
    # else: merges into the fleet ahead
return stack size
StateA stack of arrival times, one per fleet, front fleet at the bottom.
InvariantAfter sorting by position (closest to the target first), the stacked arrival times are strictly increasing from bottom to top, because a car that would arrive no later than the fleet ahead has merged into it.
Each stepCompute the car's arrival time. If it is strictly greater than the top, it is a new fleet: push. Otherwise it merges: do nothing.
ResultThe stack size is the number of fleets.
TimeO(n log n), dominated by the sort
SpaceO(n)

Template code for Type G (verified, taken from this problem)
def car_fleet(target, position, speed):
    stack = []                                # arrival times of fleets, front to back
    for p, s in sorted(zip(position, speed), reverse=True):   # closest to target first
        t = (target - p) / s
        if not stack or t > stack[-1]:        # slower than the fleet ahead: new fleet
            stack.append(t)                   # otherwise it catches up and merges
    return len(stack)
static int optimal(int target, int[] position, int[] speed) {
    int n = position.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a, b) -> position[b] - position[a]);   // closest to target first
    Deque<Double> stack = new ArrayDeque<>();            // arrival times of fleets
    for (int i : idx) {
        double t = (double) (target - position[i]) / speed[i];
        if (stack.isEmpty() || t > stack.peek()) stack.push(t);   // slower: new fleet
    }                                                    // otherwise it merges into the fleet ahead
    return stack.size();
}

Type HStack as explicit recursion

Any recursion can become a loop with your own stack. This is a preview of Trees and Graphs.

Recognize it

  • A recursive solution that can go very deep
  • DFS, tree traversals and backtracking written without recursion
Algorithm
  1. Write the recursive version first and note what it remembers between calls.
  2. Put that state on your own stack instead of the call stack.
  3. Pop to take the next piece of work, and push the pieces you discover.
  4. Push children in reverse if you want the same order as the recursion.
Pseudocode
stack = [start]
while stack not empty:
    node = pop()
    if node already seen: continue
    mark node seen and visit it
    for each neighbor in reverse order:
        if neighbor not seen: push neighbor
StateA stack of nodes that are discovered but not yet visited, plus a visited set.
InvariantThe top is the node the recursive version would visit next. A node is marked visited when popped, not when pushed.
Each stepPop a node, skip it if seen, visit it, push its unseen neighbours in reverse order.
ResultThe visit order, equal to the recursive order.
TimeO(V + E)
SpaceO(V)

def dfs_iterative(graph, start):
    seen, order = set(), []
    stack = [start]                           # our own stack replaces the call stack
    while stack:
        node = stack.pop()
        if node in seen:                      # mark seen on pop, to match the recursive order
            continue
        seen.add(node)
        order.append(node)
        for nxt in reversed(graph[node]):     # reversed, so the first neighbor is popped first
            if nxt not in seen:
                stack.append(nxt)
    return order
static List<Integer> iterative(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    Set<Integer> seen = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>();           // our own stack replaces the call stack
    stack.push(start);
    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (!seen.add(node)) continue;                   // add returns false if already seen: mark on pop
        order.add(node);
        List<Integer> nbrs = graph.get(node);
        for (int i = nbrs.size() - 1; i >= 0; i--) {     // reversed, so the first neighbor is popped first
            if (!seen.contains(nbrs.get(i))) stack.push(nbrs.get(i));
        }
    }
    return order;
}

Given a string made of ()[]{}, decide whether every bracket is closed by the right kind of bracket, in the right order. "{[]}" is valid. "([)]" is not.

Recognize before codingNesting, where a closer must match the latest opener.
Skill it teachesPush and pop discipline, and guarding against an empty stack.
1Brute force

Keep deleting adjacent pairs (), [] and {} from the string. If nothing is left, the string was valid. Every pass scans the whole string, and ((((....)))) needs n/2 passes.

def valid_parentheses_brute(s):
    # keep deleting adjacent matched pairs until nothing changes
    prev = None
    while prev != s:
        prev = s
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return s == ""
static boolean brute(String s) {
    String prev;
    do {                                  // keep deleting matched pairs until nothing changes
        prev = s;
        s = s.replace("()", "").replace("[]", "").replace("{}", "");
    } while (!s.equals(prev));
    return s.isEmpty();
}
2The bottleneck and the key observation

The pair that cancels is always the most recently opened bracket that is still unmatched. That is what LIFO means, so the unmatched openers belong on a stack. In the video the stack is exactly this: add every opener, and on a closer compare it with the top.

3Optimal approach
  1. Start with an empty stack.
  2. Opener: push it.
  3. Closer: if the stack is empty, return false. Otherwise pop and check that the popped opener pairs with this closer.
  4. After the last character, the stack must be empty. Anything left is an opener that was never closed.
def valid_parentheses(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in pairs:                              # closer
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:                                        # opener
            stack.append(ch)
    return not stack                                 # leftover openers => invalid
static boolean optimal(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char ch : s.toCharArray()) {
        if (ch == '(' || ch == '[' || ch == '{') {
            stack.push(ch);
        } else {
            if (stack.isEmpty()) return false;      // closer with nothing open
            char open = stack.pop();
            if ((ch == ')' && open != '(') || (ch == ']' && open != '[') || (ch == '}' && open != '{'))
                return false;
        }
    }
    return stack.isEmpty();                          // leftover openers => invalid
}

Two strings where # is a backspace. Are they equal after typing both into an empty editor? "ab#c" and "ad#c" both end up as "ac".

Recognize before codingA character that undoes the one before it.
Skill it teachesUsing a stack as the result so far.
1Brute force

Build each final string one character at a time, and on every # rebuild it without its last character. Slicing copies the string, so each backspace costs O(n).

def backspace_compare_brute(s, t):
    def build(x):
        res = ""
        for ch in x:
            if ch == '#':
                res = res[:-1]          # slicing copies the whole string: O(n) per '#'
            else:
                res += ch
        return res
    return build(s) == build(t)
private static String buildBrute(String x) {
    String res = "";
    for (char ch : x.toCharArray()) {
        if (ch == '#') {
            if (!res.isEmpty()) res = res.substring(0, res.length() - 1);   // copies: O(n)
        } else {
            res = res + ch;                                                  // copies: O(n)
        }
    }
    return res;
}

static boolean brute(String s, String t) { return buildBrute(s).equals(buildBrute(t)); }
2The bottleneck and the key observation

The text typed so far is a stack. A letter pushes, and a # pops the top, or does nothing when the stack is empty.

3Optimal approach
  1. Write a helper that turns a string into its final text.
  2. For each character: letter pushes, # pops if the stack is not empty.
  3. Compare the two stacks.
  4. Follow-up: O(1) space is possible by scanning both strings from the end and skipping characters that a # erases.
def backspace_compare(s, t):
    def build(x):
        stack = []
        for ch in x:
            if ch == '#':
                if stack:
                    stack.pop()
            else:
                stack.append(ch)
        return stack
    return build(s) == build(t)
private static String buildStack(String x) {
    StringBuilder stack = new StringBuilder();       // a StringBuilder works as a char stack
    for (char ch : x.toCharArray()) {
        if (ch == '#') {
            if (stack.length() > 0) stack.deleteCharAt(stack.length() - 1);
        } else {
            stack.append(ch);
        }
    }
    return stack.toString();
}

static boolean optimal(String s, String t) { return buildStack(s).equals(buildStack(t)); }

Two adjacent characters are bad if they are the same letter in different cases, like aA. Remove bad pairs until none remain. "abBAcC" becomes "".

Recognize before codingRemoving a pair can create a new pair next to it.
Skill it teachesComparing only with the last survivor, the cancel template.
1Brute force

Scan for the first bad pair, delete it, and start scanning again from the beginning. Each deletion costs a scan, and there can be n/2 deletions.

def make_great_brute(s):
    changed = True
    while changed:
        changed = False
        for i in range(len(s) - 1):
            if abs(ord(s[i]) - ord(s[i + 1])) == 32:   # same letter, opposite case
                s = s[:i] + s[i + 2:]
                changed = True
                break
    return s
static String brute(String str) {
    StringBuilder s = new StringBuilder(str);
    boolean changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i + 1 < s.length(); i++) {
            if (Math.abs(s.charAt(i) - s.charAt(i + 1)) == 32) {   // same letter, opposite case
                s.delete(i, i + 2);
                changed = true;
                break;
            }
        }
    }
    return s.toString();
}
2The bottleneck and the key observation

After a deletion, the two characters that become neighbors can form a new bad pair. A new character only ever has to be compared with the last character that survived, which is the top of a stack.

3Optimal approach
  1. Start with an empty stack.
  2. For each character, compare it with the top. If they are the same letter in opposite case, pop.
  3. Otherwise push the character.
  4. Join the stack to get the answer.
def make_great(s):
    stack = []
    for ch in s:
        if stack and abs(ord(stack[-1]) - ord(ch)) == 32:
            stack.pop()
        else:
            stack.append(ch)
    return "".join(stack)
static String optimal(String s) {
    StringBuilder stack = new StringBuilder();
    for (char ch : s.toCharArray()) {
        int n = stack.length();
        if (n > 0 && Math.abs(stack.charAt(n - 1) - ch) == 32) stack.deleteCharAt(n - 1);
        else stack.append(ch);
    }
    return stack.toString();
}

Record scores from operations. An integer adds that score, + adds the sum of the last two scores, D adds double the last score, C removes the last score. Return the total. ["5","2","C","D","+"] gives 30.

Recognize before codingEvery operation reads only the last one or two items.
Skill it teachesSpotting a stack inside a plain simulation.
1Brute force

Replay the operations and rebuild a fresh copy of the score list on every step. It works, but every step costs O(n).

def baseball_brute(ops):
    scores = []
    for op in ops:                            # rebuilds the list on every operation
        if op == 'C':
            scores = scores[:-1]
        elif op == 'D':
            scores = scores + [2 * scores[-1]]
        elif op == '+':
            scores = scores + [scores[-1] + scores[-2]]
        else:
            scores = scores + [int(op)]
    return sum(scores)
static int brute(String[] ops) {
    List<Integer> scores = new ArrayList<>();
    for (String op : ops) {
        List<Integer> next = new ArrayList<>(scores);    // rebuilds the list on every operation
        int n = next.size();
        if (op.equals("C")) next.remove(n - 1);
        else if (op.equals("D")) next.add(2 * next.get(n - 1));
        else if (op.equals("+")) next.add(next.get(n - 1) + next.get(n - 2));
        else next.add(Integer.parseInt(op));
        scores = next;
    }
    int sum = 0;
    for (int v : scores) sum += v;
    return sum;
}
2The bottleneck and the key observation

A plain list that you only touch at the end already is a stack. The problem checks whether you notice that every operation looks only at the last one or two scores.

3Optimal approach
  1. Start with an empty stack of scores.
  2. Integer: push it. D: push twice the top. +: push the sum of the top two. C: pop.
  3. Return the sum of the stack.
def baseball(ops):

        if op == 'C':

            stack.append(2 * stack[-1])
        elif op == '+':
            stack.append(stack[-1] + stack[-2])
        else:
            stack.append(int(op))
    return sum(stack)
static int optimal(String[] ops) {
    Deque<Integer> stack = new ArrayDeque<>();

        if (op.equals("C")) {
            stack.pop();
        } else if (op.equals("D")) {
            stack.push(2 * stack.peek());
        } else if (op.equals("+")) {
            int top = stack.pop();
            int sum = top + stack.peek();
            stack.push(top);
            stack.push(sum);
        } else {
            stack.push(Integer.parseInt(op));
        }
    }
    int sum = 0;
    for (int v : stack) sum += v;
    return sum;
}

Asteroid Collision

MediumLeetCode 735Added for pattern coverage
Show solutionHide

Added for pattern coverage: the multi-pop variant of Type B. Not confirmed as frequently asked by this research.

Each integer is an asteroid. The sign is the direction and the absolute value is the size. When two meet, the smaller explodes, and equal sizes both explode. Asteroids moving the same way never meet. Return the survivors. [10, 2, -5] gives [10].

Recognize before codingOnly the newest item can hit the latest survivor, and one item can remove several.
Skill it teachesA multi-pop loop with several outcomes.
1Brute force

Repeat: find the first adjacent pair where a right-mover sits left of a left-mover, resolve it, and rescan from the start. Each collision costs a scan, so the total is O(n²).

def asteroid_collision_brute(asteroids):
    a = asteroids[:]
    changed = True
    while changed:
        changed = False
        for i in range(len(a) - 1):
            if a[i] > 0 and a[i + 1] < 0:     # right-mover directly left of a left-mover
                if a[i] > -a[i + 1]:
                    del a[i + 1]
                elif a[i] < -a[i + 1]:
                    del a[i]
                else:
                    del a[i:i + 2]
                changed = True
                break                         # rescan from the start
    return a
static int[] brute(int[] asteroids) {
    List<Integer> a = new ArrayList<>();
    for (int x : asteroids) a.add(x);
    boolean changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i + 1 < a.size(); i++) {
            if (a.get(i) > 0 && a.get(i + 1) < 0) {      // right-mover next to a left-mover
                int l = a.get(i), r = -a.get(i + 1);
                if (l > r) a.remove(i + 1);
                else if (l < r) a.remove(i);
                else { a.remove(i + 1); a.remove(i); }
                changed = true;
                break;                                   // rescan from the start
            }
        }
    }
    int[] res = new int[a.size()];
    for (int i = 0; i < res.length; i++) res[i] = a.get(i);
    return res;
}
2The bottleneck and the key observation

Only a right-moving asteroid on top of the stack can be hit by a new left-moving one. Everything else is safe. One big new asteroid can destroy several, so the collision check is a while loop, not an if.

3Optimal approach
  1. Start with an empty stack of survivors.
  2. For each asteroid a, set alive = true.
  3. While a is moving left, the top is moving right, and a is still alive: if the top is smaller, pop it and continue. If equal, pop and mark a dead. If the top is larger, mark a dead.
  4. If a is still alive, push it.
def asteroid_collision(asteroids):
    stack = []
    for a in asteroids:
        alive = True
        while alive and a < 0 and stack and stack[-1] > 0:
            if stack[-1] < -a:
                stack.pop()                   # top explodes, keep checking
            elif stack[-1] == -a:
                stack.pop()                   # both explode
                alive = False
            else:
                alive = False                 # new one explodes
        if alive:
            stack.append(a)
    return stack
static int[] optimal(int[] asteroids) {
    Deque<Integer> stack = new ArrayDeque<>();
    for (int a : asteroids) {
        boolean alive = true;
        while (alive && a < 0 && !stack.isEmpty() && stack.peek() > 0) {
            if (stack.peek() < -a) stack.pop();          // top explodes, keep checking
            else if (stack.peek() == -a) { stack.pop(); alive = false; }   // both explode
            else alive = false;                          // new one explodes
        }
        if (alive) stack.push(a);
    }
    int[] res = new int[stack.size()];
    for (int i = res.length - 1; i >= 0; i--) res[i] = stack.pop();   // top is the last element
    return res;
}

Evaluate Reverse Polish Notation

MediumLeetCode 150Frequently asked
Show solutionHide

Frequently asked (sources: Grind 75, NeetCode 150).

Tokens are numbers and the operators + - * /, written in postfix order. Division truncates toward zero. ["4","13","5","/","+"] is 4 + 13 / 5, which is 6.

Recognize before codingPostfix notation, where an operator applies to the last two results.
Skill it teachesOperand order, and division that truncates toward zero.
1Brute force

Find the first operator, evaluate it with the two tokens before it, replace those three tokens with the result, and repeat. Each replacement shifts the list.

Shared helper

def _apply(op, a, b):
    if op == '+':
        return a + b
    if op == '-':
        return a - b
    if op == '*':
        return a * b
    q = abs(a) // abs(b)                      # truncate toward zero, exact for big ints
    return q if (a < 0) == (b < 0) else -q
private static boolean isOp(String t) {
    return t.equals("+") || t.equals("-") || t.equals("*") || t.equals("/");
}

private static int apply(String op, int a, int b) {
    switch (op) {
        case "+": return a + b;
        case "-": return a - b;
        case "*": return a * b;
        default:  return a / b;                          // Java int division truncates toward zero
    }
}
def eval_rpn_brute(tokens):
    tokens = tokens[:]
    while len(tokens) > 1:
        for i, t in enumerate(tokens):        # find the first operator
            if t in ('+', '-', '*', '/'):
                a, b = int(tokens[i - 2]), int(tokens[i - 1])
                tokens[i - 2:i + 1] = [str(_apply(t, a, b))]   # list splice: O(n)
                break
    return int(tokens[0])
static int brute(String[] tokens) {
    List<String> t = new ArrayList<>(Arrays.asList(tokens));
    while (t.size() > 1) {
        for (int i = 0; i < t.size(); i++) {             // find the first operator
            if (isOp(t.get(i))) {
                int a = Integer.parseInt(t.get(i - 2)), b = Integer.parseInt(t.get(i - 1));
                String r = String.valueOf(apply(t.get(i), a, b));
                t.remove(i); t.remove(i - 1); t.set(i - 2, r);   // splice: O(n)
                break;
            }
        }
    }
    return Integer.parseInt(t.get(0));
}
2The bottleneck and the key observation

An operator always applies to the two most recent results. That is the top two items of a stack, and the result goes back on top.

3Optimal approach
  1. Start with an empty stack.
  2. Number: push it.
  3. Operator: pop b first (the right operand), then pop a, compute a op b, push the result.
  4. The single value left is the answer.
def eval_rpn(tokens):
    stack = []
    for t in tokens:
        if t in ('+', '-', '*', '/'):
            b = stack.pop()                   # b is on top, so it is the RIGHT operand
            a = stack.pop()
            stack.append(_apply(t, a, b))
        else:
            stack.append(int(t))
    return stack[0]
static int optimal(String[] tokens) {
    Deque<Integer> stack = new ArrayDeque<>();
    for (String t : tokens) {
        if (isOp(t)) {
            int b = stack.pop();                         // b is on top: the RIGHT operand
            int a = stack.pop();
            stack.push(apply(t, a, b));
        } else {
            stack.push(Integer.parseInt(t));
        }
    }
    return stack.pop();
}

Decode String

Added for pattern coverage: it is also on the Hello Interview stack page, a single source. Kept as the nested-context problem.

Strings are encoded as k[encoded], meaning encoded repeated k times, and they can nest. "3[a2[c]]" decodes to "accaccacc".

Recognize before codingNested brackets whose content gets transformed.
Skill it teachesSaving and restoring state at each nesting level.
1Brute force

Use a regex to find an innermost k[...] that has no brackets inside, expand it, and repeat until no bracket is left. Every round scans the whole string, so the cost grows with the nesting depth times the output length.

import re

_INNERMOST = re.compile(r'(\d+)\[([^\[\]]*)\]')

def decode_string_brute(s):
    while True:
        m = _INNERMOST.search(s)              # an innermost k[...] has no brackets inside
        if not m:
            return s
        s = s[:m.start()] + m.group(2) * int(m.group(1)) + s[m.end():]
private static final Pattern INNERMOST = Pattern.compile("(\\d+)\\[([^\\[\\]]*)\\]");

static String brute(String s) {
    while (true) {
        Matcher m = INNERMOST.matcher(s);                // an innermost k[...] has no brackets inside
        if (!m.find()) return s;
        s = s.substring(0, m.start()) + m.group(2).repeat(Integer.parseInt(m.group(1))) + s.substring(m.end());
    }
}
2The bottleneck and the key observation

Entering a [ pauses the string you were building. Leaving at ] resumes it. Saving paused work and restoring it in reverse order is a stack.

3Optimal approach
  1. Keep cur (the string being built) and num (the count being read).
  2. Digit: num = num * 10 + digit.
  3. [: push (cur, num), then reset both.
  4. ]: pop (prev, k) and set cur = prev + cur * k.
  5. Letter: append to cur. At the end, cur is the answer.
def decode_string(s):
    stack = []                                # saved (previous_string, repeat_count)
    cur, num = "", 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)          # multi-digit counts
        elif ch == '[':
            stack.append((cur, num))          # save context
            cur, num = "", 0
        elif ch == ']':
            prev, k = stack.pop()             # restore context
            cur = prev + cur * k
        else:
            cur += ch
    return cur
static String optimal(String s) {
    Deque<StringBuilder> strs = new ArrayDeque<>();      // saved previous strings
    Deque<Integer> counts = new ArrayDeque<>();          // saved repeat counts
    StringBuilder cur = new StringBuilder();
    int num = 0;
    for (char ch : s.toCharArray()) {
        if (Character.isDigit(ch)) {
            num = num * 10 + (ch - '0');                 // multi-digit counts
        } else if (ch == '[') {
            strs.push(cur);                              // save context
            counts.push(num);
            cur = new StringBuilder();
            num = 0;
        } else if (ch == ']') {
            StringBuilder prev = strs.pop();             // restore context
            int k = counts.pop();
            for (int i = 0; i < k; i++) prev.append(cur);
            cur = prev;
        } else {
            cur.append(ch);
        }
    }
    return cur.toString();
}

2The bottleneck and the key observation

The video walks the array from the back. The stack holds candidates to the right, nearest on top. 3Optimal approach

  2. Pop while the top is less than or equal to the current value.
  3. The answer is the top, or -1 if the stack is empty.
  4. Push the current value.

        num = min((num[:i] + num[i + 1:] for i in range(len(num))), key=key)

2The bottleneck and the key observation

  5. Strip leading zeros and return "0" if nothing remains.

        stack.append(d)
    if k:

2The bottleneck and the key observation

  4. Push (start, h). The new bar can extend left as far as the last bar it popped.

            idx, height = stack.pop()
            best = max(best, height * (i - idx))
            start = idx                       # current bar extends left to idx

2The bottleneck and the key observation

Flip the question. Instead of asking for the minimum of each subarray, ask how many subarrays each element is the minimum of. If the element can start in left places and end in right places, it contributes value × left × right. The nearest smaller element on each side gives those counts, and a stack finds them.

3Optimal approach
  1. For each index, find left[i]: the distance back to the previous element that is smaller, or to the start.
  2. Find right[i]: the distance forward to the next smaller element, or to the end.
  3. Break ties on one side only: stop at equal values on the left, run over equal values on the right.
  4. Sum arr[i] × left[i] × right[i] modulo 1,000,000,007.
def sum_subarray_mins(arr):
    n = len(arr)
    left = [0] * n                            # choices for the start index
    right = [0] * n                           # choices for the end index
    stack = []
    for i in range(n):
        while stack and arr[stack[-1]] > arr[i]:        # previous <=  (stops at equal)
            stack.pop()
        left[i] = i - (stack[-1] if stack else -1)
        stack.append(i)
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and arr[stack[-1]] >= arr[i]:       # next <  (runs over equal)
            stack.pop()
        right[i] = (stack[-1] if stack else n) - i
        stack.append(i)
    return sum(a * l * r for a, l, r in zip(arr, left, right)) % (MOD)
static int optimal(int[] arr) {
    int n = arr.length;
    long[] left = new long[n], right = new long[n];      // choices for start / end index
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && arr[stack.peek()] > arr[i]) stack.pop();    // previous <= (stops at equal)
        left[i] = i - (stack.isEmpty() ? -1 : stack.peek());
        stack.push(i);
    }
    stack.clear();
    for (int i = n - 1; i >= 0; i--) {
        while (!stack.isEmpty() && arr[stack.peek()] >= arr[i]) stack.pop();   // next < (runs over equal)
        right[i] = (stack.isEmpty() ? n : stack.peek()) - i;
        stack.push(i);
    }
    long total = 0;
    for (int i = 0; i < n; i++) total = (total + arr[i] * left[i] % MOD * right[i]) % MOD;
    return (int) total;
}

2The bottleneck and the key observation

The same left-max and right-max values get recomputed again and again. Compute them once in two passes and store them in arrays (the video's approach). The stack solution fills water layer by layer: when a taller bar arrives, the popped bar is the floor, the new top is the left wall, and the new bar is the right wall. If you want O(1) space, two pointers keep one running maximum from each end.

Correction to the video: The video calls the max-left and max-right values the next greater elements to each side. They are running maxima, and a plain loop that keeps one maximum is enough to compute them, so no stack is needed for that version. The monotonic stack is a different way to solve the same problem, and it is the one that practices the pattern.

3Optimal approach
  1. Prefix version: left[i] is the max of h[0..i], right[i] is the max of h[i..n-1]. Water at i is min(left[i], right[i]) - h[i].
  2. Stack version: keep indices of decreasing heights. When h[i] is taller than the top, pop it as bottom. If the stack is empty, there is no left wall, so stop.
  3. Otherwise left is the new top, width = i - left - 1, depth = min(h[left], h[i]) - h[bottom], and water += width × depth.
  4. Push i and continue.

class QueueBrute:
    def __init__(self):
        self.main = []

    def enqueue(self, x):
        self.main.append(x)

    def _flip(self):
        helper = []
        while self.main:
            helper.append(self.main.pop())
        return helper

    def dequeue(self):
        helper = self._flip()                 # O(n) every time
        x = helper.pop()
        while helper:
            self.main.append(helper.pop())    # put everything back: another O(n)
        return x

    def peek(self):
        helper = self._flip()
        x = helper[-1]
        while helper:
            self.main.append(helper.pop())
        return x

    def empty(self):
        return not self.main

3Optimal approach

  2. To dequeue or peek: if the outbox is empty, pop every item from the inbox and push it onto the outbox.
  3. Dequeue pops the outbox. Peek reads its top.
  4. empty() is true only when both stacks are empty.

Cars drive toward a target on a one-lane road. Car i starts at position[i] with speed[i]. A car cannot pass the car ahead. It catches up and then drives at that car's speed, forming a fleet. Count the fleets that arrive. Target 12, positions [10,8,0,5,3], speeds [2,4,1,1,3] gives 3.

Recognize before codingObjects on a line that merge or block each other.
Skill it teachesTransforming the input first, then seeing the stack.
1Brute force

Compute each car's arrival time if the road were empty, (target - position) / speed. A car starts its own fleet only if every car ahead of it arrives strictly sooner. Checking all cars ahead for every car is O(n²).

def car_fleet_brute(target, position, speed):
    n = len(position)
    time = [(target - position[i]) / speed[i] for i in range(n)]
    fleets = 0
    for i in range(n):
        # car i leads its own fleet only if every car ahead arrives strictly sooner
        if all(time[j] < time[i] for j in range(n) if position[j] > position[i]):
            fleets += 1
    return fleets
static int brute(int target, int[] position, int[] speed) {
    int n = position.length;
    double[] time = new double[n];
    for (int i = 0; i < n; i++) time[i] = (double) (target - position[i]) / speed[i];
    int fleets = 0;
    for (int i = 0; i < n; i++) {
        boolean leads = true;                            // every car ahead must arrive strictly sooner
        for (int j = 0; j < n; j++) {
            if (position[j] > position[i] && time[j] >= time[i]) { leads = false; break; }
        }
        if (leads) fleets++;
    }
    return fleets;
}
2The bottleneck and the key observation

Sort by position, closest to the target first. A car that would arrive later than the fleet directly ahead can never catch it, so it forms a new fleet. A car that would arrive sooner or at the same time catches up and merges. The arrival times of fleets only grow as you go back, which is a monotonic stack.

3Optimal approach
  1. Pair each position with its speed and sort by position, descending.
  2. For each car compute t = (target - position) / speed.
  3. If the stack is empty or t is greater than the top, push t. This car is a new fleet.
  4. Otherwise it merges into the fleet ahead, so do nothing.
  5. The stack size is the number of fleets.
def car_fleet(target, position, speed):
    stack = []                                # arrival times of fleets, front to back
    for p, s in sorted(zip(position, speed), reverse=True):   # closest to target first
        t = (target - p) / s
        if not stack or t > stack[-1]:        # slower than the fleet ahead: new fleet
            stack.append(t)                   # otherwise it catches up and merges
    return len(stack)

    int n = position.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a, b) -> position[b] - position[a]);   // closest to target first
    Deque<Double> stack = new ArrayDeque<>();            // arrival times of fleets
    for (int i : idx) {
        double t = (double) (target - position[i]) / speed[i];
        if (stack.isEmpty() || t > stack.peek()) stack.push(t);   // slower: new fleet
    }                                                    // otherwise it merges into the fleet ahead
    return stack.size();
}

Depth-First Traversal Without Recursion

Added for pattern coverage: a preview of Trees and Graphs, so it is not part of the frequency research.

Visit every node reachable from a start node, going as deep as possible before backing up, and take neighbors in the order they are listed. The graph is a dictionary of adjacency lists, and cycles are allowed. {0:[1,2], 1:[3], 2:[3], 3:[]} from node 0 visits [0, 1, 3, 2].

Recognize before codingDeep recursion, or a request to avoid recursion.
Skill it teachesTurning a recursive traversal into a loop with an explicit stack.
1Recursive version

The natural first version is recursive. Each call is a frame on the system's call stack, and the stack remembers where to resume after a neighbor is finished. It is correct, but a chain of 5,000 nodes overflows Python's default recursion limit, and Java fails at a far greater depth.

Recursive version

def dfs_recursive(graph, start):
    seen, order = set(), []

    def visit(node):
        seen.add(node)
        order.append(node)
        for nxt in graph[node]:
            if nxt not in seen:
                visit(nxt)                    # each call is a frame on the call stack

    visit(start)
    return order
static List<Integer> recursive(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    visit(graph, start, new HashSet<>(), order);
    return order;
}

private static void visit(Map<Integer, List<Integer>> graph, int node, Set<Integer> seen, List<Integer> order) {
    seen.add(node);
    order.add(node);
    for (int nxt : graph.get(node)) {
        if (!seen.contains(nxt)) visit(graph, nxt, seen, order);   // each call is a frame on the call stack
    }
}
2The bottleneck and the key observation

Recursion already is a stack, managed for you. Replace it with your own and the depth limit goes away. Pop a node, skip it if it was seen, visit it, and push its neighbors in reverse so the first neighbor ends up on top and is explored first. Mark a node as seen when it is popped, not when it is pushed. That reproduces the recursive visiting order exactly.

3Optimal approach
  1. Push the start node onto the stack.
  2. Pop a node. If it was already seen, skip it.
  3. Mark it seen and record it in the visit order.
  4. Push its unseen neighbors in reverse order.
  5. Repeat until the stack is empty.

Explicit stack

def dfs_iterative(graph, start):
    seen, order = set(), []
    stack = [start]                           # our own stack replaces the call stack
    while stack:
        node = stack.pop()
        if node in seen:                      # mark seen on pop, to match the recursive order
            continue
        seen.add(node)
        order.append(node)
        for nxt in reversed(graph[node]):     # reversed, so the first neighbor is popped first
            if nxt not in seen:
                stack.append(nxt)
    return order
static List<Integer> iterative(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    Set<Integer> seen = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>();           // our own stack replaces the call stack
    stack.push(start);
    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (!seen.add(node)) continue;                   // add returns false if already seen: mark on pop
        order.add(node);
        List<Integer> nbrs = graph.get(node);
        for (int i = nbrs.size() - 1; i >= 0; i--) {     // reversed, so the first neighbor is popped first
            if (!seen.contains(nbrs.get(i))) stack.push(nbrs.get(i));
        }
    }
    return order;
}

  • Marking nodes seen on push, instead of on pop, gives a different order, and on some graphs it is not any valid depth-first order (a failing graph is run below).
  • Python's default recursion limit is about 1,000 frames. In an interview, say that an explicit stack avoids this limit.

Part 10Common Mistakes

Grouped as conceptual, Python, Java, complexity, boundary and interview-reasoning mistakes, with how to avoid each. Below the groups, every "this gives the wrong answer" claim in these notes is shown on a concrete failing input.

Conceptual

  • Choosing a stack when you need a queue, deque or heap. Ask which item must be handled first, the newest or the oldest.
  • Forgetting what the leftovers mean. After the loop, ask what it means that these items are still on the stack.
  • Wrong monotonic direction. Next greater means a decreasing stack, popping while the top is smaller. Verify with a three-element example.

Python and Java

  • Popping or peeking an empty stack. Always write if stack and ....
  • Using list.pop(0). It is O(n). Pop from the end, or use a deque.
  • Storing values when you need indices. You cannot compute distances from values.
  • Mutating the input, like heights.append(0). Use heights + [0].
  • Comparing boxed Integers with == in Java. Unbox first, or use equals.
  • Trusting Java's iteration order. A Deque iterates from the top.

Complexity

  • Calling the monotonic stack O(n²) because of the nested loop. Each element is pushed once and popped at most once.
  • Forgetting the O(n) space of the stack.

Boundaries

  • Off-by-one in widths. Test [2,4] in the histogram problem.
  • Mixing up < and <= on duplicates.
  • Checking the final stack in only some problems. Valid parentheses needs it empty. Daily temperatures does not.

Interview reasoning

  • Coding before stating the invariant.
  • Skipping the brute force. Say it, give its complexity, then name the bottleneck the stack removes.
  • Memorizing that monotonic stack means next greater. If you understand "resolve the waiting elements", variants like previous smaller or span become easy.

Python traps (also see Part 2)

  • Mutable default argument: def f(items, stack=[]) shares one list across calls. Verified run: [1] then [1, 2].
  • list.pop(0): list.pop(0) 3615.6 ms for 100,000 items versus list.pop() 6.1 ms; deque.popleft() 6.7 ms.
  • Slicing in a loop copies, so an O(n) loop with a slice inside is O(n²).

Java traps (also see Part 2)

  • Boxed Integer ==: value 1000: pop() == peek() is false, equals is true.
  • Stack versus Deque iteration: push 1,2,3 -> iterate Stack: [1, 2, 3] | iterate ArrayDeque: [3, 2, 1] | empty peek: Stack throws EmptyStackException, ArrayDeque returns null | empty pop: ArrayDeque throws NoSuchElementException.

T1 Matching

Question: Does every closer match the newest opener? Applies to: Valid Parentheses, tag validation, Min Remove (Part 14). Complexity: O(n) time, O(n) space. Line people get wrong: The empty check before the pop, and the final return not stack.

def valid_parentheses(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in pairs:                              # closer
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:                                        # opener
            stack.append(ch)
    return not stack                                 # leftover openers => invalid
static boolean optimal(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char ch : s.toCharArray()) {
        if (ch == '(' || ch == '[' || ch == '{') {
            stack.push(ch);
        } else {
            if (stack.isEmpty()) return false;      // closer with nothing open
            char open = stack.pop();
            if ((ch == ')' && open != '(') || (ch == ']' && open != '[') || (ch == '}' && open != '{'))
                return false;
        }
    }
    return stack.isEmpty();                          // leftover openers => invalid
}

T3 Monotonic stack of indices

Question: Which waiting elements does this one resolve? Applies to: Next Greater I and II, Daily Temperatures, Stock Span, Remove K Digits. Complexity: O(n) amortized time, O(n) space. Line people get wrong: The pop comparison: strict < or <=, chosen on purpose.

def daily_temps(t):
    ans = [0] * len(t)
    stack = []                                # indices, temperatures decreasing
    for i, x in enumerate(t):
        while stack and t[stack[-1]] < x:
            j = stack.pop()
            ans[j] = i - j
        stack.append(i)
    return ans
static int[] optimal(int[] t) {
    int[] ans = new int[t.length];
    Deque<Integer> stack = new ArrayDeque<>();           // indices, temperatures decreasing
    for (int i = 0; i < t.length; i++) {
        while (!stack.isEmpty() && t[stack.peek()] < t[i]) {
            int j = stack.pop();
            ans[j] = i - j;
        }
        stack.push(i);
    }
    return ans;
}

T4 Span and area

Question: How far does this element reach on each side? Applies to: Largest Rectangle, Sum of Subarray Minimums, Trapping Rain Water. Complexity: O(n) time, O(n) space. Line people get wrong: The width on pop (i - idx) and appending the sentinel.

def largest_rectangle(heights):
    stack = []                                # (start_index, height), heights increasing
    best = 0
    for i, h in enumerate(heights + [0]):     # sentinel 0 flushes the stack
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            best = max(best, height * (i - idx))
            start = idx                       # current bar extends left to idx
        stack.append((start, h))
    return best
static int optimal(int[] heights) {
    Deque<int[]> stack = new ArrayDeque<>();             // {start_index, height}, heights increasing
    int best = 0;
    for (int i = 0; i <= heights.length; i++) {
        int h = (i == heights.length) ? 0 : heights[i];  // sentinel 0 flushes the stack
        int start = i;
        while (!stack.isEmpty() && stack.peek()[1] > h) {
            int[] top = stack.pop();
            best = Math.max(best, top[1] * (i - top[0]));
            start = top[0];                              // current bar extends left to here
        }
        stack.push(new int[]{start, h});
    }
    return best;
}

        int mn = s.isEmpty() ? x : Math.min(x, s.peek()[1]);

T6 Context save and restore

Question: What do I pause when I enter a nested part? Applies to: Decode String, Basic Calculator, calculators with brackets. Complexity: O(n) or O(L) time and space. Line people get wrong: Reset the count after saving it, and restore in the reverse order.

def decode_string(s):
    stack = []                                # saved (previous_string, repeat_count)
    cur, num = "", 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)          # multi-digit counts
        elif ch == '[':
            stack.append((cur, num))          # save context
            cur, num = "", 0
        elif ch == ']':
            prev, k = stack.pop()             # restore context
            cur = prev + cur * k
        else:
            cur += ch
    return cur
static String optimal(String s) {
    Deque<StringBuilder> strs = new ArrayDeque<>();      // saved previous strings
    Deque<Integer> counts = new ArrayDeque<>();          // saved repeat counts
    StringBuilder cur = new StringBuilder();
    int num = 0;
    for (char ch : s.toCharArray()) {
        if (Character.isDigit(ch)) {
            num = num * 10 + (ch - '0');                 // multi-digit counts
        } else if (ch == '[') {
            strs.push(cur);                              // save context
            counts.push(num);
            cur = new StringBuilder();
            num = 0;
        } else if (ch == ']') {
            StringBuilder prev = strs.pop();             // restore context
            int k = counts.pop();
            for (int i = 0; i < k; i++) prev.append(cur);
            cur = prev;
        } else {
            cur.append(ch);
        }
    }
    return cur.toString();
}

T7 Two stacks

Question: Can reversing twice give me another structure? Applies to: Queue using Stacks, undo and redo. Complexity: O(1) amortized per operation. Line people get wrong: Refill the outbox only when it is EMPTY.

class MyQueue:
    def __init__(self):
        self.inbox = []                       # enqueue goes here
        self.outbox = []                      # dequeue / peek come from here

    def enqueue(self, x):
        self.inbox.append(x)

    def _shift(self):
        if not self.outbox:                   # only refill when outbox is EMPTY
            while self.inbox:
                self.outbox.append(self.inbox.pop())

    def dequeue(self):
        self._shift()
        return self.outbox.pop()

    def peek(self):
        self._shift()
        return self.outbox[-1]

    def empty(self):
        return not self.inbox and not self.outbox
class MyQueue {
    private final Deque<Integer> inbox = new ArrayDeque<>();   // enqueue goes here
    private final Deque<Integer> outbox = new ArrayDeque<>();  // dequeue / peek come from here

    void enqueue(int x) { inbox.push(x); }

    private void shift() {
        if (outbox.isEmpty()) {                              // refill only when outbox is EMPTY
            while (!inbox.isEmpty()) outbox.push(inbox.pop());
        }
    }

    int dequeue() { shift(); return outbox.pop(); }
    int peek() { shift(); return outbox.peek(); }
    boolean empty() { return inbox.isEmpty() && outbox.isEmpty(); }
}

T8 Explicit recursion

Question: Can my own stack replace the call stack? Applies to: Iterative DFS, tree traversals later. Complexity: O(V + E) time, O(V) space. Line people get wrong: Mark seen when popped, and push neighbours in reverse.

def dfs_iterative(graph, start):
    seen, order = set(), []
    stack = [start]                           # our own stack replaces the call stack
    while stack:
        node = stack.pop()
        if node in seen:                      # mark seen on pop, to match the recursive order
            continue
        seen.add(node)
        order.append(node)
        for nxt in reversed(graph[node]):     # reversed, so the first neighbor is popped first
            if nxt not in seen:
                stack.append(nxt)
    return order
static List<Integer> iterative(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    Set<Integer> seen = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>();           // our own stack replaces the call stack
    stack.push(start);
    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (!seen.add(node)) continue;                   // add returns false if already seen: mark on pop
        order.add(node);
        List<Integer> nbrs = graph.get(node);
        for (int i = nbrs.size() - 1; i >= 0; i--) {     // reversed, so the first neighbor is popped first
            if (!seen.contains(nbrs.get(i))) stack.push(nbrs.get(i));
        }
    }
    return order;
}

Given a string of lowercase letters, repeatedly remove two adjacent equal letters until none are left. Return the result. "abbaca" gives "ca".

Added for pattern coverage.

1Brute force

Scan for the first equal adjacent pair, delete it, and start again. Each deletion costs a scan and there can be n/2 deletions: O(n²) time.

def remove_dups_brute(s):
    changed = True
    while changed:
        changed = False
        for i in range(len(s) - 1):
            if s[i] == s[i + 1]:
                s = s[:i] + s[i + 2:]       # delete the first equal adjacent pair
                changed = True
                break
    return s
static String brute(String str) {
    StringBuilder s = new StringBuilder(str);
    boolean changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i + 1 < s.length(); i++) {
            if (s.charAt(i) == s.charAt(i + 1)) {   // delete the first equal adjacent pair
                s.delete(i, i + 2);
                changed = true;
                break;
            }
        }
    }
    return s.toString();
}
2The bottleneck and the key observation

A deletion makes two letters neighbours that were not before, and that new pair can only involve the letter just before the deleted spot. So a new letter only needs to be compared with the last survivor, which is the top of a stack.

3Optimal approach
  1. Start with an empty stack of survivors.
  2. For each letter: if it equals the top, pop (the pair cancels). Otherwise push it.
  3. Join the stack.
def remove_dups(s):
    stack = []
    for ch in s:
        if stack and stack[-1] == ch:
            stack.pop()
        else:
            stack.append(ch)
    return "".join(stack)
static String optimal(String s) {
    StringBuilder stack = new StringBuilder();
    for (int i = 0; i < s.length(); i++) {
        char ch = s.charAt(i);
        int n = stack.length();
        if (n > 0 && stack.charAt(n - 1) == ch) stack.deleteCharAt(n - 1);
        else stack.append(ch);
    }
    return stack.toString();
}

Implement Stack using Queues

Type FEasyLeetCode 225Added for pattern coverage
Show solutionHide

Implement a LIFO stack using only queue operations (offer, poll, peek, size, empty). Operations: push, pop, top, empty.

Added for pattern coverage.

1Brute force

Use two queues. On push, put the new item into an empty second queue, move everything from the first queue behind it, then swap the queues. The front of the queue is always the stack top. Push is O(n).

from collections import deque

class StackTwoQueues:
    def __init__(self):
        self.q1 = deque()                 # q1[0] is always the stack top

    def push(self, x):
        q2 = deque([x])                   # new item goes in front
        while self.q1:
            q2.append(self.q1.popleft())  # then everything else behind it
        self.q1 = q2                      # O(n) per push

    def pop(self):
        return self.q1.popleft()

    def top(self):
        return self.q1[0]

    def empty(self):
        return not self.q1
class StackTwoQueues {
    private Deque<Integer> q1 = new ArrayDeque<>();   // used only as a queue: offer, poll, peek

    void push(int x) {
        Deque<Integer> q2 = new ArrayDeque<>();
        q2.offer(x);                                  // new item goes in front
        while (!q1.isEmpty()) q2.offer(q1.poll());    // then everything else behind it
        q1 = q2;                                      // O(n) per push
    }
    int pop() { return q1.poll(); }
    int top() { return q1.peek(); }
    boolean empty() { return q1.isEmpty(); }
}
2The bottleneck and the key observation

The second queue is not needed. After adding the new item to the back of one queue, rotate the older items behind it: take n - 1 items from the front and add them to the back. The newest item is now at the front.

3Optimal approach
  1. push(x): add x to the back, then move the size - 1 older items from the front to the back.
  2. pop(), top(), empty(): operate on the front.
class StackOneQueue:
    def __init__(self):

    def push(self, x):
        self.q.append(x)
        for _ in range(len(self.q) - 1):  # rotate the older items behind x
            self.q.append(self.q.popleft())

    def pop(self):
        return self.q.popleft()

    def top(self):
        return self.q[0]

    def empty(self):
        return not self.q

Minimum Remove to Make Valid Parentheses

Type AMediumLeetCode 1249Frequently asked

A string contains letters and parentheses. Delete the fewest parentheses so that the result is valid, and return any valid result. "lee(t(c)o)de)" gives "lee(t(c)o)de".

Frequently asked (Meta, one 2026 guide; single source).

1Brute force

Try every subset of brackets to keep, check each for validity, and keep the largest valid one. That is exponential, O(2b · n) for b brackets. It is used here only as a test oracle on short strings (up to 12 characters).

def min_remove_brute_len(s):
    pos = [i for i, ch in enumerate(s) if ch in '()']
    best = 0
    for mask in range(1 << len(pos)):             # choose which brackets to KEEP
        bal, ok, kept = 0, True, 0
        for k, i in enumerate(pos):
            if mask >> k & 1:
                kept += 1
                bal += 1 if s[i] == '(' else -1
                if bal < 0:
                    ok = False
                    break
        if ok and bal == 0:
            best = max(best, kept)
    return len(s) - len(pos) + best               # letters + most brackets we can keep
static int bruteLen(String s) {
    List<Integer> pos = new ArrayList<>();
    for (int i = 0; i < s.length(); i++) if (s.charAt(i) == '(' || s.charAt(i) == ')') pos.add(i);
    int best = 0;
    for (int mask = 0; mask < (1 << pos.size()); mask++) {     // choose which brackets to KEEP
        int bal = 0, kept = 0;
        boolean ok = true;
        for (int k = 0; k < pos.size(); k++) {
            if ((mask >> k & 1) == 1) {
                kept++;
                bal += s.charAt(pos.get(k)) == '(' ? 1 : -1;
                if (bal < 0) { ok = false; break; }
            }
        }
        if (ok && bal == 0) best = Math.max(best, kept);
    }
    return s.length() - pos.size() + best;                     // letters + most brackets we can keep
}
2The bottleneck and the key observation

A ) with no open ( must go. A ( that never gets closed must go. A stack of indices of open ( tells you both: the stack at the end holds exactly the unmatched openers, and a closer that finds the stack empty is unmatched.

3Optimal approach
  1. Keep a stack of indices of ( and a set of indices to drop.
  2. On ( push its index. On ): pop if the stack is not empty, otherwise add this index to the drop set.
  3. After the loop add everything still on the stack to the drop set.
  4. Build the result from the characters whose index is not in the drop set.
def min_remove(s):
    drop = set()                          # indices of brackets to delete
    stack = []                            # indices of '(' still waiting for a ')'
    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        elif ch == ')':
            if stack:
                stack.pop()               # matched
            else:
                drop.add(i)               # a ')' with nothing open
    drop.update(stack)                    # '(' that never closed

    Deque<Integer> stack = new ArrayDeque<>();        // indices of '(' still waiting
    for (int i = 0; i < s.length(); i++) {
        char ch = s.charAt(i);
        if (ch == '(') stack.push(i);
        else if (ch == ')') {
            if (!stack.isEmpty()) stack.pop();        // matched
            else drop.add(i);                         // a ')' with nothing open
        }
    }
    drop.addAll(stack);                               // '(' that never closed
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < s.length(); i++) if (!drop.contains(i)) sb.append(s.charAt(i));
    return sb.toString();
}
ApproachTimeSpace
Try all subsetsO(2b · n)O(n)
Stack of indicesO(n)O(n)
4Watch for
  • The answer is not unique: "(()" can become "()" in two ways. The tests therefore check that the output is valid, keeps the letters in order, is a subsequence of the input, and has the maximum possible length (compared with the brute force). Interviewers accept any valid answer, so ask.
  • Store indices, not characters. You need to know which opener to delete.

Basic Calculator II

Show solutionHide

Evaluate an expression of non-negative integers, + - * / and spaces, no brackets. Integer division truncates toward zero. "3+2*2" gives 7. " 3/2 " gives 1.

Frequently asked (Meta, one 2026 guide; single source).

1Brute force

Tokenize into numbers and operators. Repeatedly find the first * or /, replace it and its two operands with the result (a list splice, O(n)), until none remain. Then add and subtract left to right. O(n²).

def calc2_brute(s):
    toks, num = [], None
    for ch in s:                                  # tokenise into numbers and operators
        if ch.isdigit():
            num = (num or 0) * 10 + int(ch)
        elif ch in '+-*/':
            toks += [num, ch]
            num = None
    toks.append(num)
    while '*' in toks or '/' in toks:
        i = min(k for k, t in enumerate(toks) if t in ('*', '/'))     # first * or /
        a, b = toks[i - 1], toks[i + 1]
        toks[i - 1:i + 2] = [a * b if toks[i] == '*' else a // b]     # list splice: O(n)
    total = toks[0]
    for i in range(1, len(toks), 2):
        total = total + toks[i + 1] if toks[i] == '+' else total - toks[i + 1]
    return total
static int brute(String s) {
    List<String> t = new ArrayList<>();
    StringBuilder num = new StringBuilder();
    for (char ch : s.toCharArray()) {                 // tokenise into numbers and operators
        if (Character.isDigit(ch)) num.append(ch);
        else if (ch != ' ') { t.add(num.toString()); num.setLength(0); t.add(String.valueOf(ch)); }
    }
    t.add(num.toString());
    while (true) {
        int i = -1;
        for (int k = 0; k < t.size(); k++) if (t.get(k).equals("*") || t.get(k).equals("/")) { i = k; break; }
        if (i < 0) break;                              // no * or / left
        long a = Long.parseLong(t.get(i - 1)), b = Long.parseLong(t.get(i + 1));
        long r = t.get(i).equals("*") ? a * b : a / b;
        t.remove(i + 1); t.remove(i); t.set(i - 1, String.valueOf(r));   // splice: O(n)
    }
    long total = Long.parseLong(t.get(0));
    for (int i = 1; i < t.size(); i += 2) {
        long v = Long.parseLong(t.get(i + 1));
        total = t.get(i).equals("+") ? total + v : total - v;
    }
    return (int) total;
}
2The bottleneck and the key observation

* and / bind tighter, so they can be applied right away to the most recent number. + and - can wait: store the number with its sign and add everything at the end. The stack holds the finished terms.

3Optimal approach
  1. Keep num (the number being read) and op (the operator that came before num, initially +).
  2. When you reach an operator, or the last character, apply op to num: + pushes num, - pushes -num, * and / change the top.
  3. Then set op to the new operator and reset num.
  4. The answer is the sum of the stack.
def calc2(s):
    stack, num, op = [], 0, '+'               # op is the operator BEFORE num
    for i, ch in enumerate(s):
        if ch.isdigit():
            num = num * 10 + int(ch)
        if (not ch.isdigit() and ch != ' ') or i == len(s) - 1:
            if op == '+':
                stack.append(num)
            elif op == '-':
                stack.append(-num)
            elif op == '*':
                stack.append(stack.pop() * num)
            else:                             # '/': truncate toward zero, not floor
                a = stack.pop()
                q = abs(a) // num
                stack.append(q if a >= 0 else -q)
            op, num = ch, 0
    return sum(stack)
static int optimal(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    int num = 0;
    char op = '+';                                    // the operator BEFORE num
    for (int i = 0; i < s.length(); i++) {
        char ch = s.charAt(i);
        if (Character.isDigit(ch)) num = num * 10 + (ch - '0');
        if ((!Character.isDigit(ch) && ch != ' ') || i == s.length() - 1) {
            if (op == '+') stack.push(num);
            else if (op == '-') stack.push(-num);
            else if (op == '*') stack.push(stack.pop() * num);
            else stack.push(stack.pop() / num);       // Java int division truncates toward zero
            op = ch;
            num = 0;
        }
    }
    int sum = 0;
    for (int v : stack) sum += v;
    return sum;
}

List splice per operatorO(n²)O(n)
Stack of termsO(n)O(n)

  • Division must truncate toward zero. In Python, // floors, and the stack top can be negative (after a -). Verified failing input: "5-7/2" should be 2 and floor division gives 1 (Part 10).
  • Do not forget to process the last number when the string does not end with an operator.
  • Assumes a valid expression, non-negative integers, no division by zero and 32-bit results. State these assumptions aloud.

Simplify Path

Show solutionHide

Given an absolute Unix-style path, return its canonical form: a single leading /, no trailing slash, no repeated slashes, . means "here", .. means "up one level" (nothing happens at the root), and anything else, including ..., is a name. "/a/./b/../../c/" gives "/c".

Added for pattern coverage.

1Brute force

Split on / and drop empty pieces and .. Then repeatedly find the first .. and delete it together with the name before it (or by itself at the front). Each deletion shifts a list: O(n²).

def simplify_path_brute(path):
    parts = [p for p in path.split('/') if p not in ('', '.')]
    while '..' in parts:
        i = parts.index('..')                 # first '..'
        if i == 0:
            del parts[0]                      # nothing above root: drop it
        else:
            del parts[i - 1:i + 1]            # cancel it with the name before it: O(n)
    return '/' + '/'.join(parts)
static String brute(String path) {
    List<String> parts = new ArrayList<>();
    for (String p : path.split("/")) if (!p.isEmpty() && !p.equals(".")) parts.add(p);
    while (parts.contains("..")) {
        int i = parts.indexOf("..");                  // first ".."
        if (i == 0) parts.remove(0);                  // nothing above root: drop it
        else { parts.remove(i); parts.remove(i - 1); }   // cancel it with the name before it
    }
    return "/" + String.join("/", parts);
}
2The bottleneck and the key observation

A .. cancels the most recent directory name, and only the newest one can be affected. That is a stack of names.

3Optimal approach
  1. Split the path on /.
  2. Skip empty pieces and ..
  3. For .. pop if the stack is not empty. Otherwise (a name) push it.
  4. Return / plus the names joined with /.
def simplify_path(path):
    stack = []
    for part in path.split('/'):
        if part == '' or part == '.':
            continue                          # empty piece or "stay here"
        if part == '..':
            if stack:
                stack.pop()                   # go up one level (nothing happens at root)
        else:
            stack.append(part)                # a real directory name (including '...')
    return '/' + '/'.join(stack)
static String optimal(String path) {
    Deque<String> stack = new ArrayDeque<>();
    for (String part : path.split("/")) {
        if (part.isEmpty() || part.equals(".")) continue;      // empty piece or "stay here"
        if (part.equals("..")) {
            if (!stack.isEmpty()) stack.pop();                 // go up one level
        } else {
            stack.push(part);                                  // a real directory name
        }
    }
    StringBuilder sb = new StringBuilder();
    Iterator<String> it = stack.descendingIterator();          // bottom to top
    while (it.hasNext()) sb.append('/').append(it.next());
    return sb.length() == 0 ? "/" : sb.toString();
}
ApproachTimeSpace
Repeatedly cancel the first ..O(n²)O(n)
Stack of namesO(n)O(n)
4Watch for
  • .. at the root must not pop an empty stack. Verified failing input: "/../a" raises IndexError without the guard (Part 10).
  • ... is a normal name. A trailing slash and repeated slashes produce empty pieces that you skip.
  • Java: ArrayDeque.push adds at the head, so build the result with descendingIterator() (bottom to top).

Type CHardLeetCode 224Frequently asked

Evaluate an expression with non-negative integers, +, -, parentheses and spaces. A minus can be unary at the start or right after (, as in "-(2+3)" or "(-2)". "1-(2+3)" gives -4.

Frequently asked (Grind 75; single list).

1Brute force

A recursive-descent parser (as in the Java oracle) or, as the Python oracle does, the language's own evaluator. Used only to check the stack solution; eval is never an acceptable interview answer.

def calc1_brute(s):
    return eval(s)        # test oracle only: Python's own parser. Never offer eval() as an interview answer.
private static String src;
private static int pos;

static int brute(String s) {                           // recursive descent: a different method, used as the oracle
    src = s;
    pos = 0;
    return (int) expr();
}
private static long expr() {
    long v = term();
    while (true) {
        skip();
        if (pos < src.length() && src.charAt(pos) == '+') { pos++; v += term(); }
        else if (pos < src.length() && src.charAt(pos) == '-') { pos++; v -= term(); }
        else return v;
    }
}
private static long term() {
    skip();
    char c = src.charAt(pos);
    if (c == '-') { pos++; return -term(); }           // unary minus
    if (c == '(') { pos++; long v = expr(); skip(); pos++; return v; }
    long v = 0;
    while (pos < src.length() && Character.isDigit(src.charAt(pos))) v = v * 10 + (src.charAt(pos++) - '0');
    return v;
}
private static void skip() { while (pos < src.length() && src.charAt(pos) == ' ') pos++; }
2The bottleneck and the key observation

Without * and /, you only need a running result and the sign that applies to the next number. A ( pauses the outer calculation: save result and the sign in front of the bracket, and start fresh. A ) finishes the inner result, multiplies it by the saved sign and adds the saved result. That is Decode String's context stack with arithmetic.

3Optimal approach
  1. Keep result, num, sign (+1 or -1).
  2. Digit: build num.
  3. + or -: add sign * num to result, reset num, set the new sign.
  4. (: push result then sign; reset result = 0, sign = 1.
  5. ): add the pending number, then result *= popped sign and result += popped result.
  6. At the end return result + sign * num.
def calc1(s):
    stack = []                                # saved (result_before, sign_before) per '('
    result, num, sign = 0, 0, 1
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch == '+' or ch == '-':
            result += sign * num              # finish the number before the operator
            num = 0
            sign = 1 if ch == '+' else -1
        elif ch == '(':
            stack.append(result)              # save the context ...
            stack.append(sign)
            result, sign = 0, 1               # ... and start fresh inside the bracket
        elif ch == ')':
            result += sign * num              # finish the bracket's last number
            num = 0
            result *= stack.pop()             # the sign that was in front of '('
            result += stack.pop()             # the result before '('
    return result + sign * num
static int optimal(String s) {
    Deque<Integer> stack = new ArrayDeque<>();        // saved result, then saved sign, per '('
    int result = 0, num = 0, sign = 1;
    for (int i = 0; i < s.length(); i++) {
        char ch = s.charAt(i);
        if (Character.isDigit(ch)) {
            num = num * 10 + (ch - '0');
        } else if (ch == '+' || ch == '-') {
            result += sign * num;                     // finish the number before the operator
            num = 0;
            sign = ch == '+' ? 1 : -1;
        } else if (ch == '(') {
            stack.push(result);                       // save the context ...
            stack.push(sign);
            result = 0;                               // ... and start fresh inside the bracket
            sign = 1;
        } else if (ch == ')') {
            result += sign * num;
            num = 0;
            result *= stack.pop();                    // the sign in front of '('
            result += stack.pop();                    // the result before '('
        }
    }
    return result + sign * num;
}

Recursive descent oracleO(n)O(depth)
Context stackO(n)O(depth)

  • Pop the sign first, then the saved result: they were pushed in the opposite order.
