Arrays

An array is a row of values stored side by side. Reading a slot by index is one step; searching, inserting and deleting cost a walk along the row. Most array problems are about walking it once in the right way while keeping a tiny summary of what is already finished.

Part 1First Principles

What an array is

An array is a block of memory cut into equal-size slots that sit next to each other. Slot number i holds the i-th value. Counting starts at 0.

Because the slots are equal in size and adjacent, the address of any slot is a calculation, not a search:

address of a[i] = base + i * size_of_element

index:     0      1      2      3      4
         +------+------+------+------+------+
a      = |  7   |  2   |  9   |  4   |  1   |
         +------+------+------+------+------+
address: 1000   1004   1008   1012   1016        (4-byte ints, base = 1000)

That formula is why access by index is O(1). One multiply and one add, whether the array has 10 values or 10 million.

It also explains the weak spots. Inserting at slot 2 means every value from slot 2 onward must move one slot right to open a gap, because memory cannot push neighbours apart. That shifting is the O(n) cost of inserting or deleting in the middle.

Static and dynamic arrays

A static array has a fixed length chosen at creation. Java's int[] is one. To grow it you allocate a bigger array and copy.

A dynamic array hides that copying. It wraps a static array plus a length. Python's list and Java's ArrayList are dynamic arrays. When an append finds the inner array full, it allocates one about twice as big, copies everything, then writes the new value.

capacity 4, length 4:   [a][b][c][d]          append(e) -> full
allocate capacity 8:    [ ][ ][ ][ ][ ][ ][ ][ ]
copy 4 values over:     [a][b][c][d][ ][ ][ ][ ]
write the new value:    [a][b][c][d][e][ ][ ][ ]   length 5, capacity 8

The core invariant of array algorithms

Think in invariants

Almost every array algorithm in this topic holds one idea steady as it walks: part of the array is already 'done', described by a few variables, and the rest is untouched. A running minimum describes the finished prefix. A write pointer marks the end of the kept region. Three boundaries describe three finished regions. Before coding, state this sentence out loud: 'after processing index i, I know ___'.

When to use an array

  • You need fast access by position, or you mostly read and append.
  • Order matters (time series, a sequence of events, a grid).
  • You want predictable, compact memory and fast sequential scans.

Where you already meet arrays

  • Pixels in an image: a 2D array of colour values.
  • Spreadsheet rows and columns, a database page of records.
  • Audio samples, a price history, a log file read into memory.
  • The call arguments sys.argv and args of a program.

Part 3Complexity

Time complexity counts how the number of basic steps grows with input size n. Space complexity counts how much extra memory grows with n. Neither counts the input itself unless the problem says to.

Why each cost is what it is

  • Access is O(1) because the address is base + i*size. No walking.
  • Search is O(n) because an unsorted array has no structure to exploit. In the worst case the value is last or absent, so you look at all n slots.
  • Insert or delete in the middle is O(n) because you shift every value after the gap. Averaged over positions it is n/2 moves, which is still O(n).
  • Append is amortised O(1), explained below.

Amortised O(1) append, the doubling argument

A single append that triggers a resize copies n values, so it is O(n). But resizes are rare. If capacity doubles each time, the copies for n appends cost about 1 + 2 + 4 + ... + n/2 + n, which is less than 2n. Spread over n appends, that is under 2 extra steps per append, a constant.

appends:        1  2  3  4  5  6  7  8  9 ...
resize copies:  1  2     4           8          (only at sizes 1, 2, 4, 8, ...)
total copies for 9 appends: 1 + 2 + 4 + 8 = 15  < 2 * 9

If capacity grew by a FIXED +10 instead of doubling, resizes would be frequent
and the total would be O(n^2).

Loops that look worse than they are

Nested loops are not automatically O(n²). Look at how many times the inner body runs in total. In Part 4 Type C, a while inside a for still totals O(n) when each element is touched a bounded number of times. Count work per element, not loop nesting.

Part 4Core Patterns

Six patterns cover most array interview problems. Each has a letter. The problems in Part 7 are tagged with these letters. Before coding any of them, write the four items of the table: state, invariant, step, result.

A

Traversal and running state

What it is. Walk the array once and carry a small summary of everything seen so far (a minimum, a maximum, a best answer, a counter, the previous element).

Problem it solves. Questions whose answer at each position depends on a fact about the prefix. Turns O(n²) pair checks into one pass.

Recognise it from. 'maximum profit', 'largest sum', 'is it sorted', 'longest streak', 'majority', anything with 'so far'.

Intuition. If you know the best answer ending at i-1 and one summary value, you can get the best answer ending at i without looking back.

StateInvariantStepResult
Summary of the prefixIt describes the whole prefix after each stepFold in nums[i]Best value seen
Algorithm
1. Initialise the summary from the first element (or a safe neutral value).
2. For each element: update the summary, THEN update the best answer.
3. Return the best answer.
def scan(nums):
    state = nums[0]                  # summary of the prefix
    best = nums[0]
    for x in nums[1:]:
        state = combine(state, x)    # e.g. min(state, x) or max(x, state + x)
        best = max(best, state)
    return best
static int scan(int[] nums) {
    int state = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        state = combine(state, nums[i]);   // e.g. Math.min or Math.max(x, state + x)
        best = Math.max(best, state);
    }
    return best;
}

Time: O(n). Space: O(1).

Tiny example.

day:      0  1  2  3  4  5
lowest:   7  1  1  1  1  1
profit:   0  0  4  2  5  3     best = 5
B

Prefix and suffix information

What it is. Precompute (or carry) the combined value of everything to the left (prefix) and to the right (suffix) of each position.

Problem it solves. Range questions: sum of a range, 'everything except me', balance points, subarray sums, trapped water.

Recognise it from. 'sum of elements between i and j', 'to the left of', 'except self', 'subarray sum equals k', many range queries.

Intuition. sum(i..j) = prefix[j+1] - prefix[i]. One pass up front makes every later range query O(1).

StateInvariantStepResult
prefix[k] = sum of the first k valuesprefix[i+1] - prefix[i] == nums[i]Add the next valueDifferences of prefixes
Algorithm
1. prefix[0] = 0; prefix[i+1] = prefix[i] + nums[i].
2. sum of nums[i..j] = prefix[j+1] - prefix[i].
3. Often you do not need the whole array: carry a running total instead.
def build_prefix(nums):
    prefix = [0] * (len(nums) + 1)
    for i, x in enumerate(nums):
        prefix[i + 1] = prefix[i] + x
    return prefix

def range_sum(prefix, i, j):         # sum of nums[i..j], inclusive
    return prefix[j + 1] - prefix[i]
static int[] buildPrefix(int[] nums) {
    int[] prefix = new int[nums.length + 1];
    for (int i = 0; i < nums.length; i++) prefix[i + 1] = prefix[i] + nums[i];
    return prefix;
}
static int rangeSum(int[] prefix, int i, int j) {   // nums[i..j], inclusive
    return prefix[j + 1] - prefix[i];
}

Time: O(n) to build, O(1) per query. Space: O(n), or O(1) if you carry a running total.

Tiny example.

nums   = [3, 1, 4, 1, 5]
prefix = [0, 3, 4, 8, 9, 14]
sum(nums[1..3]) = prefix[4] - prefix[1] = 9 - 3 = 6   (1 + 4 + 1)
C

Read / write pointers (in-place modification)

What it is. Two indices walk the same array. read looks at every element. write marks where the next KEPT element goes.

Problem it solves. Filtering, removing, deduplicating or compacting in place, with O(1) extra space.

Recognise it from. 'in place', 'without extra array', 'remove', 'move all X to the end', 'return the new length'.

Intuition. The kept region nums[0..write-1] is always correct. write <= read is always true, so writing never destroys an unread value.

StateInvariantStepResult
write = length of the kept regionnums[0..write-1] is the answer so farCopy the value if it is keptwrite
Algorithm
1. write = 0.
2. For read = 0 .. n-1: if nums[read] should be kept, copy it to nums[write] and write++.
3. The answer is nums[0..write-1].
def keep_if(nums, keep):
    write = 0                                   # next free slot in the kept prefix
    for read in range(len(nums)):
        if keep(nums, read, write):
            nums[write] = nums[read]
            write += 1
    return write                                # new length
static int keepIf(int[] nums) {
    int write = 0;
    for (int read = 0; read < nums.length; read++) {
        if (shouldKeep(nums, read, write)) {
            nums[write] = nums[read];
            write++;
        }
    }
    return write;
}

Time: O(n). Space: O(1).

Tiny example.

read=1: 2 keep -> nums[0]=2   write=1
read=2: 2 keep -> nums[1]=2   write=2
read=3: 3 skip           result k=2, nums[:2]=[2, 2]
D

Swap, reverse and rotate

What it is. Rearrange elements by swapping pairs from opposite ends, and build bigger moves (rotate) out of reversals.

Problem it solves. Reversing, rotating, palindrome-style symmetry, mirrored transformations.

Recognise it from. 'reverse', 'rotate by k', 'cyclic shift', 'mirror'.

Intuition. A reversal is a symmetric swap that touches each element once. Rotation = reverse all, then reverse the two parts.

StateInvariantStepResult
Two ends i, jEverything outside [i..j] is already swappedSwap and move inwardThe reversed array
Algorithm
1. i = 0, j = n-1.
2. While i < j: swap, i++, j--.
3. Rotate by k: k %= n; reverse all; reverse [0..k-1]; reverse [k..n-1].
def reverse(nums, i, j):
    while i < j:
        nums[i], nums[j] = nums[j], nums[i]
        i += 1
        j -= 1
static void reverse(int[] nums, int i, int j) {
    while (i < j) {
        int t = nums[i]; nums[i] = nums[j]; nums[j] = t;
        i++; j--;
    }
}

Time: O(n). Space: O(1).

Tiny example.

[1, 2, 3, 4, 5, 6, 7], k = 3
reverse all      -> [7, 6, 5, 4, 3, 2, 1]
reverse first 3  -> [5, 6, 7, 4, 3, 2, 1]
reverse the rest -> [5, 6, 7, 1, 2, 3, 4]
E

Partition and index-as-key

What it is. Rearrange elements into regions by value, or use the array positions themselves as a lookup table.

Problem it solves. Sorting a few categories, moving values to where they belong, finding missing or duplicate values in a known range without extra memory.

Recognise it from. 'sort 0, 1, 2', 'partition around a value', 'values are in 1..n', 'find the missing / duplicate', 'O(1) space'.

Intuition. Value v belongs at index v-1 (or v). If values are in a known range, the index can stand in for a hash table.

StateInvariantStepResult
low, mid, high boundaries[0,low)=0s, [low,mid)=1s, (high,end]=2sInspect nums[mid] and move it to its regionThe array sorted
Algorithm
Partition: keep regions [0..low), [low..mid), (high..end]; look at nums[mid] and swap it into its region.
Placement: while nums[i] is in range and not at its home slot, swap it home; then scan for the first slot holding the wrong value.
def dutch_flag(nums):
    low, mid, high = 0, 0, len(nums) - 1
    while mid <= high:
        if nums[mid] == 0:
            nums[low], nums[mid] = nums[mid], nums[low]
            low += 1; mid += 1
        elif nums[mid] == 1:
            mid += 1
        else:
            nums[mid], nums[high] = nums[high], nums[mid]
            high -= 1                    # do NOT move mid: the swapped-in value is unseen
static void dutchFlag(int[] nums) {
    int low = 0, mid = 0, high = nums.length - 1;
    while (mid <= high) {
        if (nums[mid] == 0)      { swap(nums, low++, mid++); }
        else if (nums[mid] == 1) { mid++; }
        else                     { swap(nums, mid, high--); }
    }
}

Time: O(n). Space: O(1).

Tiny example.

[2, 0, 1]  low=0 mid=0 high=2
nums[0]=2 -> swap with high: [1, 0, 2]  high=1
nums[0]=1 -> mid=1
nums[1]=0 -> swap with low : [0, 1, 2]  low=1 mid=2   mid>high, done
F

2D arrays (grids)

What it is. An m × n grid stored as an array of arrays. Cell (r, c) is grid[r][c].

Problem it solves. Rotations, traversals, markers, layer-by-layer processing.

Recognise it from. 'matrix', 'grid', 'rotate the image', 'spiral', 'set row and column', 'diagonal'.

Intuition. Treat a grid transformation as a composition of simple moves (transpose, reverse), or walk it with boundaries or direction vectors.

StateInvariantStepResult
Row and column boundsStay inside 0 <= r < rows, 0 <= c < colsVisit or move one cellThe transformed grid
Algorithm
1. Row-major loop: for r in range(rows): for c in range(cols).
2. Rotate 90° clockwise = transpose, then reverse each row.
3. Spiral: four shrinking boundaries top, bottom, left, right.
4. Walking: direction arrays dr = [0,1,0,-1], dc = [1,0,-1,0].
def transpose_in_place(m):          # square matrices only
    n = len(m)
    for i in range(n):
        for j in range(i + 1, n):       # j > i, or every pair is swapped twice
            m[i][j], m[j][i] = m[j][i], m[i][j]
static void transposeInPlace(int[][] m) {
    int n = m.length;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++) {
            int t = m[i][j]; m[i][j] = m[j][i]; m[j][i] = t;
        }
}

Time: O(m·n). Space: O(1) for in-place square moves, else O(m·n).

Tiny example.

[1 2 3]            [1 4 7]            [7 4 1]
[4 5 6]  transpose [2 5 8]  reverse   [8 5 2]
[7 8 9]     ->     [3 6 9]  each row  [9 6 3]

A. Best Time to Buy and Sell Stock

BRUTE FORCE   : for every pair (buy, sell), take the best difference
      |
WHY SLOW      : the inner loop re-scans all later days for every buy day
      |
OBSERVATION   : for a fixed sell day, the best buy is the cheapest day before it
      |
BETTER        : remember that cheapest price in one variable
      |
OPTIMAL       : single pass: update lowest, then best

Compare. O(n²) time, O(1) space → O(n) time, O(1) space.

B. Product of Array Except Self

BRUTE FORCE   : for each i, multiply every other element
      |
WHY SLOW      : n multiplications per index, n indexes
      |
OBSERVATION   : product except i = (product left of i) × (product right of i)
      |
BETTER        : store left products and right products in two arrays
      |
OPTIMAL       : left pass fills output; right pass multiplies in a running suffix (no extra array)

Compare. O(n²) → O(n) time; O(1) extra space (output not counted).

C. Move Zeroes / Remove Duplicates

BRUTE FORCE   : build a new list of kept values, or delete from the middle and shift
      |
WHY SLOW      : copying costs O(n) space; shifting costs O(n) per deletion
      |
OBSERVATION   : the kept region only ever grows by one and sits behind the reader
      |
BETTER        : two pointers: reader scans, writer places
      |
OPTIMAL       : write only when the value is kept

Compare. O(n²) shift or O(n) space → O(n) time, O(1) space.

D. Rotate Array

BRUTE FORCE   : rotate right by one step, k times
      |
WHY SLOW      : each step shifts n values: O(n·k)
      |
OBSERVATION   : a rotation is a reversal of the whole array followed by reversals of the two parts
      |
BETTER        : copy into a second array at index (i+k)%n (O(n) space)
      |
OPTIMAL       : three in-place reversals

Compare. O(n·k) → O(n) time, O(n) space → O(1) space.

E. First Missing Positive

BRUTE FORCE   : for v = 1, 2, 3 ... check whether v is in the array
      |
WHY SLOW      : each membership test scans the array
      |
OBSERVATION   : the answer must lie in 1..n+1, so only those values matter
      |
BETTER        : put all values in a set: O(n) time but O(n) space
      |
OPTIMAL       : swap each value to index v-1, then scan for the first mismatch

Compare. O(n²) → O(n) time, O(n) space → O(n) time, O(1) space.

F. Rotate Image

BRUTE FORCE   : build a new matrix and copy cell (i, j) to (j, n-1-i)

WHY SLOW      : uses O(n²) extra memory
      |
OBSERVATION   : a quarter turn clockwise equals a transpose followed by a row reversal

Best Time to Buy and Sell Stock

Type AEasyLeetCode 121O(n²) → O(n)
ShowHide

Problem. prices[i] is a stock price on day i. Buy on one day and sell on a LATER day. Return the best profit, or 0 if every trade loses money.

Example. [7, 1, 5, 3, 6, 4] → 5 (buy at 1, sell at 6).

Recognise before coding. One pass, and the answer at each index depends on one running fact about everything BEFORE it: the cheapest price so far.

Skill it teaches. Maintaining state while traversing (Type A). Turn 'best pair (i, j)' into 'best sell today, given the best buy so far'. Why it matters: The simplest example of replacing an inner loop with one remembered value. Kadane and every 'running best' problem is this idea.

1Brute force
def max_profit_brute(prices):
    best = 0
    for i in range(len(prices)):
        for j in range(i + 1, len(prices)):
            best = max(best, prices[j] - prices[i])
    return best
static int maxProfitBrute(int[] prices) {
    int best = 0;
    for (int i = 0; i < prices.length; i++)
        for (int j = i + 1; j < prices.length; j++)
            best = Math.max(best, prices[j] - prices[i]);
    return best;
}

Cost: O(n²). Bottleneck: The inner loop re-scans all later days for every buy day.

2Observation

For a fixed sell day j, the best buy day is simply the cheapest day before j. That is one number we can carry forward as we walk.

3Optimal
def max_profit(prices):
    lowest = float("inf")          # cheapest price seen so far
    best = 0                       # best profit seen so far
    for p in prices:
        lowest = min(lowest, p)
        best = max(best, p - lowest)
    return best
static int maxProfit(int[] prices) {
    int lowest = Integer.MAX_VALUE, best = 0;
    for (int p : prices) {
        lowest = Math.min(lowest, p);
        best = Math.max(best, p - lowest);
    }
    return best;
}

Maximum Subarray

Type AMediumLeetCode 53O(n²) → O(n)
ShowHide

Problem. Return the largest sum of any non-empty contiguous subarray.

Recognise before coding. 'Largest/smallest over contiguous subarrays' plus negatives. Ask: what is the best subarray that ENDS here?

Skill it teaches. Kadane's algorithm: a running value that either extends the previous run or restarts. Why it matters: The template for 'best ending here' problems. Max Product Subarray (practice) and many DP problems later are the same shape.

def max_subarray_brute(nums):

    return best

Find Pivot Index

Type BEasyLeetCode 724O(n²) → O(n)
ShowHide

Problem. Find the leftmost index where the sum of everything to its left equals the sum of everything to its right. Return -1 if none.

Example. [1, 7, 3, 6, 5, 6] → 3 (left sum 11, right sum 11).

Recognise before coding. 'Sum to the left' versus 'sum to the right' of an index. That is a prefix sum question.

Skill it teaches. Prefix sums with O(1) memory: carry the left sum, derive the right sum from the total. Why it matters: Shows you often do not need a stored prefix array. One total and one running variable are enough.

1Brute force
def pivot_index_brute(nums):
    for i in range(len(nums)):
        if sum(nums[:i]) == sum(nums[i + 1:]):
            return i
    return -1
static int pivotIndexBrute(int[] nums) {
    for (int i = 0; i < nums.length; i++) {
        int l = 0, r = 0;
        for (int j = 0; j < i; j++) l += nums[j];
        for (int j = i + 1; j < nums.length; j++) r += nums[j];
        if (l == r) return i;
    }
    return -1;
}

Cost: O(n²). Bottleneck: Recomputing the left sum and the right sum from scratch for every index.

2Observation

right = total - left - nums[i]. Keep left as a running variable and the check is O(1).

3Optimal
def pivot_index(nums):
    total, left = sum(nums), 0
    for i, x in enumerate(nums):
        if left == total - left - x:   # right sum = total - left - x
            return i
        left += x
    return -1
static int pivotIndex(int[] nums) {
    int total = 0, left = 0;
    for (int x : nums) total += x;
    for (int i = 0; i < nums.length; i++) {
        if (left == total - left - nums[i]) return i;
        left += nums[i];
    }
    return -1;
}

Product of Array Except Self

Type BMediumLeetCode 238O(n²) → O(n)
ShowHide

Problem. Return an array where out[i] is the product of every element except nums[i]. Do not use division. Target O(n).

Example. [1, 2, 3, 4] → [24, 12, 8, 6].

Recognise before coding. 'Everything except me' means left part times right part. Left part is a prefix, right part is a suffix.

Skill it teaches. Prefix and suffix passes, reusing the output array to keep extra space O(1). Why it matters: Prefix thinking beyond sums. Also trapping rain water (practice) uses prefix and suffix maxima the same way.

1Brute force
def product_except_self_brute(nums):
    out = []
    for i in range(len(nums)):
        p = 1
        for j in range(len(nums)):
            if j != i:
                p *= nums[j]
        out.append(p)
    return out
static int[] productExceptSelfBrute(int[] nums) {
    int[] out = new int[nums.length];
    for (int i = 0; i < nums.length; i++) {
        int p = 1;
        for (int j = 0; j < nums.length; j++)
            if (j != i) p *= nums[j];
        out[i] = p;
    }
    return out;
}

Cost: O(n²). Bottleneck: Multiplying all other elements for every index is O(n) per index.

2Observation

out[i] = (product of nums[0..i-1]) * (product of nums[i+1..n-1]). Fill the left products in one pass, then multiply in the right products in a second pass.

3Optimal
def product_except_self(nums):
    n = len(nums)
    out = [1] * n
    prefix = 1
    for i in range(n):             # out[i] = product of everything LEFT of i
        out[i] = prefix
        prefix *= nums[i]
    suffix = 1
    for i in range(n - 1, -1, -1): # multiply in the product of everything RIGHT of i
        out[i] *= suffix
        suffix *= nums[i]
    return out
static int[] productExceptSelf(int[] nums) {
    int n = nums.length;
    int[] out = new int[n];
    int prefix = 1;
    for (int i = 0; i < n; i++) { out[i] = prefix; prefix *= nums[i]; }
    int suffix = 1;
    for (int i = n - 1; i >= 0; i--) { out[i] *= suffix; suffix *= nums[i]; }
    return out;
}

Subarray Sum Equals K

Type BMediumLeetCode 560O(n²) → O(n)
ShowHide

Problem. Count the contiguous subarrays whose sum equals k. Values can be negative.

Example. [1, 1, 1], k = 2 → 2.

Recognise before coding. 'Count subarrays with sum k' plus negatives. A prefix sum alone is not enough, and a sliding window fails because sums are not monotonic.

Skill it teaches. Prefix sum difference: sum(i..j) = prefix[j] - prefix[i-1]. This is where arrays hand over to hashing. Why it matters: The bridge problem. The array part is the prefix sum. The new part is a dictionary of earlier prefix values, which is the next topic.

1Brute force
def subarray_sum_brute(nums, k):
    count = 0
    for i in range(len(nums)):
        total = 0
        for j in range(i, len(nums)):
            total += nums[j]
            if total == k:
                count += 1
    return count
static int subarraySumBrute(int[] nums, int k) {
    int count = 0;
    for (int i = 0; i < nums.length; i++) {
        int total = 0;
        for (int j = i; j < nums.length; j++) {
            total += nums[j];
            if (total == k) count++;
        }
    }
    return count;
}

Cost: O(n²). Bottleneck: Checking every start and end is O(n²).

2Observation

A subarray ending now sums to k exactly when some earlier prefix equals prefix - k. Count how often each prefix value has appeared so that lookup is O(1). Seed with {0: 1} for the empty prefix.

3Optimal
def subarray_sum(nums, k):
    seen = {0: 1}                  # prefix value -> how many times seen (empty prefix = 0)
    prefix = count = 0
    for x in nums:
        prefix += x
        count += seen.get(prefix - k, 0)   # an earlier prefix of (prefix - k) closes a sum-k subarray
        seen[prefix] = seen.get(prefix, 0) + 1
    return count
static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> seen = new HashMap<>();
    seen.put(0, 1);
    int prefix = 0, count = 0;
    for (int x : nums) {
        prefix += x;
        count += seen.getOrDefault(prefix - k, 0);
        seen.merge(prefix, 1, Integer::sum);
    }
    return count;
}

Example. [0, 1, 0, 3, 12] → [1, 3, 12, 0, 0].

Recognise before coding. 'In place' plus 'keep relative order' plus a rule for what to keep. That is a read/write pointer problem.

Skill it teaches. Read/write pointers (Type C). write marks the next free slot in the finished region. Why it matters: The base case for every in-place filter. Remove Element, Remove Duplicates and Merge from the back follow the same skeleton.

1Brute force
def move_zeroes_brute(nums):
    kept = [x for x in nums if x != 0]          # extra O(n) list

        nums[i] = kept[i] if i < len(kept) else 0
static void moveZeroesBrute(int[] nums) {
    int[] kept = new int[nums.length];

    for (int x : nums) if (x != 0) kept[m++] = x;
    for (int i = 0; i < nums.length; i++) nums[i] = i < m ? kept[i] : 0;
}

Cost: O(n) time, O(n) space. Bottleneck: Not time, but space: the copy approach uses O(n) extra memory and the problem forbids it.

        if i >= 0 and nums1[i] > nums2[j]:
            nums1[w] = nums1[i]
            i -= 1
        else:
            nums1[w] = nums2[j]
            j -= 1
        w -= 1

        if (i >= 0 && nums1[i] > nums2[j]) nums1[w--] = nums1[i--];
        else nums1[w--] = nums2[j--];
    }
}

Recognise before coding. Values live in a known range tied to the length. Then a closed-form total (or XOR) beats searching.

1Brute force
def missing_number_brute(nums):
    for v in range(len(nums) + 1):
        if v not in nums:                        # list membership is O(n)

static int missingNumberBrute(int[] nums) {
    for (int v = 0; v <= nums.length; v++) {
        boolean found = false;
        for (int x : nums) if (x == v) { found = true; break; }
        if (!found) return v;

    return -1;

def missing_number(nums):

static int missingNumber(int[] nums) {

    for (int x : nums) actual += x;

}

First Missing Positive

Type EHardLeetCode 41O(n²) → O(n) time, O(1) space
ShowHide

Problem. Unsorted array. Return the smallest missing positive integer in O(n) time and O(1) extra space.

Example. [3, 4, -1, 1] → 2. [1, 2, 0] → 3.

Recognise before coding. The answer must lie in 1..n+1. Values outside that range cannot matter. The array itself can serve as the lookup table.

Skill it teaches. Index as key (Type E): put value v at index v-1, using swaps, then scan for the first mismatch. Why it matters: The hardest array trick in the set. Understand it and you understand 'use the input as the hash table'.

1Brute force
def first_missing_positive_brute(nums):
    v = 1
    while v in nums:                             # list membership is O(n)
        v += 1
    return v
static int firstMissingPositiveBrute(int[] nums) {
    int v = 1;
    while (true) {
        boolean found = false;
        for (int x : nums) if (x == v) { found = true; break; }
        if (!found) return v;
        v++;
    }
}

Cost: O(n²). Bottleneck: A linear membership test per candidate. A set would be O(n) time but O(n) space, which the problem forbids.

2Observation

With n slots, only values 1..n can be in the answer range. Move each one to its own slot. The first slot holding the wrong value reveals the answer.

3Optimal
def first_missing_positive(nums):
    n = len(nums)
    for i in range(n):
        # put value v at index v-1, while it is in range and not already there
        while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            j = nums[i] - 1
            nums[i], nums[j] = nums[j], nums[i]  # compute j FIRST (see Part 10)
    for i in range(n):
        if nums[i] != i + 1:
            return i + 1
    return n + 1

}

Type FMediumLeetCode 48O(n²) time, O(n²) space → O(n²) time, O(1) space

Problem. Rotate an n × n matrix 90 degrees clockwise, in place.

Example. [[1,2,3],[4,5,6],[7,8,9]] → [[7,4,1],[8,5,2],[9,6,3]].

Recognise before coding. 'In place' 2D transformation. Decompose it into simple moves you already know: transpose and reverse.

Skill it teaches. 2D indexing (Type F) and composing reversals. Why it matters: Practice in thinking of a 2D transformation as two 1D operations.

1Brute force
def rotate_image_brute(m):
    n = len(m)
    out = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            out[j][n - 1 - i] = m[i][j]          # (i, j) lands at (j, n-1-i)
    for i in range(n):
        m[i] = out[i]
static void rotateImageBrute(int[][] m) {
    int n = m.length;
    int[][] out = new int[n][n];
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            out[j][n - 1 - i] = m[i][j];
    for (int i = 0; i < n; i++) m[i] = out[i];
}

Cost: O(n²) time, O(n²) space. Bottleneck: A new matrix uses O(n²) extra space, which the problem forbids.

2Observation

Clockwise rotation = transpose (swap m[i][j] with m[j][i]) then reverse each row. Only visit j > i in the transpose, or you swap everything back.

3Optimal
def rotate_image(m):                             # clockwise 90 degrees

    for row in m:                                # 2) reverse each row
        row.reverse()

}

Problem. If a cell is 0, set its whole row and column to 0, in place.

Recognise before coding. You must remember which rows and columns to clear, without extra space and without cascading new zeros.

static void setZeroesBrute(int[][] m) {

2Observation

def set_zeroes(m):
    rows, cols = len(m), len(m[0])
    first_row = any(m[0][j] == 0 for j in range(cols))   # first row/col double as markers,
    first_col = any(m[i][0] == 0 for i in range(rows))   # so remember their own state first
    for i in range(1, rows):
        for j in range(1, cols):
            if m[i][j] == 0:
                m[i][0] = 0
                m[0][j] = 0
    for i in range(1, rows):
        for j in range(1, cols):
            if m[i][0] == 0 or m[0][j] == 0:
                m[i][j] = 0
    if first_row:
        for j in range(cols): m[0][j] = 0
    if first_col:
        for i in range(rows): m[i][0] = 0
static void setZeroes(int[][] m) {

    for (int i = 0; i < rows; i++) if (m[i][0] == 0) firstCol = true;
    for (int i = 1; i < rows; i++)

            if (m[i][j] == 0) { m[i][0] = 0; m[0][j] = 0; }

        for (int j = 1; j < cols; j++)

    if (firstRow) for (int j = 0; j < cols; j++) m[0][j] = 0;
    if (firstCol) for (int i = 0; i < rows; i++) m[i][0] = 0;

The four lines

Before coding, write these four lines as comments: STATE (what I carry), INVARIANT (what is true after each step), STEP (what I do per element), RESULT (what I return). If you cannot fill them in, you are not ready to code.

Worked example: Product of Array Except Self

  1. Input: ints, maybe zeros, no division allowed, n up to 10⁵.
  2. Brute force: for each i multiply the rest, O(n²).
  3. Bottleneck: I multiply the same numbers again and again.
  4. Pattern: B. Everything except me is left × right.
  5. STATE: running prefix product. INVARIANT: out[i] holds the product of everything left of i. STEP: write, then multiply the prefix. RESULT: after a second pass with a suffix product, out.
  6. Complexity: two passes, O(n); the output array does not count as extra space.
  7. Test: [1,2,3,4] and [0,1], where the zero is the interesting case.

T1. Running state (A)

Applies to: Best Time to Buy and Sell, Maximum Subarray, Majority Element, Max Product. Time / space: O(n) / O(1).

Most often wrong: Update the summary BEFORE the best answer, and initialise from nums[0], not 0, if values can be negative.

def max_subarray(nums):          # Kadane's algorithm
    cur = best = nums[0]           # cur = best sum of a subarray ENDING at this index
    for x in nums[1:]:
        cur = max(x, cur + x)      # extend the previous run, or start fresh at x
        best = max(best, cur)
    return best
static int maxSubarray(int[] nums) {
    int cur = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        cur = Math.max(nums[i], cur + nums[i]);
        best = Math.max(best, cur);
    }
    return best;
}

T2. Prefix and suffix (B)

Applies to: Pivot Index, Product Except Self, Subarray Sum, Trapping Rain Water. Time / space: O(n) / O(1) to O(n).

Most often wrong: Prefix array has length n+1 and prefix[0] = 0.

def product_except_self(nums):
    n = len(nums)
    out = [1] * n
    prefix = 1
    for i in range(n):             # out[i] = product of everything LEFT of i
        out[i] = prefix
        prefix *= nums[i]
    suffix = 1
    for i in range(n - 1, -1, -1): # multiply in the product of everything RIGHT of i
        out[i] *= suffix
        suffix *= nums[i]
    return out
static int[] productExceptSelf(int[] nums) {
    int n = nums.length;
    int[] out = new int[n];
    int prefix = 1;
    for (int i = 0; i < n; i++) { out[i] = prefix; prefix *= nums[i]; }
    int suffix = 1;
    for (int i = n - 1; i >= 0; i--) { out[i] *= suffix; suffix *= nums[i]; }
    return out;
}

def spiral_order_brute(m):
    r, c = len(m), len(m[0])
    seen = [[False] * c for _ in range(r)]
    dr, dc = [0, 1, 0, -1], [1, 0, -1, 0]        # right, down, left, up
    i = j = d = 0
    out = []
    for _ in range(r * c):
        out.append(m[i][j])
        seen[i][j] = True
        ni, nj = i + dr[d], j + dc[d]
        if not (0 <= ni < r and 0 <= nj < c) or seen[ni][nj]:
            d = (d + 1) % 4                      # turn right
            ni, nj = i + dr[d], j + dc[d]
        i, j = ni, nj
    return out

def spiral_order(m):
    out = []
    top, bot, left, right = 0, len(m) - 1, 0, len(m[0]) - 1
    while top <= bot and left <= right:
        for j in range(left, right + 1): out.append(m[top][j])
        top += 1
        for i in range(top, bot + 1): out.append(m[i][right])
        right -= 1
        if top <= bot:                           # guard: single remaining row
            for j in range(right, left - 1, -1): out.append(m[bot][j])
            bot -= 1
        if left <= right:                        # guard: single remaining column
            for i in range(bot, top - 1, -1): out.append(m[i][left])
            left += 1
    return out
static List<Integer> spiralOrder(int[][] m) {
    List<Integer> out = new ArrayList<>();
    int top = 0, bot = m.length - 1, left = 0, right = m[0].length - 1;
    while (top <= bot && left <= right) {
        for (int j = left; j <= right; j++) out.add(m[top][j]);
        top++;
        for (int i = top; i <= bot; i++) out.add(m[i][right]);
        right--;
        if (top <= bot) {
            for (int j = right; j >= left; j--) out.add(m[bot][j]);
            bot--;
        }
        if (left <= right) {
            for (int i = bot; i >= top; i--) out.add(m[i][left]);
            left++;
        }

def max_product(nums):
    hi = lo = best = nums[0]                     # best and worst product ending here
    for x in nums[1:]:
        cand = (x, hi * x, lo * x)               # a negative flips worst into best
        hi, lo = max(cand), min(cand)
        best = max(best, hi)
    return best
static int maxProduct(int[] nums) {
    int hi = nums[0], lo = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        int x = nums[i];
        int a = x, b = hi * x, c = lo * x;
        hi = Math.max(a, Math.max(b, c));
        lo = Math.min(a, Math.min(b, c));
        best = Math.max(best, hi);
    }
    return best;
}

def trap(height):
    n = len(height)
    if n == 0:
        return 0
    left, right = [0] * n, [0] * n
    left[0] = height[0]
    for i in range(1, n):
        left[i] = max(left[i - 1], height[i])    # tallest wall at or left of i
    right[-1] = height[-1]
    for i in range(n - 2, -1, -1):
        right[i] = max(right[i + 1], height[i])  # tallest wall at or right of i
    return sum(min(left[i], right[i]) - height[i] for i in range(n))
static int trap(int[] h) {
    int n = h.length;
    if (n == 0) return 0;
    int[] left = new int[n], right = new int[n];
    left[0] = h[0];
    for (int i = 1; i < n; i++) left[i] = Math.max(left[i - 1], h[i]);
    right[n - 1] = h[n - 1];
    for (int i = n - 2; i >= 0; i--) right[i] = Math.max(right[i + 1], h[i]);
    int total = 0;
    for (int i = 0; i < n; i++) total += Math.min(left[i], right[i]) - h[i];
    return total;
}
