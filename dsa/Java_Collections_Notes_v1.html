Part 1First Principles

In one paragraph

A collection is an object that holds many items and offers operations on them. Java ships about a dozen of them, and each one makes one operation cheap by making others expensive: an ArrayList reads by index in O(1) but removing from the front is O(n); a HashMap finds a key in O(1) on average but keeps no order; a TreeMap keeps order and answers "nearest key" in O(log n) but pays O(log n) for everything; a PriorityQueue hands you the smallest item in O(log n) without sorting the rest. The skill is not memorising the classes. It is looking at the operation your algorithm repeats most and picking the container that makes that operation cheap. Done well, it turns an O(n²) scan into O(n log n) or O(n). Python has the same toolbox under different names, so you learn each idea once and write it twice.

What the framework is

The Java Collections Framework is the set of interfaces and classes in java.util for holding groups of objects. It has two layers, and the split is the most important idea on this page.

The core invariants

Each container is correct because one fact stays true. Know the fact and the rules follow.

ContainerInvariant (the fact that always holds)What it forbids or implies
ArrayList, arrayItems sit side by side, slot number = position.Index read is O(1). Insert or delete in the middle shifts items.
HashMap, HashSetEqual keys have equal hashCode, and a stored key does not change.Break either half and a stored key can no longer be found. No order is promised.
PriorityQueueEvery parent is ≤ its children (min-heap).Only the root is ordered. Iterating or printing shows heap order, not sorted order.
TreeMap, TreeSetKeys are in comparator order and the comparator is consistent.Keys the comparator calls equal are the same key. No null key with natural ordering.
ArrayDequeOnly the two ends move.No index access, no null items.
LinkedHashMapA list threads through the entries in insertion (or access) order.Evicting the oldest is O(1). Iteration order is defined.
The one idea of this whole topic

Every container is cheap at one thing and expensive at another. Find the operation your loop repeats, and choose the container that makes that operation cheap. If you cannot say which operation that is, you have not finished reading the problem.

When to use this, and when not to

Reach for a collection when

  • Your loop does "find", "seen before", or "count" inside another loop: a hash container.
  • You repeatedly need the min, max, or top k of a changing set: a heap.
  • You need the nearest key, a range, or sorted order that stays sorted as you insert: a tree container.
  • Items enter at one end and leave from the other, or both: a deque.
  • The size is not known in advance.

Do not, or think twice, when

  • A plain array or int[] is enough: it is faster and uses less memory than List<Integer> (every element is an object).
  • The key range is small and dense (letters, digits): a 26-slot int[] beats a HashMap.
  • You sort once and never insert again: a sorted array with binary search beats a TreeMap.
  • You only need the top 1: keep a variable, not a heap.
  • You need thread safety: the plain collections are not safe. Use the concurrent versions, a topic outside DSA interviews.

Where you already meet it

  • Python itself: list is an ArrayList, dict is a LinkedHashMap (it keeps insertion order), set is a HashSet, collections.deque is an ArrayDeque, heapq is a PriorityQueue. Python has no built-in TreeMap.
  • Databases: a hash index behaves like a HashMap (exact match only), a B-tree index behaves like a TreeMap (range queries, nearest value).
  • Caches: a least-recently-used cache is a LinkedHashMap in access order. This is Problem G1.
  • Schedulers and timers: the next thing to run is the smallest deadline in a priority queue.
  • Redis sorted sets, leaderboards: a map for score lookup plus a sorted structure for rank. This is the second build exercise in Part 15.

Heap: PriorityQueue and heapq

A priority queue gives you the smallest item first, whatever order you inserted them in. Java's PriorityQueue and Python's heapq are both min-heaps. To get a max-heap, reverse the comparison: Collections.reverseOrder() or a comparator in Java, negate the numbers in Python.

PriorityQueue and heapq

Build, peek, pop in order, max-heap, ordering by a pair, and the bulk constructor. In Java, a comparator that returns negative means "first argument comes out first".

Trap: a heap is not a sorted list

TreeSet: ordered set with floor and ceiling

floor(v) is the largest item ≤ v, ceiling(v) the smallest ≥ v, lower and higher are the strict versions. Python has no TreeSet, so the Python code keeps a sorted list and calls bisect. The catch: insort is O(n) because it shifts items. The third-party sortedcontainers package fixes that but is not in the standard library, so do not count on it in an interview.

import bisect
xs = [10, 20, 30, 40]                  # keep a SORTED list instead of a TreeSet
def floor(v):   i = bisect.bisect_right(xs, v); return xs[i - 1] if i else None
def ceiling(v): i = bisect.bisect_left(xs, v);  return xs[i] if i < len(xs) else None

def higher(v):  i = bisect.bisect_right(xs, v); return xs[i] if i < len(xs) else None
print(floor(25), ceiling(25), lower(10), higher(40), floor(20), ceiling(20))
print(xs[0], xs[-1])                   # first, last
bisect.insort(xs, 25)                  # insert keeps order, but O(n) shift
print(xs)

A hash container finds a key by hashCode, then confirms with equals. So a key must have both, consistent with each other, and must not change while stored. Strings, boxed numbers, List<Integer> and records (Java 16+) are safe. int[] and your own class without both methods are not.

Sorting and comparators

Sorting is where Collections meet most problems (Type C). Three rules cover almost everything:

  • Python: sorted(xs, key=...) with a tuple key for several fields, reverse=True for descending. To mix directions, negate the number: key=lambda p: (-p[1], p[0]).

Trap: subtraction comparators overflow

Writing (a, b) -> a - b is a classic shortcut and a classic bug: when the difference does not fit in an int it wraps around and the comparator lies. The failing input is [1, Integer.MIN_VALUE]. (A first attempt with [MAX_VALUE, -1, 0, MIN_VALUE] happened to sort correctly, a lucky pass that proves nothing.) Use Integer.compare(a, b).

# Python ints never overflow, so a - b is safe here, but key= is clearer.
print(sorted([1, -2**31], key=lambda x: x))

Hash collisions: why O(1) is an average

Why HashMap lookups are O(1) on average, not always

Every key has the same hash, so every lookup must compare against the other keys in one bucket. Python's time roughly quadruples when the key count doubles (each lookup is O(n)). Java's numbers are smaller and noisier here (JIT warm-up). The dedicated run in Appendix B separates the cases: with constant hash codes, Comparable keys stayed fast while non-Comparable keys slowed down sharply. Timings are machine-dependent, one run, and shown for the shape only.

Why these costs: the arguments

Amortized O(1) for ArrayList.add

When the array is full, add allocates a bigger array (about 1.5 times larger, verified: 10, 15, 22, 33, 49, 73) and copies everything. That one call costs O(n). But the next n/2 calls are free. Add up the copying: the last resize copies about n/1.5 items, the one before about n/1.5², and so on. That geometric series sums to at most 2n copies over n adds, so the average per add is at most 2 copies plus the write: O(1). This only works because the array grows by a multiple. Growing by a fixed +10 would make n adds cost O(n²).

The same argument everywhere

  • HashMap doubles its bucket array at load 0.75 (verified: at the 13th, 25th, 49th, 97th entry), so rehashing every key costs at most about 2n over n puts: O(1) amortized per put.
  • ArrayDeque and Python deque also grow by a multiple, so adding at either end is O(1) amortized.
  • Queue window (Problem F1): ping contains a while loop, but each timestamp is added once and removed at most once. Total pops ≤ total pushes, so n pings cost O(n) in all, O(1) each.
  • Top-k heap (Types D): n offers, each O(log k) because the heap never holds more than k items. Total O(n log k), not O(n log n).

Bulk heap build is O(n), not O(n log n)

Building a heap from n existing items (new PriorityQueue<>(collection) or heapq.heapify) is the standard O(n) result: most items sit near the bottom and sift only a step or two. Calling offer n times is O(n log n). The notes use the O(n) build in Problems P1 and P3. This standard result was not timed here.

Type A: Count and spend a budget

A map from each item to how many times it has been seen, or how many are left to spend.

What it solves

"How many of each", "are there enough", "do these two things have the same makeup".

Recognize it

  • Words: frequency, count, at most once, can be built from, anagram, majority, how many times
  • The answer depends on how many of each item, not on where they are

The intuition

Order does not matter for the answer, only the quantity of each item. A count per item is the smallest summary that keeps what matters, and a lookup replaces a scan.

Algorithm
  1. Make an empty map from item to count.
  2. Add: for each item, add 1 to its count (merge in Java, .get(k, 0) + 1 in Python).
  3. Spend: for each needed item, if its count is 0 return failure, otherwise subtract 1.
  4. Read the result off the map, or after the spend loop.
StateA map count[item].
Invariantcount[x] equals the number of copies of x seen so far (add phase) or still unspent (spend phase).
Each stepAdd: count[x]++. Spend: if count[x] == 0 fail, else count[x]--.
ResultDepends on the problem: a boolean, the largest count, the items with count above a bar.
TimeO(n) for n items.
SpaceO(k) for k distinct items. Use a 26-slot int[] when the items are lowercase letters.

Type B: Group by a canonical key

A map from a computed key to the list of items that share it. The work is deciding what the key is.

What it solves

"Group these", "which ones are equivalent", "which ones share a signature".

Recognize it

  • Words: group, anagram, same pattern, equivalent, shifted, isomorphic, bucket
  • Two items belong together when some normal form of them is equal

The intuition

If two items are equivalent exactly when their keys are equal, then one hash lookup replaces comparing an item against every group. The art is a key that is the same for equivalent items and different for the rest: sorted letters, a tuple of counts, the difference between neighbouring characters.

Algorithm
  1. Make an empty map from key to list.
  2. For each item compute its canonical key.
  3. computeIfAbsent(key, new list).add(item) (Python: setdefault or defaultdict(list)).
  4. The groups are the map's values.
StateMap<key, List<item>>.
InvariantTwo items are in the same list if and only if their keys are equal.
Each stepCompute the key, fetch or create its list, append.
Key ruleUse an immutable key with working equals and hashCode: String, List<Integer>, a record. Never int[].
TimeO(n · K) where K is the cost of building one key (O(L log L) for sorted letters).
SpaceO(n) items stored, plus the keys.

  Map<String, List<String>> groups = new HashMap<>();
  for (String w : words) {
    groups.computeIfAbsent(sortChars(w), k -> new ArrayList<>()).add(w);
  }
  return new ArrayList<>(groups.values());
}

Type C: Order with a comparator, then sweep

Sort the items by a rule you define, so that the items that interact become neighbours, then make one pass.

What it solves

Overlaps, merging, "sort by X then Y", "keep the original order for ties", scheduling by start time.

Recognize it

  • Words: sort by, custom order, merge overlapping, intervals, ties, lexicographic
  • Items that interact are not next to each other in the input but would be after sorting

The intuition

Sorting costs O(n log n) once and makes later work local. After sorting intervals by start, an interval can only overlap the latest merged one. The comparator is the whole trick, so write it first and test it with ties.

Algorithm
  1. Decide the order rule (which field first, which direction, how to break ties).
  2. Write the comparator (Integer.compare, thenComparing, or a tuple key in Python).
  3. Sort once.
  4. Sweep from left to right with one running piece of state (here, the last merged interval).
StateThe sorted list and one running value (the last merged interval).
InvariantAfter sorting, everything before the current item is already settled, and only the running value can interact with the current item.
Each stepIf the item overlaps the running value, extend the value; otherwise close it and start a new one.
Comparator ruleReturn negative, zero or positive. Use Integer.compare, never subtraction.
TimeO(n log n) for the sort, O(n) for the sweep.
SpaceO(n) for the output (plus the sort's own working space).

def merge_opt(intervals):

Type D: Top-k with a heap of size k

Keep a heap that never holds more than k items. The root is the worst of the current best k, so it is the one to throw out.

What it solves

k largest, k smallest, k closest, k most frequent, the kth largest, and the extreme of a stream.

Recognize it

  • Words: top k, k largest, k closest, kth largest, k most frequent, k nearest
  • You need only k items, not the full sorted order
  • k is much smaller than n

The intuition

Sorting all n items to read k of them wastes work on the n−k items you discard. A heap of size k does O(log k) per item. The direction is the part everyone gets backwards: to keep the k largest, use a min-heap, because the root must be the smallest of the keepers, the first to be evicted. To keep the k smallest, use a max-heap.

Algorithm
  1. Decide what "best" means and the key to rank by (count, distance, value).
  2. Choose the heap direction: root = the worst item you would keep.
  3. For each item: offer, and if the size exceeds k, poll (that evicts the worst).
  4. The heap now holds the answer. For the kth largest, the root is the answer.
StateA heap of at most k items, ordered by the rank key.
InvariantThe heap holds the best k items seen so far, and its root is the worst of them.
Each stepOffer the new item. If size > k, poll the root.
Direction ruleLargest k: min-heap. Smallest k: max-heap. Verified: a max-heap of size k for "2nd largest of [3,2,1,5,6,4]" returns 2, the right answer is 5.
TimeO(n log k).
SpaceO(k) for the heap, plus the count map in D1.

Template code for this type (verified, taken from D1 Top K Frequent Elements)
import heapq

def topk_opt(nums, k):
    cnt = {}
    for x in nums:
        cnt[x] = cnt.get(x, 0) + 1
    heap = []                                    # min-heap of (count, value)
    for v, c in cnt.items():
        heapq.heappush(heap, (c, v))
        if len(heap) > k:
            heapq.heappop(heap)                  # evict the weakest
    return [v for c, v in heap]
static int[] solve(int[] nums, int k) {
  Map<Integer, Integer> cnt = new HashMap<>();
  for (int x : nums) cnt.merge(x, 1, Integer::sum);
  PriorityQueue<int[]> heap = new PriorityQueue<>((p, q) -> Integer.compare(p[0], q[0])); // {count, value}
  for (Map.Entry<Integer, Integer> e : cnt.entrySet()) {
    heap.offer(new int[]{e.getValue(), e.getKey()});
    if (heap.size() > k) heap.poll();          // evict the weakest
  }
  int[] out = new int[k];
  for (int i = 0; i < k; i++) out[i] = heap.poll()[1];
  return out;
}

Type E: Ordered lookup: floor and ceiling

A sorted map or set, queried for the nearest key at or below (floor) or at or above (ceiling) a value.

What it solves

"Latest at or before", "next available", "nearest", "does this overlap something already stored".

Recognize it

  • Words: latest at or before, nearest, closest key, next greater key, range of keys, floor, ceiling
  • Items arrive one at a time and each query must see the current set
  • A scan works but is O(n) per query

The intuition

A hash container finds an exact key but cannot answer "nearest". A sorted structure can, because the answer is a neighbour. A balanced tree keeps the keys sorted as you insert, so each query is a walk down the tree: O(log n).

Algorithm
  1. Pick the sorted structure: TreeMap if there are values, TreeSet if not (Python: parallel sorted lists and bisect).
  2. Insert with put or add (or insort).
  3. Query with floorEntry, ceilingKey, lowerKey, higherKey.
  4. Handle null (nothing at or below): return the empty answer.
StateA sorted map from key to value (or per-key sorted map, as in E1).
InvariantKeys are in comparator order, so the nearest key is adjacent to where the query would sit.
Each stepInsert, or query a floor or ceiling and branch on null.
Boundary rulefloor and ceiling are inclusive (≤ and ≥), lower and higher are strict (< and >). Pick by whether equal counts.
TimeO(log n) per operation in Java. In Python, the search is O(log n) but insort is O(n).
SpaceO(n).

import bisect

class TimeMapOpt:
    def __init__(self):
        self.times = {}                      # key -> sorted list of timestamps
        self.vals = {}                       # key -> values, same positions

    def set(self, key, value, timestamp):    # timestamps only increase per key
        self.times.setdefault(key, []).append(timestamp)
        self.vals.setdefault(key, []).append(value)

    def get(self, key, timestamp):
        ts = self.times.get(key)
        if not ts:
            return ""
        i = bisect.bisect_right(ts, timestamp)   # first index with time > query
        return self.vals[key][i - 1] if i else ""
static class TimeMap {
  private final Map<String, TreeMap<Integer, String>> data = new HashMap<>();
  void set(String key, String value, int ts) {
    data.computeIfAbsent(key, k -> new TreeMap<>()).put(ts, value);
  }
  String get(String key, int ts) {
    TreeMap<Integer, String> tm = data.get(key);
    if (tm == null) return "";
    Map.Entry<Integer, String> e = tm.floorEntry(ts);     // largest key <= ts, or null
    return e == null ? "" : e.getValue();
  }
}

Type F: Queue or deque window

A queue holding only the items that still matter, oldest at the front. Add at the back, drop expired items from the front.

What it solves

"Last n seconds", "moving average", "evict the oldest", "first in first out", building one structure out of another.

Recognize it

  • Words: recent, last k, window, expire, oldest, queue, moving
  • Old items can be discarded for good once they fall out of range

The intuition

If an item that has expired never becomes relevant again, delete it permanently. A queue does that in O(1) at the front, and each item is added once and removed once, so the total work is linear.

Algorithm
  1. Create an empty ArrayDeque.
  2. On each event, offer it at the back.
  3. While the front is out of range, poll it.
  4. The deque now holds exactly the live items: read its size or contents.
StateA deque of live items, oldest first.
InvariantEvery item in the deque is inside the current window, in arrival order.
Each stepPush the new item, pop expired items from the front.
Boundary ruleDecide whether the edge is inclusive. [t−3000, t] keeps an item at exactly t−3000, so pop only when strictly older.
TimeAmortized O(1) per event, O(n) total.
SpaceO(window size).

A tiny example traced by hand

pings1, 100, 3001, 3002 (window is [t−3000, t])
ping(1)q = [1] → 1
ping(100)q = [1, 100] → 2
ping(3001)limit 1; front 1 is not older than 1, so keep it: q = [1, 100, 3001] → 3
ping(3002)limit 2; front 1 < 2, pop it: q = [100, 3001, 3002] → 3

The monotonic deque (Sliding Window Maximum) is this pattern with one more rule: before pushing, also pop from the back every item the new one beats. That problem is already covered in the Sliding Window notes and is listed under "Deferred" in Part 7.

Template code for this type (verified, taken from F1 Number of Recent Calls)
from collections import deque

class RecentOpt:
    def __init__(self):
        self.q = deque()

    def ping(self, t):
        self.q.append(t)
        while self.q[0] < t - 3000:    # drop requests that left the window
            self.q.popleft()
        return len(self.q)
static class RecentCounter {
  private final Deque<Integer> q = new ArrayDeque<>();
  int ping(int t) {
    q.offer(t);
    while (q.peek() < t - 3000) q.poll();           // drop requests that left the window
    return q.size();
  }
}

Type G: Two structures glued together

When one container cannot do every operation fast, keep two that describe the same items, and update both in the same method.

What it solves

"All operations in O(1)", "design a data structure", LRU and LFU caches, random pick with delete, leaderboards.

Recognize it

  • Words: design, implement a class, O(1), evict least recently used, random element, rank
  • Each container you try is slow at exactly one needed operation

The intuition

Ask, for every operation, "which container makes this cheap?". A map finds by key in O(1). A list holds order and picks an index in O(1). If the answers differ, combine them and keep them consistent: the map stores where each key sits in the other structure.

Algorithm
  1. List the operations the design must support and the cost each must have.
  2. Assign each operation to the container that makes it cheap.
  3. Decide what each container stores so the other can find it (a map from key to index, or to a node).
  4. Write every mutation so that both containers are updated together, then test the invariant.
StateTwo containers over the same items (map and list, or map and linked list).
InvariantThey hold the same set of keys, and every cross-reference (index or node) is correct.
Each stepUpdate the map and the other structure in the same method, never in separate steps a caller could see.
Typical tricksSwap the removed item with the last one so deletion is O(1) (G2). Move a touched node to the front of a linked list (G1).
TimeO(1) per operation, in both problems here.
SpaceO(n) for each of the two structures.

Template code for this type (verified, taken from G1 LRU Cache)
from collections import OrderedDict

class LRUOpt:
    def __init__(self, capacity):
        self.cap = capacity
        self.d = OrderedDict()                # oldest first

    def get(self, key):
        if key not in self.d:
            return -1
        self.d.move_to_end(key)               # mark most recent
        return self.d[key]

    def put(self, key, value):
        self.d[key] = value
        self.d.move_to_end(key)
        if len(self.d) > self.cap:
            self.d.popitem(last=False)        # evict the oldest
static class LRUCache {
  private final LinkedHashMap<Integer, Integer> map;
  LRUCache(int capacity) {
    // true = access order: get and put move the key to the end
    map = new LinkedHashMap<>(16, 0.75f, true) {
      @Override
      protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
        return size() > capacity;                 // called after every put
      }
    };
  }
  int get(int key) { return map.getOrDefault(key, -1); }
  void put(int key, int value) { map.put(key, value); }
}

Type H: The Iterator contract and safe iteration

Two related skills. First, implement or wrap an Iterator (hasNext, next, and here peek). Second, change a collection while walking it without breaking the walk.

What it solves

"Iterator", "peek", "hasNext", "flatten", and any "remove while looping".

Recognize it

  • Words: iterator, peek, hasNext, next, flatten, remove during iteration, ConcurrentModificationException
  • A source you can only move forward through, once

The intuition

An iterator cannot rewind, so "look without taking" needs a buffer. Pull one item ahead and hold it: peek shows the buffer, next returns it and refills it. For removal, never edit the collection behind a for-each: build a new one, call removeIf, or use the iterator's own remove.

Algorithm
  1. Keep the underlying iterator and a one-item buffer plus a flag saying whether the buffer is full.
  2. In the constructor, fill the buffer.
  3. peek returns the buffer. hasNext returns the flag.
  4. next returns the buffer, then refills it from the underlying iterator.
StateThe inner iterator, the buffered item, and a has flag (not a null check).
InvariantThe buffer holds the next item to return, and each source item is pulled exactly once, at most one ahead.
Each stepnext: save the buffer, pull the following item, return the saved one.
Sentinel ruleUse a flag or a unique sentinel object, not null, so the data may contain null.
TimeO(1) per call.
SpaceO(1) extra.

Template code for this type (verified, taken from H1 Peeking Iterator)
class PeekOpt:
    _END = object()                        # sentinel: works even if the data contains None

    def __init__(self, iterator):
        self.it = iterator
        self.nxt = next(iterator, PeekOpt._END)   # pull exactly one ahead

    def peek(self):
        return self.nxt

    def next(self):
        r = self.nxt
        self.nxt = next(self.it, PeekOpt._END)
        return r

    def hasNext(self):
        return self.nxt is not PeekOpt._END
static class PeekingIterator implements Iterator<Integer> {
  private final Iterator<Integer> it;
  private boolean has;                   // is there a buffered element?
  private int val;                       // the buffered element
  PeekingIterator(Iterator<Integer> iterator) { it = iterator; advance(); }
  private void advance() { has = it.hasNext(); if (has) val = it.next(); }
  public Integer peek() { return val; }
  public Integer next() { int r = val; advance(); return r; }
  public boolean hasNext() { return has; }
}

1Brute force

def merge_brute(intervals):
    iv = [list(x) for x in intervals]
    changed = True
    while changed:
        changed = False
        for i in range(len(iv)):
            for j in range(i + 1, len(iv)):
                a, b = iv[i], iv[j]
                if a[0] <= b[1] and b[0] <= a[1]:       # overlap
                    iv[i] = [min(a[0], b[0]), max(a[1], b[1])]
                    iv.pop(j)
                    changed = True
                    break
            if changed:
                break
    return iv
static List<int[]> brute(int[][] intervals) {
  List<int[]> iv = new ArrayList<>();
  for (int[] x : intervals) iv.add(new int[]{x[0], x[1]});
  boolean changed = true;
  while (changed) {
    changed = false;
    outer:
    for (int i = 0; i < iv.size(); i++) {
      for (int j = i + 1; j < iv.size(); j++) {
        int[] a = iv.get(i), b = iv.get(j);
        if (a[0] <= b[1] && b[0] <= a[1]) {
          iv.set(i, new int[]{Math.min(a[0], b[0]), Math.max(a[1], b[1])});
          iv.remove(j);                       // int index: removes by position
          changed = true;
          break outer;
        }
      }
    }
  }
  return iv;
}
2The bottleneck and the key observation

    for s, e in sorted(intervals):             # sorts by start, then end
        if out and s <= out[-1][1]:
            out[-1][1] = max(out[-1][1], e)    # extend the last merged interval
        else:
            out.append([s, e])
    return out

    if (!out.isEmpty() && cur[0] <= out.get(out.size() - 1)[1]) {
      int[] last = out.get(out.size() - 1);
      last[1] = Math.max(last[1], cur[1]);
    } else {
      out.add(new int[]{cur[0], cur[1]});
    }
  }
  return out;
}

Store each key's entries in a sorted structure. On get, ask for the floor of the timestamp. Java: TreeMap<Integer,String>. Python: parallel lists and bisect_right.

import bisect

class TimeMapOpt:
    def __init__(self):
        self.times = {}                      # key -> sorted list of timestamps
        self.vals = {}                       # key -> values, same positions

    def set(self, key, value, timestamp):    # timestamps only increase per key
        self.times.setdefault(key, []).append(timestamp)
        self.vals.setdefault(key, []).append(value)

    def get(self, key, timestamp):
        ts = self.times.get(key)
        if not ts:
            return ""
        i = bisect.bisect_right(ts, timestamp)   # first index with time > query
        return self.vals[key][i - 1] if i else ""

2The bottleneck and the key observation

Deleting from the end of an array is O(1), so move the victim to the end first. Order does not matter in a set, so the swap is free.

3Optimal approach

Keep a list of values and a map from value to its index in the list. To remove, copy the last element into the removed slot, fix its index in the map, and drop the last list entry.

import random

class RandSetOpt:
    def __init__(self):
        self.a = []                    # values
        self.pos = {}                  # value -> index in a

    def insert(self, v):
        if v in self.pos:
            return False
        self.pos[v] = len(self.a)
        self.a.append(v)
        return True

    def remove(self, v):
        if v not in self.pos:
            return False
        i = self.pos.pop(v)
        last = self.a.pop()            # O(1) from the end
        if i < len(self.a):            # v was not the last element
            self.a[i] = last           # move last into the hole
            self.pos[last] = i
        return True

    def getRandom(self):
        return random.choice(self.a)

Frequently asked (sources: Grind 75, Blind 75 / NeetCode week 3, Amazon list in techinterview.org, rank 2)

Design a cache with capacity c. get(key) returns the value or -1. put(key, value) inserts or updates, and if the cache is over capacity it evicts the least recently used key. Both operations should be O(1).

Recognize before coding"Evict the oldest" plus "look up by key in O(1)" is two structures glued together: a hash map for lookup, an ordered list for recency.
Skill it teachesLinkedHashMap in access order with removeEldestEntry, and the hash map + doubly linked list it is built from.
1Brute force

Keep a list of (key, value) ordered by recency. Every get and put scans for the key, then moves it to the back. Cost: O(n) per operation for n = capacity.

class LRUBrute:
    def __init__(self, capacity):
        self.cap = capacity
        self.items = []                       # [key, value], least recent first

    def get(self, key):
        for i, (k, v) in enumerate(self.items):   # scan
            if k == key:
                self.items.append(self.items.pop(i))
                return v
        return -1

    def put(self, key, value):
        for i, (k, v) in enumerate(self.items):
            if k == key:
                self.items.pop(i)
                break
        self.items.append([key, value])
        if len(self.items) > self.cap:
            self.items.pop(0)
static class BruteLRU {
  private final int cap;
  private final List<int[]> items = new ArrayList<>();      // {key, value}, least recent first
  BruteLRU(int capacity) { cap = capacity; }
  int get(int key) {
    for (int i = 0; i < items.size(); i++) {
      if (items.get(i)[0] == key) { int[] e = items.remove(i); items.add(e); return e[1]; }
    }
    return -1;
  }
  void put(int key, int value) {
    for (int i = 0; i < items.size(); i++) {
      if (items.get(i)[0] == key) { items.remove(i); break; }
    }

    if (items.size() > cap) items.remove(0);

2The bottleneck and the key observation

The map finds the node in O(1). The linked list moves and removes a node in O(1) because it already holds the neighbours. Neither alone can do both.

3Optimal approach

Use an ordered map that moves a key to the end whenever it is touched, and drops the front when over capacity. Java: LinkedHashMap(cap, 0.75f, true) plus removeEldestEntry. Python: OrderedDict with move_to_end and popitem(last=False). A hand-built hash map + doubly linked list (the third listing) is what many interviewers expect you to write.

from collections import OrderedDict

class LRUOpt:
    def __init__(self, capacity):
        self.cap = capacity
        self.d = OrderedDict()                # oldest first

    def get(self, key):
        if key not in self.d:
            return -1
        self.d.move_to_end(key)               # mark most recent
        return self.d[key]

    def put(self, key, value):
        self.d[key] = value
        self.d.move_to_end(key)
        if len(self.d) > self.cap:
            self.d.popitem(last=False)        # evict the oldest

class _Node:
    def __init__(self, k=0, v=0):
        self.k, self.v = k, v
        self.prev = self.next = None

class LRUManual:
    def __init__(self, capacity):
        self.cap = capacity
        self.map = {}                         # key -> node
        self.head, self.tail = _Node(), _Node()   # sentinels
        self.head.next, self.tail.prev = self.tail, self.head

    def _unlink(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _add_front(self, n):                  # front = most recent
        n.next, n.prev = self.head.next, self.head
        self.head.next.prev = n
        self.head.next = n

    def get(self, key):
        n = self.map.get(key)
        if n is None:
            return -1
        self._unlink(n)
        self._add_front(n)
        return n.v

    def put(self, key, value):
        n = self.map.get(key)
        if n:
            n.v = value
            self._unlink(n)
            self._add_front(n)
            return
        if len(self.map) == self.cap:
            lru = self.tail.prev
            self._unlink(lru)
            del self.map[lru.k]
        n = _Node(key, value)
        self.map[key] = n
        self._add_front(n)
static class LRUCache {
  private final LinkedHashMap<Integer, Integer> map;
  LRUCache(int capacity) {
    // true = access order: get and put move the key to the end
    map = new LinkedHashMap<>(16, 0.75f, true) {
      @Override
      protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
        return size() > capacity;                 // called after every put
      }
    };
  }
  int get(int key) { return map.getOrDefault(key, -1); }
  void put(int key, int value) { map.put(key, value); }
}

static class ManualLRU {
  static class Node { int k, v; Node prev, next; }
  private final int cap;
  private final Map<Integer, Node> map = new HashMap<>();
  private final Node head = new Node(), tail = new Node();        // sentinels
  ManualLRU(int capacity) { cap = capacity; head.next = tail; tail.prev = head; }
  private void unlink(Node n) { n.prev.next = n.next; n.next.prev = n.prev; }
  private void addFront(Node n) {                                    // front = most recent
    n.next = head.next; n.prev = head; head.next.prev = n; head.next = n;
  }
  int get(int key) {
    Node n = map.get(key);
    if (n == null) return -1;
    unlink(n); addFront(n);
    return n.v;
  }
  void put(int key, int value) {
    Node n = map.get(key);
    if (n != null) { n.v = value; unlink(n); addFront(n); return; }
    if (map.size() == cap) { Node lru = tail.prev; unlink(lru); map.remove(lru.k); }
    n = new Node(); n.k = key; n.v = value;
    map.put(key, n); addFront(n);
  }
}

class PeekBrute:

2The bottleneck and the key observation

"Consuming" and "looking" are different moments. Hold one element in a buffer to separate them.

3Optimal approach

Pull one element ahead and store it. peek returns it. next returns it and then pulls the following one.

class PeekOpt:
    _END = object()                        # sentinel: works even if the data contains None

    def __init__(self, iterator):
        self.it = iterator
        self.nxt = next(iterator, PeekOpt._END)   # pull exactly one ahead

    def peek(self):
        return self.nxt

    def next(self):
        r = self.nxt
        self.nxt = next(self.it, PeekOpt._END)
        return r

    def hasNext(self):
        return self.nxt is not PeekOpt._END
static class PeekingIterator implements Iterator<Integer> {
  private final Iterator<Integer> it;
  private boolean has;                   // is there a buffered element?
  private int val;                       // the buffered element
  PeekingIterator(Iterator<Integer> iterator) { it = iterator; advance(); }
  private void advance() { has = it.hasNext(); if (has) val = it.next(); }
  public Integer peek() { return val; }
  public Integer next() { int r = val; advance(); return r; }
  public boolean hasNext() { return has; }
}

[0:00] Understand

You: "I get an array of points and an integer k, and return the k points nearest the origin. Distance is Euclidean. Can two points be equally far, and can I return them in any order?" Interviewer: "Yes to both."

[2:00] Constraints and edge cases

You: "How large is n? If it is 10 to the 5, I want better than n squared. Also k equals n means return everything, and a single point is trivial."

[4:00] Brute force

You: "Compute squared distance for every point, sort, take the first k. That is O(n log n) time. I compare squared distances because the square root does not change the order, and it avoids floating point."

[6:00] Bottleneck and container

You: "The sort orders all n points, but I only need the k nearest. I will keep a heap of at most k points. The one I would evict first is the farthest of the current best k, so I want the farthest at the root: a max-heap keyed by squared distance. That is O(n log k)."

[9:00] Invariant

You: "After each point, the heap holds the k nearest points seen so far. If I push a new point and the size is k plus one, I poll the root, which is the farthest, and the invariant is restored."

import heapq

def kclose_opt(points, k):
    heap = []                                  # max-heap via negated distance
    for x, y in points:
        heapq.heappush(heap, (-(x * x + y * y), x, y))
        if len(heap) > k:
            heapq.heappop(heap)                # evict the farthest
    return [[x, y] for _, x, y in heap]
static int[][] solve(int[][] points, int k) {
  // max-heap: the farthest point is at the root
  PriorityQueue<int[]> heap = new PriorityQueue<>(
      (a, b) -> Integer.compare(b[0] * b[0] + b[1] * b[1], a[0] * a[0] + a[1] * a[1]));
  for (int[] p : points) {
    heap.offer(p);
    if (heap.size() > k) heap.poll();           // evict the farthest
  }
  return heap.toArray(new int[0][]);
}

Type D: Top-k heap

Applies toTop K Frequent, Kth Largest, K Closest, any "best k".

import heapq

def topk_opt(nums, k):
    cnt = {}
    for x in nums:
        cnt[x] = cnt.get(x, 0) + 1
    heap = []                                    # min-heap of (count, value)
    for v, c in cnt.items():
        heapq.heappush(heap, (c, v))
        if len(heap) > k:
            heapq.heappop(heap)                  # evict the weakest
    return [v for c, v in heap]
static int[] solve(int[] nums, int k) {
  Map<Integer, Integer> cnt = new HashMap<>();
  for (int x : nums) cnt.merge(x, 1, Integer::sum);
  PriorityQueue<int[]> heap = new PriorityQueue<>((p, q) -> Integer.compare(p[0], q[0])); // {count, value}
  for (Map.Entry<Integer, Integer> e : cnt.entrySet()) {
    heap.offer(new int[]{e.getValue(), e.getKey()});
    if (heap.size() > k) heap.poll();          // evict the weakest

}

Optimal
import heapq

def stone_opt(stones):
    heap = [-s for s in stones]             # negate: heapq is a min-heap
    heapq.heapify(heap)
    while len(heap) > 1:
        a = -heapq.heappop(heap)
        b = -heapq.heappop(heap)
        if a != b:
            heapq.heappush(heap, -(a - b))
    return -heap[0] if heap else 0
static int solve(int[] stones) {
  PriorityQueue<Integer> heap = new PriorityQueue<>(Collections.reverseOrder());
  for (int x : stones) heap.offer(x);
  while (heap.size() > 1) {
    int a = heap.poll(), b = heap.poll();
    if (a != b) heap.offer(a - b);
  }
  return heap.isEmpty() ? 0 : heap.peek();
}

from collections import deque

class StackQBrute:                           # two queues, pop moves n-1 items
    def __init__(self):
        self.q1, self.q2 = deque(), deque()

    def push(self, x):
        self.q1.append(x)

    def pop(self):
        while len(self.q1) > 1:
            self.q2.append(self.q1.popleft())
        x = self.q1.popleft()
        self.q1, self.q2 = self.q2, self.q1
        return x

    def top(self):
        x = self.pop()
        self.q1.append(x)
        return x

    def empty(self):
        return not self.q1

  Map<String, Integer> cnt = new HashMap<>();
  for (String w : words) cnt.merge(w, 1, Integer::sum);
  List<String> all = new ArrayList<>(cnt.keySet());
  all.sort((a, b) -> cnt.get(a).equals(cnt.get(b)) ? a.compareTo(b) : cnt.get(b) - cnt.get(a));
  return all.subList(0, k);
}
Optimal
import heapq

def words_opt(words, k):
    cnt = {}
    for w in words:
        cnt[w] = cnt.get(w, 0) + 1
    heap = [(-c, w) for w, c in cnt.items()]   # smaller tuple = higher count, then smaller word
    heapq.heapify(heap)
    return [heapq.heappop(heap)[1] for _ in range(k)]
static List<String> solve(String[] words, int k) {
  Map<String, Integer> cnt = new HashMap<>();
  for (String w : words) cnt.merge(w, 1, Integer::sum);
  PriorityQueue<String> heap = new PriorityQueue<>(
      (a, b) -> cnt.get(a).equals(cnt.get(b)) ? a.compareTo(b) : Integer.compare(cnt.get(b), cnt.get(a)));
  heap.addAll(cnt.keySet());
  List<String> out = new ArrayList<>();
  for (int i = 0; i < k; i++) out.add(heap.poll());
  return out;
}

Complexity. O(n + d + k log d): count, heapify all d words, pop k. A size-k heap needs a reversed comparator (weakest at the root) and gives O(n log k) for large d. Counts use Integer.compare or .equals, never == on boxed values.

Verified. Python 3000 checks, Java 3000 checks, optimal agreed with brute force.

P4 My Calendar I (LeetCode 729, Medium)

Implement book(start, end) for half-open intervals [start, end). If the new booking overlaps an existing one return false and store nothing. Otherwise store it and return true.

Pattern: Type E: TreeMap floor and ceiling.

Brute force
class CalBrute:
    def __init__(self):
        self.b = []

    def book(self, start, end):

                return False

        return True
static class CalBrute {
  private final List<int[]> b = new ArrayList<>();
  boolean book(int start, int end) {
    for (int[] x : b) if (start < x[1] && x[0] < end) return false;
    b.add(new int[]{start, end});
    return true;
  }
}
Optimal
import bisect

class CalOpt:
    def __init__(self):
        self.starts, self.ends = [], []        # sorted by start, same positions

    def book(self, start, end):
        i = bisect.bisect_left(self.starts, start)
        if i < len(self.starts) and self.starts[i] < end:   # next booking begins before we end
            return False
        if i > 0 and self.ends[i - 1] > start:              # previous booking ends after we start
            return False
        self.starts.insert(i, start)           # O(n) shift, fine here; a TreeMap avoids it
        self.ends.insert(i, end)
        return True
static class MyCalendar {
  private final TreeMap<Integer, Integer> map = new TreeMap<>();   // start -> end
  boolean book(int start, int end) {
    Map.Entry<Integer, Integer> lo = map.floorEntry(start);        // starts at or before us
    Integer hi = map.ceilingKey(start);                            // starts at or after us
    if (lo != null && lo.getValue() > start) return false;
    if (hi != null && hi < end) return false;
    map.put(start, end);
    return true;
  }
}

Complexity. Java TreeMap: O(log n) per booking. Python with bisect: O(log n) search but O(n) insert shifting. Intervals are half-open, so touching at an endpoint is allowed.

Verified. Python 30927 checks, Java 31277 checks, optimal agreed with brute force.

P5 Meeting Rooms II (LeetCode 253, Medium)

Given meeting intervals [start, end), return the minimum number of rooms needed so that no two overlapping meetings share a room. A meeting that ends at 10 and one that starts at 10 do not overlap.

Pattern: Types C + D: sort, then a min-heap of end times.

Brute force
def rooms_brute(intervals):
    best = 0
    for s, _ in intervals:                      # busiest moment is some meeting's start
        best = max(best, sum(1 for a, b in intervals if a <= s < b))
    return best
static int brute(int[][] iv) {
  int best = 0;
  for (int[] x : iv) {
    int c = 0;
    for (int[] y : iv) if (y[0] <= x[0] && x[0] < y[1]) c++;
    best = Math.max(best, c);
  }
  return best;
}
Optimal
import heapq

def rooms_opt(intervals):
    ends = []                                   # min-heap of end times of rooms in use
    for s, e in sorted(intervals):
        if ends and ends[0] <= s:
            heapq.heapreplace(ends, e)          # reuse the room that freed up first
        else:
            heapq.heappush(ends, e)             # need a new room
    return len(ends)
static int solve(int[][] iv) {
  int[][] s = iv.clone();
  Arrays.sort(s, (a, b) -> Integer.compare(a[0], b[0]));
  PriorityQueue<Integer> ends = new PriorityQueue<>();   // end times of rooms in use
  for (int[] m : s) {
    if (!ends.isEmpty() && ends.peek() <= m[0]) ends.poll();   // reuse the earliest-free room
    ends.offer(m[1]);
  }
  return ends.size();
}

Complexity. O(n log n): the sort, plus n heap operations of O(log n). The heap size is the number of rooms in use right now, and its final size is the answer.

Verified. Python 4000 checks, Java 4000 checks, optimal agreed with brute force.

P6 Find Median from Data Stream (LeetCode 295, Hard)

Design a structure that supports addNum(x) on a growing stream and findMedian() at any time. For an even count the median is the mean of the two middle values.

Pattern: Type D: two PriorityQueues, one of each direction.

Brute force
class MedianBrute:
    def __init__(self):
        self.a = []

    def addNum(self, x):
        self.a.append(x)

    def findMedian(self):
        s = sorted(self.a)                      # re-sort on every query
        m = len(s) // 2
        return float(s[m]) if len(s) % 2 else (s[m - 1] + s[m]) / 2
static class MedianBrute {
  private final List<Integer> a = new ArrayList<>();
  void addNum(int x) { a.add(x); }
  double findMedian() {
    List<Integer> s = new ArrayList<>(a);
    Collections.sort(s);
    int m = s.size() / 2;
    return s.size() % 2 == 1 ? s.get(m) : (s.get(m - 1) + s.get(m)) / 2.0;
  }
}
Optimal
import heapq

class MedianOpt:
    def __init__(self):
        self.lo = []        # max-heap of the lower half (stored negated)
        self.hi = []        # min-heap of the upper half

    def addNum(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))   # the lower half's max moves up
        if len(self.hi) > len(self.lo):                    # keep len(lo) >= len(hi)
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def findMedian(self):
        if len(self.lo) > len(self.hi):
            return float(-self.lo[0])
        return (-self.lo[0] + self.hi[0]) / 2
static class MedianFinder {
  private final PriorityQueue<Integer> lo = new PriorityQueue<>(Collections.reverseOrder()); // lower half
  private final PriorityQueue<Integer> hi = new PriorityQueue<>();                           // upper half
  void addNum(int x) {
    lo.offer(x);
    hi.offer(lo.poll());                       // the lower half's max moves up
    if (hi.size() > lo.size()) lo.offer(hi.poll());   // keep lo.size() >= hi.size()
  }
  double findMedian() {
    return lo.size() > hi.size() ? lo.peek() : (lo.peek() + hi.peek()) / 2.0;
  }
}

Complexity. addNum O(log n), findMedian O(1), O(n) space. Invariant: every element of lo ≤ every element of hi, and lo has the same size as hi or one more.

Verified. Python 31644 checks, Java 31122 checks, optimal agreed with brute force.
