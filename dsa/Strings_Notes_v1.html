Part 1First Principles

One-paragraph summary

A string is a sequence of characters, so it behaves like an array you cannot change. What makes string problems their own topic is the kind of question asked about that sequence: parse it (a number, a path, a format), compare or normalise it (palindromes, prefixes, "same up to a shift"), rebuild it (add two numbers written as text, wrap lines), or find a smaller string inside it. Nearly all of them are solved by one pass with a couple of cursors and a small piece of state, which turns the obvious "re-scan or re-copy for every position" O(n²) or O(n³) into O(n). The skill to learn is stating, in one sentence, what the characters you have already passed mean.

 A string is an array of characters you cannot assign into:

 index:   0   1   2   3   4   5   6   7   8
 char:    i   n   t   e   r   v   i   e   w          s[2:5] = "ter"   (a COPY of 3 characters)
          ^                               ^
          first                           last = s[len(s) - 1] = s[-1] in Python

 s[0] = "x"      Python: TypeError.   Java: no such syntax. To edit, copy to a list / char[] / StringBuilder.
 s + "!"         creates a NEW string of length n + 1 (copies all n characters).

 The four jobs, with the problems that do them:
   parse     "  -42abc"  -> -42            String to Integer, Roman to Integer, Valid Word Abbreviation
   compare   "abcba"     is it a palindrome? Longest Common Prefix, Group Shifted Strings
   build     "99" + "1"  -> "100"          Add Strings, Multiply Strings, Zigzag, Text Justification
   search    "sad" in "sadbutsad"          Find the Index of the First Occurrence (strStr), KMP

Why it exists and what problem it solves

  • Text is the most common data you meet. Logs, URLs, file paths, versions, numbers too big for an integer, user input. Every real system parses and rebuilds strings all day.
  • Strings have pitfalls that arrays do not. They are immutable in Python and Java, so "just edit it" is a copy; concatenating in a loop can be quadratic; characters are not the same as numbers; and a character is not always one position (Unicode). Interviewers use string problems to see whether you know these costs.
  • Better than the naive scan. Checking every substring of a string is O(n³) for palindromes; growing outwards from each centre is O(n²) with O(1) space. Restarting a substring search at every position is O(n·m); KMP is O(n + m).
  • Better than clever tricks. Built-ins (int(a) + int(b), split, regex) answer many of these in one line. Interviews often forbid them, because the point is whether you can do the work and handle the edge cases yourself.

The core invariant

Write this down before every loop

At every moment I can say, in one sentence, what the characters I have already passed have turned into. "result holds the number made by s[i..j)"; "best holds the longest palindrome among centres 0..c"; "write marks the end of the compressed output, and write <= read"; "k characters of the needle currently match". If I cannot say it, the loop is a guess. Each pattern in Part 4 has its own version of this sentence, and every bug in Part 10 is a case where the sentence stopped being true (a carry dropped, a bound off by one, a leading zero let through).

Common interview tricks

  • Frequency array for lowercase letters: count[ord(c) - ord("a")] += 1 (Python), count[c - 'a']++ (Java). Ask whether the alphabet is lowercase-only; if not, use a dict / HashMap.
  • Collect, then join: build a list of pieces (or a StringBuilder) and join once. Never grow a string with += in a loop in Java.
  • Convert to a mutable array when the problem says "in place": char[] in Java; in Python the input is already a list for those problems (String Compression, Reverse String).
  • Digits to a value: ord(c) - ord("0") / c - '0'. Never trust isdigit() alone if the input could be non-ASCII.
  • Two answers per index: odd and even centres for palindromes; "include the carry" for the last digit; "before and after the sign" for parsers.
  • Sentinels: returning "", 0 or -1 for "no answer" is part of the problem statement; ask which one.

Part 3Complexity

Two letters cover almost everything here: n is the length of the string, and L is the length of one string when you have a list of N strings (so the total size is N·L). Costs that look free (a slice, a concatenation, a hash-map key) are not, and that is where most string complexity mistakes come from.

Why these are what they are

  • A slice is a copy. s[a:b] costs O(b - a). s = s[1:] inside while s: therefore costs n + (n-1) + ... = O(n²). Measured on this machine: 100,000 characters took 0.953 s with slicing and 0.002 s with an index loop (Appendix B). Move an index instead of cutting the string.
  • Comparing strings costs their length. s == t stops at the first difference, but a worst case is O(n). A list of N strings of length L sorted with comparisons costs O(N log N · L), not O(N log N).
  • A string used as a dictionary key costs O(L) to hash (and O(L) to compare when buckets collide). "O(1) lookup" for a string key really means O(L). CPython and Java both cache the hash of a string after the first computation, so asking again is cheap (measured below: 0.768 ms then 0.0006 ms in Python).
  • Immutable means copy. Every "edit" of a Python or Java string copies it. One edit is fine; an edit inside a loop is quadratic. Use a list or StringBuilder.

Not everything is amortised

Expanding around centres is truly O(n²): on `"aaaa...a"` every centre expands almost to the ends, and no work is shared between centres. Do not argue it down to O(n) in an interview; say O(n²) time and O(1) space, mention Manacher's O(n) as an option, and move on. The brute-force substring search is also truly O(n·m), which is exactly why KMP exists.

Type A: Two cursors over two strings

Type AEasyone cursor each, different strides

1. What it is. Two indexes, one per string, advancing by different amounts (1 for a letter, a whole number for a digit run). Also covers merging and comparing two sequences.

2. What problem it solves. Decides whether two strings match under a compression or encoding without ever expanding it, and merges or compares two sequences in O(n + m).

3. How to recognise it. "Valid abbreviation", "merge alternately", "compare version numbers", "is s a subsequence of t". Two inputs, and one of them is a compressed form of the other or must be consumed in step.

4. Intuition. Never build the expanded form. A skip of num letters is just i += num: the alignment is the same, the cost is O(1) instead of O(num).

5. Generic algorithm
  1. i = j = 0.
  2. While both cursors are in range: if abbr[j] is a digit, reject a leading zero, parse the whole number, i += num. Otherwise the letters must match; move both by 1.
  3. On exit, i == len(word) and j == len(abbr): both must have ended together.

6. State, validity condition, step. State: i (word), j (abbr). Invariant: word[:i] is exactly what abbr[:j] describes. Step: letter -> compare and advance both; digits -> parse the run, jump i. Valid at the end: both cursors at the end.

                return False                   # no leading zeros, and no zero-length skip
            num = 0
            while j < len(abbr) and "0" <= abbr[j] <= "9":
                num = num * 10 + int(abbr[j])
                j += 1
            i += num                           # skip num letters of word
        else:
            if word[i] != abbr[j]:
                return False
            i += 1
            j += 1
    return i == len(word) and j == len(abbr)   # both must end together
static boolean validAbbr(String word, String abbr) {
    int i = 0, j = 0;                                    // i walks word, j walks abbr
    while (i < word.length() && j < abbr.length()) {
        char c = abbr.charAt(j);
        if ((c >= '0' && c <= '9')) {
            if (c == '0') return false;                  // no leading zeros
            long num = 0;                                // long: ten digits do not fit in an int
            while (j < abbr.length() && (abbr.charAt(j) >= '0' && abbr.charAt(j) <= '9')) {
                num = num * 10 + (abbr.charAt(j) - '0');
                j++;
            }
            i += num;                                    // compound assignment narrows back to int
        } else {
            if (word.charAt(i) != c) return false;
            i++;
            j++;
        }
    }
    return i == word.length() && j == abbr.length();
}

Type B: Expand around a centre

Type BMediumodd and even centres

1. What it is. Treat every position (and every gap between positions) as a possible centre of a palindrome and grow outwards while the two ends match.

2. What problem it solves. Finds the longest palindromic substring, or counts all of them, in O(n²) time and O(1) space with no table.

3. How to recognise it. "Palindromic substring", "longest palindrome", "count palindromes", n at most about 1000 to 5000.

4. Intuition. A palindrome is its centre plus a smaller palindrome plus two equal ends. Growing outwards re-uses what the previous step proved, so no substring is re-compared from scratch.

5. Generic algorithm
  1. For each centre c in 0..n-1, try two starting pairs: (c, c) (odd length) and (c, c + 1) (even length).
  2. While l >= 0, r < n and s[l] == s[r]: l -= 1, r += 1.
  3. The loop stops one step too far, so the palindrome is s[l+1 .. r-1]; record it if it is longer than the best.

6. State, validity condition, step. State: l, r, and the best bounds. Invariant: s[l+1 .. r-1] is a palindrome centred at c. Step: widen by one on both sides if the new ends match. Valid: after the loop, the palindrome is the span strictly inside l and r.

7. Template. The verified code of Problem 2 (Longest Palindromic Substring); practice: Palindromic Substrings (run against a brute force, Appendix B):

def longest_palindrome(s):
    best_l, best_r = 0, 0                       # inclusive bounds of the best palindrome so far
    for c in range(len(s)):
        for l, r in ((c, c), (c, c + 1)):       # odd centre, then even centre
            while l >= 0 and r < len(s) and s[l] == s[r]:
                l -= 1
                r += 1
            # loop stopped one step too far: palindrome is s[l+1 .. r-1]
            if (r - 1) - (l + 1) > best_r - best_l:
                best_l, best_r = l + 1, r - 1
    return s[best_l:best_r + 1]
static String longestPalindrome(String s) {
    int bestL = 0, bestR = 0;                            // inclusive bounds of the best palindrome so far
    for (int c = 0; c < s.length(); c++) {
        for (int parity = 0; parity < 2; parity++) {    // 0 = odd centre, 1 = even centre
            int l = c, r = c + parity;
            while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
                l--;
                r++;
            }
            if ((r - 1) - (l + 1) > bestR - bestL) {    // palindrome is s[l+1 .. r-1]
                bestL = l + 1;
                bestR = r - 1;
            }
        }
    }
    return s.substring(bestL, bestR + 1);
}

Type C: Parse once with a little state

Type CMediumphases in order, clamp early

1. What it is. Read the string left to right once, with one small loop per phase named in the statement (spaces, sign, digits...), or one rule that looks one character ahead.

2. What problem it solves. Turns a verbal specification (atoi, Roman numerals, a version, a path) into code with no re-reading and no regex.

3. How to recognise it. The statement is a list of steps ("skip whitespace, then an optional sign, then digits, then stop"), or it defines a conversion table with a lookahead rule. Words like "ignore", "until the first non-digit", "return 0 if".

4. Intuition. A parser is a tiny state machine. Writing the phases in the statement's order, as sequential loops, is already the algorithm. Overflow is a state problem too: test before you multiply.

5. Generic algorithm
  1. i = 0; skip leading spaces.
  2. Read one optional sign.
  3. While the character is a digit: if result * 10 + d would pass the limit, clamp and return; else result = result * 10 + d.
  4. Return sign * result. (If there were no digits, result is still 0.)

6. State, validity condition, step. State: i, sign, result. Invariant: result is the value of the digits read so far, and result is within range. Step: one digit. Valid: stop at the first non-digit or end of string.

7. Template. The verified code of Problems 3 (String to Integer) and 4 (Roman to Integer); practice: Compare Version Numbers, Encode and Decode Strings (run against a brute force, Appendix B):

def my_atoi(s):
    INT_MAX, INT_MIN = 2**31 - 1, -2**31
    i, n = 0, len(s)
    while i < n and s[i] == " ":                # 1. skip leading spaces
        i += 1
    sign = 1
    if i < n and s[i] in "+-":                  # 2. one optional sign
        sign = -1 if s[i] == "-" else 1
        i += 1
    result = 0
    while i < n and "0" <= s[i] <= "9":         # 3. digits, stop at the first non-digit
        d = ord(s[i]) - ord("0")
        if result > (INT_MAX - d) // 10:        # 4. result * 10 + d would pass INT_MAX: clamp now
            return INT_MAX if sign == 1 else INT_MIN
        result = result * 10 + d
        i += 1
    return sign * result
static int myAtoi(String s) {
    int i = 0, n = s.length();
    while (i < n && s.charAt(i) == ' ') i++;             // 1. skip leading spaces
    int sign = 1;
    if (i < n && (s.charAt(i) == '+' || s.charAt(i) == '-')) {   // 2. one optional sign
        sign = s.charAt(i) == '-' ? -1 : 1;
        i++;
    }
    int result = 0;                                      // stays in int: we clamp BEFORE it can overflow
    while (i < n && s.charAt(i) >= '0' && s.charAt(i) <= '9') {  // 3. digits
        int d = s.charAt(i) - '0';
        if (result > (Integer.MAX_VALUE - d) / 10)       // 4. result * 10 + d would pass MAX_VALUE
            return sign == 1 ? Integer.MAX_VALUE : Integer.MIN_VALUE;
        result = result * 10 + d;
        i++;
    }
    return sign * result;
}

Type D: Count or normalise, then group or look up

Type DEasyfrequency table, signature key

1. What it is. Pass 1 builds a table (character counts, or a canonical key per string). Pass 2 uses the table to answer in the original order, or to group.

2. What problem it solves. Replaces repeated scanning or comparison sorting by one counting pass, and replaces "is x equivalent to y?" by "do x and y have the same key?".

3. How to recognise it. "First/only/appears once", "same letters", "equivalent up to...", "group the strings that...", "sort by a given order" over a small alphabet.

4. Intuition. If two strings are equivalent, there is something they share. Compute it once per string and equality of keys does the work of all the pairwise comparisons.

5. Generic algorithm
  1. Choose the table: count[26] for lowercase letters, a dictionary otherwise, or a key (tuple of differences, sorted letters).
  2. Pass 1: fill the table (or compute each string's key and append the string to groups[key]).
  3. Pass 2: walk the original order and read the table.

6. State, validity condition, step. State: the table. Invariant: after pass 1 the table describes the whole input. Step (pass 2): one lookup per element. Valid: keys really are equal exactly when the strings are equivalent (the mod 26 in Group Shifted is what makes this true).

7. Template. The verified code of Problems 5 (First Unique), 6 (Custom Sort), 7 (Group Shifted) (run against a brute force, Appendix B):

from collections import Counter

def first_uniq(s):
    count = Counter(s)                          # pass 1: how many times each letter occurs
    for i, ch in enumerate(s):                  # pass 2: first index whose letter occurs once
        if count[ch] == 1:
            return i
    return -1
static int firstUniq(String s) {
    int[] count = new int[26];                           // lowercase letters only
    for (char c : s.toCharArray()) count[c - 'a']++;
    for (int i = 0; i < s.length(); i++)
        if (count[s.charAt(i) - 'a'] == 1) return i;
    return -1;
}

8. Time. O(n) (O(N·L) for N keyed strings).

9. Space. O(k) for k distinct characters (O(1) for 26 letters); O(N·L) for the groups.

Type E: Build the answer by position or digit

Type EMediumcarry, position formula, bounce

1. What it is. Produce the output piece by piece: digit by digit from the right with a carry, into a slot given by a formula (i + j + 1), or into a row picked by a bouncing counter.

2. What problem it solves. Does arithmetic or layout on text too long for a number type, or described by a picture, without building the picture.

3. How to recognise it. "Add/multiply two numbers as strings", "without converting to integer", "zigzag", "format/justify", "convert to a different layout".

4. Intuition. Do on text what you do on paper: the column rule (digit sum, remainder, carry), or find the single formula that says where each input piece goes in the output.

5. Generic algorithm
  1. Decide the direction (right to left for arithmetic) and the output container (list of digits, array of rows).
  2. Loop while there is any input left or a carry.
  3. Compute the piece and the new carry; write the piece.
  4. Reverse or strip at the end (leading zeros, reversed digits).

6. State, validity condition, step. State: cursors, carry, output list. Invariant: the output so far is the correct answer for the columns already processed, and carry is what must be added to the next column. Valid: nothing left in either input and carry == 0.

7. Template. The verified code of Problems 8 (Add Strings), 9 (Multiply Strings), 10 (Zigzag); practice: Add Binary, Text Justification (run against a brute force, Appendix B):

def add_strings(a, b):
    i, j, carry = len(a) - 1, len(b) - 1, 0
    out = []
    while i >= 0 or j >= 0 or carry:            # carry keeps the loop alive for a final extra digit
        total = carry
        if i >= 0:
            total += ord(a[i]) - ord("0")
            i -= 1
        if j >= 0:
            total += ord(b[j]) - ord("0")
            j -= 1
        out.append(str(total % 10))
        carry = total // 10
    return "".join(reversed(out))               # digits were produced least-significant first
static String addStrings(String a, String b) {
    int i = a.length() - 1, j = b.length() - 1, carry = 0;
    StringBuilder out = new StringBuilder();
    while (i >= 0 || j >= 0 || carry != 0) {
        int total = carry;
        if (i >= 0) total += a.charAt(i--) - '0';
        if (j >= 0) total += b.charAt(j--) - '0';
        out.append(total % 10);
        carry = total / 10;
    }
    return out.reverse().toString();
}

9. Space. O(output length).

Type F: Rewrite in place with read/write cursors

Type FMediumwrite <= read, or reverse twice

1. What it is. A read cursor scans the input; a write cursor marks where the next output character goes. For reordering, reverse the whole thing, then each piece.

2. What problem it solves. Rewrites a mutable array (or builds the answer from a string) in O(n) with O(1) extra space.

3. How to recognise it. "In place", "O(1) extra space", "return the new length", "reverse the words", "compress".

4. Intuition. Output is never longer than the part of the input already read, so writing cannot overwrite anything unread (write <= read). Reversing everything and then each word puts the words in reverse order with each word the right way round.

5. Generic algorithm
  1. Start read = write = 0.
  2. Measure the next piece (a run, a word) with read.
  3. Write its compressed or reordered form at write and advance write.
  4. Return write (the new length), or truncate to it.

6. State, validity condition, step. State: read, write. Invariant: chars[:write] is the finished output for chars[:read], and write <= read. Valid: read reached the end.

7. Template. The verified code of Problems 11 (Reverse Words) and 12 (String Compression) (run against a brute force, Appendix B):

def compress(chars):
    write = read = 0
    while read < len(chars):
        ch = chars[read]
        start = read
        while read < len(chars) and chars[read] == ch:   # measure the run
            read += 1
        chars[write] = ch                       # write the character once
        write += 1
        run = read - start
        if run > 1:
            for d in str(run):                  # then the count, one digit per slot
                chars[write] = d
                write += 1
    return write                                # write <= read always, so we never overwrite unread input
static int compress(char[] chars) {
    int write = 0, read = 0;
    while (read < chars.length) {
        char ch = chars[read];
        int start = read;
        while (read < chars.length && chars[read] == ch) read++;     // measure the run
        chars[write++] = ch;
        int run = read - start;
        if (run > 1)
            for (char d : Integer.toString(run).toCharArray()) chars[write++] = d;
    }
    return write;
}

Type G: Compare prefixes, search for a substring

Type GEasyvertical scan, KMP border

1. What it is. Compare many strings column by column and stop at the first mismatch; or search one string inside another while remembering how much of the needle already matches.

2. What problem it solves. Finds common prefixes in O(total characters) and substring positions in O(n + m) instead of O(n·m).

3. How to recognise it. "Common prefix", "starts with", "first occurrence", "find the needle", "repeated pattern", "shortest palindrome by prefix".

4. Intuition. A prefix grows one character at a time, so you only need the first disagreement. In substring search, when a mismatch happens the text already matched is known; its longest border says where to resume without re-reading the haystack.

5. Generic algorithm
  1. Prefix: for column i of the first word, check every other word has a character at i and it is equal; at the first failure return the prefix before i.
  2. KMP step 1: lps[i] = longest proper border of needle[:i+1].
  3. KMP step 2: scan the haystack; k = matched length; on mismatch k = lps[k-1]; on match k += 1; k == m is a hit.

6. State, validity condition, step. State: column i (prefix) or k, lps (KMP). Invariant (KMP): needle[:k] equals the last k characters of the haystack read so far, and k is the longest such value. Valid: k == m at index i means the match starts at i - m + 1.

7. Template. The verified code of Problems 13 (Longest Common Prefix) and 14 (strStr with KMP) (run against a brute force, Appendix B):

def str_str(haystack, needle):
    # KMP. lps[k] = length of the longest proper prefix of needle[:k+1] that is also its suffix
    m = len(needle)
    lps = [0] * m
    k = 0
    for i in range(1, m):
        while k and needle[i] != needle[k]:
            k = lps[k - 1]                      # fall back to a shorter border
        if needle[i] == needle[k]:
            k += 1
        lps[i] = k
    k = 0                                       # k = how many characters of needle currently match
    for i, ch in enumerate(haystack):           # i never moves backwards
        while k and ch != needle[k]:
            k = lps[k - 1]
        if ch == needle[k]:
            k += 1
        if k == m:
            return i - m + 1
    return -1
static int strStr(String haystack, String needle) {
    int m = needle.length();
    int[] lps = new int[m];
    for (int i = 1, k = 0; i < m; i++) {
        while (k > 0 && needle.charAt(i) != needle.charAt(k)) k = lps[k - 1];
        if (needle.charAt(i) == needle.charAt(k)) k++;
        lps[i] = k;
    }
    for (int i = 0, k = 0; i < haystack.length(); i++) {
        while (k > 0 && haystack.charAt(i) != needle.charAt(k)) k = lps[k - 1];
        if (haystack.charAt(i) == needle.charAt(k)) k++;
        if (k == m) return i - m + 1;
    }
    return -1;
}

9. Space. Prefix: O(1). KMP: O(m) for lps.

Valid Word Abbreviation

Type AEasyLeetCode 408
ShowHide

Where it is reported. Frequently asked: listed by 3 of the 6 companies read (company-tag scores: Google 26.3, Meta 96.8, Amazon 21.9). LeetCode Premium problem.

Problem. A word (lowercase letters) and an abbreviation abbr (lowercase letters and digit runs, where a digit run is a number saying "skip this many letters"). Return true if abbr is a valid abbreviation of word. A number may not have a leading zero and may not be zero ("01" and "0" are invalid). Each digit run is one number: replaced pieces cannot touch, so "s55n" means skipping 55 letters, not 5 then 5.

Example. word = "internationalization", abbr = "i12iz4n" -> true. word = "apple", abbr = "a2e" -> false (skips "pp" then expects "e" but the word has "l" before it).

Recognise before coding. Two strings that must stay in step, one of them compressed. Each cursor has its own stride: a letter moves both by 1, a number moves word by that many and abbr by its digit count.

Skill it teaches. Type A: two cursors, a digit-run parser, and an end condition that checks both cursors reached the end.

1Brute force

Expand the abbreviation into a pattern with one ? per skipped letter, then compare. Correct, but the pattern can be as long as the numbers say, not as long as the input: an abbreviation like "1000000000" asks for a billion ?. The Java version has to guard against that.

def valid_abbr_brute(word, abbr):
    # expand every number into that many wildcards, then compare character by character
    pattern, j = [], 0
    while j < len(abbr):
        if "0" <= abbr[j] <= "9":
            if abbr[j] == '0':
                return False                   # leading zero (also rejects a lone "0")
            k = j
            while k < len(abbr) and "0" <= abbr[k] <= "9":
                k += 1
            pattern.extend('?' * int(abbr[j:k]))
            j = k
        else:
            pattern.append(abbr[j])
            j += 1
    if len(pattern) != len(word):
        return False
    return all(p == '?' or p == c for p, c in zip(pattern, word))
static boolean validAbbrBrute(String word, String abbr) {
    StringBuilder pattern = new StringBuilder();
    int j = 0;
    while (j < abbr.length()) {
        char c = abbr.charAt(j);
        if ((c >= '0' && c <= '9')) {
            if (c == '0') return false;                  // leading zero
            int k = j;
            long num = 0;
            while (k < abbr.length() && (abbr.charAt(k) >= '0' && abbr.charAt(k) <= '9')) {
                num = num * 10 + (abbr.charAt(k) - '0');
                k++;
            }
            if (num > word.length()) return false;       // would not fit anyway; avoids a huge pattern
            for (long t = 0; t < num; t++) pattern.append('?');
            j = k;
        } else {
            pattern.append(c);
            j++;
        }
    }
    if (pattern.length() != word.length()) return false;
    for (int i = 0; i < word.length(); i++)
        if (pattern.charAt(i) != '?' && pattern.charAt(i) != word.charAt(i)) return false;
    return true;
}

Cost: O(n + sum of the numbers) time and space.

2Observation

You never need the expanded pattern. Moving i forward by the number gives exactly the same alignment, in O(1) per number instead of O(number).

def valid_abbr(word, abbr):

        if "0" <= abbr[j] <= "9":
            if abbr[j] == '0':
                return False                   # no leading zeros, and no zero-length skip
            num = 0
            while j < len(abbr) and "0" <= abbr[j] <= "9":
                num = num * 10 + int(abbr[j])
                j += 1
            i += num                           # skip num letters of word
        else:
            if word[i] != abbr[j]:
                return False
            i += 1
            j += 1
    return i == len(word) and j == len(abbr)   # both must end together
static boolean validAbbr(String word, String abbr) {
    int i = 0, j = 0;                                    // i walks word, j walks abbr
    while (i < word.length() && j < abbr.length()) {
        char c = abbr.charAt(j);
        if ((c >= '0' && c <= '9')) {
            if (c == '0') return false;                  // no leading zeros
            long num = 0;                                // long: ten digits do not fit in an int
            while (j < abbr.length() && (abbr.charAt(j) >= '0' && abbr.charAt(j) <= '9')) {
                num = num * 10 + (abbr.charAt(j) - '0');
                j++;
            }
            i += num;                                    // compound assignment narrows back to int
        } else {
            if (word.charAt(i) != c) return false;
            i++;
            j++;
        }

Say aloud. "Two cursors, i on word and j on abbr. A letter must match and moves both. A digit run: reject a leading zero, parse the whole number, jump i. At the end both cursors must be exactly at the end, so a number that overshoots the word fails."

Longest Palindromic Substring

Type BMediumLeetCode 5Look-alike with a twist
ShowHide

Where it is reported. Frequently asked: listed by 6 of the 6 companies read (company-tag scores: Google 69.5, Meta 67.1, Amazon 78.5, Microsoft 80.5, Apple 51.0, Uber 37.9). Also on the Grind 75 Strings section and in the Blind 75 String section (community copy); deferred here from the Two Pointers notes.

Problem. Given a string s, return its longest palindromic substring (if several have the same length, the leftmost).

Example. "babad" -> "bab" ("aba" is also valid; this page returns the leftmost). "cbbd" -> "bb".

Recognise before coding. "Longest palindromic substring", n up to 1000. A palindrome is mirror-symmetric around a centre, so the centre is what you enumerate. The DP table version works but needs O(n²) memory.

Skill it teaches. Type B: enumerate centres (odd and even), grow outwards while the mirror characters match. This also teaches why the loop "stops one step too far".

1Brute force

Check every substring (n² of them) with an O(n) reverse-and-compare. The work is repeated: "abcba" is checked as a whole, then "bcb", then "c", re-doing the comparisons that are already known to be true inside.

def longest_palindrome_brute(s):
    best = ""
    for i in range(len(s)):
        for j in range(i, len(s)):
            t = s[i:j + 1]
            if t == t[::-1] and len(t) > len(best):    # strict >: keep the leftmost longest
                best = t
    return best
static String longestPalindromeBrute(String s) {
    String best = "";
    for (int i = 0; i < s.length(); i++)
        for (int j = i; j < s.length(); j++) {
            String t = s.substring(i, j + 1);
            if (t.length() > best.length() && new StringBuilder(t).reverse().toString().equals(t)) best = t;
        }
    return best;
}

Cost: O(n³) time, O(n) space for the copies.

2Observation

A palindrome contains a smaller palindrome around the same centre. So start at each of the 2n - 1 centres and grow outwards: each growth step re-uses everything the previous step proved.

3Optimal solution
def longest_palindrome(s):
    best_l, best_r = 0, 0                       # inclusive bounds of the best palindrome so far
    for c in range(len(s)):
        for l, r in ((c, c), (c, c + 1)):       # odd centre, then even centre
            while l >= 0 and r < len(s) and s[l] == s[r]:
                l -= 1
                r += 1
            # loop stopped one step too far: palindrome is s[l+1 .. r-1]
            if (r - 1) - (l + 1) > best_r - best_l:
                best_l, best_r = l + 1, r - 1
    return s[best_l:best_r + 1]
static String longestPalindrome(String s) {
    int bestL = 0, bestR = 0;                            // inclusive bounds of the best palindrome so far
    for (int c = 0; c < s.length(); c++) {
        for (int parity = 0; parity < 2; parity++) {    // 0 = odd centre, 1 = even centre
            int l = c, r = c + parity;
            while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
                l--;
                r++;
            }
            if ((r - 1) - (l + 1) > bestR - bestL) {    // palindrome is s[l+1 .. r-1]
                bestL = l + 1;
                bestR = r - 1;
            }
        }
    }
    return s.substring(bestL, bestR + 1);
}

Cost: O(n²) time, O(1) space. Manacher's algorithm is O(n) but is rarely expected..

Say aloud. "There are 2n - 1 centres: n single characters for odd lengths and n - 1 gaps for even lengths. From each centre I expand while the two ends match, then record the longest. Worst case, a string of one repeated letter, is O(n²), which is fine for n = 1000."

String to Integer (atoi)

Type CMediumLeetCode 8
ShowHide

Where it is reported. Frequently asked: listed by 6 of the 6 companies read (company-tag scores: Google 44.3, Meta 57.3, Amazon 53.8, Microsoft 53.3, Apple 43.0, Uber 49.9). Also on the Grind 75 Strings section.

Problem. Implement myAtoi(s): skip leading spaces, read an optional + or -, read digits until the first non-digit, and return the number clamped to the signed 32-bit range [-2^31, 2^31 - 1]. If no digits are read, return 0.

Example. " -42" -> -42. "4193 with words" -> 4193. "words and 987" -> 0. "-91283472332" -> -2147483648.

Recognise before coding. A formal list of steps in the statement: that is a state machine written in prose. Each step is a short loop, in order, and the order is the algorithm.

Skill it teaches. Type C: scan once, one loop per phase, and clamp before overflowing (the check goes before result * 10 + d, not after).

1Reference solution (brute force)

A regex finds the number in one line. It is a good reference to test against, and not slower, but interviewers often ban library parsing and the question is really testing whether you can write the steps and the overflow check yourself.

import re

def my_atoi_regex(s):
    m = re.match(r" *([+-]?)([0-9]+)", s)       # an independent reference: let a regex find the number
    if not m:
        return 0
    v = int(m.group(2)) * (-1 if m.group(1) == "-" else 1)
    return max(-2**31, min(2**31 - 1, v))
static int myAtoiRegex(String s) {
    java.util.regex.Matcher m = java.util.regex.Pattern.compile("^ *([+-]?)([0-9]+)").matcher(s);
    if (!m.find()) return 0;
    java.math.BigInteger v = new java.math.BigInteger(m.group(2));
    if (m.group(1).equals("-")) v = v.negate();
    if (v.compareTo(java.math.BigInteger.valueOf(Integer.MAX_VALUE)) > 0) return Integer.MAX_VALUE;
    if (v.compareTo(java.math.BigInteger.valueOf(Integer.MIN_VALUE)) < 0) return Integer.MIN_VALUE;
    return v.intValue();
}

Cost: O(n) time, O(1) space.

2Observation

Four phases in a fixed order: spaces, sign, digits, clamp. Overflow must be detected before it happens: in Java the int silently wraps, so test result > (MAX - d) / 10 first.

3Optimal solution
def my_atoi(s):
    INT_MAX, INT_MIN = 2**31 - 1, -2**31
    i, n = 0, len(s)
    while i < n and s[i] == " ":                # 1. skip leading spaces
        i += 1
    sign = 1
    if i < n and s[i] in "+-":                  # 2. one optional sign
        sign = -1 if s[i] == "-" else 1
        i += 1
    result = 0
    while i < n and "0" <= s[i] <= "9":         # 3. digits, stop at the first non-digit
        d = ord(s[i]) - ord("0")
        if result > (INT_MAX - d) // 10:        # 4. result * 10 + d would pass INT_MAX: clamp now
            return INT_MAX if sign == 1 else INT_MIN
        result = result * 10 + d
        i += 1
    return sign * result
static int myAtoi(String s) {
    int i = 0, n = s.length();
    while (i < n && s.charAt(i) == ' ') i++;             // 1. skip leading spaces
    int sign = 1;
    if (i < n && (s.charAt(i) == '+' || s.charAt(i) == '-')) {   // 2. one optional sign
        sign = s.charAt(i) == '-' ? -1 : 1;
        i++;
    }
    int result = 0;                                      // stays in int: we clamp BEFORE it can overflow
    while (i < n && s.charAt(i) >= '0' && s.charAt(i) <= '9') {  // 3. digits
        int d = s.charAt(i) - '0';
        if (result > (Integer.MAX_VALUE - d) / 10)       // 4. result * 10 + d would pass MAX_VALUE
            return sign == 1 ? Integer.MAX_VALUE : Integer.MIN_VALUE;
        result = result * 10 + d;
        i++;
    }
    return sign * result;
}

Cost: O(n) time, O(1) space.

Say aloud. "I'll write it as four small loops in the order the statement gives. For overflow I compare result against (INT_MAX - d) / 10 before multiplying, so I never need a wider type. For a negative sign I return INT_MIN, because the same check also catches 2147483648."

Rewrite each subtractive pair as repeated letters (IV -> IIII) and add everything. Correct, but six special cases to remember and a second copy of the string.

def roman_to_int_brute(s):

    for pair, rep in (("IV", "IIII"), ("IX", "VIIII"), ("XL", "XXXX"),

        s = s.replace(pair, rep)
    val = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}

def roman_to_int(s):
    val = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
    total = 0
    for i, ch in enumerate(s):
        if i + 1 < len(s) and val[ch] < val[s[i + 1]]:
            total -= val[ch]                    # smaller symbol before a bigger one is subtracted
        else:
            total += val[ch]
    return total
static int romanToInt(String s) {
    java.util.Map<Character, Integer> val = java.util.Map.of(
        'I', 1, 'V', 5, 'X', 10, 'L', 50, 'C', 100, 'D', 500, 'M', 1000);
    int total = 0;
    for (int i = 0; i < s.length(); i++) {
        int cur = val.get(s.charAt(i));
        if (i + 1 < s.length() && cur < val.get(s.charAt(i + 1))) total -= cur;
        else total += cur;
    }
    return total;
}

def first_uniq_brute(s):

from collections import Counter

def first_uniq(s):
    count = Counter(s)                          # pass 1: how many times each letter occurs
    for i, ch in enumerate(s):                  # pass 2: first index whose letter occurs once
        if count[ch] == 1:
            return i
    return -1
static int firstUniq(String s) {
    int[] count = new int[26];                           // lowercase letters only
    for (char c : s.toCharArray()) count[c - 'a']++;
    for (int i = 0; i < s.length(); i++)
        if (count[s.charAt(i) - 'a'] == 1) return i;
    return -1;
}

Cost: O(n) time, O(1) space for a fixed alphabet (O(k) in general for k distinct characters).

Problem. Two strings are in the same shift group if one can be turned into the other by shifting every letter by the same amount (wrapping z -> a). Group a list of strings into shift groups.

Example. ["abc","bcd","acef","xyz","az","ba","a","z"] -> groups ["abc","bcd","xyz"], ["acef"], ["az","ba"], ["a","z"] (group order is free).

Recognise before coding. "Same up to a transformation" is a canonical form problem: find a key that is equal for every member of a group. Same family as Group Anagrams, with a different key.

Skill it teaches. Type D: normalise each string to a signature (each letter's distance from the first letter, mod 26), then group by signature in a hash map.

1Brute force

Compare each string with a representative of each existing group, trying all 26 rotations. The same comparison is repeated for every pair.

def group_shifted_brute(strings):
    groups = []                                 # each group is a list; groups[i][0] is its representative
    for s in strings:
        for g in groups:
            rep = g[0]
            if len(rep) == len(s) and any(
                    "".join(chr((ord(c) - 97 + k) % 26 + 97) for c in rep) == s
                    for k in range(26)):        # try all 26 rotations of the representative
                g.append(s)
                break
        else:
            groups.append([s])
    return groups
static java.util.List<java.util.List<String>> groupShiftedBrute(String[] strings) {

        boolean placed = false;
        for (java.util.List<String> g : groups) {
            String rep = g.get(0);
            if (rep.length() != s.length()) continue;
            for (int k = 0; k < 26 && !placed; k++) {

                for (char c : rep.toCharArray()) sb.append((char) ('a' + (c - 'a' + k) % 26));
                if (sb.toString().equals(s)) { g.add(s); placed = true; }

            if (placed) break;
        }
        if (!placed) groups.add(new java.util.ArrayList<>(java.util.List.of(s)));
    }
    return groups;
}

Skill it teaches. Type E: build the output one position at a time from the least significant end, loop while either string has digits or a carry remains.

1Brute force

int(a) + int(b) is a one-liner in Python (and BigInteger in Java), but the problem forbids it, and in Python 3.11+ converting a string with more than 4300 digits raises ValueError by default.

}

Cost: Not allowed by the problem; conversion of a long string is itself super-linear in CPython.

2Observation

Column addition needs only the current digit of each string and one carry (0 or 1). The loop condition must include the carry, or the final extra digit is lost.

3Optimal solution
def add_strings(a, b):
    i, j, carry = len(a) - 1, len(b) - 1, 0
    out = []
    while i >= 0 or j >= 0 or carry:            # carry keeps the loop alive for a final extra digit
        total = carry
        if i >= 0:
            total += ord(a[i]) - ord("0")
            i -= 1
        if j >= 0:
            total += ord(b[j]) - ord("0")
            j -= 1
        out.append(str(total % 10))
        carry = total // 10
    return "".join(reversed(out))               # digits were produced least-significant first
static String addStrings(String a, String b) {
    int i = a.length() - 1, j = b.length() - 1, carry = 0;
    StringBuilder out = new StringBuilder();
    while (i >= 0 || j >= 0 || carry != 0) {
        int total = carry;
        if (i >= 0) total += a.charAt(i--) - '0';
        if (j >= 0) total += b.charAt(j--) - '0';
        out.append(total % 10);
        carry = total / 10;
    }
    return out.reverse().toString();
}

Cost: O(max(n, m)) time, O(max(n, m)) space for the output.

Say aloud. "Two cursors from the right, one carry. Each column: sum the two digits and the carry, write sum % 10, carry sum / 10. The loop runs while either string has digits left or the carry is non-zero, so 99 + 1 produces its leading 1. I build the digits in reverse and reverse once at the end."

A product of an n-digit and an m-digit number has at most n + m digits. Keep an array of that size, add each digit-by-digit product into its column, and push the carry one column left.

def multiply(a, b):
    if a == "0" or b == "0":
        return "0"
    res = [0] * (len(a) + len(b))               # a product has at most len(a) + len(b) digits
    for i in range(len(a) - 1, -1, -1):
        for j in range(len(b) - 1, -1, -1):
            prod = (ord(a[i]) - 48) * (ord(b[j]) - 48) + res[i + j + 1]
            res[i + j + 1] = prod % 10          # digit i of a times digit j of b lands at i + j + 1
            res[i + j] += prod // 10            # the carry goes one slot to the left
    start = 0
    while start < len(res) - 1 and res[start] == 0:   # strip leading zeros
        start += 1
    return "".join(map(str, res[start:]))
static String multiply(String a, String b) {
    if (a.equals("0") || b.equals("0")) return "0";
    int[] res = new int[a.length() + b.length()];
    for (int i = a.length() - 1; i >= 0; i--)
        for (int j = b.length() - 1; j >= 0; j--) {
            int prod = (a.charAt(i) - '0') * (b.charAt(j) - '0') + res[i + j + 1];
            res[i + j + 1] = prod % 10;
            res[i + j] += prod / 10;
        }
    StringBuilder sb = new StringBuilder();
    int start = 0;
    while (start < res.length - 1 && res[start] == 0) start++;
    for (int k = start; k < res.length; k++) sb.append(res[k]);
    return sb.toString();
}

Cost: O(n · m) time, O(n + m) space.

def reverse_words(s):
    out = []
    i = len(s) - 1
    while i >= 0:                               # walk from the right end
        while i >= 0 and s[i] == " ":           # skip spaces
            i -= 1
        if i < 0:
            break
        j = i                                   # j = last char of this word
        while i >= 0 and s[i] != " ":           # find its first char
            i -= 1
        out.append(s[i + 1:j + 1])
    return " ".join(out)
static String reverseWords(String s) {

}

def reverse_words_in_place(chars):
    # chars is a list of characters. Reverse everything, reverse each word, squeeze spaces.
    def rev(l, r):
        while l < r:
            chars[l], chars[r] = chars[r], chars[l]
            l += 1
            r -= 1
    n = len(chars)
    rev(0, n - 1)
    write = 0                                   # next free slot in the compacted result
    read = 0
    while read < n:
        if chars[read] != " ":
            if write > 0:
                chars[write] = " "              # one space between words
                write += 1
            start = write
            while read < n and chars[read] != " ":
                chars[write] = chars[read]
                write += 1
                read += 1
            rev(start, write - 1)               # the word is backwards now: flip it back
        else:
            read += 1
    del chars[write:]
    return "".join(chars)
static String reverseWordsInPlace(char[] chars) {
    int n = chars.length;
    reverse(chars, 0, n - 1);

        if (chars[read] != ' ') {
            if (write > 0) chars[write++] = ' ';         // one space between words
            int start = write;
            while (read < n && chars[read] != ' ') chars[write++] = chars[read++];
            reverse(chars, start, write - 1);            // flip the (currently backwards) word back
        } else {
            read++;
        }
    }
    return new String(chars, 0, write);
}
static void reverse(char[] c, int l, int r) {
    while (l < r) { char t = c[l]; c[l++] = c[r]; c[r--] = t; }
}

Problem. Return the index of the first occurrence of needle in haystack, or -1 (needle is non-empty).

Example. "sadbutsad", "sad" -> 0. "leetcode", "leeto" -> -1.

Recognise before coding. "Find a substring". In an interview the expected first answer is the brute force; KMP is the follow-up when they say "can you do better than O(n·m)?".

Skill it teaches. Type G: the brute force with its worst case, then KMP: when a mismatch happens, reuse what the matched part already told you (the longest border) instead of restarting.

1Brute force

Try every start position and compare character by character. On "aaaa...a" searched for "aaa...ab" every start matches almost all of the needle before failing, re-comparing the same letters again and again.

def str_str_brute(haystack, needle):
    n, m = len(haystack), len(needle)
    for i in range(n - m + 1):                  # every possible start
        j = 0
        while j < m and haystack[i + j] == needle[j]:
            j += 1
        if j == m:
            return i
    return -1                                   # worst case O(n * m), e.g. "aaaa...a" with "aaa...ab"
static int strStrBrute(String haystack, String needle) {
    int n = haystack.length(), m = needle.length();
    for (int i = 0; i + m <= n; i++) {
        int j = 0;
        while (j < m && haystack.charAt(i + j) == needle.charAt(j)) j++;
        if (j == m) return i;
    }
    return -1;
}

Cost: O(n · m) time, O(1) space.

2Observation

When the first k characters of the needle matched and the next one fails, the matched text is known. The longest prefix of the needle that is also a suffix of the matched part (a border) says where to resume, without moving back in the haystack.

3Optimal solution
def str_str(haystack, needle):
    # KMP. lps[k] = length of the longest proper prefix of needle[:k+1] that is also its suffix
    m = len(needle)
    lps = [0] * m
    k = 0
    for i in range(1, m):
        while k and needle[i] != needle[k]:
            k = lps[k - 1]                      # fall back to a shorter border
        if needle[i] == needle[k]:
            k += 1
        lps[i] = k
    k = 0                                       # k = how many characters of needle currently match
    for i, ch in enumerate(haystack):           # i never moves backwards
        while k and ch != needle[k]:
            k = lps[k - 1]
        if ch == needle[k]:
            k += 1
        if k == m:
            return i - m + 1
    return -1
static int strStr(String haystack, String needle) {
    int m = needle.length();
    int[] lps = new int[m];
    for (int i = 1, k = 0; i < m; i++) {
        while (k > 0 && needle.charAt(i) != needle.charAt(k)) k = lps[k - 1];
        if (needle.charAt(i) == needle.charAt(k)) k++;
        lps[i] = k;
    }
    for (int i = 0, k = 0; i < haystack.length(); i++) {
        while (k > 0 && haystack.charAt(i) != needle.charAt(k)) k = lps[k - 1];
        if (haystack.charAt(i) == needle.charAt(k)) k++;
        if (k == m) return i - m + 1;
    }
    return -1;
}

Cost: O(n + m) time, O(m) space.

Say aloud. "First brute force, O(n·m). To do better I precompute, for each prefix of the needle, the longest proper border (lps). Then I scan the haystack once; on a mismatch I fall back to lps[k - 1] instead of restarting. k rises at most once per character, so the falls are bounded and the total is O(n + m)."

Complexity mistakes

  • Calling expand-around-centre O(n). It is O(n²); say so.
  • Forgetting that a slice, a substring or a string used as a map key costs its length.
  • Calling the brute-force substring search O(n) because the code "looks like one loop". The inner comparison loop makes it O(n·m): 25,005,000 comparisons on the worst case against 24,998 for KMP.
  • Saying KMP is O(n·m) because of the while inside the for. The fall-backs are paid for by the increases of k (Part 3).

Boundary mistakes

  • The loop stops one step too far. After expanding around a centre the palindrome is s[l+1 .. r-1], not s[l .. r].
  • i can pass the end. In Valid Word Abbreviation a number can send i beyond len(word); the final check i == len(word) rejects it, but only if you do not index word[i] first.
  • Compression count in one slot. A run of 12 written with one chars[write] = str(12) returns length 2, not 3 (reproduced).
  • Off-by-one in n - m + 1. The last valid start of a needle is n - m, so range(n - m + 1); for m > n the range is empty, which is correct.

Interview reasoning mistakes

  • Starting to code before asking what to return when there is no answer.
  • Using a library call the interviewer banned (int(), BigInteger, split, regex) without asking. Ask: "May I use...?"
  • Writing if s[i] in "0123456789" for a digit check and forgetting that "" in "0123456789" is true (empty slices).
  • Not testing the even-length, empty and carry cases, because the first example passed.
  • Presenting a hash-map or sorted-key solution as O(n) without mentioning the O(L) key cost.

def longest_palindrome(s):
    best_l, best_r = 0, 0                       # inclusive bounds of the best palindrome so far
    for c in range(len(s)):
        for l, r in ((c, c), (c, c + 1)):       # odd centre, then even centre
            while l >= 0 and r < len(s) and s[l] == s[r]:
                l -= 1
                r += 1
            # loop stopped one step too far: palindrome is s[l+1 .. r-1]

static String longestPalindrome(String s) {

    for (int c = 0; c < s.length(); c++) {
        for (int parity = 0; parity < 2; parity++) {    // 0 = odd centre, 1 = even centre
            int l = c, r = c + parity;
            while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
                l--;
                r++;
            }

                bestR = r - 1;
            }
        }
    }

}

            return i - m + 1
    return -1
static int strStr(String haystack, String needle) {
    int m = needle.length();
    int[] lps = new int[m];
    for (int i = 1, k = 0; i < m; i++) {
        while (k > 0 && needle.charAt(i) != needle.charAt(k)) k = lps[k - 1];
        if (needle.charAt(i) == needle.charAt(k)) k++;
        lps[i] = k;
    }
    for (int i = 0, k = 0; i < haystack.length(); i++) {
        while (k > 0 && haystack.charAt(i) != needle.charAt(k)) k = lps[k - 1];
        if (haystack.charAt(i) == needle.charAt(k)) k++;
        if (k == m) return i - m + 1;
    }
    return -1;
}

Applies to: Find the Index of the First Occurrence (28); Repeated Substring Pattern (459, same table)   Complexity: O(n + m) / O(m) (time / space)

The line people most often get wrong: Both loops: while k and mismatch: k = lps[k - 1]. The fall-back uses lps[k - 1], not lps[k].

Exercise 1: Access-log analyser ("which endpoints are failing?")

Scenario. A web service writes one line per request, for example 203.0.113.7 - - [13/Oct/2026:10:00:01 +0000] "GET /api/users?id=7 HTTP/1.1" 200 512 "Mozilla/5.0 (X11; Linux)". Operations wants answers without loading a database.

LevelRequirement (each adds to the previous)

Optimal:

def count_substrings(s):
    count = 0
    for c in range(len(s)):
        for l, r in ((c, c), (c, c + 1)):       # odd centre, even centre

                l -= 1
                r += 1

        for (int parity = 0; parity < 2; parity++) {

                l--;
                r++;
            }
        }

Encode and Decode Strings · LeetCode 271

Idea. Type C (format design plus parsing). Prefix each string with its length and a separator: the decoder reads the length, then takes exactly that many characters, so the data can never be confused with the format.

The tempting version, shown only so you can see how it fails. decode_naive(encode_naive(["a#b", "c"])) returns ["a", "b", "c"], not the original list (run, see Appendix B).

def encode_naive(strs):
    return "#".join(strs)                       # the tempting version: a delimiter

def decode_naive(s):
    return s.split("#")                         # breaks when a string contains "#" (or is the only empty string)
// the naive version fails the same way in Java: any delimiter that can occur inside the data is ambiguous.
// Skip it and read the length-prefix version below.

The length-prefix version. The decoder takes the first # after the current position, so # inside the text can never be mistaken for a separator.

def encode(strs):
    return "".join(str(len(s)) + "#" + s for s in strs)     # 3#abc2#xy: length first, then the text

def decode(s):
    out, i = [], 0
    while i < len(s):
        j = s.index("#", i)                     # the FIRST "#" after i ends the length, whatever the text holds
        n = int(s[i:j])
        out.append(s[j + 1:j + 1 + n])          # take exactly n characters, never scan for a delimiter
        i = j + 1 + n
    return out

def codec_roundtrip(strs):
    return decode(encode(strs))
static String encode(java.util.List<String> strs) {
    StringBuilder sb = new StringBuilder();
    for (String s : strs) sb.append(s.length()).append('#').append(s);
    return sb.toString();
}
static java.util.List<String> decode(String s) {
    java.util.List<String> out = new java.util.ArrayList<>();
    int i = 0;
    while (i < s.length()) {
        int j = s.indexOf('#', i);
        int n = Integer.parseInt(s.substring(i, j));
        out.add(s.substring(j + 1, j + 1 + n));
        i = j + 1 + n;
    }
    return out;
}

Cost: O(total characters) time and space for both directions. Follow-up: the length is a decimal number, so very long strings use more digits; a fixed 4-byte binary length is the usual production choice.

Text Justification · LeetCode 68

Idea. Type E (stretch). Pack greedily, then distribute space, extra = divmod(maxWidth - chars, gaps) so the first extra gaps get one more space. Special-case the last line and single-word lines.

Brute force (the reference it was tested against):

def full_justify_brute(words, max_width):
    lines, i = [], 0
    while i < len(words):
        line = [words[i]]
        used = len(words[i])
        i += 1
        while i < len(words) and used + 1 + len(words[i]) <= max_width:   # +1: one space per gap, at least
            used += 1 + len(words[i])
            line.append(words[i])
            i += 1
        last = i == len(words)
        if last or len(line) == 1:
            lines.append(" ".join(line).ljust(max_width))                 # left-justified
        else:
            gaps = [1] * (len(line) - 1)
            spare = max_width - used
            g = 0
            while spare > 0:                    # hand out spare spaces one at a time, left to right, round robin
                gaps[g % len(gaps)] += 1
                g += 1
                spare -= 1
            lines.append("".join(w + " " * k for w, k in zip(line, gaps + [0])))
    return lines

        lines.add(sb.toString());
        i = j;
    }
    return lines;
}

Cost: O(total characters) time and O(output) space.
