Two Pointers

Two pointers are two index variables that walk through one or two sequences under a rule that never moves them backwards. Each move proves that a whole group of candidate answers is impossible, so you never look at it. That turns the O(n²) "try every pair" scan into a single O(n) pass, often with O(1) extra memory.

Part 1First Principles

One-paragraph summary

A two-pointer algorithm keeps two positions in a sequence (or one position in each of two sequences) and moves them by a fixed rule. Because the sequence has structure (it is sorted, symmetric, or being filtered), every move eliminates a block of candidates at once. Brute force checks all n²/2 pairs; two pointers visit at most n positions. It turns O(n²) into O(n) (or O(n²) into O(n) after an O(n log n) sort) and usually needs O(1) extra space.

Terminology

TermMeaning
PointerNot a memory address here. Just an integer index (or a node reference in a linked list) that says "I am looking at this element".
Converging pointersOne starts at the left end, one at the right end, and they walk towards each other until they meet or cross.
Same-direction pointersBoth move left to right. The "read" pointer scans; the "write" pointer (or a second sequence's pointer) trails or leads.
Search spaceThe set of candidate answers that could still be correct. Brute force never shrinks it faster than one candidate per step.
InvariantA statement that is true before and after every loop iteration. It is how you prove the algorithm correct.
MonotoneMoves in one direction only. A sorted array makes sums monotone: moving right in the array can only keep a sum the same or raise it.
In placeThe input array is modified using only a few extra variables (O(1) extra space).
AmortisedCounting the total work across the whole run instead of per step. Used in Part 3 to explain why a loop inside a loop is still O(n).

What it is, and why it exists

Many array problems ask about pairs (two numbers that sum to a target, two walls that hold water) or about two ordered streams (merge them, find what they share). The obvious solution is a nested loop over all pairs, which is O(n²). Two pointers exist because, when the data has order, most pairs are provably useless and can be skipped without looking at them.

The core invariant: a shrinking search space

Take the sorted array [1, 3, 4, 6, 8, 11] and target 10. Write every pair's sum into a grid (row = left index, column = right index). Because the array is sorted, every row and every column of the grid is sorted too.

              right index ->   1      2      3      4      5
                               (3)    (4)    (6)    (8)    (11)
  left index
  0   (1)                      4      5      7      9      12
  1   (3)                             7      9      11     14
  2   (4)                                    10     12     15
  3   (6)                                           14     17
  4   (8)                                                  19

  Start at the top-right cell (left=0, right=5): sum 12 > 10.
    Every cell in column 5 is >= 12, so none can equal 10.      -> drop the column: right -= 1
  Now (0,4): sum 9 < 10.
    Every cell in row 0 is <= 9, so none can equal 10.          -> drop the row:    left += 1
  Now (1,4): 11 > 10 -> drop column 4.   (1,3): 9 < 10 -> drop row 1.   (2,3): 10 -> found.
The invariant, in one sentence

If an answer exists, it is a pair (i, j) with left ≤ i < j ≤ right. Each step removes one row or one column from that triangle, so after at most n−1 steps nothing is left to search. That is the whole technique: state the region where the answer can still be, and make each move shrink it by something provably useless.

How it works inside, conceptually

  • Decide what the two pointers mean (ends of a range? read and write? one per list?).
  • Look at the elements under the pointers and ask one yes/no question about them.
  • Move exactly one pointer (sometimes both) in the direction the answer implies. The rule must never undo earlier progress.
  • Stop when the pointers cross, when one runs off the end, or when a goal is reached.

When to use it, and when not to

Use it whenDo NOT use it when

Where you already meet it

  • Merge step of merge sort and the sorted-merge join in databases: two sorted inputs, one pointer each (Type E).
  • C++ std::unique / std::remove_if and in-place filters generally: a read pointer scans, a write pointer keeps (Type D).
  • Python heapq.merge merges already-sorted streams lazily; the two-stream case is exactly Type E (k streams add a heap, see Heaps).
  • Floyd cycle detection: finding loops in linked structures with O(1) memory (Type G).
  • Palindrome checks and in-place reversal in any string library (Type A).
  • Log and event pipelines: merging two time-ordered streams, deduplicating adjacent repeats (Part 15 build track).

How it connects to the previous and next topics

From Hashing to Two Pointers

The previous topic solved Two Sum with a hash map: remember what you have seen, look up the complement in O(1), pay O(n) memory. Two pointers solve the same question when the array is sorted (Two Sum II) by replacing memory with order: the position of a value tells you which way to move. Rule of thumb: hash map trades space for not needing order; two pointers trade order for not needing space. Both turn the nested loop into one pass.

From Two Pointers to Sliding Window

A sliding window is two pointers that both move left to right and bracket a stretch of the array, left and right being the window edges. The bridge is the never-move-backwards rule and the same amortised proof (each pointer moves at most n times). What changes is the question: in two pointers you decide by comparing the two elements under the pointers; in a sliding window you decide by a property of everything between them (sum, distinct count, character frequencies), kept up to date as the window slides.

        i += 1
    else:
        j += 1

int left = 0, right = nums.length - 1;               // converging pointers
while (left < right) {
    left++;
    right--;
}
int write = 0;                                       // read / write pointers
for (int read = 0; read < nums.length; read++) {
    if (nums[read] % 2 == 0) {
        nums[write] = nums[read];
        write++;
    }
}
int i = 0, j = 0;                                    // one pointer per sequence
int[] a = {1, 3}, b = {2, 4};
while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) i++;
    else j++;
}

Choose the loop by what the pointers do: while left < right for converging pointers (stop when they cross), for read in range(n) for read/write (visit every element once), while i < len(a) and j < len(b) for two sequences (stop when one is exhausted, then drain the other).

Why a loop inside a loop can still be O(n) (amortised analysis)

def remove_runs(nums):
    i = 0
    while i < len(nums):              # outer loop
        j = i
        while j < len(nums) and nums[j] == nums[i]:
            j += 1                    # inner loop: looks like n * n
        i = j                         # but i jumps to j: no element is visited twice
static void removeRuns(int[] nums) {
    int i = 0;
    while (i < nums.length) {                       // outer loop
        int j = i;
        while (j < nums.length && nums[j] == nums[i]) {
            j++;                                    // inner loop: looks like n * n
        }
        i = j;                                      // but i jumps to j: no element is visited twice
    }
}

(Illustration of the counting argument only; not part of the verified solutions.) The inner loop can run many times in one outer iteration, but j never moves backwards and i is set to j. So across the whole run j advances at most n times in total, not n times per outer iteration. Total work: n + n = O(n).

  The amortised argument for two pointers (the same shape every time):

      pointer L only ever moves forward, so it moves at most n times in the whole run
      pointer R only ever moves forward, so it moves at most n times in the whole run
      every loop iteration moves at least one of them
      ------------------------------------------------------------------------------
      iterations <= (moves of L) + (moves of R) <= 2n          =>  O(n)

  Compare brute force: for each of the n values of i, j starts again from i+1.  That "restart" is the n^2.
Where nested loops are real

3Sum does have a loop around the pointer pass: n anchors times an O(n) pass = O(n²). That is correct and optimal for the comparison model; do not claim O(n). The pointer pass itself is O(n) because left and right restart only when the anchor changes.

Why moving a pointer never skips the answer (correctness)

Complexity is only useful if the algorithm is right. The proof has the same three lines each time: state the invariant, show each move keeps it, show the end of the loop gives the answer.

Converging Two Sum (sorted)

  1. Invariant: if a pair summing to the target exists, both of its indices lie in [left, right].
  2. True at the start: [0, n-1] contains everything.
  3. Move keeps it: if nums[left] + nums[right] < target, then for every j ≤ right, nums[left] + nums[j] ≤ nums[left] + nums[right] < target. So left cannot be part of any answer inside the range; discarding it loses nothing. The "too big" case is symmetric for right.
  4. End: when left == right the range holds one element, so no pair remains; no pair was ever discarded unless it was provably not a solution, so "not found" is correct.

Container With Most Water (greedy)

  1. Area of the pair (l, r) is min(h[l], h[r]) * (r - l). Suppose h[l] < h[r].
  2. Any pair (l, j) with j < r has height at most h[l] and a smaller width, so its area is no larger than the area just measured for (l, r).
  3. So every pair that uses l with a smaller right end is already dominated: discard l (left += 1). Moving the taller wall instead could discard the optimum (Part 10 shows a failing input).

Floyd cycle detection

  1. Once both pointers are inside the cycle, each iteration changes the distance from slow to fast (measured along the cycle) by exactly 1 (fast gains 2 steps, slow gains 1).
  2. The distance is a whole number between 0 and cycle length minus 1 that decreases by 1 each iteration, so it must reach 0 within one cycle length. Equal positions mean the same node: they meet.
  3. If there is no cycle, fast reaches null after about n/2 iterations, so the loop ends.

Dutch National Flag

Invariant: nums[:low] are all 0, nums[low:mid] are all 1, nums[mid:high+1] are unknown, nums[high+1:] are all 2. Each branch keeps the four regions correct and shrinks "unknown" by one element. When mid > high the unknown region is empty, so the array is sorted. Swapping with high brings an unclassified value to mid, which is why mid must not advance in that branch.

Best, average, worst case

These algorithms do the same work whatever the data looks like: the loop bounds depend only on n. Early exits (found the pair, found a mismatch in a palindrome, cycle met) make the best case O(1) or O(n/2), but the worst case, which is what you quote, is O(n). Only the sort in Type C has a data-dependent cost, and it is O(n log n) in every case you should assume.

Type A: Converging (opposite ends)

1 WHATTwo pointers start at opposite ends and walk inwards. Each step looks at the pair (nums[left], nums[right]) and moves one side.
2 SOLVESPair and symmetry questions on a sorted or symmetric sequence: "two numbers that sum to target", "is this a palindrome", "reverse in place", "square a sorted array with negatives".
3 RECOGNISE"sorted array", "pair that sums to", "palindrome", "reverse in place", "from both ends", "return indices (1-indexed)".
4 INTUITIONThe sum grid in Part 1: sorted order makes every row and column sorted, so one comparison discards a whole row or column.
5 ALGORITHMleft = 0, right = n-1. While left < right: compare; if the pair is a match, finish; if the pair is "too small", left += 1; if "too big", right -= 1.
6 STATEState: left, right. Valid condition: the answer, if any, lies inside [left, right]. Step: move the pointer whose element cannot help. Answer: when the test succeeds or the pointers meet.
8-9 COSTTime O(n), space O(1).

def two_sum_ii(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return [left + 1, right + 1]
        if s < target:
            left += 1          # sum too small: only a bigger left can help
        else:
            right -= 1         # sum too big: only a smaller right can help

static int[] twoSumII(int[] nums, int target) {

        long s = (long) nums[left] + nums[right];   // long: int + int can overflow
        if (s == target) return new int[]{left + 1, right + 1};
        if (s < target) left++;
        else right--;
    }
    return new int[]{};
}

Type B: Converging with a greedy side choice

1 WHATConverging pointers where the move is a greedy choice: always advance the pointer on the side that currently limits the answer.
2 SOLVESOptimise a quantity of a pair or a range, not just find an exact match: maximum area, trapped water.
3 RECOGNISE"maximise / minimise over pairs", heights, walls, bars, "area", "water", and the array is not sorted (so the sum-grid argument does not apply; a dominance argument does).
4 INTUITIONThe shorter wall limits the area. Narrowing while keeping the shorter wall can only lose width, never gain height, so the shorter wall can never do better again: discard it.
5 ALGORITHMleft = 0, right = n-1. Evaluate the current pair, update the best, then move the side that is shorter (ties: either side).
6 STATEState: left, right, best (and for water: left_max, right_max, total). Valid condition: every pair discarded so far is no better than a pair already measured. Step: measure, then drop the limiting side.
8-9 COSTTime O(n), space O(1).

def max_area(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        best = max(best, min(height[left], height[right]) * (right - left))
        if height[left] < height[right]:
            left += 1          # the shorter wall limits the area: only moving it can help
        else:
            right -= 1
    return best

1 WHATSort the array. Fix k−2 "anchor" values with outer loops. For the last two, run the Type A converging pass on what is to the right of the last anchor.
2 SOLVESFind all unique tuples (triples, quadruples) with a given sum, or the closest sum.
3 RECOGNISE"three numbers", "all unique triplets", "sum to zero", "closest sum", "no duplicate triplets".

5 ALGORITHMSort. For each anchor i (skip it if equal to the previous anchor): left = i+1, right = n-1, converge for the target -nums[i]; after a hit, skip equal neighbours on both sides, then move both.

def three_sum(nums):
    nums.sort()                                    # note: sorts the caller's list in place
    result, n = [], len(nums)
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                               # skip a duplicate anchor
        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1
    return result

Type D: Read / write (same direction, in place)

1 WHATBoth pointers move left to right. read examines every element; write marks where the next kept element goes.
2 SOLVESIn-place filtering and partitioning with O(1) extra space: remove duplicates, remove or move values, split into two groups.
3 RECOGNISE"in place", "O(1) extra space", "return the new length", "move all zeros to the end", "remove duplicates", "keep relative order".
4 INTUITIONThe write pointer is always at or behind the read pointer, so writing never overwrites an element you still need to read.

def merge_sorted(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                   # <= keeps the merge stable
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    result.extend(a[i:])                   # at most one of these two is non-empty
    result.extend(b[j:])
    return result
static int[] mergeSorted(int[] a, int[] b) {
    int[] result = new int[a.length + b.length];

        if (a[i] <= b[j]) result[k++] = a[i++];
        else result[k++] = b[j++];
    }
    while (i < a.length) result[k++] = a[i++];
    while (j < b.length) result[k++] = b[j++];
    return result;
}

Type F: Dutch National Flag (three regions)

1 WHATThree pointers split the array into four regions: finished low values, finished middle values, unknown, finished high values. One scan classifies the unknown region from the middle.
2 SOLVESPartition into three groups in one pass and O(1) space (sort 0/1/2, partition around a pivot with a "equal" bucket).
3 RECOGNISE"sort an array of 0s, 1s and 2s", "three colours", "partition around a value", "do not use the library sort", "one pass".
4 INTUITIONValues that belong at the front are swapped to low; values that belong at the back are swapped to high; the middle value just advances.
5 ALGORITHMlow = mid = 0, high = n-1. While mid ≤ high: 0 -> swap(low, mid), both ++; 1 -> mid++; 2 -> swap(mid, high), high-- and do not move mid.
6 STATEState: low, mid, high. Valid condition: [0,low)=0, [low,mid)=1, [mid,high] unknown, (high,n)=2. Step: classify nums[mid]. Answer: the array when mid passes high.
8-9 COSTTime O(n) in one pass, space O(1).

def sort_colors(nums):
    low, mid, high = 0, 0, len(nums) - 1
    # nums[:low] == 0s, nums[low:mid] == 1s, nums[mid:high+1] unknown, nums[high+1:] == 2s
    while mid <= high:
        if nums[mid] == 0:
            nums[low], nums[mid] = nums[mid], nums[low]
            low += 1
            mid += 1
        elif nums[mid] == 1:
            mid += 1
        else:
            nums[mid], nums[high] = nums[high], nums[mid]
            high -= 1                       # do NOT advance mid: the swapped-in value is unknown
static void sortColors(int[] nums) {
    int low = 0, mid = 0, high = nums.length - 1;
    while (mid <= high) {
        if (nums[mid] == 0) {
            swap(nums, low, mid);
            low++;
            mid++;
        } else if (nums[mid] == 1) {
            mid++;
        } else {
            swap(nums, mid, high);
            high--;                         // do NOT advance mid
        }
    }
}
static void swap(int[] a, int i, int j) {
    int tmp = a[i]; a[i] = a[j]; a[j] = tmp;
}

Type G: Slow / fast (linked list)

1 WHATTwo references on a linked list that advance at different speeds: slow one node per step, fast two.

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:                    # identity, not value equality
            return True
    return False

        fast = fast.next.next;

Two Sum II (sorted input)

Type AMediumLeetCode 167O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (sources: NeetCode-150-style two-pointer list (GitHub summary), web search 2026-10-04; the unsorted Two Sum of the previous topic recurs across all lists in local research dsa-array-problem-frequency-2026.md, 2026-10-04)

Problem. Given a 1-indexed array sorted in non-decreasing order and a target, return the indices of two different elements that sum to the target. (LeetCode guarantees one answer. The version here returns [] when there is none, which is stricter and is what the tests check.)

Example. nums = [1, 3, 4, 6, 8, 11], target = 10 returns [3, 4] (values 4 and 6).

Recognise before coding. Sorted input and a pair-sum question. Ask: is a hash map allowed, or is O(1) space required? Sorted input hints that order should replace memory.

Skill it teaches. The base template of the whole topic: the sum grid, and discarding a row or a column per step. Why it matters: Every other converging problem (3Sum, Container, palindrome) is this loop with a different "which side to move" rule.

1Brute force
def two_sum_ii_brute(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return [i + 1, j + 1]
    return []
static int[] twoSumIIBrute(int[] nums, int target) {
    int n = nums.length;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (nums[i] + nums[j] == target)
                return new int[]{i + 1, j + 1};
    return new int[]{};
}

Cost: O(n²). Bottleneck: The inner loop re-scans every later element for each i and ignores the order.

2Observation

Sorted order means a too-small sum can only improve by raising the left value, and a too-big sum only by lowering the right value. So each comparison removes one index for good.

3Optimal (two pointers)
def two_sum_ii(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return [left + 1, right + 1]
        if s < target:
            left += 1          # sum too small: only a bigger left can help
        else:
            right -= 1         # sum too big: only a smaller right can help
    return []
static int[] twoSumII(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        long s = (long) nums[left] + nums[right];   // long: int + int can overflow
        if (s == target) return new int[]{left + 1, right + 1};
        if (s < target) left++;
        else right--;
    }
    return new int[]{};
}

Cost: time O(n), extra space O(1).

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python and in Java (Python 3 and JDK 27).

Valid Palindrome

Type AEasyLeetCode 125O(n) → O(n)
ShowHide

Where it is reported. Frequently asked (sources: NeetCode-150-style two-pointer list (GitHub summary), web search 2026-10-04; Google-tagged two-pointer list (hackmnc.com), 2026-10-04 lists Valid Palindrome at 59.3% in its two-pointer group). Related: Valid Palindrome II (680) is a most-reported Meta E4 problem, see Part 14.

Problem. Given a string, decide whether it reads the same forwards and backwards after removing every non-alphanumeric character and ignoring case.

Example. "A man, a plan, a canal: Panama" is a palindrome; "race a car" is not; ",. " (nothing left) is a palindrome.

Recognise before coding. Symmetry. "Ignoring punctuation" invites building a cleaned copy, which costs O(n) space; the skip loops avoid it.

Skill it teaches. Converging pointers with inner skip loops that must keep the left < right guard. Why it matters: Warm-up that appears inside harder string problems; the skip-loop shape is reused in Backspace String Compare and Valid Palindrome II.

1Brute force
def is_palindrome_brute(s):
    cleaned = [c.lower() for c in s if c.isalnum()]
    return cleaned == cleaned[::-1]
static boolean isPalindromeBrute(String s) {
    StringBuilder sb = new StringBuilder();
    for (char c : s.toCharArray())
        if (Character.isLetterOrDigit(c)) sb.append(Character.toLowerCase(c));
    String cleaned = sb.toString();
    return cleaned.equals(sb.reverse().toString());
}

Cost: O(n), O(n) space. Bottleneck: Builds a cleaned copy and a reversed copy: correct but uses O(n) extra memory.

2Observation

You never need the cleaned string: skip junk from each end and compare the next real characters.

3Optimal (two pointers)
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True
static boolean isPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        while (left < right && !Character.isLetterOrDigit(s.charAt(left))) left++;
        while (left < right && !Character.isLetterOrDigit(s.charAt(right))) right--;
        if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right)))
            return false;
        left++;
        right--;
    }
    return true;
}

Type AEasyLeetCode 344O(n) → O(n)
ShowHide

Where it is reported. Weak signal: appears in a broad two-pointer list (GitHub summary, 2026-10-04); mainly added for pattern coverage (the simplest in-place converging swap).

Problem. Reverse an array of characters in place using O(1) extra memory.

Example. [h, e, l, l, o] becomes [o, l, l, e, h].

Recognise before coding. "In place", "O(1) extra space", a character array (not a String, which is immutable).

Skill it teaches. Converging swap; the loop condition left < right leaves the middle element alone. Why it matters: The same swap is the last step of Rotate Array, Next Permutation and Reverse Words.

1Brute force
def reverse_string_brute(s):
    return s[::-1]                 # builds a NEW list: O(n) extra space
static char[] reverseStringBrute(char[] s) {
    char[] out = new char[s.length];
    for (int i = 0; i < s.length; i++) out[i] = s[s.length - 1 - i];
    return out;
}

Cost: O(n), O(n) space. Bottleneck: Allocates a second array for the reversed copy.

2Observation

Mirrored positions swap with each other; after n/2 swaps the pointers meet.

3Optimal (two pointers)
def reverse_string(s):
    left, right = 0, len(s) - 1
    while left < right:
        s[left], s[right] = s[right], s[left]
        left += 1
        right -= 1
static void reverseString(char[] s) {
    int left = 0, right = s.length - 1;
    while (left < right) {
        char tmp = s[left]; s[left] = s[right]; s[right] = tmp;
        left++;
        right--;
    }
}

Squares of a Sorted Array

Type AEasyLeetCode 977O(n log n) → O(n)
ShowHide

Where it is reported. Added for pattern coverage as the "looks like sorting, actually converging" twist (Squares of a Sorted Array, 977). Not confirmed in the research sources; from memory.

Problem. A sorted array may contain negative numbers. Return the squares of its elements in sorted order.

Example. [-4, -1, 0, 3, 10] returns [0, 1, 9, 16, 100].

Recognise before coding. The squares are almost sorted: the array is "V-shaped" after squaring. The smallest square is in the middle, the largest at an end.

Skill it teaches. Converge from both ends but write the output from the back. Why it matters: Shows that "sorted input" does not always mean "compare the two ends and move one": here the ends are the largest values, so you fill backwards.

1Brute force
def sorted_squares_brute(nums):
    return sorted(x * x for x in nums)       # O(n log n): ignores that the input is sorted
static int[] sortedSquaresBrute(int[] nums) {
    int[] out = new int[nums.length];
    for (int i = 0; i < nums.length; i++) out[i] = nums[i] * nums[i];
    Arrays.sort(out);
    return out;
}

Cost: O(n log n). Bottleneck: Sorts after squaring, ignoring that the input is already almost ordered.

2Observation

The biggest square is either the left end (a big negative) or the right end (a big positive). Take it, and place it in the last free slot.

3Optimal (two pointers)
def sorted_squares(nums):
    n = len(nums)
    result = [0] * n
    left, right = 0, n - 1
    for k in range(n - 1, -1, -1):           # fill the answer from the largest square down
        if abs(nums[left]) > abs(nums[right]):
            result[k] = nums[left] * nums[left]
            left += 1
        else:
            result[k] = nums[right] * nums[right]
            right -= 1
    return result
static int[] sortedSquares(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    int left = 0, right = n - 1;
    for (int k = n - 1; k >= 0; k--) {
        if (Math.abs(nums[left]) > Math.abs(nums[right])) {
            result[k] = nums[left] * nums[left];
            left++;
        } else {
            result[k] = nums[right] * nums[right];
            right--;
        }
    }
    return result;
}

Cost: time O(n), extra space O(n) output.

Container With Most Water

Type BMediumLeetCode 11O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (sources: Blind 75 and NeetCode lists, local research dsa-array-problem-frequency-2026.md, 2026-10-04; Google-tagged two-pointer list (hackmnc.com), 2026-10-04 at 75.1%; reported at about 62 companies in a cross-company summary)

Problem. height[i] is the height of a vertical wall at position i. Choose two walls so that, with the x-axis, they hold the most water. Return the area.

Example. [1, 8, 6, 2, 5, 4, 8, 3, 7] returns 49 (walls at index 1 and 8: min(8, 7) x 7).

Recognise before coding. Unsorted heights, "maximise a formula over pairs". Sorting would destroy positions, so the sum-grid argument is not available; look for a dominance argument instead.

Skill it teaches. Greedy elimination: prove that one side is useless and discard it. Why it matters: The most common "defend your pointer rule" question. Interviewers ask why moving the shorter side is safe.

1Brute force
def max_area_brute(height):
    best = 0
    for i in range(len(height)):
        for j in range(i + 1, len(height)):
            best = max(best, min(height[i], height[j]) * (j - i))
    return best
static int maxAreaBrute(int[] height) {
    int best = 0;
    for (int i = 0; i < height.length; i++)
        for (int j = i + 1; j < height.length; j++)
            best = Math.max(best, Math.min(height[i], height[j]) * (j - i));
    return best;
}

Cost: O(n²). Bottleneck: Each pair is evaluated although most pairs are dominated by a pair already measured.

2Observation

The area is limited by the shorter wall. Moving the taller wall inward lowers the width and cannot raise the height limit, so it cannot help. Only moving the shorter wall might.

3Optimal (two pointers)
def max_area(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        best = max(best, min(height[left], height[right]) * (right - left))
        if height[left] < height[right]:
            left += 1          # the shorter wall limits the area: only moving it can help
        else:
            right -= 1
    return best
static int maxArea(int[] height) {
    int left = 0, right = height.length - 1, best = 0;
    while (left < right) {
        best = Math.max(best, Math.min(height[left], height[right]) * (right - left));
        if (height[left] < height[right]) left++;
        else right--;
    }
    return best;
}

Cost: time O(n), extra space O(1).

Trapping Rain Water

Type BHardLeetCode 42O(n²) → O(n)
ShowHide

Where it is reported. Frequently asked (sources: Google-tagged two-pointer list (hackmnc.com), 2026-10-04 at 85.9%, about 100 appearances across 42 companies in a cross-company summary; also in the Meta list in local research dsa-array-problem-frequency-2026.md, 2026-10-04)

Problem. Given non-negative bar heights, compute how much rain water is trapped between the bars.

Example. [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1] returns 6.

Recognise before coding. Water above bar i is min(max to the left, max to the right) - height[i]. Two maxima suggests two pointers if one side can be decided without knowing the other.

Skill it teaches. Type B with running maxima: the smaller wall decides, because its own side's max is already known to be the limit. Why it matters: A top-frequency hard problem. The O(1)-space two-pointer answer is the upgrade from the O(n)-space prefix/suffix version.

1Brute force
def trap_brute(height):
    water = 0
    for i in range(len(height)):
        left_max = max(height[:i + 1])       # tallest wall at or left of i
        right_max = max(height[i:])          # tallest wall at or right of i
        water += min(left_max, right_max) - height[i]
    return water
static int trapBrute(int[] height) {
    int water = 0;
    for (int i = 0; i < height.length; i++) {
        int leftMax = 0, rightMax = 0;
        for (int j = 0; j <= i; j++) leftMax = Math.max(leftMax, height[j]);
        for (int j = i; j < height.length; j++) rightMax = Math.max(rightMax, height[j]);
        water += Math.min(leftMax, rightMax) - height[i];
    }
    return water;
}

Cost: O(n²). Bottleneck: For each bar it re-scans both sides to find the two maxima.

2Observation

If height[left] < height[right], then the right side has a wall at least as tall as everything we need, so left_max alone fixes the water at left. Process it and move left; symmetric otherwise.

3Optimal (two pointers)
def trap(height):
    left, right = 0, len(height) - 1
    left_max = right_max = 0
    water = 0
    while left < right:
        if height[left] < height[right]:
            left_max = max(left_max, height[left])
            water += left_max - height[left]       # right wall is taller, so left_max decides
            left += 1
        else:
            right_max = max(right_max, height[right])
            water += right_max - height[right]     # left wall is at least as tall
            right -= 1
    return water
static int trap(int[] height) {
    int left = 0, right = height.length - 1;
    int leftMax = 0, rightMax = 0, water = 0;
    while (left < right) {
        if (height[left] < height[right]) {
            leftMax = Math.max(leftMax, height[left]);
            water += leftMax - height[left];
            left++;
        } else {
            rightMax = Math.max(rightMax, height[right]);
            water += rightMax - height[right];
            right--;
        }
    }
    return water;
}

Cost: time O(n), extra space O(1).

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python and in Java (Python 3 and JDK 27).

3Sum

Type CMediumLeetCode 15O(n³) → O(n²)
ShowHide

Where it is reported. Frequently asked (sources: Blind 75 and Tech Interview Handbook week 1, local research dsa-array-problem-frequency-2026.md, 2026-10-04; Google-tagged two-pointer list (hackmnc.com), 2026-10-04 at 76.7%; about 85 companies in a cross-company summary)

Problem. Return all unique triplets [a, b, c] from the array with a + b + c = 0. The output must not contain duplicate triplets.

Example. [-1, 0, 1, 2, -1, -4] returns [[-1, -1, 2], [-1, 0, 1]] (any order).

Recognise before coding. "Triplets", "unique", "sum to zero". Hash map for the third value is possible but duplicate handling is painful.

Skill it teaches. Reduce k-Sum to (k-1)-Sum with an anchor; duplicate skipping at three places. Why it matters: The single most-asked two-pointer medium. The follow-ups (3Sum Closest, 4Sum, k-Sum) all reuse it.

1Brute force
def three_sum_brute(nums):
    found = set()
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                if nums[i] + nums[j] + nums[k] == 0:
                    found.add(tuple(sorted((nums[i], nums[j], nums[k]))))
    return [list(t) for t in found]
static List<List<Integer>> threeSumBrute(int[] nums) {
    Set<List<Integer>> found = new HashSet<>();
    int n = nums.length;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            for (int k = j + 1; k < n; k++)
                if (nums[i] + nums[j] + nums[k] == 0) {
                    int[] t = {nums[i], nums[j], nums[k]};
                    Arrays.sort(t);
                    found.add(Arrays.asList(t[0], t[1], t[2]));
                }
    return new ArrayList<>(found);
}

Cost: O(n³). Bottleneck: Three nested loops; the innermost loop searches blindly for a value that is determined by the other two.

2Observation

Sort. Fixing one value leaves a Two Sum II on the suffix. Sorted order also means equal values are adjacent, so duplicates are skipped by comparing neighbours.

3Optimal (two pointers)
def three_sum(nums):
    nums.sort()                                    # note: sorts the caller's list in place
    result, n = [], len(nums)
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                               # skip a duplicate anchor
        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1
    return result
static List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> result = new ArrayList<>();
    int n = nums.length;
    for (int i = 0; i < n - 2; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;       // skip a duplicate anchor
        int left = i + 1, right = n - 1;
        while (left < right) {
            int total = nums[i] + nums[left] + nums[right];
            if (total == 0) {
                result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                while (left < right && nums[left] == nums[left + 1]) left++;
                while (left < right && nums[right] == nums[right - 1]) right--;
                left++;
                right--;
            } else if (total < 0) left++;
            else right--;
        }
    }
    return result;
}

Cost: time O(n²), extra space O(1) beyond sort and output.

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python and in Java (Python 3 and JDK 27).

Remove Duplicates from Sorted Array

Type DEasyLeetCode 26O(n log n) → O(n)
ShowHide

Where it is reported. Frequently asked (source: Google-tagged two-pointer list (hackmnc.com), 2026-10-04 at 62.9%)

Problem. A sorted array is given. Remove duplicates in place so each value appears once; return the new length k. The first k elements must hold the result in order.

Example. [0, 0, 1, 1, 1, 2] returns 3 with the first three elements [0, 1, 2].

Recognise before coding. "Sorted", "in place", "return the new length". Sorted means duplicates are adjacent.

Skill it teaches. Read/write pointers; compare against the last kept element. Why it matters: The canonical Type D problem and the prerequisite for the "at most k copies" variant.

1Brute force
def remove_duplicates_brute(nums):
    unique = sorted(set(nums))            # extra O(n) space
    for i, v in enumerate(unique):
        nums[i] = v
    return len(unique)
static int removeDuplicatesBrute(int[] nums) {
    int[] unique = Arrays.stream(nums).distinct().sorted().toArray();
    System.arraycopy(unique, 0, nums, 0, unique.length);
    return unique.length;
}

Cost: O(n log n), O(n) space. Bottleneck: Uses a set and a sort (O(n log n) and O(n) space) and ignores that duplicates are adjacent.

2Observation

Because the array is sorted, a value is new exactly when it differs from the last value we kept.

3Optimal (two pointers)
def remove_duplicates(nums):
    if not nums:
        return 0
    write = 1                              # nums[0:write] is the de-duplicated prefix
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]
            write += 1
    return write
static int removeDuplicates(int[] nums) {
    if (nums.length == 0) return 0;
    int write = 1;
    for (int read = 1; read < nums.length; read++) {
        if (nums[read] != nums[write - 1]) {
            nums[write] = nums[read];
            write++;
        }
    }
    return write;
}

Merge Two Sorted Arrays

Type EEasynot on LeetCode as statedO((m+n) log(m+n)) → O(m + n)
ShowHide

Where it is reported. Added for pattern coverage (the merge step of merge sort). The in-place form, Merge Sorted Array (88), is Problem 17.

Problem. Given two sorted arrays, return one sorted array containing all their elements.

Example. [1, 4, 7] and [2, 3, 9] give [1, 2, 3, 4, 7, 9].

Recognise before coding. "Two sorted arrays". The temptation is sorted(a + b), which is correct but O((m+n) log(m+n)).

Skill it teaches. One pointer per array, plus draining the leftover. Why it matters: Gives you the compare-and-advance loop of Type E and the reason you need the drain step.

1Brute force
def merge_sorted_brute(a, b):
    return sorted(a + b)
static int[] mergeSortedBrute(int[] a, int[] b) {
    int[] all = new int[a.length + b.length];
    System.arraycopy(a, 0, all, 0, a.length);
    System.arraycopy(b, 0, all, a.length, b.length);
    Arrays.sort(all);
    return all;
}

Cost: O((m+n) log(m+n)). Bottleneck: Re-sorts two already-sorted arrays.

2Observation

The smaller of the two current heads is the smallest remaining element overall.

3Optimal (two pointers)
def merge_sorted(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                   # <= keeps the merge stable
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    result.extend(a[i:])                   # at most one of these two is non-empty
    result.extend(b[j:])
    return result
static int[] mergeSorted(int[] a, int[] b) {
    int[] result = new int[a.length + b.length];
    int i = 0, j = 0, k = 0;
    while (i < a.length && j < b.length) {
        if (a[i] <= b[j]) result[k++] = a[i++];
        else result[k++] = b[j++];
    }
    while (i < a.length) result[k++] = a[i++];
    while (j < b.length) result[k++] = b[j++];
    return result;
}

Cost: time O(m + n), extra space O(m + n) output.

Intersection of Two Sorted Arrays

Type EEasyLeetCode 349O(m + n) but O(m) space (set) → O(m + n)
ShowHide

Where it is reported. Added for pattern coverage. LeetCode 349 states its inputs as UNSORTED (usually solved with a set); this problem fixes the sorted-input version, which is the two-pointer follow-up.

Problem. Given two sorted arrays, return the distinct values that appear in both.

Example. [1, 2, 2, 3] and [2, 2, 3, 4] give [2, 3].

Recognise before coding. "Common elements" on sorted arrays. A hash set costs O(min(m, n)) space; pointers cost none.

Skill it teaches. Advance the smaller side; advance both on a match; de-duplicate the output by comparing with its last element. Why it matters: Shows the "no drain needed" variant: after one array ends nothing can match.

1Brute force
def intersection_brute(a, b):
    return sorted(set(a) & set(b))
static List<Integer> intersectionBrute(int[] a, int[] b) {
    Set<Integer> sa = new TreeSet<>(), out = new TreeSet<>();
    for (int x : a) sa.add(x);
    for (int y : b) if (sa.contains(y)) out.add(y);
    return new ArrayList<>(out);
}

Cost: O(m + n) but O(m) space (set). Bottleneck: A set costs O(m) space and ignores the order.

2Observation

If a[i] < b[j], then a[i] is smaller than everything left in b, so it has no partner: drop it.

3Optimal (two pointers)
def intersection(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            if not result or result[-1] != a[i]:    # no duplicates in the output
                result.append(a[i])
            i += 1
            j += 1
        elif a[i] < b[j]:
            i += 1                                   # a[i] is too small to match anything left in b
        else:
            j += 1
    return result
static List<Integer> intersection(int[] a, int[] b) {
    List<Integer> result = new ArrayList<>();
    int i = 0, j = 0;
    while (i < a.length && j < b.length) {
        if (a[i] == b[j]) {
            if (result.isEmpty() || result.get(result.size() - 1) != a[i])   // Integer vs int: unboxes
                result.add(a[i]);
            i++;
            j++;
        } else if (a[i] < b[j]) i++;
        else j++;
    }
    return result;
}

Cost: time O(m + n), extra space O(1) beyond output.

Union of Two Sorted Arrays

Type EEasynot on LeetCode as statedO((m+n) log(m+n)) → O(m + n)
ShowHide

Where it is reported. Added for pattern coverage (not a LeetCode problem in this form).

Problem. Given two sorted arrays, return the sorted array of distinct values that appear in either.

Example. [1, 2, 2, 3] and [2, 4] give [1, 2, 3, 4].

Recognise before coding. Merge with duplicate suppression.

Skill it teaches. A single "emit" rule: append the value only if it differs from the last output value. Why it matters: Combines merge (drain) with the neighbour-comparison trick of Problem 7.

1Brute force
def union_brute(a, b):
    return sorted(set(a) | set(b))

    Set<Integer> out = new TreeSet<>();
    for (int x : a) out.add(x);
    for (int y : b) out.add(y);
    return new ArrayList<>(out);
}

Cost: O((m+n) log(m+n)). Bottleneck: Re-sorts two already-sorted arrays.

2Observation

Treat the two arrays as one merged stream and apply "skip if equal to the last emitted value".

3Optimal (two pointers)
def union(a, b):
    result = []
    i = j = 0
    while i < len(a) or j < len(b):
        if j >= len(b) or (i < len(a) and a[i] <= b[j]):
            v = a[i]
            i += 1
        else:
            v = b[j]
            j += 1
        if not result or result[-1] != v:            # one append rule for every source
            result.append(v)
    return result
static List<Integer> union(int[] a, int[] b) {
    List<Integer> result = new ArrayList<>();
    int i = 0, j = 0;
    while (i < a.length || j < b.length) {
        int v;
        if (j >= b.length || (i < a.length && a[i] <= b[j])) v = a[i++];
        else v = b[j++];
        if (result.isEmpty() || result.get(result.size() - 1) != v) result.add(v);
    }
    return result;
}

Merge Sorted Array (in place)

Type EEasyLeetCode 88O((m+n) log(m+n)) → O(m + n)
ShowHide

Where it is reported. Frequently asked (sources: Google-tagged two-pointer list (hackmnc.com), 2026-10-04 at 81.4%, about 65 appearances in a cross-company summary). Also solved in the Arrays notes.

Problem. nums1 has length m + n: its first m slots hold sorted values and the last n are padding zeros. nums2 is sorted with n values. Merge nums2 into nums1 in place.

Example. nums1 = [1, 2, 3, 0, 0, 0], m = 3, nums2 = [2, 5, 6], n = 3 gives [1, 2, 2, 3, 5, 6].

Recognise before coding. A sorted array with a free tail and an in-place requirement. Merging from the front would overwrite values you still need.

Skill it teaches. Run the merge backwards: three pointers, largest first, into the empty tail. Why it matters: A top-frequency easy. The follow-up "why from the back?" separates candidates.

1Brute force
def merge_in_place_brute(nums1, m, nums2, n):
    merged = sorted(nums1[:m] + nums2[:n])
    for i, v in enumerate(merged):
        nums1[i] = v
static void mergeInPlaceBrute(int[] nums1, int m, int[] nums2, int n) {
    int[] merged = new int[m + n];
    System.arraycopy(nums1, 0, merged, 0, m);
    System.arraycopy(nums2, 0, merged, m, n);
    Arrays.sort(merged);
    System.arraycopy(merged, 0, nums1, 0, m + n);
}

Cost: O((m+n) log(m+n)). Bottleneck: Sorting everything again; also needs O(m + n) extra space for the merged copy.

2Observation

The tail of nums1 is free, so the largest remaining value can go there without destroying anything unread.

3Optimal (two pointers)
def merge_in_place(nums1, m, nums2, n):
    i, j, k = m - 1, n - 1, m + n - 1        # three pointers, all walking BACKWARDS
    while j >= 0:                            # when nums2 is used up, nums1's prefix is already in place
        if i >= 0 and nums1[i] > nums2[j]:
            nums1[k] = nums1[i]
            i -= 1
        else:
            nums1[k] = nums2[j]
            j -= 1
        k -= 1
static void mergeInPlace(int[] nums1, int m, int[] nums2, int n) {
    int i = m - 1, j = n - 1, k = m + n - 1;
    while (j >= 0) {
        if (i >= 0 && nums1[i] > nums2[j]) nums1[k--] = nums1[i--];
        else nums1[k--] = nums2[j--];
    }
}

Cost: time O(m + n), extra space O(1).

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python and in Java (Python 3 and JDK 27).

Sort Colors (Dutch National Flag)

Type FMediumLeetCode 75O(n) → O(n)
ShowHide

Where it is reported. Added for pattern coverage (three-way partition). Not confirmed in the research sources above; it is on common curated lists from memory.

Problem. An array contains only 0, 1 and 2 (red, white, blue). Sort it in place in one pass without the library sort.

Example. [2, 0, 2, 1, 1, 0] becomes [0, 0, 1, 1, 2, 2].

Recognise before coding. Three values, in place, "one pass". Counting needs two passes.

Skill it teaches. Maintain four regions with three pointers. The one subtle rule: after swapping with high, do not advance mid. Why it matters: Quicksort three-way partition and quickselect use exactly this loop. The mid-not-advanced bug is a classic interview failure.

1Brute force
def sort_colors_brute(nums):
    counts = [0, 0, 0]
    for x in nums:                          # pass 1: count
        counts[x] += 1
    k = 0
    for colour in range(3):                 # pass 2: overwrite
        for _ in range(counts[colour]):
            nums[k] = colour
            k += 1
static void sortColorsBrute(int[] nums) {
    int[] counts = new int[3];
    for (int x : nums) counts[x]++;
    int k = 0;
    for (int colour = 0; colour < 3; colour++)
        for (int c = 0; c < counts[colour]; c++) nums[k++] = colour;
}

Cost: O(n), two passes. Bottleneck: Two passes over the data (count, then overwrite).

2Observation

The value at mid tells you which end it belongs to; the value you swap in from high is still unclassified.

3Optimal (two pointers)
def sort_colors(nums):
    low, mid, high = 0, 0, len(nums) - 1
    # nums[:low] == 0s, nums[low:mid] == 1s, nums[mid:high+1] unknown, nums[high+1:] == 2s
    while mid <= high:
        if nums[mid] == 0:
            nums[low], nums[mid] = nums[mid], nums[low]
            low += 1
            mid += 1
        elif nums[mid] == 1:
            mid += 1
        else:
            nums[mid], nums[high] = nums[high], nums[mid]
            high -= 1                       # do NOT advance mid: the swapped-in value is unknown
static void sortColors(int[] nums) {
    int low = 0, mid = 0, high = nums.length - 1;
    while (mid <= high) {
        if (nums[mid] == 0) {
            swap(nums, low, mid);
            low++;
            mid++;
        } else if (nums[mid] == 1) {
            mid++;
        } else {
            swap(nums, mid, high);
            high--;                         // do NOT advance mid
        }
    }
}
static void swap(int[] a, int i, int j) {
    int tmp = a[i]; a[i] = a[j]; a[j] = tmp;
}

Cost: time O(n), one pass, extra space O(1).

Verified: optimal and brute force agreed on 4,000 random inputs that respect the constraints, in Python and in Java (Python 3 and JDK 27).

Linked List Cycle (Floyd)

Type GEasyLeetCode 141O(n) → O(n)
ShowHide

Where it is reported. Added for pattern coverage. This is also a Linked List topic problem (curated lists, from memory; not researched here).

Problem. Given the head of a singly linked list, return whether it contains a cycle.

Example. 3 -> 2 -> 0 -> -4 with -4 pointing back to the node holding 2: true.

Recognise before coding. "Cycle", "loop", "without extra space". The visited-set solution is the brute force.

Skill it teaches. Floyd's tortoise and hare, and comparing nodes by identity (is / == on references). Why it matters: Must-know. The proof that they meet (gap closes by one per step) is a common follow-up.

1Brute force
def has_cycle_brute(head):
    seen = set()                            # O(n) extra space
    node = head
    while node:
        if node in seen:
            return True
        seen.add(node)
        node = node.next
    return False
static boolean hasCycleBrute(ListNode head) {
    Set<ListNode> seen = new HashSet<>();   // ListNode does not override equals: identity
    for (ListNode node = head; node != null; node = node.next)
        if (!seen.add(node)) return true;
    return false;
}

Cost: O(n), O(n) space. Bottleneck: The visited set stores every node: O(n) space.

2Observation

Inside a cycle the faster pointer gains one node per step on the slower, so it cannot jump over it.

3Optimal (two pointers)
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:                    # identity, not value equality
            return True
    return False
static boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;      // reference equality: the same node object
    }
    return false;
}

Cost: time O(n), extra space O(1).

T1. Converging pair search (sorted)

def two_sum_ii(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return [left + 1, right + 1]
        if s < target:
            left += 1          # sum too small: only a bigger left can help
        else:
            right -= 1         # sum too big: only a smaller right can help
    return []
static int[] twoSumII(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        long s = (long) nums[left] + nums[right];   // long: int + int can overflow
        if (s == target) return new int[]{left + 1, right + 1};
        if (s < target) left++;
        else right--;
    }
    return new int[]{};
}
Applies toComplexityThe line most often wrong
Two Sum II, 3Sum Closest, pair with difference, palindrome checks (comparison instead of sum).O(n) time, O(1) spacewhile left < right (not <=), and moving the correct side on "too small" / "too big".

T3. k-Sum (sort + recursive anchors + converging base case)

def k_sum(nums, target, k):
    nums = sorted(nums)
    result = []

    def solve(start, k, target, path):
        if k == 2:                                   # base case: the converging pass
            left, right = start, len(nums) - 1
            while left < right:
                s = nums[left] + nums[right]
                if s == target:
                    result.append(path + [nums[left], nums[right]])
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1
                    left += 1
                    right -= 1
                elif s < target:
                    left += 1
                else:
                    right -= 1
            return
        for i in range(start, len(nums) - k + 1):    # leave room for the other k-1 values
            if i > start and nums[i] == nums[i - 1]:
                continue                             # skip a duplicate anchor
            solve(i + 1, k - 1, target - nums[i], path + [nums[i]])

    solve(0, k, target, [])
    return result
static List<List<Integer>> kSum(int[] nums, long target, int k) {
    int[] a = nums.clone();
    Arrays.sort(a);
    List<List<Integer>> result = new ArrayList<>();
    solveK(a, 0, k, target, new ArrayList<>(), result);
    return result;
}
static void solveK(int[] a, int start, int k, long target, List<Integer> path, List<List<Integer>> result) {
    if (k == 2) {
        int left = start, right = a.length - 1;
        while (left < right) {
            long s = (long) a[left] + a[right];
            if (s == target) {
                List<Integer> t = new ArrayList<>(path);
                t.add(a[left]);
                t.add(a[right]);
                result.add(t);
                while (left < right && a[left] == a[left + 1]) left++;
                while (left < right && a[right] == a[right - 1]) right--;
                left++;
                right--;
            } else if (s < target) left++;
            else right--;
        }
        return;
    }
    for (int i = start; i < a.length - k + 1; i++) {
        if (i > start && a[i] == a[i - 1]) continue;
        path.add(a[i]);
        solveK(a, i + 1, k - 1, target - a[i], path, result);
        path.remove(path.size() - 1);
    }
}

T5. Two sequences (merge)

def merge_sorted(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                   # <= keeps the merge stable
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    result.extend(a[i:])                   # at most one of these two is non-empty

    return result

def sort_colors(nums):

static void sortColors(int[] nums) {

            swap(nums, low, mid);
            low++;
            mid++;

            mid++;
        } else {

}

Exercise 1: Merge and de-duplicate sorted event logs

Backspace String Compare (LeetCode 844) — Type A (backward converging, O(1) space)

Scan both strings from the right. Keep a count of pending backspaces per string; skip characters while the count is positive. Compare the next surviving characters. Both exhausted together means equal. O(n + m) time, O(1) space; the stack version is the brute force.

Brute force
def backspace_compare_brute(s, t):
    def build(x):
        stack = []
        for c in x:
            if c == '#':
                if stack:
                    stack.pop()
            else:
                stack.append(c)
        return stack
    return build(s) == build(t)
static boolean backspaceCompareBrute(String s, String t) {
    return build(s).equals(build(t));
}
static String build(String x) {
    StringBuilder sb = new StringBuilder();
    for (char c : x.toCharArray()) {
        if (c == '#') { if (sb.length() > 0) sb.deleteCharAt(sb.length() - 1); }
        else sb.append(c);
    }
    return sb.toString();
}
Optimal
def backspace_compare(s, t):
    i, j = len(s) - 1, len(t) - 1
    skip_s = skip_t = 0
    while i >= 0 or j >= 0:
        while i >= 0:                              # move i to the next character that survives
            if s[i] == '#':
                skip_s += 1
                i -= 1
            elif skip_s > 0:
                skip_s -= 1
                i -= 1
            else:
                break
        while j >= 0:
            if t[j] == '#':
                skip_t += 1
                j -= 1
            elif skip_t > 0:
                skip_t -= 1
                j -= 1
            else:
                break
        if i >= 0 and j >= 0:
            if s[i] != t[j]:
                return False
        elif i >= 0 or j >= 0:                     # one string ran out, the other did not
            return False
        i -= 1
        j -= 1
    return True
static boolean backspaceCompare(String s, String t) {
    int i = s.length() - 1, j = t.length() - 1, skipS = 0, skipT = 0;
    while (i >= 0 || j >= 0) {
        while (i >= 0) {
            if (s.charAt(i) == '#') { skipS++; i--; }
            else if (skipS > 0) { skipS--; i--; }
            else break;
        }
        while (j >= 0) {
            if (t.charAt(j) == '#') { skipT++; j--; }
            else if (skipT > 0) { skipT--; j--; }
            else break;
        }
        if (i >= 0 && j >= 0) {
            if (s.charAt(i) != t.charAt(j)) return false;
        } else if (i >= 0 || j >= 0) return false;
        i--;
        j--;
    }
    return true;
}
Valid Palindrome II (LeetCode 680) — Type A with one allowed deletion

Converge until the first mismatch, then check whether the inner range with the left character removed, or with the right character removed, is a palindrome. O(n) time, O(1) space. Trying only one side is wrong (Part 10).

Brute force
def valid_palindrome_ii_brute(s):
    def pal(x):
        return x == x[::-1]
    if pal(s):
        return True
    return any(pal(s[:i] + s[i + 1:]) for i in range(len(s)))
static boolean validPalindromeIIBrute(String s) {
    if (isPal(s)) return true;
    for (int i = 0; i < s.length(); i++)
        if (isPal(s.substring(0, i) + s.substring(i + 1))) return true;
    return false;
}
static boolean isPal(String x) {
    return new StringBuilder(x).reverse().toString().equals(x);
}
Optimal
def valid_palindrome_ii(s):
    def pal(l, r):
        while l < r:
            if s[l] != s[r]:
                return False
            l += 1
            r -= 1
        return True
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return pal(left + 1, right) or pal(left, right - 1)   # spend the one deletion here
        left += 1
        right -= 1
    return True
static boolean validPalindromeII(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s.charAt(left) != s.charAt(right))
            return pal(s, left + 1, right) || pal(s, left, right - 1);
        left++;
        right--;
    }
    return true;
}
static boolean pal(String s, int l, int r) {
    while (l < r) {
        if (s.charAt(l) != s.charAt(r)) return false;
        l++;
        r--;
    }
    return true;
}

Boats to Save People (LeetCode 881) — Type A (sort + converge, greedy pairing)

Sort. The heaviest person goes with the lightest if they fit, otherwise alone. Use left <= right: a single person left needs a boat. O(n log n) time. The brute force is an exhaustive subset DP (n at most 8 in the tests).

Brute force
def num_boats_brute(people, limit):
    n = len(people)
    INF = float('inf')
    dp = [INF] * (1 << n)                  # dp[mask] = fewest boats to carry the people in mask
    dp[0] = 0
    for mask in range(1 << n):
        if dp[mask] == INF:
            continue
        for i in range(n):
            if mask & (1 << i):
                continue
            dp[mask | (1 << i)] = min(dp[mask | (1 << i)], dp[mask] + 1)        # i rides alone
            for j in range(i + 1, n):
                if not mask & (1 << j) and people[i] + people[j] <= limit:
                    dp[mask | (1 << i) | (1 << j)] = min(dp[mask | (1 << i) | (1 << j)], dp[mask] + 1)
    return dp[(1 << n) - 1]
static int numBoatsBrute(int[] people, int limit) {
    int n = people.length;
    int INF = Integer.MAX_VALUE / 2;
    int[] dp = new int[1 << n];
    Arrays.fill(dp, INF);
    dp[0] = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        if (dp[mask] == INF) continue;
        for (int i = 0; i < n; i++) {
            if ((mask & (1 << i)) != 0) continue;
            int m1 = mask | (1 << i);
            dp[m1] = Math.min(dp[m1], dp[mask] + 1);
            for (int j = i + 1; j < n; j++) {
                if ((mask & (1 << j)) == 0 && people[i] + people[j] <= limit) {
                    int m2 = m1 | (1 << j);
                    dp[m2] = Math.min(dp[m2], dp[mask] + 1);
                }
            }
        }
    }
    return dp[(1 << n) - 1];
}
Optimal
def num_boats(people, limit):
    people = sorted(people)
    left, right = 0, len(people) - 1
    boats = 0
    while left <= right:                    # <=: a single person left still needs a boat
        if people[left] + people[right] <= limit:
            left += 1                       # the lightest person shares with the heaviest
        right -= 1                          # the heaviest always leaves
        boats += 1
    return boats
static int numBoats(int[] people, int limit) {
    int[] a = people.clone();
    Arrays.sort(a);
    int left = 0, right = a.length - 1, boats = 0;
    while (left <= right) {
        if (a[left] + a[right] <= limit) left++;
        right--;
        boats++;
    }
    return boats;
}

def four_sum(nums, target):
    nums = sorted(nums)
    n, result = len(nums), []
    for i in range(n - 3):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        for j in range(i + 1, n - 2):
            if j > i + 1 and nums[j] == nums[j - 1]:
                continue
            left, right = j + 1, n - 1
            while left < right:
                s = nums[i] + nums[j] + nums[left] + nums[right]
                if s == target:
                    result.append([nums[i], nums[j], nums[left], nums[right]])
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1
                    left += 1
                    right -= 1
                elif s < target:
                    left += 1
                else:
                    right -= 1
    return result
static List<List<Integer>> fourSum(int[] nums, int target) {
    int[] a = nums.clone();
    Arrays.sort(a);
    int n = a.length;
    List<List<Integer>> result = new ArrayList<>();
    for (int i = 0; i < n - 3; i++) {
        if (i > 0 && a[i] == a[i - 1]) continue;
        for (int j = i + 1; j < n - 2; j++) {
            if (j > i + 1 && a[j] == a[j - 1]) continue;
            int left = j + 1, right = n - 1;
            while (left < right) {
                long s = (long) a[i] + a[j] + a[left] + a[right];   // long: four ints can overflow
                if (s == target) {
                    result.add(Arrays.asList(a[i], a[j], a[left], a[right]));
                    while (left < right && a[left] == a[left + 1]) left++;
                    while (left < right && a[right] == a[right - 1]) right--;
                    left++;
                    right--;
                } else if (s < target) left++;
                else right--;
            }
        }
    }

}

Input constraints respected

  • Sorted inputs are generated sorted (non-decreasing) with many duplicates; values are small so ties are frequent.
  • Merge Sorted Array: m sorted values then n zeros of padding; sizes include 0.
  • Linked lists: many equal values, so a value-based comparison would give false positives; cycle detection uses 0 to 9 nodes with a random cycle position or none; middle of the list uses 1 to 10 nodes.
  • Container With Most Water uses at least two walls. Boats to Save People: every weight is at most the limit. 3Sum Closest: at least three numbers.
  • 4Sum includes inputs with values near +/-109 so Java int overflow would be caught.
  • Strings use a small ASCII alphabet (letters, digits, space, punctuation). Non-ASCII behaviour of isalnum versus Character.isLetterOrDigit was not tested.
  • Two Sum II returns "no pair" for no answer (LeetCode guarantees one); the harness validates that a returned pair is real (distinct indices, correct sum) and that existence agrees with the brute force, rather than demanding the identical pair.
