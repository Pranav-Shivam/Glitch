Sliding Window

A window is a contiguous slice of an array or string. Slide it one element at a time and update what you know about it, instead of recomputing every slice from scratch. That turns O(n²) and O(n·k) scans into a single O(n) pass.

Part 1First Principles

In one paragraph. A sliding window keeps a running summary of one contiguous slice of an array or string, and moves that slice along the input one element at a time: one element enters on the right, and (when the rule needs it) one leaves on the left. The summary is updated in O(1) instead of being rebuilt from scratch, so a problem that looks like "check every subarray" (O(n²), or O(n·k) for fixed-size windows) becomes one left-to-right pass: O(n).

What it is

A window is a contiguous chunk of an array or string, described by two indices:

index:   0   1   2   3   4   5   6
nums:  [ 2 , 1 , 5 , 1 , 3 , 2 , 4 ]
               ↑           ↑
             left        right
               └─ window ──┘   = nums[2..4] = [5, 1, 3]

Sliding means you move this window across the input. You add the element entering on the right and remove the element leaving on the left. You never rebuild the window from scratch.

video The window is your area of concern. At any moment you only care about the elements inside it, and every result you report is derived from the state of that window. That is what keeps you focused: you are never looking at the whole array, only at one segment and how it changes by one element.

Terminology:

Term Meaning
Contiguous Elements next to each other, with no gaps. [5,1,3] is contiguous in the array above. [2,5,3] is not.
Subarray / substring A contiguous piece of an array / string.
Subsequence Elements in order, but gaps are allowed. Sliding window does not handle these.
Window state Whatever you track about the current window: sum, character counts, number of distinct items, max.
Expand Move right forward (right++), which adds an element.
Shrink Move left forward (left++), which removes an element.
Valid window A window that satisfies the problem's condition, e.g. "no repeated characters".

Why it exists — the problem it solves

Many problems ask about every contiguous subarray (or every one of length k):

"Find the maximum sum of any 3 consecutive elements."

The naive way recomputes each window independently:

[2,1,5] → 2+1+5 = 8
  [1,5,1] → 1+5+1 = 7     ← recomputed 1 and 5 again
    [5,1,3] → 5+1+3 = 9   ← recomputed 5 and 1 again

Neighbouring windows overlap almost entirely. Only one element leaves and one enters:

[2, 1, 5]            sum = 8
    [1, 5, 1]        sum = 8 - 2 + 1 = 7     (remove 2, add 1)
       [5, 1, 3]     sum = 7 - 1 + 3 = 9     (remove 1, add 3)

Core idea: reuse the work from the previous window. Update the state incrementally in O(1) instead of recomputing it in O(k).

video The same idea is asked in many different wordings. "Maximum sum of a subarray of size k", "maximum average of a subarray of size k" and "maximum number of vowels in a substring of size k" are one problem with three different pieces of state (a sum, a sum divided by k, a vowel count). Once you see the window, only the state changes.

How it works conceptually

There are two kinds of windows.

1. Fixed-size window. The size is always k. Both pointers move together.

[ 2  1  5 ] 1  3  2      →   2 [ 1  5  1 ] 3  2      →   2  1 [ 5  1  3 ] 2

2. Variable-size window. The size changes. right expands to explore, and left shrinks to fix problems.

Expand right until the window breaks the rule
        ↓
Shrink left until the rule holds again
        ↓
Record the answer
        ↓
Repeat until right reaches the end

Finish the scan keep going until right has visited every element

The core invariant

An invariant is a fact that is true at the same point of every loop iteration. It is what you rely on to argue the code is correct. Sliding window has one invariant with two halves:

1. SUMMARY MATCHES SLICE
   After each update, the state describes exactly arr[left..right].
   No element outside the window is still counted, and none inside is missing.

2. NOTHING USEFUL IS DISCARDED   (variable windows only)
   Every start index below `left` has been proven useless for the current
   right AND for every later right. That proof is the monotonic condition below.
   So left only moves forward, and no answer is lost.

Every pattern in Part 4 is this invariant with a more specific second sentence, and each pattern card states its own version. If you cannot say what your invariant is, you cannot yet say why your code is correct. That is the sentence to say aloud in an interview before you write the loop.

The one condition that makes it work (most important idea)

A variable window works only when validity is monotonic. Shrinking a window must never make a valid window invalid, and growing it must never make an invalid window valid. Then you can be sure of two things:

  • When the window becomes invalid, moving left forward is the right fix.
  • You never need to move left backwards.

Example (works): "Longest substring with no repeated characters." If "abc" has no repeats, then "bc" has no repeats either. Removing elements can't create a duplicate.

Example (breaks): "Longest subarray with sum exactly 5" when negatives are present. [3, -2, 4] has sum 5, and [3, -2] has sum 1. Adding 4 fixed it. Since adding can fix a window and removing can break it, you don't know which way to move. Use prefix sums + a hash map instead.

Before using a variable sliding window, ask: "If I shrink a valid window, does it stay valid? If I grow an invalid one, does it stay invalid?" If yes, the window applies.

The video does not state this condition, but every one of its variable-window examples satisfies it. In particular, its "minimum size subarray with sum ≥ 7" walkthrough works only because all the numbers are positive, so growing the window always raises the sum and shrinking always lowers it.

Fixed windows do not need monotonicity. Negative numbers are fine in "maximum sum of size k", because the window never has to decide which way to move.

When to use it

  • video The structure is linear: an array or a string (a linked list or a stream also works). Not trees or graphs.
  • The problem is about contiguous subarrays or substrings.
  • You want the longest, shortest, maximum, minimum, or count of subarrays satisfying a condition.
  • The condition can be maintained incrementally (sum, counts, distinct count).
  • For variable windows, the condition is monotonic as described above.

When NOT to use it

  • Subsequences (non-contiguous) → usually DP.
  • Sum problems with negative numbers and a variable window → prefix sum + hash map.
  • Unsorted pair problems like "find two numbers summing to X" → hash map.
  • Problems needing the k-th largest inside a window → heaps (later topic).

Where you already meet it

General knowledge, not researched or run here. These are examples to anchor the idea.

  • TCP flow control. The sender keeps a "window" of bytes sent but not yet acknowledged. When an ACK arrives the left edge moves forward and more data may enter on the right.
  • Rate limiters. "At most 100 requests per user in any 60 seconds" is a window over the last 60 seconds of timestamps. The left edge is now - 60s. See Part 15.
  • Moving averages and rolling metrics. A 7-day average on a dashboard, or rate(x[5m]) in a monitoring query, recomputes from a window that slides with time. In pandas it is df.rolling(7), in SQL it is ROWS BETWEEN 6 PRECEDING AND CURRENT ROW.
  • Rolling hashes. Rabin-Karp substring search hashes every length-k window by removing the leaving character and adding the entering one, the same "one in, one out" update as Type A.
  • "Trending in the last N minutes". A stream of events where old ones expire is a window over time instead of over indices (the practical exercise in Part 15).

2A. The tools

1. Looping with the index, and the window length

Almost every window loop walks right and needs both the index (for the length) and the value. Window length = right - left + 1 (inclusive on both ends). Memorize this.

def tk_loop():
    s = "abca"
    out = []
    for right, ch in enumerate(s):        # index AND value
        out.append(str(right) + ch)
    left, right = 1, 3
    return "".join(out) + "|" + str(right - left + 1)   # window length is right - left + 1
static String tkLoop() {
    String s = "abca";
    StringBuilder out = new StringBuilder();
    for (int right = 0; right < s.length(); right++) {
        char ch = s.charAt(right);              // O(1)
        out.append(right).append(ch);
    }
    int left = 1, right = 3;
    return out + "|" + (right - left + 1);      // window length is right - left + 1
}

2. A dictionary or map for counts

Add and remove are O(1) on average. Delete a key when its count hits zero, so the number of keys equals the number of distinct items in the window. In Python, defaultdict(int) removes the .get call, but the delete-at-zero rule still applies.

def tk_count():
    count = {}
    count['a'] = count.get('a', 0) + 1    # add:    O(1)
    count['a'] = count.get('a', 0) + 1
    count['b'] = count.get('b', 0) + 1
    count['a'] -= 1                       # remove: O(1)
    count['b'] -= 1
    if count['b'] == 0:
        del count['b']                    # keep len(count) == number of distinct keys
    return len(count)                     # distinct elements in the window: O(1)
static int tkCount() {
    Map<Character, Integer> count = new HashMap<>();
    count.merge('a', 1, Integer::sum);                  // add: count['a'] += 1
    count.merge('a', 1, Integer::sum);
    count.merge('b', 1, Integer::sum);
    count.merge('a', -1, Integer::sum);                 // remove
    if (count.merge('b', -1, Integer::sum) == 0) {      // merge returns the new value
        count.remove('b');                              // keep size() == number of distinct keys
    }
    return count.size();                                // distinct elements in the window
}

Ran: distinct count 1 in both languages.

3. Letter counts: Counter in Python, int[26] in Java

For lowercase letters an int[26] indexed by ch - 'a' is the fastest count map in Java: O(1) space, no hashing. For any ASCII character use new int[128] and index with the char itself. For other keys use a HashMap with merge and getOrDefault. Comparing two of them is 26 steps, which counts as O(1). Python's Counter returns 0 for a missing key and compares by counts, not order, but the comparison costs O(distinct keys), not O(1).

def tk_counter():
    need = Counter("aab")                 # {'a': 2, 'b': 1}   O(len)
    missing = need['z']                   # 0, and no KeyError
    same = Counter("ab") == Counter("ba") # compares counts, not order
    return str(need['a']) + str(missing) + str(same)
static String tkCounter() {
    int[] need = new int[26];
    for (char c : "aab".toCharArray()) need[c - 'a']++;     // letter counts, O(len)
    int missing = need['z' - 'a'];                          // 0, no null check
    int[] other = new int[26], other2 = new int[26];
    for (char c : "ab".toCharArray()) other[c - 'a']++;
    for (char c : "ba".toCharArray()) other2[c - 'a']++;
    boolean same = Arrays.equals(other, other2);            // 26 comparisons
    return "" + need['a' - 'a'] + missing + (same ? "True" : "False");
}

4. A set: "is it already in my window?"

Java's add() returns false when the element was already present, which is a free duplicate check.

def tk_set():
    seen = set()
    seen.add('a')                         # O(1) average
    dup = 'a' in seen                     # membership: O(1) average
    seen.remove('a')
    return str(dup) + str(len(seen))
static String tkSet() {
    Set<Character> seen = new HashSet<>();
    boolean first = seen.add('a');              // true: it was new
    boolean again = seen.add('a');              // false: already present, a free duplicate check
    seen.remove('a');
    return "" + first + again + seen.size();
}

5. A deque: remove from both ends in O(1)

You need it for Sliding Window Maximum. In Java use ArrayDeque. In Python use collections.deque, never list.pop(0).

def tk_deque():
    dq = deque()
    dq.append(5)                          # push right  O(1)
    dq.append(7)
    dq.append(9)
    last = dq.pop()                       # pop right   O(1)
    first = dq.popleft()                  # pop left    O(1)  (list.pop(0) is O(n))
    return str(last) + str(first) + str(dq[0]) + str(dq[-1])   # peek both ends: O(1)
static String tkDeque() {
    Deque<Integer> dq = new ArrayDeque<>();
    dq.offerLast(5);                            // push right
    dq.offerLast(7);
    dq.offerLast(9);
    int last = dq.pollLast();                   // pop right
    int first = dq.pollFirst();                 // pop left
    return "" + last + first + dq.peekFirst() + dq.peekLast();   // peek both ends
}

Ran: both languages print 9577 (last popped, first popped, front, back).

6. "No answer yet" for minimum problems

Start best at infinity (Python) or Integer.MAX_VALUE (Java), and convert it back to the required "no answer" value (usually 0 or -1) before returning.

def tk_inf():
    best = float('inf')                   # "no answer yet" for minimum-length problems
    nothing = 0 if best == float('inf') else best
    best = min(best, 3)
    return str(nothing) + str(best)
static String tkInf() {
    int best = Integer.MAX_VALUE;               // "no answer yet" for minimum-length problems
    int nothing = best == Integer.MAX_VALUE ? 0 : best;

}

Slicing copies

Both a Python slice and Arrays.copyOfRange / substring make a new object. Changing the copy does not touch the original, and the copy costs O(length).

def tk_copy():
    a = [1, 2, 3, 4]
    b = a[1:3]                            # slicing COPIES: O(length of the slice)
    b[0] = 99
    return str(a[1]) + str(b[0])          # the original is untouched
static String tkCopy() {
    int[] a = {1, 2, 3, 4};
    int[] b = Arrays.copyOfRange(a, 1, 3);      // also a copy: O(length of the slice)
    b[0] = 99;
    String s = "abcd";
    String t = s.substring(1, 3);               // substring copies too: O(length)
    return "" + a[1] + b[0] + t;                // the original is untouched
}

Python trap: mutable default argument

The first function below keeps results from earlier calls because its default list is created once, when the function is defined. Java has no default arguments, so the equivalent trap is a static field that is reused across calls (the Java side shows that).

def tk_window_sums(nums, k, out=[]):      # TRAP: the default list is created ONCE

def tk_window_sums_ok(nums, k, out=None):  # fix: None, then a fresh list per call

Java trap: == on boxed Integers

The Java output is three results in a row: a == b for 1000, c == d for 100, then a.equals(b). This is why map.get(a) == map.get(b) is a bug above 127. The 127 limit is the default Integer cache; it can be changed with a JVM flag, so never rely on it.

def tk_boxed():
    a, b = 1000, 1000
    return str(a == b)                    # Python == always compares values
static String tkBoxed() {
    Integer a = 1000, b = 1000;                 // boxed objects
    Integer c = 100, d = 100;                   // small values come from a cache (-128..127)

Part 3Complexity

The key argument: amortized O(n)

Beginners see a while loop inside a for loop and assume O(n²). It's actually O(n):

left never moves backwards and never passes n. Across the entire run the inner while executes at most n times in total, not n times per iteration.

Each element is added once  (when right reaches it)    → n operations
Each element is removed once (when left passes it)     → n operations
Total = 2n = O(n)

This is amortized analysis: an individual step might do a lot of work, but the total work is bounded.

video This is what the video means by "it removes the O(n²) complexity": the brute force restarts from every index, the window makes one pass and never revisits an element more than twice.

Why the nested loop is O(n): the counting argument

Do not count work per iteration of the for loop. Count work per element, over the whole run:

for right in range(n):          # right takes n values, each used once   -> n ADDs
    while invalid:
        left += 1                # left only ever increases and never passes right
                                 # so it takes at most n values in total  -> at most n REMOVEs

total work  <=  n adds + n removes  =  2n  = O(n)
(The inner loop may run 0 times for most steps and many times for one step.
 It cannot run many times for every step, because left is shared, not reset.)

That is an amortized argument: the cost of one step can be large, but the total over all steps is bounded, so the average cost per step is O(1). It holds only if the work inside the loop is O(1) per add and per remove. If the shrink step recomputes a sum, takes max(window), slices a substring, or calls list.pop(0), each remove costs O(k) and the total is O(n·k) again.

The same argument for the monotonic deque

Each index is pushed once and popped at most once (from the back when dominated, or from the front when expired). So the inner while in Type F is also O(n) in total, even though one step can pop many entries.

Evidence, not just argument

These two functions count the operations. They were run on 5,000 random inputs each, in Python and in Java. In every run the window made exactly n adds and at most n removes, and the deque made exactly n pushes and at most n pops.

def longest_k_distinct_counted(s, k):
    count = {}
    left = best = adds = removes = 0
    for right, ch in enumerate(s):
        count[ch] = count.get(ch, 0) + 1
        adds += 1                             # one add per right
        while len(count) > k:
            out = s[left]
            count[out] -= 1
            if count[out] == 0:
                del count[out]
            left += 1
            removes += 1                      # one remove per left move
        best = max(best, right - left + 1)
    return [best, adds, removes]
static int[] longestKDistinctCounted(String s, int k) {
    Map<Character, Integer> count = new HashMap<>();
    int left = 0, best = 0, adds = 0, removes = 0;
    for (int right = 0; right < s.length(); right++) {
        count.merge(s.charAt(right), 1, Integer::sum);
        adds++;                                 // one add per right
        while (count.size() > k) {
            char out = s.charAt(left);
            if (count.merge(out, -1, Integer::sum) == 0) count.remove(out);
            left++;
            removes++;                          // one remove per left move
        }
        best = Math.max(best, right - left + 1);
    }
    return new int[]{best, adds, removes};
}
def max_sliding_window_counted(nums, k):
    dq = deque()
    res = []
    pushes = pops = 0
    for right, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()
            pops += 1
        dq.append(right)
        pushes += 1                           # one push per index
        if dq[0] <= right - k:
            dq.popleft()
            pops += 1
        if right >= k - 1:
            res.append(nums[dq[0]])
    return res + [pushes, pops]               # counters appended after the answer
static int[] maxSlidingWindowCounted(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1 + 2];
    Deque<Integer> dq = new ArrayDeque<>();
    int pushes = 0, pops = 0;
    for (int right = 0; right < n; right++) {
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[right]) {
            dq.pollLast();
            pops++;
        }
        dq.offerLast(right);
        pushes++;                               // one push per index
        if (dq.peekFirst() <= right - k) {
            dq.pollFirst();
            pops++;
        }
        if (right >= k - 1) res[right - k + 1] = nums[dq.peekFirst()];
    }
    res[n - k + 1] = pushes;                    // counters appended after the answer
    res[n - k + 2] = pops;
    return res;
}

Looks worse than it is: a loop inside a loop is O(n²) only when the inner loop restarts from scratch each time. Here the inner loop resumes from where it stopped, because left lives outside both loops.

A

Fixed-Size Window

  1. What: A window of exactly size k slides one step at a time.
  2. Solves: "For every block of k consecutive elements, compute something."
  3. Recognize: The problem says "of length k", "k consecutive", "size k". video Also "moving average" and "rolling sum".
  4. Intuition: One element in, one element out. Update the state, don't rebuild it.
Core invariant (Type A)

After every step, the state describes exactly arr[right-k+1 .. right], the k newest elements. The element that just left is no longer counted.

The five blanks for this type

STATEan aggregate of the last k elements: a sum, a count, a set, a map
VALIDnot needed: the size is fixed. (Some problems add a CHECK, such as "is this value already in the set?")
ADD / REMOVEarr[right] enters, arr[right - k] leaves
RECORDonce per step, from the first full window on
Algorithm
1. If k > n (or k <= 0), there is no window: return the problem's "no answer" value.
2. Build the STATE for the first window, indices 0 .. k-1.        (O(k), done once)
3. RECORD the answer for this first window.
4. For right = k, k+1, ..., n-1:
     a. ADD    arr[right]        (the element entering)
     b. REMOVE arr[right - k]    (the element that just fell out)
     c. RECORD the answer for the window [right-k+1 .. right]
5. Return the answer.

Skeleton (shown with a sum as the state)

def fixed_window(arr, k):
    state = sum(arr[:k])                  # STATE for the first window
    best = state                          # RECORD the first window
    for right in range(k, len(arr)):
        state += arr[right]               # ADD the element entering
        state -= arr[right - k]           # REMOVE the element leaving
        best = max(best, state)           # RECORD
    return best
static int fixedWindow(int[] arr, int k) {
    int state = 0;
    for (int i = 0; i < k; i++) state += arr[i];    // STATE for the first window
    int best = state;                               // RECORD the first window
    for (int right = k; right < arr.length; right++) {
        state += arr[right];                        // ADD the element entering
        state -= arr[right - k];                    // REMOVE the element leaving
        best = Math.max(best, state);               // RECORD
    }
    return best;
}

B

Variable Window: Longest Valid

  1. What: Grow the window as far as possible while it stays valid.
  2. Solves: "Longest / maximum-length subarray satisfying a rule."
  3. Recognize: "longest substring with…", "maximum length subarray where…", "at most k …".
  4. Intuition: Greedily expand. When the rule breaks, shrink from the left only as much as needed to restore it. Record the answer only when the window is valid.
Core invariant (Type B)

At RECORD time, [left..right] is valid and left is as small as possible for this right. Every start index below left was invalid for some earlier right, and by monotonicity stays invalid for every later right, so no longer window is ever skipped.

The five blanks for this type

STATEwhatever answers "is the window valid?": set, count map, a counter of zeros
VALIDa condition on the state that stays true when you shrink (monotonic)
ADD / REMOVEadd arr[right]; while invalid, remove arr[left] and left += 1
RECORDbest = max(best, right - left + 1) after the shrink loop
Algorithm
1. left = 0, best = 0, STATE = empty.
2. For right = 0, 1, ..., n-1:
     a. ADD arr[right] to the state.               (expand)
     b. While the window is INVALID:
            REMOVE arr[left] from the state
            left += 1                              (shrink)
     c. The window [left .. right] is now valid.
        RECORD: best = max(best, right - left + 1)
3. Return best.

C

Variable Window: Shortest Valid

  1. What: Find the smallest window that satisfies a rule.
  2. Solves: "Minimum length subarray / substring that contains / reaches X."
  3. Recognize: "minimum length", "smallest subarray with sum ≥ target", "minimum window containing".
  4. Intuition: Opposite of Type B. Expand until the window becomes valid, then shrink while it stays valid, recording the answer at each step, because every shrink gives a smaller candidate.
Core invariant (Type C)

Inside the while, the window is valid, so every recorded length is real. A start index is retired the first time its window becomes valid, which is exactly its shortest valid window, so it never needs to be looked at again. When the loop exits the window is invalid and the answer so far is final for all starts below left.

STATEa sum, or counts plus "how many requirements are still missing"
VALIDthe window already meets the goal (and meeting it stays true when you grow)

RECORDbest = min(best, right - left + 1) inside the loop, before the removal

1. left = 0, best = infinity, STATE = empty.
2. For right = 0, 1, ..., n-1:
     a. ADD arr[right] to the state.               (expand)

            REMOVE arr[left] from the state
            left += 1                              (shrink)

D

Counting Subarrays

  1. What: Count how many subarrays satisfy a condition.
  2. Solves: "Number of subarrays where …"
  3. Recognize: "count the number of subarrays", "how many contiguous …".

  4. Intuition: After shrinking, [left..right] is the longest valid window ending at right. Every window ending at right and starting anywhere from left to right is also valid (monotonicity). That's right - left + 1 subarrays.

    left=2, right=4 → valid subarrays ending at 4:
[2..4], [3..4], [4..4]  → 3 = right - left + 1
Core invariant (Type D)

After the shrink loop, left is the smallest start for which [start..right] is valid. By monotonicity every start from left to right is valid and every start below left is not, so exactly right - left + 1 valid subarrays end at right.

E

Fixed Window with Frequency Matching

  1. What: A fixed window whose state is a frequency map, compared against a target map.
  2. Solves: "Does s contain a permutation/anagram of p?" / "Find all anagram positions."
  3. Recognize: "permutation", "anagram", "rearrangement of" together with "substring".
  4. Intuition: Two strings are anagrams exactly when their character counts are equal. Order inside the window doesn't matter, so the counts are the whole state. The window size is fixed at len(p).
Core invariant (Type E)

After each slide, window[c] equals the number of times letter c appears in s[right-k+1 .. right]. Two strings are permutations of each other exactly when all their letter counts are equal, so comparing the two count tables is an exact test.

The five blanks for this type

STATEletter counts of the window, plus the fixed counts of the target
VALIDthe two count tables are equal
ADD / REMOVEwindow[s[right]] += 1, window[s[right - k]] -= 1
RECORDwhen equal: return true, or collect the start index right - k + 1
Algorithm
1. k = len(p). If k > len(s): no window fits, return false / empty list.
2. need   = character counts of p.
3. window = character counts of s[0 .. k-1].
4. If window == need: RECORD (index 0).
5. For right = k, ..., len(s)-1:
     a. ADD    s[right]       : window[s[right]] += 1
     b. REMOVE s[right - k]   : window[s[right-k]] -= 1   (delete the key at 0 if using a map)
     c. If window == need: RECORD (start index right - k + 1)
6. Return the result.

def check_inclusion(p, s):
    k = len(p)
    if k > len(s):
        return False
    need = Counter(p)
    window = Counter(s[:k])
    if window == need:
        return True
    for right in range(k, len(s)):
        window[s[right]] += 1             # entering
        out = s[right - k]                # leaving
        window[out] -= 1
        if window[out] == 0:
            del window[out]               # not needed for Counter on 3.10+, needed for a plain dict
        if window == need:
            return True
    return False
static boolean checkInclusion(String p, String s) {
    int k = p.length();
    if (k > s.length()) return false;
    int[] need = new int[26];
    int[] window = new int[26];
    for (int i = 0; i < k; i++) {
        need[p.charAt(i) - 'a']++;
        window[s.charAt(i) - 'a']++;
    }
    if (Arrays.equals(need, window)) return true;
    for (int right = k; right < s.length(); right++) {
        window[s.charAt(right) - 'a']++;        // entering
        window[s.charAt(right - k) - 'a']--;    // leaving
        if (Arrays.equals(need, window)) return true;   // 26 comparisons
    }
    return false;
}

F

Window Extreme with a Monotonic Deque

  1. What: Track the max (or min) of every window in O(1) amortized per step.
  2. Solves: "Maximum in each window of size k."
  3. Recognize: "max/min of each window", "sliding window maximum", or any condition depending on the window's max − min. video These are the "min and max queues" in the video's list of window state.
  4. Intuition: A sum is easy to update (subtract the leaving element), but a max is not. If the max leaves, what's the new max? Keep a deque of indices whose values are decreasing. When a new big element arrives, every smaller element before it can never be a window max again, because the new one is bigger and will stay in the window longer. Throw them away.
Core invariant (Type F)

The deque holds indices from the current window, increasing left to right, with strictly decreasing values. So the front is always the window maximum. Any index that is not in the deque is either expired (≤ right - k) or dominated: a later element that is at least as large will stay in the window longer.

The five blanks for this type

STATEa deque of indices (not values), values decreasing
VALIDfront index is inside the window: front > right - k
ADD / REMOVEpop back while arr[back] <= arr[right], push right; pop front if expired
RECORDarr[front] once right >= k - 1
Algorithm
The deque holds INDICES. Their values are strictly decreasing from front to back,
so the front is always the index of the current window's maximum.

For right = 0, 1, ..., n-1:
  1. While the deque is not empty and arr[back] <= arr[right]: pop the back.
     (those elements are dominated by arr[right])
  2. Push right onto the back.
  3. If front <= right - k: pop the front.        (it has slid out of the window)
  4. If right >= k - 1: output arr[front].        (the window is full)

Template. Like Type E, this one is always written the same way.

def max_sliding_window(nums, k):
    dq = deque()                          # indices; their values are decreasing
    res = []
    for right, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()                      # dominated: can never be a max again
        dq.append(right)
        if dq[0] <= right - k:
            dq.popleft()                  # front has left the window
        if right >= k - 1:                # first full window reached
            res.append(nums[dq[0]])
    return res
static int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();     // indices; values decreasing
    for (int right = 0; right < n; right++) {
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[right]) {
            dq.pollLast();                      // dominated: never a max again
        }
        dq.offerLast(right);
        if (dq.peekFirst() <= right - k) {
            dq.pollFirst();                     // front has left the window
        }
        if (right >= k - 1) {                   // first full window reached
            res[right - k + 1] = nums[dq.peekFirst()];
        }
    }
    return res;
}

Time: O(n), since each index is pushed once and popped at most once. Space: O(k). For window minimum: flip <= to >= in step 1, so the deque is increasing. Tiny example: nums=[1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]. Solved in Part 7: Problem 15.

When the window fails: what to write instead

The lookalike you will meet most often is "count subarrays with sum exactly k" where the array can contain negatives (LeetCode 560). A window cannot decide whether to grow or shrink, so use the Hashing topic's tool: a running prefix sum and a map of the prefix sums seen so far.

The sum of nums[i..j] is prefix[j] − prefix[i−1]. So a subarray ending at j sums to k exactly when some earlier prefix equals prefix[j] − k. Count how many earlier prefixes have that value.

def subarray_sum_equals_k(nums, k):
    seen = {0: 1}                         # prefix sum -> how many times seen so far
    prefix = ans = 0
    for x in nums:
        prefix += x
        ans += seen.get(prefix - k, 0)    # earlier prefixes that leave a sum of exactly k
        seen[prefix] = seen.get(prefix, 0) + 1
    return ans
static int subarraySumEqualsK(int[] nums, int k) {
    Map<Integer, Integer> seen = new HashMap<>();   // prefix sum -> times seen so far
    seen.put(0, 1);
    int prefix = 0, ans = 0;
    for (int x : nums) {
        prefix += x;
        ans += seen.getOrDefault(prefix - k, 0);    // earlier prefixes that leave exactly k
        seen.merge(prefix, 1, Integer::sum);
    }
    return ans;
}

Time: O(n). Space: O(n) for the map. Compare with a window's O(1): that extra space is the price of handling negatives.

Proof that the window fails on negatives (run, not just argued)

Count subarrays of [1, -1, 1] whose sum is exactly 1. The subarrays are [1], [1, -1, 1] and the last [1]: 3. The window version below returns 2, in Python and in Java. When the window sum is already 0 at the second element, nothing says "shrink", and when the third element arrives the window has long since dropped the 1 at the start.

def subarray_sum_equals_k_window(nums, k):      # BUG: a window cannot handle negatives
    left = total = ans = 0
    for right, x in enumerate(nums):
        total += x
        while total > k and left <= right:    # "too big, shrink" is false when negatives follow
            total -= nums[left]
            left += 1
        if total == k:
            ans += 1
    return ans

    for (int right = 0; right < nums.length; right++) {

Part 6Brute Force → Optimization

Every solved problem in Part 7 follows the same chain:

Brute Force        enumerate every window / every (start, end) pair
    ↓
Why it is slow     neighbouring windows overlap; the same elements are re-processed
    ↓
Observation        one of the three below
    ↓
Better approach    keep the state, update it for one element in and one out
    ↓
Optimal            a single left-to-right pass: O(n)

The three observations that turn brute force into a window

Observation 1 — overlap (fixed windows). Two consecutive windows of size k share k−1 elements, so new_state = old_state − leaving + entering. This removes the inner loop over k. (Problems 1–5, 15.)

Observation 2 — don't restart (variable windows). The brute force, after failing at j from start i, goes back and rebuilds everything from i+1. But [i+1 .. j-1] is a shrunk version of a window you already know is valid, so by monotonicity it is still valid. Keep right where it is and only move left. This removes the restart. (Problems 6–12.)

Observation 3 — count by ending position (counting). Instead of testing each (start, end) pair, find for each right the smallest valid left. All right − left + 1 starts in between are valid, so add them in one step. (Problems 13, 14.)

Where it is reported. added for pattern coverage The classic "maximum sum of k consecutive elements" exercise from the video. It is not a LeetCode problem and was not found in the sources checked.

Problem. Given an integer array nums and an integer k, return the largest sum of any k consecutive elements.

Example. nums = [-2, -5, 6, 4, 3, 8], k = 4 → 21 (the window [6, 4, 3, 8]). This array reproduces the video's walkthrough: the window sums go 3 → 8 → 21.

1Brute force

Try every start index i, and add up the k elements from there.

def max_sum_k_brute(nums, k):
    n = len(nums)
    if k <= 0 or k > n:
        return None                       # no window of size k exists
    best = float('-inf')
    for i in range(n - k + 1):            # every possible start
        total = 0
        for j in range(i, i + k):         # re-add all k elements
            total += nums[j]
        best = max(best, total)
    return best
static int maxSumKBrute(int[] nums, int k) {
    int n = nums.length;
    if (k <= 0 || k > n) throw new IllegalArgumentException("no window of size k");
    int best = Integer.MIN_VALUE;
    for (int i = 0; i + k <= n; i++) {          // every possible start
        int total = 0;
        for (int j = i; j < i + k; j++) {       // re-add all k elements
            total += nums[j];
        }
        best = Math.max(best, total);
    }
    return best;
}

Time: O(n·k), there are n−k+1 windows and each costs k additions. Space: O(1).

2Why it is slow → observation

Windows [i .. i+k-1] and [i+1 .. i+k] share k−1 elements, and the brute force adds those again. Only one element leaves and one enters, so new_sum = old_sum − leaving + entering.

3Optimal: fixed window
STATE window = sum of the current k elements
ADD window += nums[right]
REMOVE window -= nums[right - k]
RECORD best = max(best, window) after every slide
Algorithm
  1. If k > n, no window exists.
  2. Sum the first k elements. That is the first window and the first best.
  3. For each right from k to n−1: add nums[right], subtract nums[right − k], update best.
  4. Return best.
def max_sum_k(nums, k):
    n = len(nums)
    if k <= 0 or k > n:
        return None
    window = sum(nums[:k])                # first window, built once: O(k)
    best = window
    for right in range(k, n):
        window += nums[right]             # element entering on the right
        window -= nums[right - k]         # element leaving on the left
        best = max(best, window)
    return best
static int maxSumK(int[] nums, int k) {
    int n = nums.length;
    if (k <= 0 || k > n) throw new IllegalArgumentException("no window of size k");
    int window = 0;
    for (int i = 0; i < k; i++) window += nums[i];   // first window: O(k)
    int best = window;
    for (int right = k; right < n; right++) {
        window += nums[right];                  // element entering
        window -= nums[right - k];              // element leaving
        best = Math.max(best, window);
    }
    return best;
}

Time: O(n). Space: O(1).

Variant — return the window itself

video "If you want to return that array, you can keep a track of these four elements also." You do not need to store the elements. Remember the start index of the best window and cut the subarray out once, at the end.

def max_sum_window(nums, k):
    window = sum(nums[:k])
    best, best_start = window, 0
    for right in range(k, len(nums)):
        window += nums[right] - nums[right - k]
        if window > best:
            best, best_start = window, right - k + 1   # where this window starts
    return nums[best_start:best_start + k]             # slice once, at the end
static int[] maxSumWindow(int[] nums, int k) {
    int window = 0;
    for (int i = 0; i < k; i++) window += nums[i];
    int best = window, bestStart = 0;
    for (int right = k; right < nums.length; right++) {
        window += nums[right] - nums[right - k];
        if (window > best) {
            best = window;
            bestStart = right - k + 1;              // where this window starts
        }
    }
    return Arrays.copyOfRange(nums, bestStart, bestStart + k);   // copy once, at the end
}

Time: O(n). Space: O(k) for the returned subarray. For the example it returns [6, 4, 3, 8]. With > the first best window wins a tie; use >= if you want the last one.

Problem. Given nums and k, return the maximum average of any contiguous subarray of length k.

Example. nums = [1, 12, -5, -6, 50, 3], k = 4 → 12.75 (window [12, -5, -6, 50], sum 51).

1Brute force

Compute the sum of every window of length k from scratch and keep the largest.

def find_max_average_brute(nums, k):
    best = float('-inf')
    for i in range(len(nums) - k + 1):
        best = max(best, sum(nums[i:i + k]))   # O(k) slice + sum each time
    return best / k
static double findMaxAverageBrute(int[] nums, int k) {
    int best = Integer.MIN_VALUE;
    for (int i = 0; i + k <= nums.length; i++) {
        int total = 0;
        for (int j = i; j < i + k; j++) total += nums[j];
        best = Math.max(best, total);
    }
    return (double) best / k;
}

Time: O(n·k). Space: O(1) in Java; O(k) in Python because the slice makes a copy.

2Why it is slow → observation

Same overlap as Problem 1. And one more observation: k is the same for every window, so the window with the largest sum is also the window with the largest average. Track integer sums and divide once at the end. That avoids floating-point work inside the loop.

ADD / REMOVE window += nums[right] - nums[right - k]

Algorithm
  1. Sum the first k elements.
  2. Slide: add the entering element, subtract the leaving one, keep the maximum sum.
  3. Return maximum sum / k.

3Optimal: fixed window
STATE cnt = vowels in the current window

  2. For each right from k onward: if the entering character is a vowel add 1, if the leaving character is a vowel subtract 1, update best.

def max_vowels(s, k):

Problem. Given nums and k, return true if there are two different indices i and j with nums[i] == nums[j] and |i − j| ≤ k.

Example. nums = [1, 2, 3, 1], k = 3 → true (indices 0 and 3). nums = [1, 2, 3, 1, 2, 3], k = 2 → false (equal values are 3 apart).

1Brute force

For each index i, compare it with the next k elements.

def contains_nearby_duplicate_brute(nums, k):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, min(n, i + k + 1)):   # only look k steps ahead
            if nums[i] == nums[j]:
                return True
    return False
static boolean containsNearbyDuplicateBrute(int[] nums, int k) {
    int n = nums.length;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n && j <= i + k; j++) {   // only k steps ahead
            if (nums[i] == nums[j]) return true;
        }
    }
    return false;
}

Time: O(n·min(n, k)). Space: O(1).

2Why it is slow → observation

"Indices at most k apart" means "inside the same window of k+1 consecutive indices". For the element at right, the only question is: is its value already among the previous k values? A hash set answers that in O(1), and the set can be updated as the window slides.

3Optimal: fixed window whose state is a set
STATE window = set of the values at the previous k indices
CHECK if nums[right] is already in the set → duplicate within distance k
ADD insert nums[right]
REMOVE once the set has more than k values, delete nums[right - k]
Algorithm
  1. Start with an empty set.
  2. For each right: if nums[right] is in the set, return true.
  3. Otherwise insert it. If the set now holds more than k values, remove nums[right − k], the value that is now too far away.
  4. If the loop ends, return false.
def contains_nearby_duplicate(nums, k):
    window = set()                        # values at the previous k indices
    for right, x in enumerate(nums):
        if x in window:
            return True
        window.add(x)
        if len(window) > k:               # keep only the last k values
            window.remove(nums[right - k])
    return False
static boolean containsNearbyDuplicate(int[] nums, int k) {
    Set<Integer> window = new HashSet<>();      // values at the previous k indices
    for (int right = 0; right < nums.length; right++) {
        if (!window.add(nums[right])) return true;   // add() is false if present
        if (window.size() > k) {
            window.remove(nums[right - k]);     // keep only the last k values
        }
    }
    return false;
}

Time: O(n). Space: O(min(n, k)).

The set never contains duplicates of its own, because the function returns the moment one would be inserted. That is why removing nums[right − k] by value is safe.

static boolean checkInclusionBrute(String p, String s) {
    int k = p.length();
    char[] target = p.toCharArray();
    Arrays.sort(target);
    for (int i = 0; i + k <= s.length(); i++) {
        char[] w = s.substring(i, i + k).toCharArray();
        Arrays.sort(w);                         // sort every window: O(k log k)
        if (Arrays.equals(w, target)) return true;
    }
    return false;
}

Time: O(n · k log k) where n = len(s), k = len(p). Space: O(k).

2Why it is slow → observation

Sorting is only a way to check "same letters". Character counts check the same thing without sorting, and counts can be updated in O(1) when one character enters and one leaves. The window size is fixed at len(p).

3Optimal: fixed window + frequency counts
STATE window = letter counts of the current k characters; need = letter counts of p
ADD window[s[right]] += 1
REMOVE window[s[right - k]] -= 1
RECORD if window == need, return true
Algorithm
  1. If len(p) > len(s), return false.
  2. Build need from p and window from the first k characters of s. If equal, return true.
  3. For each right from k onward: add s[right], remove s[right − k], compare the two count tables.
  4. Return false if no window matched.
def check_inclusion(p, s):
    k = len(p)
    if k > len(s):
        return False
    need = Counter(p)
    window = Counter(s[:k])
    if window == need:
        return True
    for right in range(k, len(s)):
        window[s[right]] += 1             # entering
        out = s[right - k]                # leaving
        window[out] -= 1
        if window[out] == 0:
            del window[out]               # not needed for Counter on 3.10+, needed for a plain dict
        if window == need:
            return True
    return False
static boolean checkInclusion(String p, String s) {
    int k = p.length();
    if (k > s.length()) return false;
    int[] need = new int[26];
    int[] window = new int[26];
    for (int i = 0; i < k; i++) {
        need[p.charAt(i) - 'a']++;
        window[s.charAt(i) - 'a']++;
    }
    if (Arrays.equals(need, window)) return true;
    for (int right = k; right < s.length(); right++) {
        window[s.charAt(right) - 'a']++;        // entering
        window[s.charAt(right - k) - 'a']--;    // leaving
        if (Arrays.equals(need, window)) return true;   // 26 comparisons
    }
    return false;
}

Time: O(26·n) = O(n). Space: O(26) = O(1).

Delete the zero-count key: it keeps len(window) honest, and a plain dict (or a Java HashMap) would otherwise treat {'a': 1, 'b': 0} and {'a': 1} as different (a failing input is in Part 10). Python's Counter ignores zero counts in == from 3.10 on (checked on 3.11.9), so with a Counter the delete is not needed for the comparison on modern Python. In Java the int[26] arrays always have all 26 slots, so there is nothing to delete.

A further refinement, if an interviewer asks for it: keep a counter of how many of the 26 letters currently have equal counts in window and need, and update it when a letter enters or leaves. The window matches when that counter is 26. This removes the 26-step comparison, so each slide is strictly O(1). The comparison version above is what most people write, and it is accepted.

Problem. Given a string s, return the length of the longest substring in which no character appears twice.

Example. "abcabcbb" → 3 ("abc"). "bbbbb" → 1. "pwwkew" → 3 ("wke").

1Brute force

def length_of_longest_substring_brute(s):
    best = 0
    for i in range(len(s)):               # every start
        seen = set()
        for j in range(i, len(s)):        # extend until a repeat

static int lengthOfLongestSubstringBrute(String s) {

    for (int i = 0; i < s.length(); i++) {      // every start
        Set<Character> seen = new HashSet<>();
        for (int j = i; j < s.length(); j++) {  // extend until a repeat

Time: O(n²) in general (O(n·σ) when the alphabet is bounded, because the inner loop stops after at most σ characters). Space: O(min(n, σ)).

2Why it is slow → observation

When the brute force hits a repeat at j, it throws the set away and starts again from i+1. But s[i+1 .. j-1] is part of a window already known to have no repeats, so it has no repeats either. There is nothing to recheck. Keep right where it is and move only left, until the earlier copy of the repeated character has left the window.

VALID no character appears twice

RECORD best = max(best, right - left + 1) after the window is valid
Algorithm
  1. left = 0, best = 0, empty set.
  2. For each right: while s[right] is already in the set, remove s[left] and advance left.
  3. Insert s[right]. The window [left .. right] now has no repeats.
  4. Update best with the window length.
  5. Return best.
def length_of_longest_substring(s):

    for right, ch in enumerate(s):

            window.remove(s[left])
            left += 1
        window.add(ch)

    return best
static int lengthOfLongestSubstring(String s) {

}

static int lengthOfLongestSubstringJump(String s) {
    Map<Character, Integer> last = new HashMap<>();   // char -> last index
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char ch = s.charAt(right);
        Integer prev = last.get(ch);
        if (prev != null && prev >= left) {
            left = prev + 1;                    // jump past the previous copy
        }
        last.put(ch, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}

Time: O(n). Space: O(min(n, σ)).

Problem. Given a string s and an integer k, return the length of the longest substring that contains at most k distinct characters.

From every start, extend right while the set of distinct characters has at most k members.

def longest_k_distinct_brute(s, k):
    best = 0

        seen = set()
        for j in range(i, len(s)):
            seen.add(s[j])

static int longestKDistinctBrute(String s, int k) {

        Set<Character> seen = new HashSet<>();
        for (int j = i; j < s.length(); j++) {
            seen.add(s.charAt(j));

Time: O(n²). Space: O(k).

2Why it is slow → observation

As in Problem 6, restarting from i+1 rebuilds a window that was already known to be valid. Only left needs to move.

The state must change, though. A set is not enough, because when a character leaves from the left you need to know whether another copy of it is still inside. video "If you removed an i, you still have five distinct characters … that happened because these characters were duplicated." So keep a frequency map and treat a character as gone only when its count reaches zero.

3Optimal: variable window with a frequency map
STATE count = character → frequency inside the window
VALID number of keys in count ≤ k
ADD count[s[right]] += 1
REMOVE count[s[left]] -= 1, delete the key at 0, left += 1
RECORD best = max(best, right - left + 1)
Algorithm
  1. left = 0, best = 0, empty map.
  2. For each right: increment the count of s[right].
  3. While the map has more than k keys: decrement the count of s[left], delete the key if it hit zero, advance left.
  4. Update best.
  5. Return best.
def longest_k_distinct(s, k):
    count = {}                            # char -> frequency in window
    left = best = 0
    for right, ch in enumerate(s):
        count[ch] = count.get(ch, 0) + 1
        while len(count) > k:             # invalid: more than k distinct
            out = s[left]
            count[out] -= 1
            if count[out] == 0:
                del count[out]            # keeps len(count) == distinct count
            left += 1
        best = max(best, right - left + 1)
    return best
static int longestKDistinct(String s, int k) {
    Map<Character, Integer> count = new HashMap<>();   // char -> frequency
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        count.merge(s.charAt(right), 1, Integer::sum);
        while (count.size() > k) {              // invalid: more than k distinct
            char out = s.charAt(left);
            if (count.merge(out, -1, Integer::sum) == 0) {
                count.remove(out);              // keeps size() == distinct count
            }
            left++;
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}

Time: O(n). Space: O(k), the map never holds more than k+1 keys.

Type BMediumLeetCode 424from the notesO(n²) → O(n)
ShowHide

Where it is reported. frequently asked In the NeetCode 150 Sliding Window section and the Blind 75.

Problem. Given an uppercase string s and an integer k, you may change at most k characters to any other uppercase letter. Return the length of the longest substring consisting of one repeated letter that you can obtain.

Example. s = "AABABBA", k = 1 → 4 (in the window "AABA", replace the B to get "AAAA"). s = "ABAB", k = 2 → 4.

Reframe. In any window, keep the most frequent letter and replace all the others. The number of replacements is window_length − max_freq. A window is valid when window_length − max_freq ≤ k.

1Brute force

For every start, extend right while maintaining letter counts and the highest count. Whenever the window is valid, record its length.

def character_replacement_brute(s, k):
    best = 0
    for i in range(len(s)):
        count = {}
        max_freq = 0
        for j in range(i, len(s)):
            count[s[j]] = count.get(s[j], 0) + 1
            max_freq = max(max_freq, count[s[j]])
            if (j - i + 1) - max_freq <= k:   # replacements needed <= k
                best = max(best, j - i + 1)
    return best
static int characterReplacementBrute(String s, int k) {
    int best = 0;
    for (int i = 0; i < s.length(); i++) {
        int[] count = new int[26];
        int maxFreq = 0;
        for (int j = i; j < s.length(); j++) {
            int c = s.charAt(j) - 'A';
            count[c]++;
            maxFreq = Math.max(maxFreq, count[c]);
            if ((j - i + 1) - maxFreq <= k) {   // replacements needed <= k
                best = Math.max(best, j - i + 1);
            }
        }
    }
    return best;
}

Time: O(n²). Space: O(26) = O(1).

2Why it is slow → observation

Validity is monotonic: if a window needs at most k replacements, any sub-window needs at most k as well. So the longest-valid template applies and the restart can go.

3Optimal: variable window with len − max_freq ≤ k
STATE count per letter, and max_freq = highest count seen
VALID (right - left + 1) - max_freq <= k
ADD count[ch] += 1, max_freq = max(max_freq, count[ch])
REMOVE count[s[left]] -= 1, left += 1
RECORD best = max(best, right - left + 1)
Algorithm
  1. left = 0, max_freq = 0, best = 0, empty counts.
  2. For each right: increment the count of s[right] and update max_freq.
  3. While window_length − max_freq > k: decrement the count of s[left] and advance left.
  4. Update best.
  5. Return best.
def character_replacement(s, k):
    count = {}
    left = max_freq = best = 0
    for right, ch in enumerate(s):
        count[ch] = count.get(ch, 0) + 1
        max_freq = max(max_freq, count[ch])
        while (right - left + 1) - max_freq > k:   # too many to replace
            count[s[left]] -= 1
            left += 1
        best = max(best, right - left + 1)
    return best
static int characterReplacement(String s, int k) {
    int[] count = new int[26];
    int left = 0, maxFreq = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        int c = s.charAt(right) - 'A';
        count[c]++;
        maxFreq = Math.max(maxFreq, count[c]);
        while ((right - left + 1) - maxFreq > k) {   // too many to replace
            count[s.charAt(left) - 'A']--;
            left++;
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}

Time: O(n). Space: O(26) = O(1).

A longer answer is only possible when some letter reaches a count higher than any seen before, and at that moment max_freq is updated to a true value. A stale value only stops the window from shrinking below the best length already found. 2Why it is slow → observation

All numbers are positive, so adding an element always increases the sum and removing one always decreases it. Once [left .. right] reaches the target, extending right only gives longer windows, which are useless for a minimum. The useful move is to shrink from the left and see whether the window still reaches the target.

video "When I'm increasing the size of my window, my sum increases. When I'm decreasing the size of the window, the sum decreases."

Positivity is what gives monotonicity. With negative numbers this technique fails.

3Optimal: variable window, shrink while valid
STATE total = sum of the window
VALID total >= target
ADD total += nums[right]
REMOVE total -= nums[left], left += 1
RECORD best = min(best, right - left + 1) inside the while loop, before shrinking
Algorithm
  1. left = 0, total = 0, best = infinity.
  2. For each right: add nums[right] to total.
  3. While total >= target: record the window length, subtract nums[left], advance left.
  4. Return 0 if best is still infinity, otherwise best.
def min_subarray_len(target, nums):
    left = total = 0
    best = float('inf')
    for right, x in enumerate(nums):
        total += x
        while total >= target:            # valid: record, then try smaller
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == float('inf') else best
static int minSubArrayLen(int target, int[] nums) {
    int left = 0, total = 0;
    int best = Integer.MAX_VALUE;
    for (int right = 0; right < nums.length; right++) {
        total += nums[right];
        while (total >= target) {               // valid: record, then try smaller
            best = Math.min(best, right - left + 1);
            total -= nums[left];
            left++;
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}

Minimum Window Substring

Type C with countsHardLeetCode 76from the notesO(n²) → O(n)
ShowHide

Where it is reported. frequently asked In the NeetCode 150 (hard) and the Blind 75. TechScreen (2026-04-04) says it appears "across all FAANG companies", with no counts.

Problem. Given strings s and t, return the shortest substring of s that contains every character of t, including duplicates. Return "" if there is none.

Example. s = "ADOBECODEBANC", t = "ABC" → "BANC". s = "a", t = "aa" → "" (two a's are needed).

1Brute force

For every start i, extend right until the window covers t. The first such end is the shortest window for this start.

To test "covers t" cheaply, keep need (how many of each character are still required) and missing (how many required characters are still absent in total). The window covers t exactly when missing == 0.

def min_window_brute(s, t):
    if not s or not t:
        return ""
    best_len, best_l = float('inf'), 0
    for i in range(len(s)):               # every start
        need = Counter(t)                 # fresh requirement for each start
        missing = len(t)
        for j in range(i, len(s)):
            if need[s[j]] > 0:
                missing -= 1
            need[s[j]] -= 1
            if missing == 0:              # first j that covers t
                if j - i + 1 < best_len:
                    best_len, best_l = j - i + 1, i
                break
    return "" if best_len == float('inf') else s[best_l:best_l + best_len]
static String minWindowBrute(String s, String t) {
    if (s.isEmpty() || t.isEmpty()) return "";
    int bestLen = Integer.MAX_VALUE, bestL = 0;
    for (int i = 0; i < s.length(); i++) {      // every start
        int[] need = new int[128];              // fresh requirement per start
        for (char c : t.toCharArray()) need[c]++;
        int missing = t.length();
        for (int j = i; j < s.length(); j++) {
            char c = s.charAt(j);
            if (need[c] > 0) missing--;
            need[c]--;
            if (missing == 0) {                 // first j that covers t
                if (j - i + 1 < bestLen) {
                    bestLen = j - i + 1;
                    bestL = i;
                }
                break;
            }
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestL, bestL + bestLen);
}

Time: O(|s|·(|s| + |t|)), i.e. O(n²). Space: O(σ).

2Why it is slow → observation

"Covers t" is monotonic: growing a covering window keeps it covering, shrinking a non-covering window keeps it non-covering. So this is the shortest-valid template: expand until covered, then shrink while still covered.

The only new idea is how to keep need and missing correct when characters leave:

  • need[c] > 0 → the window still lacks need[c] copies of c.
  • need[c] == 0 → exactly enough.
  • need[c] < 0 → surplus copies (or c is not in t at all).

When a character leaves and its need rises above 0, the window has just lost something it required, so missing goes up.

3Optimal: variable window with need and missing
STATE need[c] and missing
VALID missing == 0
ADD if need[ch] > 0 then missing -= 1; always need[ch] -= 1
REMOVE need[s[left]] += 1; if it became > 0 then missing += 1; left += 1
RECORD inside the while loop: remember (length, left) if shorter
Algorithm
  1. Build need from t; missing = len(t).
  2. For each right: if s[right] is still needed, decrement missing. Decrement need[s[right]] either way.
  3. While missing == 0: record the window if it is the shortest so far, then give back s[left] (increment its need; if that makes it positive, increment missing) and advance left.
  4. Slice the answer out of s once, at the end.
def min_window(s, t):
    if not s or not t:
        return ""
    need = Counter(t)                     # how many of each char still needed
    missing = len(t)                      # total characters still needed
    left = 0
    best_len, best_l = float('inf'), 0
    for right, ch in enumerate(s):
        if need[ch] > 0:
            missing -= 1                  # this char was actually needed
        need[ch] -= 1                     # negative means surplus
        while missing == 0:               # valid: record, then shrink
            if right - left + 1 < best_len:
                best_len, best_l = right - left + 1, left
            need[s[left]] += 1
            if need[s[left]] > 0:
                missing += 1              # just removed a needed char
            left += 1
    return "" if best_len == float('inf') else s[best_l:best_l + best_len]
static String minWindow(String s, String t) {
    if (s.isEmpty() || t.isEmpty()) return "";
    int[] need = new int[128];                  // how many of each char still needed
    for (char c : t.toCharArray()) need[c]++;
    int missing = t.length();                   // total characters still needed
    int left = 0, bestLen = Integer.MAX_VALUE, bestL = 0;
    for (int right = 0; right < s.length(); right++) {
        char ch = s.charAt(right);
        if (need[ch] > 0) missing--;            // this char was actually needed
        need[ch]--;                             // negative means surplus
        while (missing == 0) {                  // valid: record, then shrink
            if (right - left + 1 < bestLen) {
                bestLen = right - left + 1;
                bestL = left;
            }
            char out = s.charAt(left);
            need[out]++;
            if (need[out] > 0) missing++;       // just removed a needed char
            left++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestL, bestL + bestLen);
}

Time: O(|s| + |t|). Space: O(σ).

Indices are stored during the loop and the substring is built once at the end. Slicing inside the loop would make it O(n²).

Subarray Product Less Than K

Problem. Given an array of positive integers nums and an integer k, return the number of contiguous subarrays whose product is strictly less than k.

Example. nums = [10, 5, 2, 6], k = 100 → 8: [10] [5] [2] [6] [10,5] [5,2] [2,6] [5,2,6].

1Brute force

For every start, extend right while the running product stays below k, counting each valid end.

def num_subarray_product_less_than_k_brute(nums, k):
    ans = 0
    for i in range(len(nums)):
        prod = 1
        for j in range(i, len(nums)):
            prod *= nums[j]
            if prod >= k:                 # positives: it only gets bigger
                break
            ans += 1
    return ans
static int numSubarrayProductLessThanKBrute(int[] nums, int k) {
    int ans = 0;
    for (int i = 0; i < nums.length; i++) {
        long prod = 1;
        for (int j = i; j < nums.length; j++) {
            prod *= nums[j];
            if (prod >= k) break;               // positives: it only gets bigger
            ans++;
        }
    }
    return ans;
}

Time: O(n²) in the worst case (for example, many 1s). Space: O(1).

2Why it is slow → observation

The values are positive integers, so the product never decreases as the window grows and never increases as it shrinks. That is monotonic.

Count by ending position: for each right, find the smallest left such that [left .. right] has product < k. Then every start from left to right works, which is right − left + 1 subarrays, added in one step.

3Optimal: counting window
STATE prod = product of the window
VALID prod < k
ADD prod *= nums[right]
REMOVE prod /= nums[left], left += 1
RECORD ans += right - left + 1
Algorithm
  1. If k <= 1, return 0 (a product of positive integers is at least 1).
  2. left = 0, prod = 1, ans = 0.
  3. For each right: multiply prod by nums[right].
  4. While prod >= k: divide by nums[left], advance left.
  5. Add right − left + 1 to ans.
  6. Return ans.
def num_subarray_product_less_than_k(nums, k):
    if k <= 1:
        return 0                          # no product of positives is < 1
    left = ans = 0
    prod = 1
    for right, x in enumerate(nums):
        prod *= x
        while prod >= k:
            prod //= nums[left]
            left += 1
        ans += right - left + 1           # valid subarrays ending at right
    return ans
static int numSubarrayProductLessThanK(int[] nums, int k) {
    if (k <= 1) return 0;                       // no product of positives is < 1
    int left = 0, ans = 0;
    long prod = 1;
    for (int right = 0; right < nums.length; right++) {
        prod *= nums[right];
        while (prod >= k) {
            prod /= nums[left];
            left++;
        }
        ans += right - left + 1;                // valid subarrays ending at right
    }
    return ans;
}

Time: O(n). Space: O(1).

The k <= 1 guard is not optional. Without it, prod >= k stays true even for an empty window, so left runs past right and you get wrong counts or an index error.

Subarrays with K Different Integers

Where it is reported. added for pattern coverage The "exactly K" trick. Not found in the sources checked.

Problem. Given an integer array nums and an integer k, return the number of contiguous subarrays that contain exactly k distinct integers.

Example. nums = [1, 2, 1, 2, 3], k = 2 → 7: [1,2] [2,1] [1,2] [2,3] [1,2,1] [2,1,2] [1,2,1,2].

1Brute force

For every start, extend right with a set of distinct values. Count each end where the set has exactly k values, and stop when it exceeds k.

def subarrays_with_k_distinct_brute(nums, k):
    ans = 0
    for i in range(len(nums)):
        seen = set()
        for j in range(i, len(nums)):
            seen.add(nums[j])
            if len(seen) > k:
                break
            if len(seen) == k:
                ans += 1
    return ans
static int subarraysWithKDistinctBrute(int[] nums, int k) {
    int ans = 0;
    for (int i = 0; i < nums.length; i++) {
        Set<Integer> seen = new HashSet<>();
        for (int j = i; j < nums.length; j++) {
            seen.add(nums[j]);
            if (seen.size() > k) break;
            if (seen.size() == k) ans++;
        }
    }
    return ans;
}

Time: O(n²). Space: O(k).

2Why it is slow → observation

"Exactly k distinct" is not monotonic. A window can go from 1 distinct (too few) to 2 (valid) to 3 (too many) as it grows, so there is no single rule for when to shrink.

"At most k distinct" is monotonic, and every subarray with at most k distinct values has either exactly k or at most k−1. Therefore:

exactly(k) = atMost(k) − atMost(k − 1)
3Optimal: two counting windows
STATE count = value → frequency
VALID (inside atMost) number of keys ≤ limit
ADD / REMOVE as in Problem 7
RECORD ans += right - left + 1
Algorithm
  1. Write atMost(limit): the counting window from Type D with the frequency map from Problem 7.
  2. Return atMost(k) − atMost(k − 1).
def subarrays_with_k_distinct(nums, k):
    def at_most(limit):                   # subarrays with <= limit distinct
        count = {}
        left = ans = 0
        for right, x in enumerate(nums):
            count[x] = count.get(x, 0) + 1
            while len(count) > limit:
                out = nums[left]
                count[out] -= 1
                if count[out] == 0:
                    del count[out]
                left += 1
            ans += right - left + 1
        return ans
    return at_most(k) - at_most(k - 1)
static int subarraysWithKDistinct(int[] nums, int k) {
    return atMostDistinct(nums, k) - atMostDistinct(nums, k - 1);
}

static int atMostDistinct(int[] nums, int limit) {   // subarrays with <= limit distinct
    Map<Integer, Integer> count = new HashMap<>();
    int left = 0, ans = 0;
    for (int right = 0; right < nums.length; right++) {
        count.merge(nums[right], 1, Integer::sum);
        while (count.size() > limit) {
            int out = nums[left];
            if (count.merge(out, -1, Integer::sum) == 0) {
                count.remove(out);
            }
            left++;
        }
        ans += right - left + 1;
    }
    return ans;
}

Time: O(n), two passes. Space: O(k).

For the example: atMost(2) = 12, atMost(1) = 5, and 12 − 5 = 7.

Sliding Window Maximum

Type FHardLeetCode 239from the notesO(n·k) → O(n)

Where it is reported. frequently asked In the NeetCode 150 (hard). TechScreen (2026-04-04) says it appears at Amazon and Microsoft, with no counts.

Problem. Given nums and a window size k, return a list with the maximum of every window of size k, from left to right.

Example. nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3 → [3, 3, 5, 5, 6, 7].

1Brute force

Take the maximum of every window from scratch.

def max_sliding_window_brute(nums, k):
    return [max(nums[i:i + k]) for i in range(len(nums) - k + 1)]
static int[] maxSlidingWindowBrute(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    for (int i = 0; i + k <= n; i++) {
        int mx = nums[i];
        for (int j = i + 1; j < i + k; j++) mx = Math.max(mx, nums[j]);
        res[i] = mx;
    }
    return res;
}

Time: O(n·k). Space: O(1) besides the output.

2Why it is slow → observation

A sum can be repaired when an element leaves (subtract it). A maximum cannot: if the maximum leaves, the next largest is unknown unless you rescan.

So keep the candidates for "next largest". An element that has a larger-or-equal element to its right is dominated: the newer element is at least as big and will stay in the window longer, so the older one can never be a window maximum again. Delete dominated elements as soon as they appear.

What remains is a list of indices whose values are strictly decreasing. The front is the maximum. New elements enter at the back and old ones expire at the front, which is exactly what a deque supports in O(1).

(A max-heap of (value, index) with lazy deletion of expired tops also works, in O(n log n). You'll learn it in Heaps.)

Approach Time Space
Brute force O(n·k) O(1) extra
Heap O(n log n) O(n)
Monotonic deque O(n) O(k)
3Optimal: monotonic deque
STATE deque of indices, values strictly decreasing front → back
ADD pop the back while its value ≤ nums[right], then push right
REMOVE pop the front if its index ≤ right − k
RECORD once right >= k − 1, output nums[front]
Algorithm
  1. For each right: pop from the back every index whose value is ≤ nums[right].
  2. Push right onto the back.
  3. If the front index is ≤ right − k, it is outside the window: pop it.
  4. If right ≥ k − 1, the window is full: the answer for this window is nums[front].
def max_sliding_window(nums, k):
    dq = deque()                          # indices; their values are decreasing
    res = []
    for right, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()                      # dominated: can never be a max again
        dq.append(right)
        if dq[0] <= right - k:
            dq.popleft()                  # front has left the window
        if right >= k - 1:                # first full window reached
            res.append(nums[dq[0]])
    return res
static int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();     // indices; values decreasing
    for (int right = 0; right < n; right++) {
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[right]) {
            dq.pollLast();                      // dominated: never a max again
        }
        dq.offerLast(right);
        if (dq.peekFirst() <= right - k) {
            dq.pollFirst();                     // front has left the window
        }
        if (right >= k - 1) {                   // first full window reached
            res[right - k + 1] = nums[dq.peekFirst()];
        }
    }
    return res;
}

Time: O(n), every index is pushed once and popped at most once. Space: O(k).

Part 8Problem-Solving Method (Sliding Window Edition)

1. Understand the input
   → Array or string? Is a contiguous answer required?

2. Identify constraints
   → n up to 10^5? Then O(n²) is too slow, so you need O(n) / O(n log n).
   → Are values all positive? Is the alphabet bounded?

3. Clarify edge cases
   → Empty input? k > n? No valid window — return 0, -1, or ""?

4. Brute force (say it aloud)
   → "Check every subarray: O(n²)."  or  "Rebuild every window of size k: O(n·k)."

5. Identify the bottleneck
   → "Neighbouring subarrays overlap. I'm recomputing shared work."

6. Recognise the pattern
   → Restate the story as a condition on a window ("at most k zeros", "at most 2 types").
   → Fixed size or variable?
   → Longest, shortest, or count?
   → Monotonicity check: does shrinking a valid window keep it valid?

7. Design the window
   → What is the STATE?        (sum, count map, set, deque)
   → What is VALID?            (an expression on the state)
   → How do I ADD right?
   → How do I REMOVE left?
   → WHERE do I record the answer? (after shrink for longest; inside while for shortest)

8. State complexity
   → "Each element enters and leaves once: O(n). Map is bounded by the alphabet: O(1) space."

9. Code — using the skeleton for that type

10. Test
   → Walk through a small example, tracking left, right, and state in a table.
   → Then empty input, single element, all identical, no valid window.

Step 7 does most of the work. If you can fill in those five blanks, the code follows from the skeleton. Every problem in Part 7 has this table filled in; compare yours against it.

Part 10Common Mistakes

Conceptual
  • Using a variable window on a non-monotonic condition (sum = k with negatives). → Always run the monotonicity check. (Failing input in Part 5.)
  • Using a window for subsequences. → Check for "contiguous" first.
  • Confusing longest and shortest. → Longest: shrink while invalid, record after. Shortest: record inside while valid, then shrink.
  • Solving "exactly K" directly. → Use atMost(K) - atMost(K-1).
  • Using a set where a count map is needed. → If the window can hold duplicates (Problems 7, 8), removing one copy must not make the element "disappear". Use frequencies.
  • Shrinking with if instead of while. → Safe habit is while. It is wrong for counting and shortest-window problems (failing input below). Read the correction box: for a pure longest-length answer the if trick is actually correct.
  • Moving left backwards. → Shrinking is always left += 1.
Python
  • list.pop(0) for the left side is O(n). → deque.popleft() or an index.
  • Slicing inside the loop (sum(nums[l:r+1]), s[l:r+1]) is secretly O(n·k).
  • Not deleting zero counts when len(count) is the distinct count, or when comparing plain dicts (a Counter ignores zeros in == from Python 3.10).
  • dict[key] -= 1 on a missing key raises KeyError. → defaultdict, Counter or .get.
  • A mutable default argument (def f(x, out=[])) is shared across calls (Part 2 traps).
Java
  • substring inside the loop is an O(k) copy every step. → Keep bestL and bestLen, call it once.
  • Comparing boxed Integers with == fails above 127. → .equals() or unbox (Part 2 traps).
  • int overflow in sums and products. → long (failing input below).
  • Forgetting to remove zero-count keys from a HashMap when using size() as the distinct count, or when using equals on two maps.
  • Using LinkedList or Stack for the deque. → ArrayDeque.
Complexity
  • Calling a while-inside-for O(n²). → Give the amortized argument: left only moves forward, at most n times in total (Part 3).
  • Forgetting the count-comparison cost. → O(sigma) per comparison; fine for 26 letters, but say so.
  • Putting an O(k) step (a slice, max(window)) inside the shrink loop, which silently brings back O(n·k).
Boundary
  • Window length is right - left + 1, not right - left.
  • In fixed windows, the leaving element is nums[right - k], not nums[right - k + 1].
  • The start of the fixed window ending at right is right - k + 1.
  • Deque expiry check: dq[0] <= right - k.
  • Recording the answer before the window is full (fixed windows: right >= k - 1).
  • No-answer sentinel: starting longest at 0 when 0 is a legal answer.
Interview reasoning
  • Jumping straight to code without stating the brute force.
  • Not stating what "valid" means, or what the invariant is, before coding.
  • Not dry-running a small example. A 4-row trace table of left / right / state / best catches most bugs.
  • Writing code you cannot run (many interviews give no run button) without a hand trace.
A correction to a common claim: if instead of while

It is often said that using if instead of while to shrink is simply wrong. That is too strong. For a problem that asks only for the longest length (Type B), the "non-shrinking window" trick, which uses if, is correct: the window slides instead of shrinking, and its size never decreases. The code block below passed the same 5,000 random inputs as Problem 8 in both languages (Part 7 harness, label p8.if); on Problem 8 the if and while versions gave identical answers in a separate 200,000-input Python run.

What if breaks: any problem that counts (Type D, see the verified failing input below), any problem that records inside the loop (Type C), and any problem that must return the window itself or read its state, because the window can be left invalid. The safe habit is while, and say why aloud: one removal may not restore validity.

def total_fruit_non_shrinking(fruits):     # "if" instead of "while": the window never shrinks
    count = {}
    left = 0
    for right, f in enumerate(fruits):
        count[f] = count.get(f, 0) + 1
        if len(count) > 2:                # slide the window one step instead of shrinking it
            out = fruits[left]
            count[out] -= 1
            if count[out] == 0:
                del count[out]
            left += 1
    return len(fruits) - left             # the window size only ever grows, so this is the longest length
static int totalFruitNonShrinking(int[] fruits) {   // "if" instead of "while": the window never shrinks
    Map<Integer, Integer> count = new HashMap<>();
    int left = 0;
    for (int right = 0; right < fruits.length; right++) {
        count.merge(fruits[right], 1, Integer::sum);
        if (count.size() > 2) {                 // slide the window one step instead of shrinking it
            int out = fruits[left];
            if (count.merge(out, -1, Integer::sum) == 0) count.remove(out);
            left++;
        }
    }
    return fruits.length - left;                // the window size only ever grows: the longest length
}

def max_sum_k(nums, k):
    n = len(nums)
    if k <= 0 or k > n:
        return None
    window = sum(nums[:k])                # first window, built once: O(k)
    best = window
    for right in range(k, n):
        window += nums[right]             # element entering on the right
        window -= nums[right - k]         # element leaving on the left
        best = max(best, window)
    return best
static int maxSumK(int[] nums, int k) {
    int n = nums.length;
    if (k <= 0 || k > n) throw new IllegalArgumentException("no window of size k");
    int window = 0;
    for (int i = 0; i < k; i++) window += nums[i];   // first window: O(k)
    int best = window;
    for (int right = k; right < n; right++) {
        window += nums[right];                  // element entering
        window -= nums[right - k];              // element leaving
        best = Math.max(best, window);
    }
    return best;
}

T4 — Monotonic deque (this is Problem 15)

def max_sliding_window(nums, k):
    dq = deque()                          # indices; their values are decreasing
    res = []
    for right, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()                      # dominated: can never be a max again
        dq.append(right)
        if dq[0] <= right - k:
            dq.popleft()                  # front has left the window
        if right >= k - 1:                # first full window reached
            res.append(nums[dq[0]])
    return res
static int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();     // indices; values decreasing
    for (int right = 0; right < n; right++) {
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[right]) {
            dq.pollLast();                      // dominated: never a max again
        }
        dq.offerLast(right);
        if (dq.peekFirst() <= right - k) {
            dq.pollFirst();                     // front has left the window
        }
        if (right >= k - 1) {                   // first full window reached
            res[right - k + 1] = nums[dq.peekFirst()];
        }
    }
    return res;
}

Time: O(n). Space: O(k). Flip <= to >= for the window minimum.

The monotonic deque in Type F keeps elements in decreasing order and pops dominated ones from the back. If you only ever use the back, that is a monotonic stack, the core idea of the next topic. Here is a tiny preview, tested like everything else (brute force against stack on 5,000 random inputs in each language). It is not a problem to solve now.

def next_greater(nums):
    res = [-1] * len(nums)
    stack = []                            # indices still waiting; values decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x          # x is the first greater element to the right
        stack.append(i)
    return res
static int[] nextGreater(int[] nums) {
    int[] res = new int[nums.length];
    Arrays.fill(res, -1);
    Deque<Integer> stack = new ArrayDeque<>();  // indices still waiting; values decreasing
    for (int i = 0; i < nums.length; i++) {
        while (!stack.isEmpty() && nums[stack.peekLast()] < nums[i]) {
            res[stack.pollLast()] = nums[i];    // nums[i] is the first greater to the right
        }
        stack.offerLast(i);
    }
    return res;
}

Next greater element: for each value, the first larger value to its right, or -1. Each index is pushed once and popped once (the same amortized argument), so it is O(n). Brute force: next_greater_brute, tested against it.

Time: O(n) because the window size is the constant 3. For a general window size k the same idea (build a set from every window) costs O(n·k). Space: O(1).

2Observation

With k fixed at 3 the direct check is already optimal. The window version matters when k is a parameter: keep character counts and the number of distinct characters. A window of size k is "all distinct" exactly when it has k distinct characters.

3Optimal for any k: fixed window with counts
STATE count per character; number of distinct characters
ADD increment the entering character's count
REMOVE decrement the leaving character's count (it stops being distinct at 0)
RECORD if distinct == k, ans += 1
Algorithm
  1. If len(s) < k, return 0.
  2. Slide a window of size k, maintaining counts.
  3. After each slide, if the number of distinct characters equals k, count this window.
def count_good_substrings(s, k=3):
    if len(s) < k:
        return 0
    count = {}
    for ch in s[:k]:
        count[ch] = count.get(ch, 0) + 1
    ans = 1 if len(count) == k else 0     # k distinct keys == all distinct
    for right in range(k, len(s)):
        count[s[right]] = count.get(s[right], 0) + 1
        out = s[right - k]
        count[out] -= 1
        if count[out] == 0:
            del count[out]
        if len(count) == k:
            ans += 1
    return ans
static int countGoodSubstrings(String s, int k) {
    if (s.length() < k) return 0;
    int[] count = new int[26];
    int distinct = 0, ans = 0;
    for (int right = 0; right < s.length(); right++) {
        if (count[s.charAt(right) - 'a']++ == 0) distinct++;        // entering
        if (right >= k) {
            if (--count[s.charAt(right - k) - 'a'] == 0) distinct--; // leaving
        }
        if (right >= k - 1 && distinct == k) ans++;   // k distinct == all distinct
    }
    return ans;
}

Time: O(n) for any k. Space: O(σ) = O(1).

def minimum_recolors_brute(blocks, k):

static int minimumRecolorsBrute(String blocks, int k) {

    for (int i = 0; i + k <= blocks.length(); i++) {

        for (int j = i; j < i + k; j++) {

  2. Slide: +1 if the entering block is white, −1 if the leaving block is white; keep the minimum.
  3. Return the minimum.
def minimum_recolors(blocks, k):
    whites = blocks[:k].count('W')        # whites in the window = recolors
    best = whites
    for right in range(k, len(blocks)):
        if blocks[right] == 'W':
            whites += 1
        if blocks[right - k] == 'W':
            whites -= 1
        best = min(best, whites)
    return best
static int minimumRecolors(String blocks, int k) {
    int whites = 0;                             // whites in window = recolors
    for (int i = 0; i < k; i++) {
        if (blocks.charAt(i) == 'W') whites++;
    }
    int best = whites;
    for (int right = k; right < blocks.length(); right++) {
        if (blocks.charAt(right) == 'W') whites++;
        if (blocks.charAt(right - k) == 'W') whites--;
        best = Math.min(best, whites);
    }
    return best;
}

Time: O(n). Space: O(1).

Time: O(n · k log k). Space: O(k).

2Observation

This is Problem 5 (567) with one change: instead of returning true at the first match, collect the start index of every match and keep going. The start index of the window ending at right is right − k + 1.

3Optimal: fixed window + frequency counts
Algorithm
  1. If len(p) > len(s), return an empty list.
  2. Build need from p and window from the first k characters. If equal, record index 0.
  3. For each right from k onward: add s[right], remove s[right − k]; if the counts match, record right − k + 1.
def find_anagrams(s, p):
    k = len(p)
    if k > len(s):
        return []
    need = Counter(p)
    window = Counter(s[:k])
    res = [0] if window == need else []
    for right in range(k, len(s)):
        window[s[right]] += 1
        out = s[right - k]
        window[out] -= 1
        if window[out] == 0:
            del window[out]
        if window == need:
            res.append(right - k + 1)     # start index of this window
    return res
static List<Integer> findAnagrams(String s, String p) {
    List<Integer> res = new ArrayList<>();
    int k = p.length();
    if (k > s.length()) return res;
    int[] need = new int[26];
    int[] window = new int[26];
    for (int i = 0; i < k; i++) {
        need[p.charAt(i) - 'a']++;
        window[s.charAt(i) - 'a']++;
    }
    if (Arrays.equals(need, window)) res.add(0);
    for (int right = k; right < s.length(); right++) {
        window[s.charAt(right) - 'a']++;
        window[s.charAt(right - k) - 'a']--;
        if (Arrays.equals(need, window)) res.add(right - k + 1);   // window start
    }
    return res;
}

Minimum Operations to Reduce X to Zero

Inverse window (Type B with an equality check)MediumLeetCode 1658
Show solutionHide

Where it is reported. added for pattern coverage Inverse window. Not found in the sources checked.

Problem. Given an array of positive integers nums and an integer x. In one operation you remove either the leftmost or the rightmost element and subtract its value from x. Return the minimum number of operations to make x exactly 0, or −1 if impossible.

Example. nums = [1, 1, 4, 2, 3], x = 5 → 2 (remove 3, then 2). nums = [5, 6, 7, 8, 9], x = 4 → −1. nums = [3, 2, 20, 1, 1, 3], x = 10 → 5.

1Brute force

You end up removing some prefix of length i and some suffix of length j. Try every pair, using prefix sums to get each total in O(1).

def min_operations_brute(nums, x):
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]
    total = prefix[n]
    best = float('inf')
    for i in range(n + 1):                # take i elements from the left
        for j in range(n - i + 1):        # take j elements from the right
            if prefix[i] + (total - prefix[n - j]) == x:
                best = min(best, i + j)
    return -1 if best == float('inf') else best
static int minOperationsBrute(int[] nums, int x) {
    int n = nums.length;
    int[] prefix = new int[n + 1];
    for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
    int total = prefix[n];
    int best = Integer.MAX_VALUE;
    for (int i = 0; i <= n; i++) {              // take i from the left
        for (int j = 0; i + j <= n; j++) {      // take j from the right
            if (prefix[i] + (total - prefix[n - j]) == x) {
                best = Math.min(best, i + j);
            }
        }
    }
    return best == Integer.MAX_VALUE ? -1 : best;
}

Time: O(n²). Space: O(n) for the prefix sums.

2Observation

Removing a prefix and a suffix leaves a contiguous middle. If the removed elements sum to x, the middle sums to total − x. Fewest removals means the longest middle.

So: find the longest subarray with sum exactly total − x; the answer is n − that length.

"Sum exactly T" is normally not windowable, but here all values are positive, so the window sum strictly grows when expanding and strictly drops when shrinking. Shrink while the sum is too big, then check for equality.

3Optimal: longest window with sum == target
STATE window = sum of the middle
VALID window <= target (then test == target)
ADD / REMOVE window += nums[right] / window -= nums[left]
RECORD if window == target, longest = max(longest, right - left + 1)
Algorithm
  1. target = sum(nums) − x. If target < 0, return −1 (even removing everything is not enough).
  2. left = 0, window = 0, longest = −1.
  3. For each right: add nums[right]; while window > target, subtract nums[left] and advance left.
  4. If window == target, update longest.
  5. Return −1 if longest is still −1, otherwise n − longest.
def min_operations(nums, x):
    target = sum(nums) - x                # what the kept middle must sum to
    if target < 0:
        return -1
    left = window = 0
    longest = -1
    for right, v in enumerate(nums):
        window += v
        while window > target:            # all values >= 1, so shrinking helps
            window -= nums[left]
            left += 1
        if window == target:
            longest = max(longest, right - left + 1)
    return -1 if longest == -1 else len(nums) - longest
static int minOperations(int[] nums, int x) {
    int total = 0;
    for (int v : nums) total += v;
    int target = total - x;                     // what the kept middle must sum to
    if (target < 0) return -1;
    int left = 0, window = 0, longest = -1;
    for (int right = 0; right < nums.length; right++) {
        window += nums[right];
        while (window > target) {               // all values >= 1, so shrinking helps
            window -= nums[left];
            left++;
        }
        if (window == target) {
            longest = Math.max(longest, right - left + 1);
        }
    }
    return longest == -1 ? -1 : nums.length - longest;
}

Time: O(n). Space: O(1).

When target == 0 (you must remove everything), the window shrinks to empty, window == 0 == target, and longest becomes 0, so the answer is n. longest starts at −1, not 0, so that "an empty middle works" can be told apart from "nothing works".

Problem. Given a binary array nums and an integer goal, return the number of non-empty contiguous subarrays whose sum is exactly goal.

Example. nums = [1, 0, 1, 0, 1], goal = 2 → 4. nums = [0, 0, 0, 0, 0], goal = 0 → 15.

1Brute force

For every start, extend right with a running sum; count each end where the sum equals goal, and stop once it exceeds goal.

def num_subarrays_with_sum_brute(nums, goal):
    ans = 0
    for i in range(len(nums)):
        total = 0
        for j in range(i, len(nums)):
            total += nums[j]
            if total == goal:
                ans += 1
            elif total > goal:
                break
    return ans
static int numSubarraysWithSumBrute(int[] nums, int goal) {
    int ans = 0;
    for (int i = 0; i < nums.length; i++) {
        int total = 0;
        for (int j = i; j < nums.length; j++) {
            total += nums[j];
            if (total == goal) ans++;
            else if (total > goal) break;
        }
    }
    return ans;
}

Time: O(n²). Space: O(1).

2Observation

"Sum exactly goal" cannot be counted with one window because of zeros: adding or removing a 0 does not change the sum, so for one right there can be several valid left positions that the window cannot tell apart.

"Sum at most goal" is monotonic (values are non-negative), and

exactly(goal) = atMost(goal) − atMost(goal − 1)
3Optimal: two counting windows
Algorithm
  1. Write atMost(g): if g < 0 return 0. Otherwise run the counting window: add nums[right], shrink while total > g, add right − left + 1.
  2. Return atMost(goal) − atMost(goal − 1).
def num_subarrays_with_sum(nums, goal):
    def at_most(g):                       # subarrays with sum <= g
        if g < 0:
            return 0
        left = total = ans = 0
        for right, x in enumerate(nums):
            total += x
            while total > g:
                total -= nums[left]
                left += 1
            ans += right - left + 1
        return ans
    return at_most(goal) - at_most(goal - 1)
static int numSubarraysWithSum(int[] nums, int goal) {
    return atMostSum(nums, goal) - atMostSum(nums, goal - 1);
}

static int atMostSum(int[] nums, int g) {       // subarrays with sum <= g
    if (g < 0) return 0;
    int left = 0, total = 0, ans = 0;
    for (int right = 0; right < nums.length; right++) {
        total += nums[right];
        while (total > g) {
            total -= nums[left];
            left++;
        }
        ans += right - left + 1;
    }
    return ans;
}

Time: O(n). Space: O(1).

The g < 0 guard handles goal = 0, where the second call is atMost(−1). Without it the while loop would run left past the end of the array.

(The other standard solution is prefix sums + a hash map, also O(n) time but O(n) space. That is the technique to use when the array can contain negatives.)

    int n = nums.length;

        long total = 0;
        for (int j = i; j < n; j++) {

            if (total >= k) {                   // first j for this start is the shortest

                break;
            }
        }

Time: O(n²). Space: O(1).

2Why Problem 11's window fails

With negatives, growing the window can lower the sum and shrinking it can raise the sum, so "shrink while valid" is no longer safe (Part 5 shows [-3, -3, 1], target 1 failing). Use prefix sums: prefix[j] - prefix[i] is the sum of nums[i..j-1], so you want the closest pair i < j with prefix[j] - prefix[i] >= k.

3Optimal: a monotonic deque over prefix sums
STATEa deque of indices into prefix, with increasing prefix values
FRONT POPwhile prefix[j] - prefix[front] >= k: record j - front and pop it. That start can never give a shorter answer for a later j.
BACK POPwhile prefix[back] >= prefix[j]: pop. A later start with a smaller or equal prefix is closer and gives at least as large a sum.
PUSHpush j
def shortest_subarray(nums, k):
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]
    dq = deque()                          # indices into prefix; prefix values increasing
    best = n + 1
    for j in range(n + 1):
        while dq and prefix[j] - prefix[dq[0]] >= k:
            best = min(best, j - dq.popleft())   # this start is used up: later ends are longer
        while dq and prefix[dq[-1]] >= prefix[j]:
            dq.pop()                      # a later, smaller-or-equal prefix beats it
        dq.append(j)
    return best if best <= n else -1
static int shortestSubarray(int[] nums, int k) {
    int n = nums.length;
    long[] prefix = new long[n + 1];
    for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
    Deque<Integer> dq = new ArrayDeque<>();     // indices into prefix; values increasing
    int best = n + 1;
    for (int j = 0; j <= n; j++) {
        while (!dq.isEmpty() && prefix[j] - prefix[dq.peekFirst()] >= k) {
            best = Math.min(best, j - dq.pollFirst());   // this start is used up
        }
        while (!dq.isEmpty() && prefix[dq.peekLast()] >= prefix[j]) {
            dq.pollLast();                      // a later, smaller-or-equal prefix beats it
        }
        dq.offerLast(j);
    }
    return best <= n ? best : -1;
}

Time: O(n) (each index pushed once and popped once). Space: O(n) for the prefix array and deque.

This is Type F (a monotonic deque) used on prefix sums instead of values. It reuses exactly the "dominated elements" reasoning of Problem 15.

Points to read carefully

The video is an intuition-level overview and a few of its spoken statements are loose. These are the ones worth pinning down.

The video says Precise version
"To decrease your length, you do a left minus minus." (during the minimum-sum walkthrough) Shrinking is always left++. The video says so itself in its summary ("you do left plus plus, your window size becomes smaller"). left-- would grow the window backwards.
"If you're looking at at most k elements, then you want the minimum possible sum … a shrinking window strategy." Two separate ideas are mixed here. "At most k" is normally a longest problem: shrink while invalid (Type B). "Minimum / shortest" is the one where you shrink while valid (Type C).
"Contiguous subarray, or a longest or shortest segment … you are looking at a variable size sliding window." True when the size is not given. If the problem fixes the length ("of size k"), it is a fixed window even though it says "contiguous subarray".
"Maximum sum or a minimum value between certain k elements → fixed size." Correct. Note that a min/max value per window cannot be updated by subtraction like a sum; it needs the monotonic deque (Type F).
"This i is repeated, so you will not include it in your window" (checks before adding) The code in these notes sometimes adds first and then shrinks, sometimes shrinks first and then adds. Both produce the same windows. Pick one style and be consistent.
"Change this K to one … this value now changes to zero" (K used as a remaining-flips budget) Equivalent to counting zeros in the window and requiring zeros <= k (Problem 9). Counting leaves the input k untouched, which is easier to reason about.
"If you want to return that array, you can keep a track of these four elements also." Track the start index of the best window, not the elements, and slice once at the end. See the variant under Problem 1.
"Find me the array that has k distinct characters." Said loosely. "At most k distinct" is Problem 7. "Exactly k distinct, longest" is the same window with a stricter RECORD step. "Exactly k distinct, count" needs atMost(k) − atMost(k−1), Problem 14.
"Slide one character at a time, or even faster." "Faster" is the jump variant in Problem 6: move left directly past the previous copy using a last-index map.
"Sliding window only operates when your structure is linear." Correct. Arrays and strings are the usual cases; linked lists and data streams are linear too.

What the video does not cover (and these notes add)

  • Monotonicity: the condition that decides whether a variable window is legal at all, and why negatives break sum windows.
  • The amortized O(n) argument for the while inside the for.
  • Counting subarrays (ans += right − left + 1) and the exactly-K = atMost(K) − atMost(K−1) trick.
  • Frequency matching for anagram / permutation problems.
  • The monotonic deque behind the "min and max queues" it mentions in passing.
  • Lookalike problems that are not sliding window.
