Queue and Deque

A queue serves items in the order they arrived (first in, first out). That one rule turns "process things fairly in arrival order", "explore a graph by distance" and "forget what fell out of the window" into O(1)-per-step loops, and a deque (double-ended queue) adds the trick behind the monotonic-window pattern.

Part 1First Principles

One-paragraph summary

A queue is a line: you add at the back (enqueue) and remove from the front (dequeue), so the item that has waited longest always leaves first. A deque ("deck", double-ended queue) lets you add and remove at both ends in O(1). In problems this gives you three powers: (1) simulate a line exactly as described; (2) breadth-first search (BFS), which visits things in order of distance and therefore finds the shortest path when every step costs the same; (3) a window that forgets old items in O(1) amortised, and with a deque a window that also knows its maximum. It never makes a slow loop magically fast by itself: it makes the order of work correct so each item is handled once.

Why it exists and what problem it solves

  • Fairness and order. Print jobs, customer requests, tickets, network packets and tasks must be served in arrival order. A list you search for the oldest item is O(n) per step; a queue makes it O(1).
  • Distance order. If you explore from a start and always handle the earliest-discovered node next, you discover nodes in order of distance. The first time you reach a goal is therefore the shortest route (when all steps cost the same). A stack would go deep first and would not give shortest paths.
  • Recent history. "Average of the last 3 values", "calls in the last 300 seconds", "max of the last k values": the window is a queue where old items leave from the front.
  • Better than the simple approach: the simple approach for "oldest first" is a list plus pop(0), which shifts every element and costs O(n) (measured in Appendix B: 200,000 pops took 29 s on a list and 0.006 s on a deque).

How it works inside (conceptual)

  • Python deque is a doubly linked list of small blocks. Both ends are O(1). Indexing the middle is O(n) (measured: 2,000 reads at index n/2 of a 200,000-item deque took 0.010 s, versus 0.000 s at index 0).
  • Java ArrayDeque is a resizable circular array with a head and tail index. Both ends are O(1) amortised (the array doubles when full). It has no get(i).
  • Java LinkedList also implements Queue and Deque, but allocates a node per item, uses more memory, and allows null. Interview default is ArrayDeque.
The core invariants (the facts that make queue solutions correct)

Simulation: the front of the queue is always the person (or task) who is next in the real process. BFS: the queue holds nodes in non-decreasing distance order, and contains at most two different distances (d and d+1), so the first time a node is reached is by a shortest path. Window: the queue holds exactly the items still inside the window, oldest first. Monotonic deque: the deque holds candidate indexes whose values are strictly decreasing from front to back, so the front is the window maximum.

When to use it

  • The statement describes a line, rounds, turns, or "goes to the back of the line".
  • You want the minimum number of steps / moves / turns / minutes and every step costs the same.
  • Spreading from several sources at once ("nearest zero", "all rotten oranges rot their neighbours each minute").
  • You keep a time or size window and need to drop the oldest items.
  • You need the max or min of every window of a moving range, or a DP transition that looks back at the best of the last k states.

When NOT to use it

  • Steps have different costs (roads with different lengths): use Dijkstra with a heap (Heaps/Graphs). The one exception is 0/1 costs: 0-1 BFS (Type G).
  • You need the smallest or largest item overall, not the oldest: heap.
  • You need "next greater / previous smaller" or matching pairs like brackets: that is the stack (LIFO) pattern.
  • You need any path or all paths, not the shortest: DFS/backtracking is simpler.
  • You need lookup by key: hash map. A queue only gives you the ends.

Where you already meet it

  • Message queues and job systems (SQS, Kafka partitions, Celery/RQ queues, Sidekiq): producers enqueue, workers dequeue.
  • OS and runtime schedulers: run queues, the JavaScript event loop (task queue), thread pool work queues.
  • Printer spoolers, ticket lines, network router buffers, rate limiters ("requests in the last minute").
  • BFS inside every shortest-path-in-a-grid, word-ladder, level-order-traversal and web-crawler problem.
  • Streaming: moving averages and sliding-window maximum over a metric stream.

Why: the amortised argument

Each item enters once and leaves once

Look at getHits in a hit counter: it has a while loop that pops old items. One call could pop 1,000 items. But an item can only be popped after it was pushed, and it is pushed exactly once. So over m calls the total pops are at most the total pushes, which is at most m. The total work is O(m), so each call is O(1) amortised. The same argument gives O(n) for the monotonic deque (each index pushed once, popped once) and O(V + E) for BFS (each node enqueued once because we mark it when we enqueue).

Code that looks worse than it is

  • BFS has while q: and, inside it, loops over 4 or 8 neighbours: that is O(nodes x constant), not O(nodes squared).
  • Level-by-level BFS adds for _ in range(len(q)) inside while q:. Still one pass: the inner loop just chops the same pops into groups.
  • Monotonic deque has a while inside a for. Each index is popped at most once, so the total is O(n).
  • Perfect Squares by BFS looks like it could blow up (every remainder tries every square), but there are only n distinct remainders, each enqueued once: O(n * sqrt(n)), the same as the DP.

Where memory goes

  • BFS stores up to one whole level. On a grid that is the "width of the frontier", at worst O(R*C) in total, and the visited structure is also O(R*C). If the interviewer asks for O(1) extra space for a grid, mark visited in the grid itself (as Binary Matrix and Rotting Oranges do) and say you are mutating the input.
  • A sliding window keeps only the window, O(k), not O(n).
  • Two-sided BFS (bidirectional) halves the depth but both frontiers are stored. Mentioned only as a follow-up.

Best, average, worst

Queue operations have no best/worst split. BFS can stop early when it reaches the goal (best case: goal next to start; worst case: goal unreachable or farthest, so the whole reachable graph is visited). Stating "O(V + E) worst case, early exit when found" is the complete answer.

Type A: Simulate a line

Type AEasy to Mediumdeque

1. What it is. Put the people (or tasks, cards, senators) in a queue in their starting order and repeat the process in the statement: take the front, decide, and either remove it or send it to the back.

2. What problem it solves. Problems whose statement is a queue procedure. A direct simulation is always correct; the question is whether it is fast enough, and whether the structure of the process gives a shortcut.

3. How to recognise it. Phrases like "goes to the back of the line", "moves to the end of the queue", "rounds", "each takes a turn", "bans the next opposing". Small constraints (n up to 100) suggest simulation is intended.

4. Intuition. A queue is the data structure that already behaves like the story, so writing the story as code is the safest first version. The optimisation step is to ask: "Who actually decides the answer?" (Tickets: only the line position relative to k matters. Lunch: only the counts of each preference matter.)

5. Generic algorithm
  1. Load the starting order into a deque.
  2. While there is something to process: take the front.
  3. Apply the rule: remove it (done), or put it back at the end (append(popleft())).
  4. Add a termination guard if the process can cycle forever (Lunch: stop after a whole round with no change).
  5. Return what the question asks (time, count, order).

6. State, validity condition, step. State: the deque, plus a clock or counter. Invariant: the front is the next actor in the real process. Validity: each step removes or re-queues exactly one item. Danger: an infinite loop if nothing can ever change.

7. Template (Python and Java), taken from the verified brute force of Students Unable to Eat Lunch

def count_students_brute(students, sandwiches):
    q = deque(students)
    i = 0                              # top sandwich
    spins = 0                          # consecutive students who refused
    while q and spins < len(q):
        if q[0] == sandwiches[i]:
            q.popleft()
            i += 1
            spins = 0
        else:
            q.append(q.popleft())      # refuse, go to the back
            spins += 1
    return len(q)
static int countStudentsBrute(int[] students, int[] sandwiches) {
    Deque<Integer> q = new ArrayDeque<>();
    for (int s : students) q.addLast(s);
    int i = 0, spins = 0;
    while (!q.isEmpty() && spins < q.size()) {
        if (q.peekFirst() == sandwiches[i]) {
            q.pollFirst();
            i++;
            spins = 0;
        } else {
            q.addLast(q.pollFirst());
            spins++;
        }
    }
    return q.size();
}

Type B: Window with eviction

Type BEasy to Mediumdeque + running sum

1. What it is. A queue that always holds exactly the items still inside a size or time window, plus one running aggregate (sum, count) updated as items enter and leave.

2. What problem it solves. Averages, counts and rate limits over "the last k items" or "the last T seconds" of a stream, without re-scanning the window each time.

3. How to recognise it. "Last k", "in the past 300 seconds", "stream", "data stream", "recent", "moving".

4. Intuition. Recomputing the aggregate costs O(window) per update. But an update only adds one item and removes the expired ones, so adjust the aggregate by exactly those: add the new value, subtract each evicted value.

5. Generic algorithm
  1. Create an empty deque and a running total.
  2. On each new item: append it and add it to the total.
  3. While the front is expired (too old, or the queue is longer than k): pop it and subtract it.
  4. Answer from the total and the queue length.

6. State, validity condition, step. State: deque + total. Invariant: total equals the sum of the deque. Valid window: size ≤ k, or front time > now − T. Step: append, then evict.

7. Template (Python and Java), taken from the verified solution of Moving Average from Data Stream

class MovingAverage:
    def __init__(self, size):
        self.size = size
        self.q = deque()
        self.total = 0

    def next(self, val):
        self.q.append(val)
        self.total += val
        if len(self.q) > self.size:
            self.total -= self.q.popleft()     # oldest leaves the window
        return self.total / len(self.q)
static class MovingAverage {
    int size; long total = 0; Deque<Integer> q = new ArrayDeque<>();
    MovingAverage(int size) { this.size = size; }
    double next(int val) {
        q.addLast(val);
        total += val;
        if (q.size() > size) total -= q.pollFirst();
        return (double) total / q.size();
    }
}

Type C: Level-order BFS (single source)

Type CMediumdeque of cells

1. What it is. Breadth-first search from one start, processing the queue one level at a time. The number of levels completed is the shortest distance.

2. What problem it solves. Minimum steps / moves / turns in a grid or graph where every step costs the same, including when diagonals are allowed.

3. How to recognise it. "Shortest path", "minimum number of steps", "fewest moves", "unweighted", grid with obstacles. Answer is a count of steps, not the path itself.

4. Intuition. The queue holds the whole current frontier. Everything in it is exactly d steps away; everything it adds is d+1 away. So counting how many times you empty the current frontier counts the distance.

5. Generic algorithm
  1. If start or goal is blocked, return -1 now.
  2. Put the start in the queue and mark it visited now.
  3. Set steps = 1 (cells on the path) or 0 (edges), depending on what is asked.
  4. While the queue is not empty: freeze size = len(q); process exactly that many cells; if one is the goal, return steps; mark and enqueue unvisited neighbours.
  5. After the level, steps += 1.
  6. Queue empty without reaching the goal: return -1.

6. State, validity condition, step. State: queue, visited, steps. Invariant: at the top of each level the queue holds all cells at distance steps−1 (or steps) and nothing else. Valid move: in bounds, open, not visited. Answer: steps when the goal is dequeued (or when it is enqueued, an equally good early exit).

7. Template (Python and Java), taken from the verified solution of Shortest Path in Binary Matrix

def shortest_path(grid):
    n = len(grid)
    if grid[0][0] or grid[n-1][n-1]:
        return -1
    q = deque([(0, 0)])
    grid[0][0] = 1                             # visited (reuse the input as the seen set)
    steps = 1                                  # path length counts cells, so the start is 1
    while q:
        for _ in range(len(q)):
            r, c = q.popleft()
            if r == n - 1 and c == n - 1:
                return steps
            for dr in (-1, 0, 1):
                for dc in (-1, 0, 1):
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < n and 0 <= nc < n and not grid[nr][nc]:
                        grid[nr][nc] = 1
                        q.append((nr, nc))
        steps += 1
    return -1
static int shortestPath(int[][] grid) {
    int n = grid.length;
    if (grid[0][0] != 0 || grid[n-1][n-1] != 0) return -1;
    Deque<int[]> q = new ArrayDeque<>();
    q.addLast(new int[]{0, 0});
    grid[0][0] = 1;
    int steps = 1;
    while (!q.isEmpty()) {
        for (int s = q.size(); s > 0; s--) {
            int[] cur = q.pollFirst();
            if (cur[0] == n - 1 && cur[1] == n - 1) return steps;
            for (int dr = -1; dr <= 1; dr++)
                for (int dc = -1; dc <= 1; dc++) {
                    int nr = cur[0] + dr, nc = cur[1] + dc;
                    if (nr >= 0 && nr < n && nc >= 0 && nc < n && grid[nr][nc] == 0) {
                        grid[nr][nc] = 1;
                        q.addLast(new int[]{nr, nc});
                    }
                }
        }
        steps++;
    }
    return -1;
}

Type D: Multi-source BFS

Type DMediumdeque of cells

1. What it is. The same BFS, but you enqueue all starting cells before the first step. Every cell is reached from its nearest source.

2. What problem it solves. Distance from each cell to the nearest zero / gate / rotten orange / fire, or "time until everything has spread".

3. How to recognise it. "Nearest", "closest", "distance to the nearest 0", "spreads to adjacent cells every minute", "all sources start at the same time".

4. Intuition. Running one BFS from every cell costs (cells) x (cells). But imagine a super-source connected to all sources by zero-length edges: one BFS from it gives the same distances. Filling the queue with all sources first is that super-source.

5. Generic algorithm
  1. Scan the grid once: enqueue every source, set its distance 0 (or count the fresh targets).
  2. Run the level-order BFS from Type C.
  3. Each cell is set the first time it is reached, which is by its nearest source.
  4. Return the distances, or the number of levels if the question is "how long until all are reached" (and -1 if some target was never reached).

6. State, validity condition, step. State: queue of sources, distance or a fresh counter. Invariant: same as Type C; all sources count as level 0. Stop: queue empty, or (Rotting) no fresh cells left.

Type E: State-space BFS

Type EMediumdeque of states + seen set

1. What it is. BFS where a node is any state (a 4-digit lock code, the remaining amount to make) and an edge is one legal move. There is no grid; you generate neighbours by applying moves.

2. What problem it solves. "Minimum number of moves/operations to turn A into B" when each move has the same cost and the number of states is manageable.

3. How to recognise it. "Minimum number of turns / operations / moves", a puzzle with rules, "transform", deadends or forbidden states, small alphabet or small numeric range.

4. Intuition. Any "fewest steps" puzzle is a shortest-path problem in a hidden graph. If you can list the neighbours of a state and the number of states is not astronomical, BFS finds the answer.

5. Generic algorithm
  1. Define the state and how to compare it (string, tuple, int).
  2. Enqueue the start; put it in seen.
  3. Level loop: dequeue; if it is the target return the level count.
  4. Generate every neighbour by applying each legal move; skip forbidden or seen ones; mark and enqueue.
  5. Queue empty: unreachable, return -1.

6. State, validity condition, step. State: queue + seen set of states. Invariant: as Type C. Cost to count first: number of states x moves per state (Lock: 10,000 x 8).

Type F: Monotonic deque

Type FMedium to Harddeque of indexes

1. What it is. A deque of indexes whose values are strictly decreasing from front to back. Before pushing a new index, pop every index from the back whose value is not larger. Pop the front when its index leaves the window.

2. What problem it solves. The maximum (or minimum) of every window, and DP transitions of the form "best of the previous k states".

3. How to recognise it. "Maximum/minimum in every window of size k", "can jump up to k steps", "indexes differ by at most k", DP where the inner loop scans the last k values (O(n*k) brute force).

4. Intuition. If an older value is not larger than a newer one, the older one can never be the maximum of any future window: the newer one lasts longer and is at least as big. So you may discard it forever. What remains is sorted, so the maximum is at the front.

5. Generic algorithm
  1. Create an empty deque of indexes.
  2. For each i: while the front index is outside the window (front < i - k), pop it from the front.
  3. The front now holds the best value in the window: use it.
  4. Compute the new value for i (for DP: dp[i] = nums[i] + dp[front]).
  5. While the back index has value ≤ the new one, pop the back.
  6. Push i at the back.

6. State, validity condition, step. State: deque of indexes. Invariant: indexes increase front to back and their values strictly decrease, all inside the window. Order matters: evict the front, then read the front, then clean the back, then push.

7. Template (Python and Java), taken from the verified solution of Jump Game VI

def max_result(nums, k):
    n = len(nums)
    dp = [0] * n
    dp[0] = nums[0]
    dq = deque([0])                            # indices; dp values strictly decreasing from front
    for i in range(1, n):
        while dq[0] < i - k:                   # front fell out of the window of size k
            dq.popleft()
        dp[i] = nums[i] + dp[dq[0]]            # front = best dp in the window
        while dq and dp[dq[-1]] <= dp[i]:      # back can never beat the new, later, bigger value
            dq.pop()
        dq.append(i)
    return dp[-1]
static int maxResult(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    dp[0] = nums[0];
    Deque<Integer> dq = new ArrayDeque<>();
    dq.addLast(0);
    for (int i = 1; i < n; i++) {
        while (dq.peekFirst() < i - k) dq.pollFirst();
        dp[i] = nums[i] + dp[dq.peekFirst()];
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.addLast(i);
    }
    return dp[n - 1];
}

Type G: 0-1 BFS

Type GHard (stretch)deque with both ends

1. What it is. BFS on a graph whose edges cost 0 or 1. A free move is pushed to the front of the deque (same level), a paid move to the back (next level). The deque is a two-level priority queue.

2. What problem it solves. Minimum cost where each step is free or costs exactly one: obstacles to remove, arrows to change, flips.

3. How to recognise it. "Minimum number of obstacles to remove", "minimum cost to make a valid path", edge weights only 0 and 1.

4. Intuition. Plain BFS cannot give 0-cost edges the same level as their source, and Dijkstra with a heap is overkill. Putting free moves at the front processes them before anything costing more, which keeps the deque ordered by distance.

5. Generic algorithm
  1. dist = infinity everywhere; dist[start] = 0; deque holds the start.
  2. Pop the front cell.
  3. For each neighbour with weight w: if dist[cell] + w < dist[nb], update it.
  4. If w = 0, appendleft the neighbour; if w = 1, append it.
  5. Answer: dist[goal].

6. State, validity condition, step. State: dist array + deque. Invariant: deque distances are non-decreasing front to back and differ by at most 1. Valid update: strictly smaller distance only (this is why a cell can be pushed more than once).

7. Template (Python and Java), taken from the verified solution of Minimum Obstacle Removal to Reach Corner

def min_obstacles(grid):
    R, C = len(grid), len(grid[0])
    INF = float('inf')
    dist = [[INF] * C for _ in range(R)]
    dist[0][0] = 0
    dq = deque([(0, 0)])
    while dq:
        r, c = dq.popleft()
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C:
                nd = dist[r][c] + grid[nr][nc]         # weight 0 or 1
                if nd < dist[nr][nc]:
                    dist[nr][nc] = nd
                    if grid[nr][nc] == 0:
                        dq.appendleft((nr, nc))        # free step: same level, front of the line
                    else:
                        dq.append((nr, nc))            # costs 1: next level, back of the line
    return dist[R-1][C-1]
static int minObstacles(int[][] grid) {
    int R = grid.length, C = grid[0].length, INF = Integer.MAX_VALUE / 2;
    int[][] dist = new int[R][C];
    for (int[] row : dist) Arrays.fill(row, INF);
    dist[0][0] = 0;
    Deque<int[]> dq = new ArrayDeque<>();
    dq.addLast(new int[]{0, 0});
    int[][] D = {{1,0},{-1,0},{0,1},{0,-1}};
    while (!dq.isEmpty()) {
        int[] cur = dq.pollFirst();
        for (int[] d : D) {
            int nr = cur[0] + d[0], nc = cur[1] + d[1];
            if (nr >= 0 && nr < R && nc >= 0 && nc < C) {
                int nd = dist[cur[0]][cur[1]] + grid[nr][nc];
                if (nd < dist[nr][nc]) {
                    dist[nr][nc] = nd;
                    if (grid[nr][nc] == 0) dq.addFirst(new int[]{nr, nc});
                    else dq.addLast(new int[]{nr, nc});
                }
            }
        }
    }
    return dist[R-1][C-1];
}

Type H: Ring buffer and queue design

Type HMediumarray + head + count

1. What it is. Implement a queue yourself: a fixed array, a head index and a count. Index (head + count) % capacity is the next free slot.

2. What problem it solves. "Design a queue/deque/buffer" questions, and any bounded buffer (logs, recent events, streaming).

3. How to recognise it. "Design Circular Queue", "fixed size", "bounded", "overwrite oldest", O(1) for every operation, no built-in queue allowed.

4. Intuition. Shifting items on dequeue is O(n). Instead, never move the items: move the head pointer and wrap around with the modulo. Keeping a separate count removes the classic ambiguity that head == tail means both empty and full.

5. Generic algorithm
  1. Allocate buf = [0] * k, head = 0, count = 0.
  2. enqueue: if count == k return False; write at (head + count) % k; count++.
  3. dequeue: if count == 0 return False; head = (head + 1) % k; count--.
  4. front = buf[head]; rear = buf[(head + count - 1) % k]; empty and full from count.

6. State, validity condition, step. State: buf, head, count. Invariant: the live items are the count slots starting at head, wrapping. Check empty/full before touching an index.

7. Template (Python and Java), taken from the verified solution of Design Circular Queue

class CircularQueue:
    def __init__(self, k):
        self.buf = [0] * k
        self.head = 0                          # index of the front item
        self.count = 0                         # how many items stored

    def enQueue(self, v):
        if self.count == len(self.buf):
            return False
        self.buf[(self.head + self.count) % len(self.buf)] = v
        self.count += 1
        return True

    def deQueue(self):
        if self.count == 0:
            return False
        self.head = (self.head + 1) % len(self.buf)
        self.count -= 1
        return True

    def Front(self):
        return self.buf[self.head] if self.count else -1

    def Rear(self):
        return self.buf[(self.head + self.count - 1) % len(self.buf)] if self.count else -1

    def isEmpty(self):
        return self.count == 0

    def isFull(self):
        return self.count == len(self.buf)
static class CircularQueue {
    int[] buf; int head = 0, count = 0;
    CircularQueue(int k) { buf = new int[k]; }
    boolean enQueue(int v) {
        if (count == buf.length) return false;
        buf[(head + count) % buf.length] = v;
        count++;
        return true;
    }
    boolean deQueue() {
        if (count == 0) return false;
        head = (head + 1) % buf.length;
        count--;
        return true;
    }
    int Front() { return count == 0 ? -1 : buf[head]; }
    int Rear() { return count == 0 ? -1 : buf[(head + count - 1) % buf.length]; }
    boolean isEmpty() { return count == 0; }
    boolean isFull() { return count == buf.length; }
}

The recurring insight

Three moves turn slow into fast

(1) Reverse the direction: spread from the answers (sources) instead of searching to them. (2) Do the change, not the recompute: add the new, subtract the old. (3) Throw away what can never win: the monotonic deque pops values that a newer, larger value has beaten.

Measured, not claimed

  • Python list as a queue versus deque, 200,000 items: pop(0) 29.08 s, popleft() 0.006 s.
  • Marking visited on enqueue versus on dequeue on an open 60x60 grid: 3,600 pushes versus 7,081 pushes (cells: 3,600). Marking late lets a cell be queued by several neighbours.

Time Needed to Buy Tickets

Type AEasyLeetCode 2073
ShowHide

Where it is reported. Added for pattern coverage (a clean queue simulation; not individually confirmed in the sources read).

Problem. n people stand in a line. Person i wants tickets[i] tickets and buys one per turn, then goes to the back if they still want more. How many seconds until person k has all their tickets?

Example. tickets = [2, 3, 2], k = 2 → 6.

Recognise before coding. The words "goes to the back of the line". Constraints are small (n ≤ 100, tickets ≤ 100), so a simulation is allowed.

Skill it teaches. Type A, then the leap from simulation to a formula. Interviewers like to ask "can you do it without simulating?".

1Brute force
def time_to_buy_brute(tickets, k):
    q = deque((t, i) for i, t in enumerate(tickets))
    time = 0
    while True:
        t, i = q.popleft()
        time += 1                      # this person buys one ticket
        if t - 1 == 0:
            if i == k:
                return time
        else:
            q.append((t - 1, i))       # back of the line
static int timeToBuyBrute(int[] tickets, int k) {
    Deque<int[]> q = new ArrayDeque<>();
    for (int i = 0; i < tickets.length; i++) q.addLast(new int[]{tickets[i], i});
    int time = 0;
    while (true) {
        int[] cur = q.pollFirst();
        time++;
        if (cur[0] - 1 == 0) {
            if (cur[1] == k) return time;
        } else {
            q.addLast(new int[]{cur[0] - 1, cur[1]});
        }
    }
}

Cost: O(sum of tickets) time, O(n) space.

2Observation

Think about one person j and ask: how many seconds can j spend before k finishes? Everyone at or before k in line buys at most tickets[k] times. Everyone after k stops one round earlier, at most tickets[k] − 1, because k finishes first inside the last round. Each person buys min(tickets[j], that cap). The sum is the time. No queue is needed at all.

3Optimal solution
def time_to_buy(tickets, k):
    total = 0
    for i, t in enumerate(tickets):
        # people at or before k buy at most tickets[k]; people after k at most tickets[k] - 1
        total += min(t, tickets[k] if i <= k else tickets[k] - 1)
    return total
static int timeToBuy(int[] tickets, int k) {
    int total = 0;
    for (int i = 0; i < tickets.length; i++)
        total += Math.min(tickets[i], i <= k ? tickets[k] : tickets[k] - 1);
    return total;
}

Cost: O(n) time, O(1) space.

This is the honest lesson of Type A: write the queue first (it is obviously correct), then replace it if the process has structure. The test harness compared the queue and the formula on 4,000 random inputs in each language.

Number of Students Unable to Eat Lunch

Type AEasyLeetCode 1700
ShowHide

Where it is reported. Added for pattern coverage.

Problem. Students in a queue each prefer sandwich type 0 or 1. Sandwiches are in a stack (top first). If the front student likes the top sandwich they take it; otherwise they go to the back. Return how many students never eat.

Example. students = [1,1,0,0], sandwiches = [0,1,0,1] → 0.

Recognise before coding. "Goes to the end of the queue" plus a stop condition: the process can loop forever when no one in the line wants the top sandwich.

Skill it teaches. Type A with a termination guard (spins), then recognising that only the counts matter.

1Brute force
def count_students_brute(students, sandwiches):
    q = deque(students)
    i = 0                              # top sandwich
    spins = 0                          # consecutive students who refused
    while q and spins < len(q):
        if q[0] == sandwiches[i]:
            q.popleft()
            i += 1
            spins = 0
        else:
            q.append(q.popleft())      # refuse, go to the back
            spins += 1
    return len(q)
static int countStudentsBrute(int[] students, int[] sandwiches) {
    Deque<Integer> q = new ArrayDeque<>();
    for (int s : students) q.addLast(s);
    int i = 0, spins = 0;
    while (!q.isEmpty() && spins < q.size()) {
        if (q.peekFirst() == sandwiches[i]) {
            q.pollFirst();
            i++;
            spins = 0;
        } else {
            q.addLast(q.pollFirst());
            spins++;
        }
    }
    return q.size();
}

Cost: O(n²) time, O(n) space.

2Observation

The order of students never changes who can eat. A sandwich on top can be taken if and only if at least one remaining student wants that type, because everyone eventually reaches the front. So keep two counters (how many want 0, how many want 1) and walk the sandwiches: the first sandwich nobody wants blocks everything behind it, and all remaining students are stuck.

3Optimal solution
def count_students(students, sandwiches):
    want = [0, 0]
    for s in students:
        want[s] += 1
    for i, sw in enumerate(sandwiches):
        if want[sw] == 0:              # nobody left wants the top sandwich
            return len(sandwiches) - i
        want[sw] -= 1
    return 0
static int countStudents(int[] students, int[] sandwiches) {
    int[] want = new int[2];
    for (int s : students) want[s]++;
    for (int i = 0; i < sandwiches.length; i++) {
        if (want[sandwiches[i]] == 0) return sandwiches.length - i;
        want[sandwiches[i]]--;
    }
    return 0;
}

Cost: O(n) time, O(1) space.

Why the guard in the brute force: without spins < len(q) the loop runs forever when the front sandwich is unwanted. "Every student refused once in a row" is the signal that nothing will change.

Reveal Cards In Increasing Order

Type AMediumLeetCode 950
ShowHide

Where it is reported. Added for pattern coverage (queue of indexes).

Problem. Reveal procedure: show the top card, move the next top card to the bottom, repeat. Return an ordering of the deck so that the revealed cards come out in increasing order.

Example. [17,13,11,2,3,5,7] → [2,13,3,11,5,17,7].

Recognise before coding. A procedure that reveals / moves to the bottom, and you must produce the input arrangement for a required output order.

Skill it teaches. Queue of positions instead of values: simulate the procedure on indexes, and use it to decide where each sorted card goes.

1Brute force
def reveal_brute(deck):
    def reveal_order(arr):                     # the dealing procedure from the problem
        q = deque(arr)
        out = []
        while q:
            out.append(q.popleft())            # reveal top card
            if q:
                q.append(q.popleft())          # next card to the bottom
        return out
    want = sorted(deck)
    for perm in itertools.permutations(deck):  # try every ordering
        if reveal_order(perm) == want:
            return list(perm)
static int[] revealBrute(int[] deck) {
    int[] want = deck.clone();
    Arrays.sort(want);
    return permSearch(deck.clone(), 0, want);
}
static int[] permSearch(int[] a, int k, int[] want) {
    if (k == a.length) {
        Deque<Integer> q = new ArrayDeque<>();
        for (int x : a) q.addLast(x);
        int[] out = new int[a.length];
        int p = 0;
        while (!q.isEmpty()) {
            out[p++] = q.pollFirst();
            if (!q.isEmpty()) q.addLast(q.pollFirst());
        }
        return Arrays.equals(out, want) ? a.clone() : null;
    }
    for (int i = k; i < a.length; i++) {
        int t = a[k]; a[k] = a[i]; a[i] = t;
        int[] r = permSearch(a, k + 1, want);
        t = a[k]; a[k] = a[i]; a[i] = t;
        if (r != null) return r;
    }
    return null;
}

Cost: O(n! x n) time (try every permutation), O(n) space; only possible for tiny decks.

2Observation

Run the revealing procedure on positions 0..n−1 instead of cards. The first position revealed gets the smallest card, the next position revealed gets the second smallest, and so on. Simulating the procedure once on the index queue tells you, in order, which slot gets which sorted card.

3Optimal solution
def reveal(deck):
    n = len(deck)
    res = [0] * n
    idx = deque(range(n))                      # positions still unfilled, in dealing order
    for card in sorted(deck):
        res[idx.popleft()] = card              # this position is revealed next: smallest card
        if idx:
            idx.append(idx.popleft())          # the following position goes to the bottom
    return res
static int[] reveal(int[] deck) {
    int n = deck.length;
    int[] sorted = deck.clone();
    Arrays.sort(sorted);
    int[] res = new int[n];
    Deque<Integer> idx = new ArrayDeque<>();
    for (int i = 0; i < n; i++) idx.addLast(i);
    for (int card : sorted) {
        res[idx.pollFirst()] = card;
        if (!idx.isEmpty()) idx.addLast(idx.pollFirst());
    }
    return res;
}

Cost: O(n log n) for the sort, O(n) for the simulation; O(n) space.

The twist is that the queue does not hold the data, it holds where the data will go. This "simulate on indexes" idea appears again in Dota2 Senate below (the queue holds indexes there too).

Dota2 Senate

Type AMediumLeetCode 649
ShowHide

Where it is reported. Added for pattern coverage (two queues; not individually confirmed in the sources read).

Problem. A string of R and D senators votes in rounds. In turn, each senator may ban one opposing senator (they lose all rights) or announce victory if all remaining senators are on their side. Banned senators are skipped. Return which party wins, assuming optimal play.

Example. "RDD" → "Dire".

Recognise before coding. Two groups acting in a fixed cyclic order, with repeated rounds. Optimal play means: always ban the next opponent who would act.

Skill it teaches. Two queues of indexes, and the trick of re-enqueueing the winner at index + n to keep a global ordering across rounds.

1Brute force
def predict_victory_brute(senate):
    s = list(senate)
    n = len(s)
    alive = [True] * n
    while True:
        for i in range(n):
            if not alive[i]:
                continue
            j, found = (i + 1) % n, -1         # next living opponent, going round the circle
            for _ in range(n - 1):
                if alive[j] and s[j] != s[i]:
                    found = j
                    break
                j = (j + 1) % n
            if found < 0:
                return "Radiant" if s[i] == 'R' else "Dire"
            alive[found] = False
static String predictVictoryBrute(String senate) {
    char[] s = senate.toCharArray();
    int n = s.length;
    boolean[] alive = new boolean[n];
    Arrays.fill(alive, true);
    while (true) {
        for (int i = 0; i < n; i++) {
            if (!alive[i]) continue;
            int j = (i + 1) % n, found = -1;
            for (int t = 0; t < n - 1; t++) {
                if (alive[j] && s[j] != s[i]) { found = j; break; }
                j = (j + 1) % n;
            }
            if (found < 0) return s[i] == 'R' ? "Radiant" : "Dire";
            alive[found] = false;
        }
    }
}

Cost: O(n²) or worse time (find the next living opponent by scanning, over many rounds), O(n) space.

2Observation

Only who acts first matters. Keep each party's senators in a queue ordered by index. Pop one from each: the smaller index acts first, bans the other, and returns to the queue for the next round, which is exactly "n positions later", so push index + n. The loser disappears. The party whose queue is empty loses.

3Optimal solution
def predict_victory(senate):
    n = len(senate)
    radiant, dire = deque(), deque()
    for i, c in enumerate(senate):
        (radiant if c == 'R' else dire).append(i)
    while radiant and dire:
        r, d = radiant.popleft(), dire.popleft()
        if r < d:
            radiant.append(r + n)              # r acts first, bans d, votes again next round
        else:
            dire.append(d + n)
    return "Radiant" if radiant else "Dire"
static String predictVictory(String senate) {
    int n = senate.length();
    Deque<Integer> radiant = new ArrayDeque<>(), dire = new ArrayDeque<>();
    for (int i = 0; i < n; i++) (senate.charAt(i) == 'R' ? radiant : dire).addLast(i);
    while (!radiant.isEmpty() && !dire.isEmpty()) {
        int r = radiant.pollFirst(), d = dire.pollFirst();
        if (r < d) radiant.addLast(r + n);
        else dire.addLast(d + n);
    }
    return radiant.isEmpty() ? "Dire" : "Radiant";
}

Cost: O(n) time, O(n) space (each senator is pushed back at most once per ban, and there are at most n bans).

Verified bug. Re-enqueuing the winner at index instead of index + n gave a wrong answer on 2 of the 16 length-4 strings, for example "RDDD" (correct Dire, buggy Radiant), because the winner would act before senators who really come earlier next round.

Moving Average from Data Stream

Type BEasyLeetCode 346
ShowHide

Where it is reported. Added for pattern coverage. Not in Grind 75 per the local cache (2026-10-09); a classic queue-window problem that is commonly practised, but I found no frequency data.

Problem. Design a class with next(val) that returns the average of the last size values seen so far.

Example. size = 3, stream 1, 10, 3, 5 → 1.0, 5.5, 4.667, 6.0.

Recognise before coding. "Moving", "last k", "data stream".

Skill it teaches. Type B: queue plus running total; the idea behind every rolling metric.

1Brute force
class MovingAverageBrute:
    def __init__(self, size):
        self.size = size
        self.vals = []                 # keeps everything

    def next(self, val):
        self.vals.append(val)
        window = self.vals[-self.size:]        # copies up to size items every call
        return sum(window) / len(window)
static class MovingAverageBrute {
    int size; List<Integer> vals = new ArrayList<>();
    MovingAverageBrute(int size) { this.size = size; }
    double next(int val) {
        vals.add(val);
        long sum = 0;
        int from = Math.max(0, vals.size() - size);
        for (int i = from; i < vals.size(); i++) sum += vals.get(i);
        return (double) sum / (vals.size() - from);
    }
}

Cost: O(size) time per call, O(n) space (the brute force keeps everything).

2Observation

The window changes by one value in and at most one value out. Keep the sum and adjust it: add the new value, subtract the evicted one. The queue exists only to know which value to evict.

3Optimal solution
class MovingAverage:
    def __init__(self, size):
        self.size = size
        self.q = deque()
        self.total = 0

    def next(self, val):
        self.q.append(val)
        self.total += val
        if len(self.q) > self.size:
            self.total -= self.q.popleft()     # oldest leaves the window
        return self.total / len(self.q)
static class MovingAverage {
    int size; long total = 0; Deque<Integer> q = new ArrayDeque<>();
    MovingAverage(int size) { this.size = size; }
    double next(int val) {
        q.addLast(val);
        total += val;
        if (q.size() > size) total -= q.pollFirst();
        return (double) total / q.size();
    }
}

Cost: O(1) time per call, O(size) space.

Verified bug. Forgetting to subtract the evicted value (keeping the queue right but the total wrong) printed 6.333 where the correct fourth average is 6.0. If an interviewer asks for no queue, say the circular buffer from Part 7, problem 13, does the same job with a fixed array.

Shortest Path in Binary Matrix

Type CMediumLeetCode 1091
ShowHide

Where it is reported. Added for pattern coverage (the single-source BFS archetype; named in a search answer from general knowledge, not from a frequency list).

Problem. In an n x n grid of 0 (open) and 1 (blocked), find the length of the shortest path from the top-left to the bottom-right moving in 8 directions through open cells. Return -1 if none. Length counts cells.

Example. [[0,0,0],[1,1,0],[1,1,0]] → 4.

Recognise before coding. "Shortest path", unweighted, grid. Diagonals only add 4 more neighbours.

Skill it teaches. Type C: level-order BFS, the visited-on-enqueue rule, the level-size loop, and the start/goal-blocked edge cases.

1Brute force
def shortest_path_brute(grid):
    n = len(grid)
    if grid[0][0] or grid[n-1][n-1]:
        return -1
    INF = float('inf')
    dist = [[INF] * n for _ in range(n)]
    dist[0][0] = 1
    changed = True
    while changed:                             # relax every cell again and again until nothing improves
        changed = False
        for r in range(n):
            for c in range(n):
                if grid[r][c] or dist[r][c] == INF:
                    continue
                for dr in (-1, 0, 1):
                    for dc in (-1, 0, 1):
                        nr, nc = r + dr, c + dc
                        if 0 <= nr < n and 0 <= nc < n and not grid[nr][nc] and dist[r][c] + 1 < dist[nr][nc]:
                            dist[nr][nc] = dist[r][c] + 1
                            changed = True
    return -1 if dist[n-1][n-1] == INF else dist[n-1][n-1]
static int shortestPathBrute(int[][] grid) {
    int n = grid.length;
    if (grid[0][0] != 0 || grid[n-1][n-1] != 0) return -1;
    int INF = Integer.MAX_VALUE / 2;
    int[][] dist = new int[n][n];
    for (int[] row : dist) Arrays.fill(row, INF);
    dist[0][0] = 1;
    boolean changed = true;
    while (changed) {
        changed = false;
        for (int r = 0; r < n; r++)
            for (int c = 0; c < n; c++) {
                if (grid[r][c] != 0 || dist[r][c] == INF) continue;
                for (int dr = -1; dr <= 1; dr++)
                    for (int dc = -1; dc <= 1; dc++) {
                        int nr = r + dr, nc = c + dc;
                        if (nr >= 0 && nr < n && nc >= 0 && nc < n && grid[nr][nc] == 0 && dist[r][c] + 1 < dist[nr][nc]) {
                            dist[nr][nc] = dist[r][c] + 1;
                            changed = true;
                        }
                    }
            }
    }
    return dist[n-1][n-1] == INF ? -1 : dist[n-1][n-1];
}

Cost: O((n²)²) time: relax every cell again and again until nothing improves.

2Observation

Moves all cost 1, so BFS reaches each cell first by a shortest path. Mark a cell visited when you enqueue it; count levels with a loop over the current queue size.

3Optimal solution
def shortest_path(grid):
    n = len(grid)
    if grid[0][0] or grid[n-1][n-1]:
        return -1
    q = deque([(0, 0)])
    grid[0][0] = 1                             # visited (reuse the input as the seen set)
    steps = 1                                  # path length counts cells, so the start is 1
    while q:
        for _ in range(len(q)):
            r, c = q.popleft()
            if r == n - 1 and c == n - 1:
                return steps
            for dr in (-1, 0, 1):
                for dc in (-1, 0, 1):
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < n and 0 <= nc < n and not grid[nr][nc]:
                        grid[nr][nc] = 1
                        q.append((nr, nc))
        steps += 1
    return -1
static int shortestPath(int[][] grid) {
    int n = grid.length;
    if (grid[0][0] != 0 || grid[n-1][n-1] != 0) return -1;
    Deque<int[]> q = new ArrayDeque<>();
    q.addLast(new int[]{0, 0});
    grid[0][0] = 1;
    int steps = 1;
    while (!q.isEmpty()) {
        for (int s = q.size(); s > 0; s--) {
            int[] cur = q.pollFirst();
            if (cur[0] == n - 1 && cur[1] == n - 1) return steps;
            for (int dr = -1; dr <= 1; dr++)
                for (int dc = -1; dc <= 1; dc++) {
                    int nr = cur[0] + dr, nc = cur[1] + dc;
                    if (nr >= 0 && nr < n && nc >= 0 && nc < n && grid[nr][nc] == 0) {
                        grid[nr][nc] = 1;
                        q.addLast(new int[]{nr, nc});
                    }
                }
        }
        steps++;
    }
    return -1;
}

Cost: O(n²) time, O(n²) space (O(1) extra if you reuse the grid as visited, as here).

Verified bugs. (a) Counting steps once per cell popped instead of once per level returned 5 where the correct answer is 4 for the grid above. (b) The start cell counts as 1: [[0]] returns 1, [[1]] returns -1. (c) Marking visited on dequeue instead of enqueue queued 7,081 cells instead of 3,600 on an open 60x60 grid (same answer, double the work).

Rotting Oranges

Type DMediumLeetCode 994
ShowHide

Where it is reported. Frequently asked (Grind 75 Graphs section, fetched 2026-10-10; described in several guides as the standard multi-source BFS problem).

Problem. Grid: 0 empty, 1 fresh orange, 2 rotten orange. Every minute, a fresh orange adjacent (4 directions) to a rotten one becomes rotten. Return the minutes until no fresh orange is left, or -1 if impossible.

Example. [[2,1,1],[1,1,0],[0,1,1]] → 4.

Recognise before coding. "Every minute", "spreads to adjacent", several rotten oranges at once.

Skill it teaches. Type D: all sources enter the queue first; levels are minutes; a fresh counter detects the impossible case.

1Brute force
def oranges_rotting_brute(grid):
    g = [row[:] for row in grid]
    R, C = len(g), len(g[0])
    minutes = 0
    while True:
        rot = []                               # fresh oranges that touch a rotten one right now
        for r in range(R):
            for c in range(C):
                if g[r][c] == 1:
                    for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                        nr, nc = r + dr, c + dc
                        if 0 <= nr < R and 0 <= nc < C and g[nr][nc] == 2:
                            rot.append((r, c))
                            break
        if not rot:
            break
        for r, c in rot:
            g[r][c] = 2
        minutes += 1
    return -1 if any(1 in row for row in g) else minutes
static int orangesRottingBrute(int[][] grid) {
    int R = grid.length, C = grid[0].length;
    int[][] g = new int[R][];
    for (int i = 0; i < R; i++) g[i] = grid[i].clone();
    int[][] D = {{1,0},{-1,0},{0,1},{0,-1}};
    int minutes = 0;
    while (true) {
        List<int[]> rot = new ArrayList<>();
        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++)
                if (g[r][c] == 1)
                    for (int[] d : D) {
                        int nr = r + d[0], nc = c + d[1];
                        if (nr >= 0 && nr < R && nc >= 0 && nc < C && g[nr][nc] == 2) { rot.add(new int[]{r, c}); break; }
                    }
        if (rot.isEmpty()) break;
        for (int[] p : rot) g[p[0]][p[1]] = 2;
        minutes++;
    }
    for (int[] row : g) for (int v : row) if (v == 1) return -1;
    return minutes;
}

def num_squares(n):
    squares = [k * k for k in range(1, int(n ** 0.5) + 1)]
    seen = {n}
    q = deque([n])                             # a node is "what is left to make"
    level = 0
    while q:
        level += 1                             # number of squares used so far
        for _ in range(len(q)):
            rem = q.popleft()
            for sq in squares:
                nxt = rem - sq
                if nxt == 0:
                    return level
                if nxt < 0:

                    q.append(nxt)
    return level

2Observation

def max_result(nums, k):
    n = len(nums)
    dp = [0] * n
    dp[0] = nums[0]
    dq = deque([0])                            # indices; dp values strictly decreasing from front
    for i in range(1, n):
        while dq[0] < i - k:                   # front fell out of the window of size k
            dq.popleft()
        dp[i] = nums[i] + dp[dq[0]]            # front = best dp in the window
        while dq and dp[dq[-1]] <= dp[i]:      # back can never beat the new, later, bigger value
            dq.pop()
        dq.append(i)
    return dp[-1]
static int maxResult(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    dp[0] = nums[0];
    Deque<Integer> dq = new ArrayDeque<>();
    dq.addLast(0);
    for (int i = 1; i < n; i++) {
        while (dq.peekFirst() < i - k) dq.pollFirst();
        dp[i] = nums[i] + dp[dq.peekFirst()];
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.addLast(i);
    }
    return dp[n - 1];
}

        if self.count == len(self.buf):
            return False
        self.buf[(self.head + self.count) % len(self.buf)] = v
        self.count += 1
        return True

    def deQueue(self):
        if self.count == 0:
            return False
        self.head = (self.head + 1) % len(self.buf)
        self.count -= 1
        return True

    def Front(self):
        return self.buf[self.head] if self.count else -1

    def Rear(self):
        return self.buf[(self.head + self.count - 1) % len(self.buf)] if self.count else -1

    def isEmpty(self):
        return self.count == 0

    def isFull(self):
        return self.count == len(self.buf)
static class CircularQueue {
    int[] buf; int head = 0, count = 0;
    CircularQueue(int k) { buf = new int[k]; }
    boolean enQueue(int v) {
        if (count == buf.length) return false;
        buf[(head + count) % buf.length] = v;
        count++;
        return true;
    }
    boolean deQueue() {
        if (count == 0) return false;
        head = (head + 1) % buf.length;
        count--;
        return true;
    }
    int Front() { return count == 0 ? -1 : buf[head]; }
    int Rear() { return count == 0 ? -1 : buf[(head + count - 1) % buf.length]; }
    boolean isEmpty() { return count == 0; }
    boolean isFull() { return count == buf.length; }
}

Cost: O(1) per operation, O(k) space.

Worked interview walkthrough: Rotting Oranges

Interviewer: "Grid of 0 empty, 1 fresh, 2 rotten. Each minute rot spreads to the 4 neighbours of every rotten orange. Minutes until none is fresh, or -1?"

  1. Clarify (30 s). "Is the grid possibly empty or all empty cells? Then I return 0. Do diagonals spread? No, four directions. Can the answer be -1? Yes if a fresh orange is walled off."
  2. Brute force (1 min). "Each minute, scan the whole grid, rot every fresh orange next to a rotten one, repeat until nothing changes. Each scan is O(RC) and there can be O(RC) minutes in a snake-like grid, so O((RC)²)."
  3. Bottleneck (30 s). "Each minute I rescan cells that cannot change. Only oranges that rotted last minute can rot new ones."
  4. Pattern (30 s). "Spreading simultaneously from several sources, one step per minute: multi-source BFS. Minutes are levels."
  5. Design (1 min). "Queue of rotten cells. One scan fills it and counts fresh oranges. BFS by levels: for each rotten cell, rot its fresh neighbours, decrement fresh, enqueue them. After each level, minutes + 1. I mark an orange rotten when I enqueue it, so it is enqueued once. I stop as soon as fresh is 0."
  6. Complexity (15 s). "O(RC) time and space: every cell enqueued at most once, four neighbour checks each."
  7. Code (5 min). Template T3. Say out loud the two lines that are easy to get wrong: while q and fresh (otherwise an extra minute is counted) and marking the orange before enqueueing.
  8. Test (2 min). "Example gives 4. [[2,1,1],[0,1,1],[1,0,1]] gives -1 because the bottom-left orange is isolated. [[0]] gives 0 and [[0,2]] gives 0."
  9. Follow-ups to expect. "What if you must return the path?" (store parents). "What if the grid is huge and sparse?" (hash set of coordinates). "What if oranges rot at different speeds?" (weights: Dijkstra, or 0-1 BFS if 0/1).

def shortest_path(grid):
    n = len(grid)
    if grid[0][0] or grid[n-1][n-1]:
        return -1

    grid[0][0] = 1                             # visited (reuse the input as the seen set)

    return -1

                        q.addLast(new int[]{nr, nc});

def max_result(nums, k):
    n = len(nums)
    dp = [0] * n
    dp[0] = nums[0]
    dq = deque([0])                            # indices; dp values strictly decreasing from front
    for i in range(1, n):
        while dq[0] < i - k:                   # front fell out of the window of size k
            dq.popleft()
        dp[i] = nums[i] + dp[dq[0]]            # front = best dp in the window
        while dq and dp[dq[-1]] <= dp[i]:      # back can never beat the new, later, bigger value
            dq.pop()
        dq.append(i)
    return dp[-1]
static int maxResult(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    dp[0] = nums[0];
    Deque<Integer> dq = new ArrayDeque<>();
    dq.addLast(0);
    for (int i = 1; i < n; i++) {
        while (dq.peekFirst() < i - k) dq.pollFirst();
        dp[i] = nums[i] + dp[dq.peekFirst()];
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.addLast(i);
    }
    return dp[n - 1];
}

T8. Ring buffer

class CircularQueue:
    def __init__(self, k):
        self.buf = [0] * k
        self.head = 0                          # index of the front item
        self.count = 0                         # how many items stored

    def enQueue(self, v):
        if self.count == len(self.buf):
            return False
        self.buf[(self.head + self.count) % len(self.buf)] = v
        self.count += 1
        return True

    def deQueue(self):
        if self.count == 0:
            return False
        self.head = (self.head + 1) % len(self.buf)
        self.count -= 1
        return True

    def Front(self):
        return self.buf[self.head] if self.count else -1

    def Rear(self):
        return self.buf[(self.head + self.count - 1) % len(self.buf)] if self.count else -1

    def isEmpty(self):
        return self.count == 0

    def isFull(self):
        return self.count == len(self.buf)

        return true;
    }
    int Front() { return count == 0 ? -1 : buf[head]; }
    int Rear() { return count == 0 ? -1 : buf[(head + count - 1) % buf.length]; }
    boolean isEmpty() { return count == 0; }
    boolean isFull() { return count == buf.length; }
}

Applies to. Type H. Design Circular Queue and Deque, bounded log buffers.

Complexity. O(1) per operation, O(k) space

The line people most often get wrong. Use count to tell empty from full; next free slot is (head + count) % k.

Exercise 1: Sliding-window rate limiter

Scenario. An API gateway must allow each user at most N requests per rolling window of W seconds and reject the rest.

LevelRequirement (each adds to the previous)
1allow(user, timestamp) returns true/false for one user with limit N per W seconds. Exact sliding window (not a fixed bucket). Timestamps are non-decreasing.
2Many users. Per-user limits (some users have N = 10, others N = 1000). Memory must not grow without bound for users who go quiet.
3Report retry_after(user, timestamp): how many seconds until the next request would be allowed. Also support an injected clock and timestamps that arrive slightly out of order.

What this exercises. Type B: a deque of timestamps per user with eviction from the front. Justify the structure: why a deque of timestamps rather than a counter (exact versus approximate), what it costs in memory (up to N timestamps per user), and when you would switch to a token bucket or fixed-window counters or a circular array of per-second counts.

  • Test: exactly N requests allowed, N+1 rejected; boundary at exactly W seconds old; two users independent; a quiet user cleaned up; N = 0; W = 0; many requests with the same timestamp.
  • Edge cases: timestamps equal or going backwards, huge W, unknown user, negative values.
  • Interviewer extensions (stated, not solved): thread safety (what must be locked: the per-user deque or the whole map?), a distributed limiter across many servers (shared store, clock skew), burst allowance, fairness between users, memory cap with eviction of idle users.

Exercise 2: Job queue with retries

Scenario. A small service receives jobs and a pool of workers processes them. Some jobs fail and must be retried.

LevelRequirement (each adds to the previous)
1submit(job) and next_job() in FIFO order. Define what next_job() returns when the queue is empty (None/null, an exception, or blocks).
2fail(job) re-queues the job at the back with an attempt count. After 3 failures it moves to a dead-letter list. Jobs have priorities: high-priority jobs jump the line.
3Retry delay: a failed job may not run again before now + backoff(attempt). next_job() must return the oldest runnable job and never spin on jobs that are waiting.

What this exercises. Type A/H: a FIFO deque for level 1; a second queue (or a heap) for priority in level 2; and at level 3 you will notice a plain FIFO is not enough because the next runnable job depends on time. Justify when a heap keyed by "ready time" beats a queue (that is where this meets Heaps).

  • Test: FIFO order, empty queue, a job failing 1, 2, 3 times, dead-letter content, a high-priority job inserted while others wait, a delayed job becoming runnable exactly at its ready time.
  • Edge cases: the same job submitted twice (idempotency), a job failing after being dead-lettered, clock going backwards, a huge backlog (memory).
  • Interviewer extensions (stated, not solved): multiple workers pulling at once (thread-safe queue, locks or a blocking queue), at-least-once versus at-most-once delivery, visibility timeouts, crash recovery (persist the queue), backpressure (a bounded queue and what submit does when it is full).

            dq.popleft()
        dp[i] = nums[i] + (dp[dq[0]] if dq and dp[dq[0]] > 0 else 0)
        while dq and dp[dq[-1]] <= dp[i]:
            dq.pop()
        dq.append(i)
    return max(dp)
static int constrainedSubsetSum(int[] nums, int k) {
    int n = nums.length, ans = Integer.MIN_VALUE;
    int[] dp = new int[n];
    Deque<Integer> dq = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!dq.isEmpty() && dq.peekFirst() < i - k) dq.pollFirst();
        dp[i] = nums[i] + (!dq.isEmpty() && dp[dq.peekFirst()] > 0 ? dp[dq.peekFirst()] : 0);
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.addLast(i);
        ans = Math.max(ans, dp[i]);
    }
    return ans;
}
