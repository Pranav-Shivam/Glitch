Part 1 · FoundationsWhat a stack is

A stack is a list with one open end, called the top. You add at the top (push), remove from the top (pop), and look at the top without removing it (peek). The last item in is the first item out. This is LIFO, last in, first out.

The video's picture is a stack of plates in a cafeteria. Clean plates go on the pile, and the plate on top is the first one taken to be used.

Why it exists

Many problems have this shape: you start something, you cannot finish it until something later happens, and when it happens you must finish the most recent unfinished thing first.

  • Brackets: the last bracket opened must be the first one closed.
  • Nested function calls: the innermost call returns first.
  • Undo: the latest action is reversed first.

A stack remembers unresolved things in the order they must be resolved.

What it does better than an array and a loop

With only an array and a loop, finding the most recent unresolved item means rescanning backwards, which costs O(n) every time. A stack keeps that item at the top, so you reach it in O(1).

How it works inside

A stack is a dynamic array where you only touch the last slot, or a linked list where you only touch the head. Both give O(1) push and pop. Nothing has to shift, because the open end is the only end you use.

Use a stack when

  • Symbols must match or nest
  • You need the most recent unresolved item
  • You are simulating reversal or undo
  • You need the next greater or smaller element
  • You want to simulate recursion with your own loop
  • You are evaluating expressions

Do not use a stack when

  • You need the middle or both ends (use a deque)
  • You need the smallest or largest of everything seen so far (use a heap)
  • A contiguous range with both ends moving is the idea (use a sliding window)
  • You need lookup by value (use a hash map)
  • First come, first served (use a queue)

Where you already meet stacks

From the video: A stack is not only a data structure. After enough problems it becomes a coding pattern you can spot: you have pending items, and a later item resolves the most recent ones.

  • Matching parentheses. The first stack problem most people see. It checks whether an expression is valid before you spend time evaluating it.
  • Evaluating expressions. Use the same stack to solve small portions and combine them.
  • Parsing code. A compiler knows a bracket was never matched the same way parenthesis matching does.
  • Undo and redo. The undo button keeps a stack of your operations and undoes the topmost one first.
  • The call stack. Recursion is the system's stack. An iterative DFS uses your own.

  • Push, pop and peek are O(1) because they touch only the last slot. Nothing shifts. Popping from the front of a Python list is O(n) because every element moves left, which is why you always pop from the end.
  • Amortized push. A dynamic array sometimes resizes at a cost of O(n), but it happens so rarely that across all pushes the average is O(1).
  • Space is O(n) because in the worst case every element is pushed and none is popped, like "(((((((" or a strictly decreasing array in next greater element.

Why the monotonic stack is O(n), not O(n²)

A monotonic stack has a while loop inside a for loop, which looks quadratic. It is not. Each element is pushed exactly once and popped at most once, so across the whole run there are at most n pushes and n pops. The total work is at most 2n, which is O(n). This is amortized analysis.

Say this aloud in an interview: The inner while loop looks nested, but each element enters and leaves the stack at most once, so the total work is O(n).

Part 5 · PatternsProblem-solving method

  1. Understand the input. Characters, numbers, tokens? What does the output look like?
  2. Check the constraints. With n up to 105, O(n²) is too slow.
  3. Clarify edge cases. Empty input, unmatched symbols, negative numbers.
  4. Say the brute force and its complexity. It is usually "for each element, scan back or forward".
  5. Find the bottleneck. "I keep rescanning to find the most recent item, or the next bigger one."
  6. Ask the stack questions. Is there a most recent unresolved item? Does a later element resolve earlier ones? Is there nesting?
  7. Decide what goes on the stack. Values, indices, (value, extra) pairs, or saved contexts.
  8. State the invariant. Monotonic increasing or decreasing, or "only unmatched openers".
  9. Decide the pop condition and what to do on a pop: record an answer, compute an area, or cancel.
  10. State the complexity. For a monotonic stack, mention the amortized argument.
  11. Code it.
  12. Test on empty, a single element, all equal, strictly increasing and strictly decreasing inputs.

Say the invariant aloud: The stack holds indices of days still waiting for a warmer day, with temperatures decreasing from bottom to top.

Naming the invariant shows the interviewer that you understand the algorithm rather than a memorized template.

Type A · Problem labMatching and nesting

Every closer must match the most recent opener that is still open.

Recognize it

  • Brackets, tags, quotes, or any paired symbols
  • The words valid, balanced, well-formed, nested
Algorithm
  1. Start with an empty stack.
  2. Push every opener.
  3. On a closer, the stack must be non-empty and its top must pair with the closer. Pop it.
  4. After the last symbol the stack must be empty.

Valid Parentheses

EasyLeetCode 20Video and notes
Show solutionHide

Given a string made of ()[]{}, decide whether every bracket is closed by the right kind of bracket, in the right order. "{[]}" is valid. "([)]" is not.

Recognize before codingNesting, where a closer must match the latest opener.
Skill it teachesPush and pop discipline, and guarding against an empty stack.
1Brute force

Keep deleting adjacent pairs (), [] and {} from the string. If nothing is left, the string was valid. Every pass scans the whole string, and ((((....)))) needs n/2 passes.

def valid_parentheses_brute(s):
    # keep deleting adjacent matched pairs until nothing changes
    prev = None
    while prev != s:
        prev = s
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return s == ""
static boolean brute(String s) {
    String prev;
    do {                                  // keep deleting matched pairs until nothing changes
        prev = s;
        s = s.replace("()", "").replace("[]", "").replace("{}", "");
    } while (!s.equals(prev));
    return s.isEmpty();
}
2The bottleneck and the key observation

The pair that cancels is always the most recently opened bracket that is still unmatched. That is what LIFO means, so the unmatched openers belong on a stack. In the video the stack is exactly this: add every opener, and on a closer compare it with the top.

3Optimal approach
  1. Start with an empty stack.
  2. Opener: push it.
  3. Closer: if the stack is empty, return false. Otherwise pop and check that the popped opener pairs with this closer.
  4. After the last character, the stack must be empty. Anything left is an opener that was never closed.
def valid_parentheses(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in pairs:                              # closer
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:                                        # opener
            stack.append(ch)
    return not stack                                 # leftover openers => invalid
static boolean optimal(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char ch : s.toCharArray()) {
        if (ch == '(' || ch == '[' || ch == '{') {
            stack.push(ch);
        } else {
            if (stack.isEmpty()) return false;      // closer with nothing open
            char open = stack.pop();
            if ((ch == ')' && open != '(') || (ch == ']' && open != '[') || (ch == '}' && open != '{'))
                return false;
        }
    }
    return stack.isEmpty();                          // leftover openers => invalid
}

Type B · Problem labCancel and undo

The stack is the result so far, and a new item may cancel the top.

Recognize it

  • Remove adjacent pairs, backspace, undo, cancel out
  • Simulations where only the latest survivor can interact with the new arrival
Algorithm
  1. Treat the stack as the answer built so far.
  2. For each item, check whether it cancels the top.
  3. Use a while loop if one item can cancel several, as in asteroids.
  4. If the item survives, push it. The stack read bottom to top is the result.
Pseudocode
stack = empty
for each item x:
    alive = true
    while alive and stack not empty and cancels(stack.top, x):
        resolve(stack.pop(), x)       # may mark x as destroyed
    if alive: push x
return stack, bottom to top

Backspace String Compare

EasyLeetCode 844Notes
Show solutionHide

Two strings where # is a backspace. Are they equal after typing both into an empty editor? "ab#c" and "ad#c" both end up as "ac".

Recognize before codingA character that undoes the one before it.
Skill it teachesUsing a stack as the result so far.
1Brute force

Build each final string one character at a time, and on every # rebuild it without its last character. Slicing copies the string, so each backspace costs O(n).

def backspace_compare_brute(s, t):
    def build(x):
        res = ""
        for ch in x:
            if ch == '#':
                res = res[:-1]          # slicing copies the whole string: O(n) per '#'
            else:
                res += ch
        return res
    return build(s) == build(t)
private static String buildBrute(String x) {
    String res = "";
    for (char ch : x.toCharArray()) {
        if (ch == '#') {
            if (!res.isEmpty()) res = res.substring(0, res.length() - 1);   // copies: O(n)
        } else {
            res = res + ch;                                                  // copies: O(n)
        }
    }
    return res;
}

static boolean brute(String s, String t) { return buildBrute(s).equals(buildBrute(t)); }
2The bottleneck and the key observation

The text typed so far is a stack. A letter pushes, and a # pops the top, or does nothing when the stack is empty.

3Optimal approach
  1. Write a helper that turns a string into its final text.
  2. For each character: letter pushes, # pops if the stack is not empty.
  3. Compare the two stacks.
  4. Follow-up: O(1) space is possible by scanning both strings from the end and skipping characters that a # erases.
def backspace_compare(s, t):
    def build(x):
        stack = []
        for ch in x:
            if ch == '#':
                if stack:
                    stack.pop()
            else:
                stack.append(ch)
        return stack
    return build(s) == build(t)
private static String buildStack(String x) {
    StringBuilder stack = new StringBuilder();       // a StringBuilder works as a char stack
    for (char ch : x.toCharArray()) {
        if (ch == '#') {
            if (stack.length() > 0) stack.deleteCharAt(stack.length() - 1);
        } else {
            stack.append(ch);
        }
    }
    return stack.toString();
}

static boolean optimal(String s, String t) { return buildStack(s).equals(buildStack(t)); }

Make The String Great

EasyLeetCode 1544Practice set
Show solutionHide

Two adjacent characters are bad if they are the same letter in different cases, like aA. Remove bad pairs until none remain. "abBAcC" becomes "".

Recognize before codingRemoving a pair can create a new pair next to it.
Skill it teachesComparing only with the last survivor, the cancel template.
1Brute force

Scan for the first bad pair, delete it, and start scanning again from the beginning. Each deletion costs a scan, and there can be n/2 deletions.

def make_great_brute(s):
    changed = True
    while changed:
        changed = False
        for i in range(len(s) - 1):
            if abs(ord(s[i]) - ord(s[i + 1])) == 32:   # same letter, opposite case
                s = s[:i] + s[i + 2:]
                changed = True
                break
    return s
static String brute(String str) {
    StringBuilder s = new StringBuilder(str);
    boolean changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i + 1 < s.length(); i++) {
            if (Math.abs(s.charAt(i) - s.charAt(i + 1)) == 32) {   // same letter, opposite case
                s.delete(i, i + 2);
                changed = true;
                break;
            }
        }
    }
    return s.toString();
}
2The bottleneck and the key observation

After a deletion, the two characters that become neighbors can form a new bad pair. A new character only ever has to be compared with the last character that survived, which is the top of a stack.

3Optimal approach
  1. Start with an empty stack.
  2. For each character, compare it with the top. If they are the same letter in opposite case, pop.
  3. Otherwise push the character.
  4. Join the stack to get the answer.
def make_great(s):
    stack = []
    for ch in s:
        if stack and abs(ord(stack[-1]) - ord(ch)) == 32:
            stack.pop()
        else:
            stack.append(ch)
    return "".join(stack)
static String optimal(String s) {
    StringBuilder stack = new StringBuilder();
    for (char ch : s.toCharArray()) {
        int n = stack.length();
        if (n > 0 && Math.abs(stack.charAt(n - 1) - ch) == 32) stack.deleteCharAt(n - 1);
        else stack.append(ch);
    }
    return stack.toString();
}

  • Opposite case means the character codes differ by exactly 32, or a.swapcase() == b.
  • Compare with the top of the stack, not with the previous character of the input.

Baseball Game

EasyLeetCode 682Practice set
Show solutionHide

Record scores from operations. An integer adds that score, + adds the sum of the last two scores, D adds double the last score, C removes the last score. Return the total. ["5","2","C","D","+"] gives 30.

Recognize before codingEvery operation reads only the last one or two items.
Skill it teachesSpotting a stack inside a plain simulation.
1Brute force

Replay the operations and rebuild a fresh copy of the score list on every step. It works, but every step costs O(n).

def baseball_brute(ops):
    scores = []
    for op in ops:                            # rebuilds the list on every operation
        if op == 'C':
            scores = scores[:-1]
        elif op == 'D':
            scores = scores + [2 * scores[-1]]
        elif op == '+':
            scores = scores + [scores[-1] + scores[-2]]
        else:
            scores = scores + [int(op)]
    return sum(scores)
static int brute(String[] ops) {
    List<Integer> scores = new ArrayList<>();
    for (String op : ops) {
        List<Integer> next = new ArrayList<>(scores);    // rebuilds the list on every operation
        int n = next.size();
        if (op.equals("C")) next.remove(n - 1);
        else if (op.equals("D")) next.add(2 * next.get(n - 1));
        else if (op.equals("+")) next.add(next.get(n - 1) + next.get(n - 2));
        else next.add(Integer.parseInt(op));
        scores = next;
    }
    int sum = 0;
    for (int v : scores) sum += v;
    return sum;
}
2The bottleneck and the key observation

A plain list that you only touch at the end already is a stack. The problem checks whether you notice that every operation looks only at the last one or two scores.

3Optimal approach
  1. Start with an empty stack of scores.
  2. Integer: push it. D: push twice the top. +: push the sum of the top two. C: pop.
  3. Return the sum of the stack.
def baseball(ops):
    stack = []
    for op in ops:
        if op == 'C':
            stack.pop()
        elif op == 'D':
            stack.append(2 * stack[-1])
        elif op == '+':
            stack.append(stack[-1] + stack[-2])
        else:
            stack.append(int(op))
    return sum(stack)
static int optimal(String[] ops) {
    Deque<Integer> stack = new ArrayDeque<>();
    for (String op : ops) {
        if (op.equals("C")) {
            stack.pop();
        } else if (op.equals("D")) {
            stack.push(2 * stack.peek());
        } else if (op.equals("+")) {
            int top = stack.pop();
            int sum = top + stack.peek();
            stack.push(top);
            stack.push(sum);
        } else {
            stack.push(Integer.parseInt(op));
        }
    }
    int sum = 0;
    for (int v : stack) sum += v;
    return sum;
}

Asteroid Collision

MediumLeetCode 735Notes
Show solutionHide

Each integer is an asteroid. The sign is the direction and the absolute value is the size. When two meet, the smaller explodes, and equal sizes both explode. Asteroids moving the same way never meet. Return the survivors. [10, 2, -5] gives [10].

Recognize before codingOnly the newest item can hit the latest survivor, and one item can remove several.
Skill it teachesA multi-pop loop with several outcomes.
1Brute force

Repeat: find the first adjacent pair where a right-mover sits left of a left-mover, resolve it, and rescan from the start. Each collision costs a scan, so the total is O(n²).

def asteroid_collision_brute(asteroids):
    a = asteroids[:]
    changed = True
    while changed:
        changed = False
        for i in range(len(a) - 1):
            if a[i] > 0 and a[i + 1] < 0:     # right-mover directly left of a left-mover
                if a[i] > -a[i + 1]:
                    del a[i + 1]
                elif a[i] < -a[i + 1]:
                    del a[i]
                else:
                    del a[i:i + 2]
                changed = True
                break                         # rescan from the start
    return a
static int[] brute(int[] asteroids) {
    List<Integer> a = new ArrayList<>();
    for (int x : asteroids) a.add(x);
    boolean changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i + 1 < a.size(); i++) {
            if (a.get(i) > 0 && a.get(i + 1) < 0) {      // right-mover next to a left-mover
                int l = a.get(i), r = -a.get(i + 1);
                if (l > r) a.remove(i + 1);
                else if (l < r) a.remove(i);
                else { a.remove(i + 1); a.remove(i); }
                changed = true;
                break;                                   // rescan from the start
            }
        }
    }
    int[] res = new int[a.size()];
    for (int i = 0; i < res.length; i++) res[i] = a.get(i);
    return res;
}
2The bottleneck and the key observation

Only a right-moving asteroid on top of the stack can be hit by a new left-moving one. Everything else is safe. One big new asteroid can destroy several, so the collision check is a while loop, not an if.

3Optimal approach
  1. Start with an empty stack of survivors.
  2. For each asteroid a, set alive = true.
  3. While a is moving left, the top is moving right, and a is still alive: if the top is smaller, pop it and continue. If equal, pop and mark a dead. If the top is larger, mark a dead.
  4. If a is still alive, push it.
def asteroid_collision(asteroids):
    stack = []
    for a in asteroids:
        alive = True
        while alive and a < 0 and stack and stack[-1] > 0:
            if stack[-1] < -a:

            elif stack[-1] == -a:
                stack.pop()                   # both explode
                alive = False
            else:

def _apply(op, a, b):
    if op == '+':
        return a + b
    if op == '-':
        return a - b
    if op == '*':
        return a * b
    q = abs(a) // abs(b)                      # truncate toward zero, exact for big ints
    return q if (a < 0) == (b < 0) else -q
private static boolean isOp(String t) {
    return t.equals("+") || t.equals("-") || t.equals("*") || t.equals("/");
}

private static int apply(String op, int a, int b) {
    switch (op) {
        case "+": return a + b;
        case "-": return a - b;
        case "*": return a * b;
        default:  return a / b;                          // Java int division truncates toward zero
    }
}
def eval_rpn_brute(tokens):
    tokens = tokens[:]
    while len(tokens) > 1:
        for i, t in enumerate(tokens):        # find the first operator
            if t in ('+', '-', '*', '/'):
                a, b = int(tokens[i - 2]), int(tokens[i - 1])
                tokens[i - 2:i + 1] = [str(_apply(t, a, b))]   # list splice: O(n)
                break
    return int(tokens[0])
static int brute(String[] tokens) {
    List<String> t = new ArrayList<>(Arrays.asList(tokens));
    while (t.size() > 1) {

            if (isOp(t.get(i))) {

                String r = String.valueOf(apply(t.get(i), a, b));
                t.remove(i); t.remove(i - 1); t.set(i - 2, r);   // splice: O(n)
                break;

        }

2The bottleneck and the key observation

Entering a [ pauses the string you were building. Leaving at ] resumes it. Saving paused work and restoring it in reverse order is a stack.

3Optimal approach

  2. Digit: num = num * 10 + digit.

def decode_string(s):
    stack = []                                # saved (previous_string, repeat_count)
    cur, num = "", 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)          # multi-digit counts
        elif ch == '[':
            stack.append((cur, num))          # save context
            cur, num = "", 0
        elif ch == ']':
            prev, k = stack.pop()             # restore context
            cur = prev + cur * k
        else:
            cur += ch
    return cur

            num = num * 10 + (ch - '0');                 // multi-digit counts

            for (int i = 0; i < k; i++) prev.append(cur);
            cur = prev;
        } else {
            cur.append(ch);
        }
    }
    return cur.toString();

2The bottleneck and the key observation

The video walks the array from the back. The stack holds candidates to the right, nearest on top.   5. Strip leading zeros and return "0" if nothing remains.

2The bottleneck and the key observation

Every candidate rectangle is limited by its shortest bar. For each bar, the best rectangle that uses its full height reaches left and right until a shorter bar appears. A stack of increasing heights finds both borders: when a bar is popped, the bar that popped it is the right border and the new top is the left border.

3Optimal approach

  2. For each bar at index i with height h, set start = i.

  4. Push (start, h). The new bar can extend left as far as the last bar it popped.

2The bottleneck and the key observation

Flip the question. Instead of asking for the minimum of each subarray, ask how many subarrays each element is the minimum of. If the element can start in left places and end in right places, it contributes value × left × right. The nearest smaller element on each side gives those counts, and a stack finds them.

3Optimal approach
  1. For each index, find left[i]: the distance back to the previous element that is smaller, or to the start.
  2. Find right[i]: the distance forward to the next smaller element, or to the end.
  3. Break ties on one side only: stop at equal values on the left, run over equal values on the right.
  4. Sum arr[i] × left[i] × right[i] modulo 1,000,000,007.
def sum_subarray_mins(arr):
    n = len(arr)
    left = [0] * n                            # choices for the start index
    right = [0] * n                           # choices for the end index
    stack = []
    for i in range(n):
        while stack and arr[stack[-1]] > arr[i]:        # previous <=  (stops at equal)
            stack.pop()
        left[i] = i - (stack[-1] if stack else -1)
        stack.append(i)
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and arr[stack[-1]] >= arr[i]:       # next <  (runs over equal)
            stack.pop()
        right[i] = (stack[-1] if stack else n) - i
        stack.append(i)
    return sum(a * l * r for a, l, r in zip(arr, left, right)) % (10**9 + 7)
static int optimal(int[] arr) {
    int n = arr.length;
    long[] left = new long[n], right = new long[n];      // choices for start / end index
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && arr[stack.peek()] > arr[i]) stack.pop();    // previous <= (stops at equal)
        left[i] = i - (stack.isEmpty() ? -1 : stack.peek());
        stack.push(i);
    }
    stack.clear();
    for (int i = n - 1; i >= 0; i--) {
        while (!stack.isEmpty() && arr[stack.peek()] >= arr[i]) stack.pop();   // next < (runs over equal)
        right[i] = (stack.isEmpty() ? n : stack.peek()) - i;
        stack.push(i);
    }
    long total = 0;
    for (int i = 0; i < n; i++) total = (total + arr[i] * left[i] % MOD * right[i]) % MOD;
    return (int) total;
}

def trap_brute(h):
    total = 0
    for i in range(len(h)):
        left_max = max(h[:i + 1])             # tallest wall at or left of i
        right_max = max(h[i:])                # tallest wall at or right of i
        total += min(left_max, right_max) - h[i]
    return total
static int brute(int[] h) {
    int total = 0;
    for (int i = 0; i < h.length; i++) {
        int leftMax = 0, rightMax = 0;
        for (int j = 0; j <= i; j++) leftMax = Math.max(leftMax, h[j]);          // tallest at or left of i
        for (int j = i; j < h.length; j++) rightMax = Math.max(rightMax, h[j]);  // tallest at or right of i

    }
    return total;

2The bottleneck and the key observation

The same left-max and right-max values get recomputed again and again. Compute them once in two passes and store them in arrays (the video's approach). The stack solution fills water layer by layer: when a taller bar arrives, the popped bar is the floor, the new top is the left wall, and the new bar is the right wall. If you want O(1) space, two pointers keep one running maximum from each end.

Correction to the video: The video calls the max-left and max-right values the next greater elements to each side. They are running maxima, and a plain loop that keeps one maximum is enough to compute them, so no stack is needed for that version. The monotonic stack is a different way to solve the same problem, and it is the one that practices the pattern.

3Optimal approach
  1. Prefix version: left[i] is the max of h[0..i], right[i] is the max of h[i..n-1]. Water at i is min(left[i], right[i]) - h[i].
  2. Stack version: keep indices of decreasing heights. When h[i] is taller than the top, pop it as bottom. If the stack is empty, there is no left wall, so stop.
  3. Otherwise left is the new top, width = i - left - 1, depth = min(h[left], h[i]) - h[bottom], and water += width × depth.
  4. Push i and continue.

Build a FIFO queue with enqueue, dequeue, peek and empty using only stack operations.

Recognize before codingBuild one structure out of another.
Skill it teachesAmortized analysis with two stacks.
1Brute force

Keep one stack. On every dequeue, move everything to a helper stack (which reverses it), pop the oldest, then move everything back. Each dequeue and peek costs O(n).

class QueueBrute:
    def __init__(self):
        self.main = []

    def enqueue(self, x):
        self.main.append(x)

    def _flip(self):
        helper = []
        while self.main:
            helper.append(self.main.pop())
        return helper

    def dequeue(self):
        helper = self._flip()                 # O(n) every time
        x = helper.pop()
        while helper:
            self.main.append(helper.pop())    # put everything back: another O(n)
        return x

    def peek(self):
        helper = self._flip()
        x = helper[-1]
        while helper:
            self.main.append(helper.pop())
        return x

    def empty(self):
        return not self.main
class QueueBrute {
    private final Deque<Integer> main = new ArrayDeque<>();
    void enqueue(int x) { main.push(x); }

    private Deque<Integer> flip() {
        Deque<Integer> helper = new ArrayDeque<>();
        while (!main.isEmpty()) helper.push(main.pop());
        return helper;
    }

    int dequeue() {
        Deque<Integer> helper = flip();                      // O(n) every time
        int x = helper.pop();
        while (!helper.isEmpty()) main.push(helper.pop());   // put everything back: O(n)
        return x;
    }

    int peek() {
        Deque<Integer> helper = flip();
        int x = helper.peek();
        while (!helper.isEmpty()) main.push(helper.pop());
        return x;
    }

    boolean empty() { return main.isEmpty(); }
}
2The bottleneck and the key observation

Moving items from one stack to another reverses their order, so the oldest item ends up on top. Keep two stacks. Enqueue always goes to the inbox. When someone dequeues, serve from the outbox, and only when the outbox is empty move the whole inbox into it. Each element moves at most once, so dequeue is O(1) amortized.

3Optimal approach
  1. enqueue(x): push onto the inbox.
  2. To dequeue or peek: if the outbox is empty, pop every item from the inbox and push it onto the outbox.
  3. Dequeue pops the outbox. Peek reads its top.
  4. empty() is true only when both stacks are empty.
class MyQueue:
    def __init__(self):
        self.inbox = []                       # enqueue goes here
        self.outbox = []                      # dequeue / peek come from here

    def enqueue(self, x):
        self.inbox.append(x)

    def _shift(self):
        if not self.outbox:                   # only refill when outbox is EMPTY
            while self.inbox:
                self.outbox.append(self.inbox.pop())

    def dequeue(self):
        self._shift()
        return self.outbox.pop()

    def peek(self):
        self._shift()
        return self.outbox[-1]

    def empty(self):
        return not self.inbox and not self.outbox
class MyQueue {
    private final Deque<Integer> inbox = new ArrayDeque<>();   // enqueue goes here
    private final Deque<Integer> outbox = new ArrayDeque<>();  // dequeue / peek come from here

    void enqueue(int x) { inbox.push(x); }

    private void shift() {
        if (outbox.isEmpty()) {                              // refill only when outbox is EMPTY
            while (!inbox.isEmpty()) outbox.push(inbox.pop());
        }
    }

    int dequeue() { shift(); return outbox.pop(); }
    int peek() { shift(); return outbox.peek(); }
    boolean empty() { return inbox.isEmpty() && outbox.isEmpty(); }
}

Car Fleet

MediumLeetCode 853Notes

Cars drive toward a target on a one-lane road. Car i starts at position[i] with speed[i]. A car cannot pass the car ahead. It catches up and then drives at that car's speed, forming a fleet. Count the fleets that arrive. Target 12, positions [10,8,0,5,3], speeds [2,4,1,1,3] gives 3.

Recognize before codingObjects on a line that merge or block each other.
Skill it teachesTransforming the input first, then seeing the stack.
1Brute force

Compute each car's arrival time if the road were empty, (target - position) / speed. A car starts its own fleet only if every car ahead of it arrives strictly sooner. Checking all cars ahead for every car is O(n²).

def car_fleet_brute(target, position, speed):
    n = len(position)
    time = [(target - position[i]) / speed[i] for i in range(n)]
    fleets = 0
    for i in range(n):
        # car i leads its own fleet only if every car ahead arrives strictly sooner
        if all(time[j] < time[i] for j in range(n) if position[j] > position[i]):
            fleets += 1
    return fleets
static int brute(int target, int[] position, int[] speed) {
    int n = position.length;
    double[] time = new double[n];
    for (int i = 0; i < n; i++) time[i] = (double) (target - position[i]) / speed[i];
    int fleets = 0;
    for (int i = 0; i < n; i++) {
        boolean leads = true;                            // every car ahead must arrive strictly sooner
        for (int j = 0; j < n; j++) {
            if (position[j] > position[i] && time[j] >= time[i]) { leads = false; break; }
        }
        if (leads) fleets++;
    }
    return fleets;
}
2The bottleneck and the key observation

Sort by position, closest to the target first. A car that would arrive later than the fleet directly ahead can never catch it, so it forms a new fleet. A car that would arrive sooner or at the same time catches up and merges. The arrival times of fleets only grow as you go back, which is a monotonic stack.

3Optimal approach
  1. Pair each position with its speed and sort by position, descending.
  2. For each car compute t = (target - position) / speed.
  3. If the stack is empty or t is greater than the top, push t. This car is a new fleet.
  4. Otherwise it merges into the fleet ahead, so do nothing.
  5. The stack size is the number of fleets.
def car_fleet(target, position, speed):
    stack = []                                # arrival times of fleets, front to back
    for p, s in sorted(zip(position, speed), reverse=True):   # closest to target first
        t = (target - p) / s
        if not stack or t > stack[-1]:        # slower than the fleet ahead: new fleet
            stack.append(t)                   # otherwise it catches up and merges
    return len(stack)
static int optimal(int target, int[] position, int[] speed) {
    int n = position.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a, b) -> position[b] - position[a]);   // closest to target first
    Deque<Double> stack = new ArrayDeque<>();            // arrival times of fleets
    for (int i : idx) {
        double t = (double) (target - position[i]) / speed[i];
        if (stack.isEmpty() || t > stack.peek()) stack.push(t);   // slower: new fleet
    }                                                    // otherwise it merges into the fleet ahead
    return stack.size();
}

Depth-First Traversal Without Recursion

PreviewPreview of Trees and GraphsNotes
Show solutionHide

Visit every node reachable from a start node, going as deep as possible before backing up, and take neighbors in the order they are listed. The graph is a dictionary of adjacency lists, and cycles are allowed. {0:[1,2], 1:[3], 2:[3], 3:[]} from node 0 visits [0, 1, 3, 2].

Recognize before codingDeep recursion, or a request to avoid recursion.
Skill it teachesTurning a recursive traversal into a loop with an explicit stack.
1Recursive version

The natural first version is recursive. Each call is a frame on the system's call stack, and the stack remembers where to resume after a neighbor is finished. It is correct, but a chain of 5,000 nodes overflows Python's default recursion limit, and Java fails at a far greater depth.

Recursive version

def dfs_recursive(graph, start):
    seen, order = set(), []

    def visit(node):
        seen.add(node)
        order.append(node)
        for nxt in graph[node]:
            if nxt not in seen:
                visit(nxt)                    # each call is a frame on the call stack

    visit(start)
    return order
static List<Integer> recursive(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    visit(graph, start, new HashSet<>(), order);
    return order;
}

private static void visit(Map<Integer, List<Integer>> graph, int node, Set<Integer> seen, List<Integer> order) {
    seen.add(node);
    order.add(node);
    for (int nxt : graph.get(node)) {
        if (!seen.contains(nxt)) visit(graph, nxt, seen, order);   // each call is a frame on the call stack
    }
}
2The bottleneck and the key observation

Recursion already is a stack, managed for you. Replace it with your own and the depth limit goes away. Pop a node, skip it if it was seen, visit it, and push its neighbors in reverse so the first neighbor ends up on top and is explored first. Mark a node as seen when it is popped, not when it is pushed. That reproduces the recursive visiting order exactly.

3Optimal approach
  1. Push the start node onto the stack.
  2. Pop a node. If it was already seen, skip it.
  3. Mark it seen and record it in the visit order.
  4. Push its unseen neighbors in reverse order.
  5. Repeat until the stack is empty.

Explicit stack

def dfs_iterative(graph, start):
    seen, order = set(), []
    stack = [start]                           # our own stack replaces the call stack
    while stack:
        node = stack.pop()
        if node in seen:                      # mark seen on pop, to match the recursive order
            continue
        seen.add(node)
        order.append(node)
        for nxt in reversed(graph[node]):     # reversed, so the first neighbor is popped first
            if nxt not in seen:
                stack.append(nxt)
    return order
static List<Integer> iterative(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    Set<Integer> seen = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>();           // our own stack replaces the call stack
    stack.push(start);
    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (!seen.add(node)) continue;                   // add returns false if already seen: mark on pop
        order.add(node);
        List<Integer> nbrs = graph.get(node);
        for (int i = nbrs.size() - 1; i >= 0; i--) {     // reversed, so the first neighbor is popped first
            if (!seen.contains(nbrs.get(i))) stack.push(nbrs.get(i));
        }
    }
    return order;
}

  • Without the reversal, neighbors are visited in the opposite order. The traversal is still a valid depth-first search, but it will not match the recursive output.
  • Marking nodes seen on push, instead of on pop, gives a different order, and on some graphs it is no longer a true depth-first order.
  • Python's default recursion limit is about 1,000 frames. In an interview, say that an explicit stack avoids this limit.

Part 9 · ReviewCommon mistakes

Conceptual

  • Choosing a stack when you need a queue, deque or heap. Ask which item must be handled first, the newest or the oldest.
  • Forgetting what the leftovers mean. After the loop, ask what it means that these items are still on the stack.
  • Wrong monotonic direction. Next greater means a decreasing stack, popping while the top is smaller. Verify with a three-element example.

Python and Java

  • Popping or peeking an empty stack. Always write if stack and ....
  • Using list.pop(0). It is O(n). Pop from the end, or use a deque.
  • Storing values when you need indices. You cannot compute distances from values.
  • Mutating the input, like heights.append(0). Use heights + [0].
  • Comparing boxed Integers with == in Java. Unbox first, or use equals.
  • Trusting Java's iteration order. A Deque iterates from the top.

Complexity

  • Calling the monotonic stack O(n²) because of the nested loop. Each element is pushed once and popped at most once.
  • Forgetting the O(n) space of the stack.

Boundaries

  • Off-by-one in widths. Test [2,4] in the histogram problem.
  • Mixing up < and <= on duplicates.
  • Checking the final stack in only some problems. Valid parentheses needs it empty. Daily temperatures does not.

Interview reasoning

  • Coding before stating the invariant.
  • Skipping the brute force. Say it, give its complexity, then name the bottleneck the stack removes.
  • Memorizing that monotonic stack means next greater. If you understand "resolve the waiting elements", variants like previous smaller or span become easy.
