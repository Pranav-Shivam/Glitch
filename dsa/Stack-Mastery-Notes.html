Foundations

What a stack is

A stack is a list with one open end, called the top. You add at the top (push), remove from the top (pop), and look at the top without removing it (peek). The last item in is the first item out. This is LIFO, last in, first out.

The video's picture is a stack of plates in a cafeteria. Clean plates go on the pile, and the plate on top is the first one taken to be used.

CallStack after (bottom to top)Returns
push(1)1
push(2)1, 2
push(3)1, 2, 3
pop()1, 23
pop()12

Why it exists

Many problems have this shape: you start something, you cannot finish it until something later happens, and when it happens you must finish the most recent unfinished thing first.

  • Brackets: the last bracket opened must be the first one closed.
  • Nested function calls: the innermost call returns first.
  • Undo: the latest action is reversed first.

A stack remembers unresolved things in the order they must be resolved.

What it does better than an array and a loop

With only an array and a loop, finding the most recent unresolved item means rescanning backwards, which costs O(n) every time. A stack keeps that item at the top, so you reach it in O(1).

How it works inside

A stack is a dynamic array where you only touch the last slot, or a linked list where you only touch the head. Both give O(1) push and pop. Nothing has to shift, because the open end is the only end you use.

Use a stack when

  • Symbols must match or nest
  • You need the most recent unresolved item
  • You are simulating reversal or undo
  • You need the next greater or smaller element
  • You want to simulate recursion with your own loop
  • You are evaluating expressions

Do not use a stack when

  • You need the middle or both ends (use a deque)
  • You need the smallest or largest of everything seen so far (use a heap)
  • A contiguous range with both ends moving is the idea (use a sliding window)
  • You need lookup by value (use a hash map)
  • First come, first served (use a queue)

Where you already meet stacks

From the video

A stack is not only a data structure. After enough problems it becomes a coding pattern you can spot: you have pending items, and a later item resolves the most recent ones.

  • Matching parentheses. The first stack problem most people see. It checks whether an expression is valid before you spend time evaluating it.
  • Evaluating expressions. Use the same stack to solve small portions and combine them.
  • Parsing code. A compiler knows a bracket was never matched the same way parenthesis matching does.
  • Undo and redo. The undo button keeps a stack of your operations and undoes the topmost one first.
  • The call stack. Recursion is the system's stack. An iterative DFS uses your own.

How it connects to earlier topics

A window remembers a range. A stack remembers candidates waiting for an answer. Both scan once. Binary Search comes next and uses different reasoning, halving a search space. Stacks return in DFS and in trees.

A typical one-pass stack algorithmO(n)O(n) in the worst case
  • Push, pop and peek are O(1) because they touch only the last slot. Nothing shifts. Popping from the front of a Python list is O(n) because every element moves left, which is why you always pop from the end.
  • Amortized push. A dynamic array sometimes resizes at a cost of O(n), but it happens so rarely that across all pushes the average is O(1).
  • Space is O(n) because in the worst case every element is pushed and none is popped, like "(((((((" or a strictly decreasing array in next greater element.

Why the monotonic stack is O(n), not O(n²)

A monotonic stack has a while loop inside a for loop, which looks quadratic. It is not. Each element is pushed exactly once and popped at most once, so across the whole run there are at most n pushes and n pops. The total work is at most 2n, which is O(n). This is amortized analysis.

Say this aloud in an interview

The inner while loop looks nested, but each element enters and leaves the stack at most once, so the total work is O(n).

Patterns

Problem-solving method

  1. Understand the input. Characters, numbers, tokens? What does the output look like?
  2. Check the constraints. With n up to 105, O(n²) is too slow.
  3. Clarify edge cases. Empty input, unmatched symbols, negative numbers.
  4. Say the brute force and its complexity. It is usually "for each element, scan back or forward".
  5. Find the bottleneck. "I keep rescanning to find the most recent item, or the next bigger one."
  6. Ask the stack questions. Is there a most recent unresolved item? Does a later element resolve earlier ones? Is there nesting?
  7. Decide what goes on the stack. Values, indices, (value, extra) pairs, or saved contexts.
  8. State the invariant. Monotonic increasing or decreasing, or "only unmatched openers".
  9. Decide the pop condition and what to do on a pop: record an answer, compute an area, or cancel.
  10. State the complexity. For a monotonic stack, mention the amortized argument.
  11. Code it.
  12. Test on empty, a single element, all equal, strictly increasing and strictly decreasing inputs.
Say the invariant aloud

The stack holds indices of days still waiting for a warmer day, with temperatures decreasing from bottom to top.

Naming the invariant shows the interviewer that you understand the algorithm rather than a memorized template.

Problem lab

Type A

Matching and nesting

Every closer must match the most recent opener that is still open.

Recognize it

  • Brackets, tags, quotes, or any paired symbols
  • The words valid, balanced, well-formed, nested

Algorithm

  1. Start with an empty stack.
  2. Push every opener.
  3. On a closer, the stack must be non-empty and its top must pair with the closer. Pop it.
  4. After the last symbol the stack must be empty.

Pseudocode

stack = empty
for each symbol c:
    if c is an opener:    push c
    else:                 if stack is empty: return invalid
                          top = pop()
                          if top does not pair with c: return invalid
return stack is empty

Valid Parentheses

  • Easy
  • LeetCode 20
  • Video and notes

Given a string made of ()[]{}, decide whether every bracket is closed by the right kind of bracket, in the right order. "{[]}" is valid. "([)]" is not.

Recognize before coding
Nesting, where a closer must match the latest opener.
Skill it teaches
Push and pop discipline, and guarding against an empty stack.

Brute force

Keep deleting adjacent pairs (), [] and {} from the string. If nothing is left, the string was valid. Every pass scans the whole string, and ((((....)))) needs n/2 passes.

The bottleneck and the key observation

The pair that cancels is always the most recently opened bracket that is still unmatched. That is what LIFO means, so the unmatched openers belong on a stack. In the video the stack is exactly this: add every opener, and on a closer compare it with the top.

Optimal approach

  1. Start with an empty stack.
  2. Opener: push it.
  3. Closer: if the stack is empty, return false. Otherwise pop and check that the popped opener pairs with this closer.
  4. After the last character, the stack must be empty. Anything left is an opener that was never closed.
ApproachTimeSpace
Brute forceO(n²)O(n)
StackO(n)O(n)

Type B

Cancel and undo

The stack is the result so far, and a new item may cancel the top.

Recognize it

  • Remove adjacent pairs, backspace, undo, cancel out
  • Simulations where only the latest survivor can interact with the new arrival

Algorithm

  1. Treat the stack as the answer built so far.
  2. For each item, check whether it cancels the top.
  3. Use a while loop if one item can cancel several, as in asteroids.
  4. If the item survives, push it. The stack read bottom to top is the result.

Pseudocode

stack = empty
for each item x:
    alive = true
    while alive and stack not empty and cancels(stack.top, x):
        resolve(stack.pop(), x)       # may mark x as destroyed
    if alive: push x
return stack, bottom to top

Backspace String Compare

  • Easy
  • LeetCode 844
  • Notes

Two strings where # is a backspace. Are they equal after typing both into an empty editor? "ab#c" and "ad#c" both end up as "ac".

Recognize before coding
A character that undoes the one before it.
Skill it teaches
Using a stack as the result so far.

Brute force

Build each final string one character at a time, and on every # rebuild it without its last character. Slicing copies the string, so each backspace costs O(n).

The bottleneck and the key observation

The text typed so far is a stack. A letter pushes, and a # pops the top, or does nothing when the stack is empty.

Optimal approach

  1. Write a helper that turns a string into its final text.
  2. For each character: letter pushes, # pops if the stack is not empty.
  3. Compare the two stacks.
  4. Follow-up: O(1) space is possible by scanning both strings from the end and skipping characters that a # erases.
ApproachTimeSpace
Re-slice on every #O(n²)O(n)
StackO(n)O(n)

Watch for

  • A # on an empty stack must not raise an error. "###" equals "".
  • Compare the stacks after the loop, not while building them.

Make The String Great

  • Easy
  • LeetCode 1544
  • Practice set

Two adjacent characters are bad if they are the same letter in different cases, like aA. Remove bad pairs until none remain. "abBAcC" becomes "".

Recognize before coding
Removing a pair can create a new pair next to it.
Skill it teaches
Comparing only with the last survivor, the cancel template.

Brute force

Scan for the first bad pair, delete it, and start scanning again from the beginning. Each deletion costs a scan, and there can be n/2 deletions.

The bottleneck and the key observation

After a deletion, the two characters that become neighbors can form a new bad pair. A new character only ever has to be compared with the last character that survived, which is the top of a stack.

Optimal approach

  1. Start with an empty stack.
  2. For each character, compare it with the top. If they are the same letter in opposite case, pop.
  3. Otherwise push the character.
  4. Join the stack to get the answer.
ApproachTimeSpace
Rescan after each removalO(n²)O(n)
StackO(n)O(n)

Watch for

  • Opposite case means the character codes differ by exactly 32, or a.swapcase() == b.
  • Compare with the top of the stack, not with the previous character of the input.

Baseball Game

  • Easy
  • LeetCode 682
  • Practice set

Record scores from operations. An integer adds that score, + adds the sum of the last two scores, D adds double the last score, C removes the last score. Return the total. ["5","2","C","D","+"] gives 30.

Recognize before coding
Every operation reads only the last one or two items.
Skill it teaches
Spotting a stack inside a plain simulation.

Brute force

Replay the operations and rebuild a fresh copy of the score list on every step. It works, but every step costs O(n).

The bottleneck and the key observation

A plain list that you only touch at the end already is a stack. The problem checks whether you notice that every operation looks only at the last one or two scores.

Optimal approach

  1. Start with an empty stack of scores.
  2. Integer: push it. D: push twice the top. +: push the sum of the top two. C: pop.
  3. Return the sum of the stack.
ApproachTimeSpace
Copy the list each stepO(n²)O(n)
StackO(n)O(n)

Watch for

  • + needs the top two values without losing them. In Python use stack[-1] + stack[-2]. In Java pop one, peek the next, push both back.
  • Parse integers with int(op), so "-2" works as a score.

Asteroid Collision

  • Medium
  • LeetCode 735
  • Notes

Each integer is an asteroid. The sign is the direction and the absolute value is the size. When two meet, the smaller explodes, and equal sizes both explode. Asteroids moving the same way never meet. Return the survivors. [10, 2, -5] gives [10].

Recognize before coding
Only the newest item can hit the latest survivor, and one item can remove several.
Skill it teaches
A multi-pop loop with several outcomes.

Brute force

Repeat: find the first adjacent pair where a right-mover sits left of a left-mover, resolve it, and rescan from the start. Each collision costs a scan, so the total is O(n²).

The bottleneck and the key observation

Only a right-moving asteroid on top of the stack can be hit by a new left-moving one. Everything else is safe. One big new asteroid can destroy several, so the collision check is a while loop, not an if.

Optimal approach

  1. Start with an empty stack of survivors.
  2. For each asteroid a, set alive = true.
  3. While a is moving left, the top is moving right, and a is still alive: if the top is smaller, pop it and continue. If equal, pop and mark a dead. If the top is larger, mark a dead.
  4. If a is still alive, push it.
ApproachTimeSpace
Rescan after each collisionO(n²)O(n)
StackO(n)O(n)

Watch for

  • A left-mover with an empty stack, or with a left-mover on top, just gets pushed.
  • Equal sizes remove both. Forgetting this leaves a ghost on the stack.

Type C

Expressions and nested context

Operators act on the latest results, and brackets pause the work in progress.

Recognize it

  • Postfix or prefix expressions, calculators
  • Nested structures where content is transformed, like 3[a2[c]]

Algorithm

  1. Postfix: push numbers. An operator pops the right operand, then the left operand, and pushes the result.
  2. Nested: on an opening bracket, push the state you are in the middle of, and start fresh.
  3. On a closing bracket, pop the saved state and combine it with what you just built.
  4. Compilers match brackets in code the same way.

Pseudocode

RPN:     for token: if number: push
                    else: b = pop(); a = pop(); push(a op b)
Nested:  on '[':  push (current, count); reset current and count
         on ']':  (prev, k) = pop(); current = prev + current * k

Evaluate Reverse Polish Notation

  • Medium
  • LeetCode 150
  • Notes

Tokens are numbers and the operators + - * /, written in postfix order. Division truncates toward zero. ["4","13","5","/","+"] is 4 + 13 / 5, which is 6.

Recognize before coding
Postfix notation, where an operator applies to the last two results.
Skill it teaches
Operand order, and division that truncates toward zero.

Brute force

Find the first operator, evaluate it with the two tokens before it, replace those three tokens with the result, and repeat. Each replacement shifts the list.

The bottleneck and the key observation

An operator always applies to the two most recent results. That is the top two items of a stack, and the result goes back on top.

Optimal approach

  1. Start with an empty stack.
  2. Number: push it.
  3. Operator: pop b first (the right operand), then pop a, compute a op b, push the result.
  4. The single value left is the answer.
ApproachTimeSpace
Replace three tokens at a timeO(n²)O(n)
Operand stackO(n)O(n)

Watch for

  • The first pop is the right operand. Subtraction and division break if you swap them.
  • Python's // floors toward negative infinity, but the problem wants truncation toward zero. The code uses the absolute values and fixes the sign. Java's / already truncates.
  • "-11" is a number, not an operator. Test whether the whole token is in the operator set.

Decode String

  • Medium
  • LeetCode 394
  • Notes

Strings are encoded as k[encoded], meaning encoded repeated k times, and they can nest. "3[a2[c]]" decodes to "accaccacc".

Recognize before coding
Nested brackets whose content gets transformed.
Skill it teaches
Saving and restoring state at each nesting level.

Brute force

Use a regex to find an innermost k[...] that has no brackets inside, expand it, and repeat until no bracket is left. Every round scans the whole string, so the cost grows with the nesting depth times the output length.

The bottleneck and the key observation

Entering a [ pauses the string you were building. Leaving at ] resumes it. Saving paused work and restoring it in reverse order is a stack.

Optimal approach

  1. Keep cur (the string being built) and num (the count being read).
  2. Digit: num = num * 10 + digit.
  3. [: push (cur, num), then reset both.
  4. ]: pop (prev, k) and set cur = prev + cur * k.
  5. Letter: append to cur. At the end, cur is the answer.
ApproachTimeSpace

Context stackO(L)O(L)

Type D

Monotonic stack: next greater or smaller

Elements wait on the stack for an answer, and a later element resolves many of them at once.

Recognize it

  • Next greater, next smaller, previous greater, previous smaller
  • How many days until, how far until, the first element to the right that is bigger
  • Spans and online streams of values

Algorithm

  1. Keep a stack of indices that are still waiting for an answer.
  2. For each new element, while it beats the top, pop the top and record the answer for it.
  3. Push the new element.
  4. Whatever remains at the end has no answer. Give it -1 or 0.

Pseudocode

stack = empty                     # holds indices
for i in 0 .. n-1:
    while stack not empty and nums[stack.top] < nums[i]:
        j = pop()
        answer[j] = f(i, j)           # value nums[i], or distance i - j
    push i
# leftovers have no answer
Reverse the scan direction and the tie rule shifts by one (greater becomes greater or equal).

Next Greater Element

  • Medium
  • Video problem
  • Video

For each element, find the first larger element to its right, or -1 if there is none. [3,1,5,2,1,0,7,9,2,3] gives [5,5,7,7,7,7,9,-1,3,-1].

Recognize before coding
For each element, the first larger one to its right.
Skill it teaches
Your first monotonic stack, in both scan directions.

Brute force

For every index, scan to the right until something bigger appears. A decreasing array makes every scan run to the end, so this is O(n²).

The bottleneck and the key observation

The video walks the array from the back. The stack holds candidates to the right, nearest on top. When you reach a new value, every candidate that is not larger can be thrown away, because the new value is closer and at least as big, so none of them can be the answer for anything further left. What remains on top is the answer. You can also run it left to right: each new value resolves every smaller waiting element at once.

Optimal approach

  1. Walk from the last index to the first with an empty stack of values.
  2. Pop while the top is less than or equal to the current value.
  3. The answer is the top, or -1 if the stack is empty.
  4. Push the current value.
ApproachTimeSpace
Scan right from every indexO(n²)O(1) extra
Monotonic stackO(n)O(n)

Next Greater Element I

  • Easy
  • LeetCode 496
  • Notes

nums1 is a subset of nums2, and all values are distinct. For each value in nums1, find its next greater element to the right inside nums2, or -1. nums1 = [4,1,2], nums2 = [1,3,4,2] gives [-1,3,-1].

Recognize before coding
Next greater element, asked about a subset of values.
Skill it teaches
A monotonic stack combined with a hash map.

Brute force

For each value in nums1, find where it sits in nums2 and scan to its right. That is O(m × n).

The bottleneck and the key observation

Answer the question for every element of nums2 in one monotonic pass and store the results in a hash map. Then each query in nums1 is a lookup. It combines the previous topic with this one.

Optimal approach

Algorithm

Sum of Subarray Minimums

  • Medium (stretch)
  • LeetCode 907
  • Practice set

Return the sum of min(subarray) over all contiguous subarrays, modulo 1,000,000,007. [3,1,2,4] gives 17.

Recognize before coding
A sum, over all subarrays, of their minimum.
Skill it teaches
Counting each element's contribution from its nearest smaller neighbors.

Brute force

Enumerate every start, extend the end while tracking the running minimum, and add it up. That is O(n²).

The bottleneck and the key observation

Flip the question. Instead of asking for the minimum of each subarray, ask how many subarrays each element is the minimum of. If the element can start in left places and end in right places, it contributes value × left × right. The nearest smaller element on each side gives those counts, and a stack finds them.

Optimal approach

  1. For each index, find left[i]: the distance back to the previous element that is smaller, or to the start.
  2. Find right[i]: the distance forward to the next smaller element, or to the end.
  3. Break ties on one side only: stop at equal values on the left, run over equal values on the right.
  4. Sum arr[i] × left[i] × right[i] modulo 1,000,000,007.
ApproachTimeSpace
Every subarrayO(n²)O(1)
Two monotonic passesO(n)O(n)

Watch for

  • With duplicates, a subarray must be credited to exactly one of the equal minimums. One strict and one non-strict comparison guarantees that.
  • Multiply in long in Java and reduce modulo as you go.

Trapping Rain Water

  • Hard
  • LeetCode 42
  • Video

Bar heights form walls. After it rains, how many units of water are trapped between them? [0,1,0,2,1,0,1,3,2,1,2,1] gives 6.

Recognize before coding
Water held between walls, limited by the shorter wall on each side.
Skill it teaches
Comparing prefix arrays, a stack and two pointers on one problem.

Brute force

Water above one position is limited by the shorter of the tallest wall on its left and the tallest wall on its right, minus its own height. The video computes that for each position by scanning both sides, which is O(n²).

The bottleneck and the key observation

The same left-max and right-max values get recomputed again and again. Compute them once in two passes and store them in arrays (the video's approach). The stack solution fills water layer by layer: when a taller bar arrives, the popped bar is the floor, the new top is the left wall, and the new bar is the right wall. If you want O(1) space, two pointers keep one running maximum from each end.

Correction to the video

The video calls the max-left and max-right values the next greater elements to each side. They are running maxima, and a plain loop that keeps one maximum is enough to compute them, so no stack is needed for that version. The monotonic stack is a different way to solve the same problem, and it is the one that practices the pattern.

Optimal approach

  1. Prefix version: left[i] is the max of h[0..i], right[i] is the max of h[i..n-1]. Water at i is min(left[i], right[i]) - h[i].
  2. Stack version: keep indices of decreasing heights. When h[i] is taller than the top, pop it as bottom. If the stack is empty, there is no left wall, so stop.
  3. Otherwise left is the new top, width = i - left - 1, depth = min(h[left], h[i]) - h[bottom], and water += width × depth.
  4. Push i and continue.
ApproachTimeSpace
Scan both sides per indexO(n²)O(1)
Prefix and suffix maximaO(n)O(n)
Monotonic stack, by layersO(n)O(n)
Two pointersO(n)O(1)

Car Fleet

  • Medium
  • LeetCode 853
  • Notes

Cars drive toward a target on a one-lane road. Car i starts at position[i] with speed[i]. A car cannot pass the car ahead. It catches up and then drives at that car's speed, forming a fleet. Count the fleets that arrive. Target 12, positions [10,8,0,5,3], speeds [2,4,1,1,3] gives 3.

Recognize before coding
Objects on a line that merge or block each other.
Skill it teaches
Transforming the input first, then seeing the stack.

Brute force

Compute each car's arrival time if the road were empty, (target - position) / speed. A car starts its own fleet only if every car ahead of it arrives strictly sooner. Checking all cars ahead for every car is O(n²).

The bottleneck and the key observation

Sort by position, closest to the target first. A car that would arrive later than the fleet directly ahead can never catch it, so it forms a new fleet. A car that would arrive sooner or at the same time catches up and merges. The arrival times of fleets only grow as you go back, which is a monotonic stack.

Optimal approach

  1. Pair each position with its speed and sort by position, descending.
  2. For each car compute t = (target - position) / speed.
  3. If the stack is empty or t is greater than the top, push t. This car is a new fleet.
  4. Otherwise it merges into the fleet ahead, so do nothing.
  5. The stack size is the number of fleets.
ApproachTimeSpace
Compare with every car aheadO(n²)O(n)
Sort, then stack of timesO(n log n)O(n)

Watch for

  • The comparison is strict. Equal arrival times merge into one fleet.
  • Positions are distinct in the problem. Sort descending so the car nearest the target is handled first.
  • Only the top of the stack is ever read, so a single running maximum also works. The stack makes the pattern explicit.

Recognize it

Algorithm

  1. Write the recursive version first and note what it remembers between calls.
  2. Put that state on your own stack instead of the call stack.
  3. Pop to take the next piece of work, and push the pieces you discover.
  4. Push children in reverse if you want the same order as the recursion.

Pseudocode

stack = [start]

    node = pop()
    if node already seen: continue
    mark node seen and visit it
    for each neighbor in reverse order:
        if neighbor not seen: push neighbor

Depth-First Traversal Without Recursion

  • Preview
  • Preview of Trees and Graphs
  • Notes

Visit every node reachable from a start node, going as deep as possible before backing up, and take neighbors in the order they are listed. The graph is a dictionary of adjacency lists, and cycles are allowed. {0:[1,2], 1:[3], 2:[3], 3:[]} from node 0 visits [0, 1, 3, 2].

Recognize before coding
Deep recursion, or a request to avoid recursion.
Skill it teaches
Turning a recursive traversal into a loop with an explicit stack.

Recursive version

The natural first version is recursive. Each call is a frame on the system's call stack, and the stack remembers where to resume after a neighbor is finished. It is correct, but a chain of 5,000 nodes overflows Python's default recursion limit, and Java fails at a far greater depth.

The bottleneck and the key observation

Recursion already is a stack, managed for you. Replace it with your own and the depth limit goes away. Pop a node, skip it if it was seen, visit it, and push its neighbors in reverse so the first neighbor ends up on top and is explored first. Mark a node as seen when it is popped, not when it is pushed. That reproduces the recursive visiting order exactly.

Optimal approach

  1. Push the start node onto the stack.
  2. Pop a node. If it was already seen, skip it.
  3. Mark it seen and record it in the visit order.
  4. Push its unseen neighbors in reverse order.
  5. Repeat until the stack is empty.
ApproachTimeSpace
Recursion (call stack)O(V + E)O(V) for the call stack
Explicit stackO(V + E)O(V)

Watch for

  • Without the reversal, neighbors are visited in the opposite order. The traversal is still a valid depth-first search, but it will not match the recursive output.
  • Marking nodes seen on push, instead of on pop, gives a different order, and on some graphs it is no longer a true depth-first order.
  • Python's default recursion limit is about 1,000 frames. In an interview, say that an explicit stack avoids this limit.

Review

Common mistakes

Conceptual

  • Choosing a stack when you need a queue, deque or heap. Ask which item must be handled first, the newest or the oldest.
  • Forgetting what the leftovers mean. After the loop, ask what it means that these items are still on the stack.
  • Wrong monotonic direction. Next greater means a decreasing stack, popping while the top is smaller. Verify with a three-element example.

Python and Java

  • Popping or peeking an empty stack. Always write if stack and ....
  • Using list.pop(0). It is O(n). Pop from the end, or use a deque.
  • Storing values when you need indices. You cannot compute distances from values.
  • Mutating the input, like heights.append(0). Use heights + [0].
  • Comparing boxed Integers with == in Java. Unbox first, or use equals.
  • Trusting Java's iteration order. A Deque iterates from the top.

Complexity

  • Calling the monotonic stack O(n²) because of the nested loop. Each element is pushed once and popped at most once.
  • Forgetting the O(n) space of the stack.

Boundaries

  • Off-by-one in widths. Test [2,4] in the histogram problem.
  • Mixing up < and <= on duplicates.
  • Checking the final stack in only some problems. Valid parentheses needs it empty. Daily temperatures does not.

Interview reasoning

  • Coding before stating the invariant.
  • Skipping the brute force. Say it, give its complexity, then name the bottleneck the stack removes.
  • Memorizing that monotonic stack means next greater. If you understand "resolve the waiting elements", variants like previous smaller or span become easy.
